# Phase 9 — UI Design Contract

> Visual and interaction contract for Open-Capacity Bookings (OPEN-01..04). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase adds NO new design system, tokens, fonts, spacing steps, or color values.** It EXTENDS the FitOut design system locked across Phases 02–08 (shadcn `radix-nova` / neutral / lucide / Geist; the 8-point spacing scale; 4-size / 2-weight typography; the 60/30/10 coral-accent contract). Every surface below composes from, or forks, a component that already ships in `src/components/ui` or `src/components/{availability,booking,listing,search,host}`.
>
> **The phase's shape is set by ONE invariant** (09-CONTEXT OC-02): **a date is one pass.** The booker picks a DATE — never an hour window — pays a flat per-head price, and may enter any time during the host's operating hours that day. Duration NEVER scales price. Everything visual follows from that: no hour chips, no "Book full day" button, no duration line, no time range presented as a reservation.
>
> **The second invariant is scarcity honesty** (OC-11): the number of spots left is a *server-derived* fact, shown *exactly* only when it is genuinely low, and `Fully booked` is a normal, calm, programmatically-disabled state — never an error and never a dead end.

## Spots-left contract (OPEN-04 · OC-11 / OC-12 / OC-13) — **the researcher-owned core of this phase**

### The threshold — decided and justified **[researcher's call]**

```
OPEN_LOW_STOCK_MAX = 5                                   // config-tunable, server-side
lowStockThreshold(cap) = clamp(floor(cap / 2), 1, OPEN_LOW_STOCK_MAX)
```

| `cap` | threshold | urgency fires at |
|---|---|---|
| 1 | 1 | 1 left |
| 2 | 1 | 1 left |
| 4 | 2 | ≤ 2 left |
| 6 | 3 | ≤ 3 left |
| 10 | 5 | ≤ 5 left |
| 40 | 5 | ≤ 5 left |

**Why the half-capacity clamp, and not a flat ≤5** (OC-11's stated default): a flat 5 on a 6-person studio marks the date urgent from the **very first booking** (5 of 6 remaining), and on a 4-person space it is urgent before anyone has booked at all. A scarcity signal that is on by default is noise, and bookers learn within one session to ignore it — which then costs the signal its value on the 40-cap gym where it is genuinely true. The clamp guarantees the urgency state **can never fire while more than half the day's admissions are still open**, and the `≤5` ceiling stops a 40-cap gym announcing "Only 18 left", which is not scarcity. OC-11's "default ≤5, config-tunable" is preserved exactly: `OPEN_LOW_STOCK_MAX` is the tunable, and it is 5.

### The state must be SERVER-DERIVED and ride on the read model

The read model returns, per queried date, `{ remaining, cap }` (09-RESEARCH Pattern 4) **plus** a discrete `state: "open" | "low" | "full"` computed server-side from the threshold above.

**The client must NOT re-derive the threshold.** Two shipped precedents make this non-negotiable:
- **D-100** — `bookingMode` rides along on `DayAvailability` "so the picker's minimum-notice copy can never disagree with the thresholds the server actually enforces" (`availability-calendar.tsx:213-215`).
- **D-75 / `serviceFeeBps`** — a non-public env override is not inlined into the browser bundle, so a client-side default silently disagrees with the server (`availability-calendar.tsx:236-242`). `OPEN_LOW_STOCK_MAX` is a server config constant with exactly the same exposure profile.

### The three chip states — exact contract

| `state` | Copy | Treatment | Non-color signal |
|---|---|---|---|
| `open` (remaining > threshold) | `Spots available` | `Badge variant="secondary"` + lucide `UsersRound` (muted) | The word "available"; **NO number** (OC-11) |
| `low` (1 ≤ remaining ≤ threshold) | `Only {remaining} left` | Soft brand tint — `border-brand/30 bg-brand/10 text-foreground`, coral `UsersRound` glyph, text 14/600, `tabular-nums` on the numeral | The exact numeral in the text; distinct wording |
| `full` (remaining = 0) | `Fully booked` | `Badge variant="secondary"` + `text-muted-foreground` + lucide `CalendarX2` | The words; the date cell is `disabled` + struck |

Rules:
- **`Only 1 left` is the singular form of the same string** — no separate copy, no "Last one!".
- The chip lives inside a container with `role="status"` so a date change is announced to AT (mirrors the SlotPicker gap hint, `slot-picker.tsx:242-244`). The chip itself is never focusable and never clickable.
- The chip renders in exactly **three** places: the listing-page day panel, the search card **when a date is in play**, and the reserve-page booking summary. Nowhere else.
- `full` **never appears on a search card** — Stage-2 filters open listings out of results unless the picked date has ≥1 spot left (OC-12). It appears only on the listing page's day panel and month grid.

### Where the number does and does not appear

| Context | Badge | Price | Scarcity |
|---|---|---|---|
| Search card, **no date** chosen | `Drop-in` | `₱350/person` + `Service fee included` | **None** (OC-12) |
| Search card, **date in play** | `Drop-in` | `₱350/person` + `Service fee included` | The chip, on its own line with `{Fri, Aug 8} · {City} time` |
| Listing page month grid | — | — | Binary only: selectable vs `Fully booked` |
| Listing page day panel | — | rail carries price | The chip |
| Reserve page summary | `Drop-in` | `PriceBreakdown` | The chip (the state at hold time) |

**Month grid is binary [researcher's call]:** cells render two states only — selectable, or `Fully booked` (disabled + struck + `aria-label`). No per-cell counts, no per-cell dots. *Rationale: 42 scarcity markers competing with 42 date numerals is illegible at 320px, and OC-11/OC-12 both frame the exact count as something shown once a date is **in play** — which is the day panel, not the ambient month.* See Open Question 3.

### 1. Host wizard + editor — the occupancy-mode fork (OPEN-01 · OC-08 / OC-10 / OC-17) — MODIFY `wizard.tsx`

**This is the highest-stakes comprehension moment in the phase.** A host who misreads it either sells their whole gym to one person or sells one court thirty times.

#### 1a. A NEW step, before pricing **[researcher's call]**

Current steps (`wizard.tsx:118-131`): `0 type → 1 details → 2 location → 3 photos → 4 pricing → 5 booking mode → 6 cancellation → 7 review`.

Insert **`occupancy`** as the **new step 4**, immediately before pricing: `… 3 photos → 4 occupancy → 5 pricing → 6 booking mode → 7 cancellation → 8 review`.

*Rationale: the mode determines which fields the pricing step renders **and** whether the booking-mode step exists at all, so it must precede both. Burying a mutually-exclusive business-model choice inside a scroll of currency inputs guarantees misconfigured listings. ### 3. OC-07 — offer-the-partial. **The interaction this phase must not get wrong.**

**Recommendation: an inline `alert` pinned at the top of the reserve page — NOT a dialog. [researcher's call]**

*Rationale: by the time `granted` is known, the pending hold already exists (the hold **is** the claim — 09-RESEARCH Pattern 2) and **no money has moved**; payment is a separate, later, affirmative act. A modal fired mid-navigation would have to either block the redirect or unwind a hold the booker never saw, and a dismissed modal leaves the reduction invisible on the very page where the booker approves the charge. A persistent alert on the payment screen is present at the exact moment of consent and cannot be dismissed away.*

| Element | Contract |
|---|---|
| Placement | Top of `/listings/[id]/book`, **above** the `Your booking` summary. Not dismissable. `role="status"`. |
| Variant | Neutral `alert` — **never destructive.** Icon lucide `Info`. Losing a spot to someone faster is a normal marketplace outcome, not an error. |
| Title (20/600) | `Only {M} left for {date}` |
| Body (16/1.5) | `You picked {N} passes, but only {M} {is\|are} still available. Your booking is set to {M} — **{₱new}** instead of the {₱old} estimated for {N}. Nothing has been charged yet.` |
| Secondary action | `Pick another date` — neutral `outline`. Releases the hold and returns to the listing page. |
| The "yes" | The page's **existing coral `Confirm & pay {₱new}`**. The affirmative act on the reduced amount is the confirmation OC-07 requires. There is **no** extra checkbox — that friction pattern is reserved for host cancellation (07-UI-SPEC § 4) and would be misapplied here. |

**Price-delta presentation — both figures, always:**
- `{₱new}` is the **frozen** `quotedTotalCents` for `M` passes — the exact amount PayMongo will charge.
- `{₱old}` is a **display-only, server-computed** all-in figure for `N` passes, labelled as what it was — an *estimate*, because the booker did see it on the listing rail before clicking Book. Showing only the new number would let a figure the booker already read change silently, which is the same class of failure D-75 exists to prevent (here in the downward direction).
- Both are **server-computed props**; the alert performs zero arithmetic (`price-breakdown.tsx` contract).
- Both render `tabular-nums`. **No strikethrough on `{₱old}`** — struck-through pricing is discount grammar, and the booker is getting *less*, not a deal.

**Zero remaining → refuse, calmly.** `placeHold` returns the OC-13 sentinel; `BookCta` renders it through its **existing** calm neutral `role="status"` notice and calls `router.refresh()` so the calendar re-reflects (`book-cta.tsx:76-80`, the shipped `taken` branch). Copy is exactly:

> `Just sold out — pick another date.`

Matching the shipped `That time was just taken. Pick another slot.` grammar (statement + imperative next step, no exclamation, never red). `mapBookingError` (`units.ts:600`) gains the open-capacity branch that returns it.

### 5. Time rendering + cancellation (OC-03 / OC-15 / OC-16) — reuse, with two required copy forks

### 6. Research Open Question Q2 — stepping UP a held open booking (flag, do not over-design)

Stepping **DOWN** is always safe (it frees seats). Stepping **UP** must re-enter the capacity claim, because there may be no room. **The mechanism is the planner's call** (09-RESEARCH Q2 offers: route the step-up through the claim and grant `min(delta, remaining)`, or disallow step-up on a held open booking and require a fresh hold). This contract fixes only what the booker sees, for each outcome the mechanism can produce:

| Outcome | UI contract |
|---|---|
| Full grant | Shipped behaviour: `router.refresh()` re-renders the server-frozen breakdown. No toast. |
| **Partial grant** | The persisted `declaredPax` returns as the granted number (the shipped `useOptimistic` revert already handles the display), plus a `sonner` toast: `Only {K} more were left — your booking is now {M} passes.` **And the § 3 partial-grant alert re-renders on the refreshed page** with the new figures — the same OC-07 confirmation path, not a second pattern. |
| **Sold out** (no room for any extra) | `sonner` error toast: `No more passes left for this day — your {M} are still held.` The existing passes are untouched; the message must say so, or the booker will fear they lost the booking. |
| Step-up disallowed by design | The stepper's `+` control is `disabled` at `declaredPax` with helper `To add more passes, book them separately.` — never a control that fails on click. |

`updateDeclaredPax`'s shipped **expire-before-refreeze** gate (D-108 / 08-13) applies unchanged: a failed expire refuses the re-price and the toast surfaces the refusal.

|---|---|---|---|
| **1** | **Low-stock threshold = `clamp(floor(cap/2), 1, 5)`**, not a flat ≤5. | A flat 5 marks a 6-cap studio urgent from the first booking, training bookers to ignore the signal.
