# Phase 3 — UI Design Contract

> Visual and interaction contract for the Availability & Double-Booking-Guarantee phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase surfaces (from 03-CONTEXT.md + ROADMAP UI hint = yes):**
> 1. **Booker availability calendar** on the public listing detail page (`src/app/listings/[id]/page.tsx:219`) — replaces the "Availability coming soon" placeholder. Month grid → day → hourly-slot selection, rendered in the **venue's local IANA timezone** (D-27 / SC#2). Occupied/blocked/closed hours are visibly unselectable (AVAIL-05); a booker selects a run of consecutive available hours **or** a full day (AVAIL-04 / D-22 / D-23). The book action stays a **state-reflecting placeholder** (real booking is Phase 4) and respects `deriveBookable()`.
> 2. **Host weekly operating-hours editor** — recurring weekly hours with **multiple open–close windows per weekday** (D-25), under the `(host)` dashboard.
> 3. **Host blocks editor** — **close-only** date/time overrides (D-24): a partial time range on a date **or** a whole day; targeting a single **unit** or the whole listing. "Unblock" = remove a block.
>
> **Occupancy model (D-21):** a listing has `unitCount` (default 1). An hour is "available" if **any** unit is free; a free unit is **auto-assigned** at booking. A named-unit picker is **out of scope for v1** (see § Units affordance). Search, checkout, the pending hold, the "just got taken" race UX, and pricing math are **Phase 4** — not this contract.

## Spacing Scale

Reuses the locked 8-point scale (Tailwind v4 defaults; all multiples of 4). No custom spacing tokens.

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `1` | Icon-to-label gaps, slot-chip inner padding, tz-note spacing |
| sm | 8px | `2` | Slot-grid gutter, weekly-hours window row gap, badge padding |
| md | 16px | `4` | Default control spacing, calendar ↔ slot-column gap (mobile), card inner padding (mobile) |
| lg | 24px | `6` | Card inner padding (desktop), editor section padding, calendar ↔ slot-column gap (desktop) |
| xl | 32px | `8` | Detail-page section gaps, host-editor page column gaps |
| 2xl | 48px | `12` | Major detail-page section breaks (…Location → Availability → rail) |
| 3xl | 64px | `16` | Page top/bottom padding (desktop) |

**Exceptions:**
- **Touch targets ≥44×44px** for every interactive cell: calendar day cells, hour-slot chips, weekly-hours time selects, add/remove-window buttons, block-list rows. On dense desktop slot grids the *visual* chip may be shorter, but the **hit area is padded to ≥44px**. This is a hit-area floor, not a new spacing step.
- **Hour-slot grid** uses a fixed 8px gutter (`gap-2`). Slot chips are a uniform min-height of 44px.

## Typography

Reuses the locked contract: single family (Geist), exactly **4 sizes**, exactly **2 weights** (400 regular, 600 semibold). No third weight, no italic.

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Display | 28px | 600 | 1.2 | (Reused) page/section-level heading — not net-new here |

Rules:
- **Slot times and the price estimate use `tabular-nums`** so digits align in the grid and the rail (Geist sans — never switch to mono).

- Headings stay weight 600 — never 700. The two-weight contract is regular(400) + semibold(600).

**Accent (FitOut Coral) reserved for — EXPLICIT, exhaustive list this phase:**
1. **Selected date** in the month calendar (react-day-picker `selected` day → brand fill).
2. **Selected hour-slot chip(s)** and the selected "Full day" option (the consecutive run the booker has chosen).
3. The **terminal "Book this space" CTA** in the booking rail (state-reflecting placeholder, wired Phase 4) — coral only in its bookable state; its not-bookable state stays neutral-muted "Not bookable yet" (unchanged from Phase 2).

Accent is **NOT** used for: available (unselected) slots, hover states, the "today" ring, occupied/blocked/closed slots, host-editor Save buttons (neutral `primary`), block-list rows, tabs, or the timezone note. Occupied/unavailable slots are **never** red — they are neutral-muted + disabled (occupancy is a normal state, not an error).

### Availability-state visual recipes (executor reference — built from existing tokens, no new tokens)

| State | Surface / text | Signal beyond color (a11y — never color-only) | Interaction |
|-------|----------------|-----------------------------------------------|-------------|
| **Available** (≥1 unit free) | `--card`/`--background` bg, `--border`, `--foreground` text; hover → `--accent`/`--muted` bg | Enabled control, focus ring `--ring` | selectable (pointer) |
| **Selected** (in the chosen run / day) | `--brand` bg, `--brand-foreground` text | `aria-pressed="true"`; check/filled affordance | toggles selection |
| **Unavailable** (fully booked · host-blocked · outside operating hours / closed) | `--muted` bg, `--muted-foreground` text, `line-through` **or** diagonal-hatch | `aria-disabled="true"` + `cursor-not-allowed`; tooltip: "Booked" / "Unavailable" / "Closed" | not selectable |
| **Past / beyond horizon** | `--muted` bg, `--muted-foreground` text, reduced opacity | `disabled` | not selectable |
| **Partially available** (multi-unit: some but not all units free) | Same as **Available** + Label-400 annotation "N of M free" | Text annotation carries the nuance | selectable (auto-assign a free unit) |

Calendar day cells mirror this: days with any availability = Available; fully closed/booked/past/beyond-horizon days = Unavailable (disabled); selected day = coral; **today** = subtle `--ring` outline (never coral).

## Copywriting Contract

Voice (continued from Phase 2): clear, warm, plain verbs; no jargon ("timezone/UTC/exclusion constraint/unit id" never appear in booker copy). Sentence case. **Always name the timezone** the calendar is shown in (SC#2).

### Primary CTAs (one primary per surface)

| Surface / context | Primary CTA label | Notes |
|-------------------|-------------------|-------|
| Booking rail — bookable, slots selectable | `Book this space` | Coral. State-reflecting **placeholder** (wired Phase 4). A selection-summary line above shows chosen date · time range · est. price. |
| Booking rail — published but not payable | `Not bookable yet` (disabled) | Neutral-muted + tooltip (unchanged from Phase 2). Calendar renders **read-only** (see Screen Contract). |
| Host weekly-hours editor | `Save hours` | Neutral `primary`; toast on success (`sonner`). |
| Host weekly-hours — a day with no windows | `Add hours` | Adds a window row to that weekday; day otherwise shows "Closed". |
| Host blocks editor | `Block dates` / `Add block` | Opens the add-block dialog. |
| Add-block dialog | `Save block` | Neutral `primary`. |

### Timezone affordance (SC#2 — load-bearing, always visible)

| Element | Copy |
|---------|------|
| Calendar tz note (Label-400, muted, directly under the "Availability" heading) | `Times shown in {City} time ({GMT±N})` — e.g. `Times shown in Manila time (GMT+8)` |
| Host editors tz note | `These hours are in your space's local time — {City} ({GMT±N}).` |

### Empty states

| Surface | Heading | Body + next step |
|---------|---------|------------------|
| Booker — host has set **no** operating hours | `No availability yet` | `This host hasn't set their hours yet. Check back soon.` (replaces the "Availability coming soon" placeholder) |
| Booker — hours exist but the selected day is fully unavailable | `Nothing open on {date}` | `Every time is booked or closed. Try another day.` |
| Host weekly-hours — none set | `Set your weekly hours` | `Tell bookers when your space is open. Add open and close times for each day — you can add more than one block per day.` |
| Host blocks — none set | `No blocked dates` | `Block off dates or times when your space isn't available — holidays, maintenance, or personal use. Bookers won't see blocked times.` |

### Error / blocked states

| Condition | Copy (problem + solution path) |
|-----------|--------------------------------|
| Weekly hours: close ≤ open | `Close time must be after open time.` |
| Weekly hours: two windows on one day overlap | `These hours overlap. Adjust them so each block stands on its own.` |
| Add-block: end ≤ start (partial range) | `Pick an end time that's after the start time.` |
| Add-block: no date chosen | `Choose a date to block.` |
| Save failed (hours or block) | `Couldn't save your changes. Try again.` |
| Availability refreshed (live refetch found new bookings) | `Some times just filled up — we've refreshed the calendar.` (info toast; Phase-4 relevance, spec'd here for the live view) |

### Destructive / reversible confirmations

No hard-destructive (irreversible) actions in this phase. All removals are reversible and use **neutral** styling — never `--destructive`.

| Action | Confirmation | Confirm button |
|--------|--------------|----------------|
| Remove one operating-hours window | Inline, no dialog (reversible until Save) | (trash/×, `aria-label="Remove hours"`) |
| Remove / unblock a block | Inline or light `dialog`: `Remove this block? Those times will open for booking again.` | `Remove block` (neutral `secondary`) |

## Units affordance (D-21 — decided here, autonomous)

- **Locked:** the booker calendar shows **no unit picker** in v1. An hour is Available if **any** unit is free; the system **auto-assigns** a free unit at booking (Phase 4 performs the assignment; Phase 3 only surfaces availability). This satisfies D-21 without per-unit UI.
- **Recommended (planner's discretion, low-cost):** when `unitCount > 1`, annotate each available slot / day with an "N of M free" Label-400 muted count (e.g. "3 of 8 courts free"). This is the *trivial* surfacing of unit identity that CONTEXT.md allows — it communicates scarcity and the multi-unit model without a picker.
- **Deferred:** named units ("Court A") and a named-unit picker (per D-21 / Deferred Ideas). If the planner later adds a picker, it does not change this contract's color/typography rules — a selected unit uses the neutral `primary` selected state, not coral.

## Screen / State Contract

Every interactive surface defines loading / empty / error / selected / disabled states.

| Screen | Key states the executor must implement |
|--------|----------------------------------------|
| **Booker availability calendar** (public detail page) | loading (skeleton calendar + slot column) · **no hours set** (empty: "No availability yet") · day selected + slots shown · **day fully unavailable** (empty: "Nothing open on {date}") · slot(s) selected (coral + rail summary) · occupied/blocked/closed slots disabled+labelled (AVAIL-05) · **`!bookable` → read-only** (slots visible, selection disabled, rail shows "Not bookable yet") · past/beyond-horizon days disabled · tz note always visible |
| **Host weekly-hours editor** | loading · empty ("Set your weekly hours") · editing (add/remove windows, multiple per day, "Closed" days) · validation error (close ≤ open / overlap) · saving / saved (toast) · save-failed |
| **Host blocks editor** | loading · empty ("No blocked dates") · list populated · add-block dialog (date → whole-day/partial → whole-listing/unit → optional reason) · validation error (end ≤ start / no date) · saving / saved · remove/unblock (reversible confirm) |

**Visual hierarchy / focal point (locked, per surface):**
- **Booker availability calendar:** the day's **hour-slot grid is the primary focal point** once a day is chosen — the month calendar is the entry point that leads the eye into it, and the **booking rail summary is secondary**, staying quiet until a slot is selected. On selection the coral chip(s) and then the coral **"Book this space" CTA** become the terminal focal point, so the eye travels date → slots → rail. Coral appears nowhere else, which is what enforces this order.
- **Host weekly-hours editor:** the **weekly windows list is the anchor**; the single neutral `Save hours` primary is the terminal action.
- **Host blocks editor:** the **list of existing blocks is the anchor**; `Add block` is the entry point and, inside the dialog, `Save block` is the terminal action.

**Interaction rules (locked):**
- **Selection is enabled only when the listing is `bookable`** (`deriveBookable()`). A published-but-not-payable listing still **displays** its real availability (read-only preview) but the rail shows the existing disabled "Not bookable yet" affordance — no dead-end selection. Availability may be *shown*; a slot is only *selectable/sellable* when bookable (CONTEXT § Bookability).
- The booker may select **any run of consecutive Available hours** within one operating window (D-22), **or** the "Full day" option (the operating window at the day rate, D-23). No fixed max run.
- **60-minute, on-the-hour slots only** (D-22). Times render in venue-local **12-hour** format with the timezone always named (SC#2).
- Occupied / host-blocked / closed hours are **visibly distinct and unselectable** (AVAIL-05) — disabled + strike/hatch + tooltip, never red, never color-only.

**Accessibility (non-negotiable):**
- Slot chips are real buttons: `aria-pressed` for selected, `aria-disabled` + tooltip for unavailable, keyboard-operable (arrow-key roving focus within the grid). Selection is **not** drag-only.
- Calendar day-cell state is exposed to assistive tech (react-day-picker handles `aria` for disabled/selected/today); the "today" indicator is not the sole cue.
- The timezone note is programmatically associated with the calendar region (`aria-describedby`) so screen-reader users hear which timezone the times are in.
- Availability state is **never signalled by color alone** — always paired with disabled state + strike/hatch + a text/tooltip label.
- All host time `select`s have associated `<label>`s; validation errors announced via `aria-live` (reuse the `form` pattern).
- Coral selected chips: `--brand` + `--brand-foreground` meets ≥4.5:1 (verified in Phase 2).
