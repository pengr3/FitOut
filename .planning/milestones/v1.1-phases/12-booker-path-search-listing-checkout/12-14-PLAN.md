THE D-58 TRAP, quoted so it cannot be discovered late: the OG route answers 200 WITHOUT a database —
`og-facts.ts` returns null and it serves the `GenericCard`, byte-identical to the root card at 25,844 B.
A baseline shot without a fixture is green forever while covering the wrong card. FALSIFIABLE: the
captured listing OG image's byte length is NOT 25,844, and its `alt` export contains the seeded listing's
title. Both assertions go in the spec, not in a comment.

THE CLOCK. Phase 11's GATE-01 note reads: "none of the baselined surfaces renders a clock, so no time
freeze is needed — record that, so the first surface that does (Phase 12's countdown) knows it must add
one." The checkout baseline installs a fixed clock IN ADDITION to `e2e/visual/freeze.css`. Install the
clock BEFORE navigating — that is the API's own caveat, and this is the repo's first clock user outside
`e2e/hold-countdown.spec.ts`.

THE THEME-SWAP SMOKE (D-135) applies to every surface above: the two theme captures must differ byte-wise.
Grove moves geometry, type and elevation, so IDENTICAL two-theme screenshots mean that surface ignored the
tokens.

WHAT MUST NOT CHANGE IN `.github/workflows/baselines.yml`, because these are security properties and not
style — the file's own header enumerates them:
  · the ONLY trigger stays `workflow_dispatch` (no push, no pull_request, no schedule)
  · the workflow-level default stays `permissions: contents: read`, with write granted on the ONE job
  · `github.event_name` stays in the concurrency group
  · the commit step stages the Linux-baseline glob and NOTHING else, and fails if anything else is staged
  · `--update-snapshots` stays confined to this file, in exactly one run command
  · ZERO `secrets.*`, zero third-party actions, and the pinned Playwright image tag equals the installed
    `@playwright/test` version exactly

⚠ THAT FILE'S HEADER ALSO RECORDS THAT A SUBSTRING CHECK OVER IT IS FALSELY GREEN FOR SIX OF SIX REAL
MUTATIONS, including an ADDED `push:` trigger — the single most dangerous edit anyone could make here.
Verify any change by PARSING the yaml, never by grepping it.

WHAT DOES CHANGE, and it is the one security-relevant edit: the job currently sets `DATABASE_URL` to a
deliberately unreachable port BECAUSE every Phase-11 baselined surface was DB-free. Phase 12's are not.
Replace it with an EPHEMERAL POSTGRES SERVICE CONTAINER plus a seed step running the committed script.
That is not a credential — the service's user and password are fixed, local to the runner, and reachable
only from inside the job. The invariant the old value encoded is preserved in a new form and must be
written into the header: if a baselined surface ever needs a REAL secret, that is the signal it has left
GATE-01's scope, and the fix is the inventory rather than a credential in the one job that can write to
the repository.

⚠ AND THE INVARIANT THAT MAKES THIS PLAN NON-AUTONOMOUS: a `GITHUB_TOKEN` push creates no workflow run, so
the job that WRITES the baselines has never compared against them. The follow-up run is a required step.
Without it, D-27 produces baselines nobody has ever seen pass — strictly worse than having none, because
the gate now looks armed.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI job with `contents: write` <-> repository | The one job that can write to the repo must be reachable only by a deliberate human action |
| baseline reference <-> every future run | Whoever produces a baseline decides what "correct" means for the rest of the project's life |
| seeded fixture <-> captured pixels | A capture of the wrong page becomes a reference every future run agrees with |
