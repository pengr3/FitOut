<objective>
Make the listing rail render the real `PriceBreakdown` from the widened table, give the fee line its own
explanation, and remove the second rate that only becomes visible once the breakdown moves in.

Purpose: BFLOW-04 says the booker should recognise the rail's price and checkout's price as *the same
fact*. That is a claim about pixels, so it is settled by a computed-style comparison in a real browser, not
by the two files importing the same component.
Output: an itemised rail, one fee explainer, and the gate that proves the two totals are the same shape.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server-computed table -> rail render | Money crosses as finished figures only; a rail that computes is a GATE-05 failure |
| client copy -> fee disclosure | A hardcoded percentage in a client component is a number that can go stale while checkout charges something else |
| overlay primitives -> focus management | A second focus-trap implementation is where hand-rolled overlays fail |
