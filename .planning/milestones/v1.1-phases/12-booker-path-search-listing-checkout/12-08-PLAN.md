  container  `grid rounded-lg border overflow-hidden`; `grid-cols-2` below 700px, `grid-cols-{n}` at
             >=700px where n is the number of cells rendered (3 or 4)
  cell       `p-4 border-r last:border-r-0`; below 700px the right border drops on even cells and a bottom
             border appears on the first row
  label      `<dt>` `text-label text-muted-foreground`
  value      `<dd>` `text-body font-semibold text-foreground mt-0.5`
  icons      NONE. Variant A's glyph row lost; adding glyphs back is a third treatment nobody chose.

  exclusive listing, up to four cells in this order:
    `Capacity` / `Up to {N}`                       when maxOccupancy != null
    `Space`    / `{SPACE_TYPE_LABELS[primary]}`    when a space type exists
    `Booking`  / `Instant` | `Host approves`       always
    `Units`    / `1 of {N} {courts|rooms|spaces}`  when unitCount > 1

  drop-in listing, four cells, and `Units` is NEVER one of them (a drop-in listing sells spots in one
  shared space, so a unit count says nothing true about what is being bought):
    `Space` / `{space type}` · `Booking` / `Instant` | `Host approves` ·
    `Day pass` / `Shared space, any time they're open` · `Spots a day` / `Up to {N}`
  The label reads `Spots a day` rather than `Capacity` because the 09-UI-SPEC booker vocabulary bans
  "capacity" on drop-in surfaces.

THE HOST BLOCK — avatar, first name, `Host since {June 2026}` (`formatMemberSince` is shipped), bio, all
from the Phase-1 `publicProfile()` allow-list. On a request-to-book listing it adds, in words:
