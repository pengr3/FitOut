<objective>
Move the day, the day's availability, its loading flag and its error flag out of `AvailabilityCalendar`'s
local state into the provider that already wraps the booking grid, and make the listing page finally read
the window the booker searched.

Purpose: this is the first of the three architectural seams. The D-48 sheet mounts a second booking view,
the D-55 collision must land refreshed availability in the same paint, and D-59 #1 requires the searched
day to survive the whole path — all three are impossible while the day is `useState(initialDay)` seeded
for today inside one of two placements.
Output: one hook, one fetch, one day; and a listing page that opens on the day the booker asked for.
</objective>

Move `day`, `dayAvail`, `loading` and `error` out of `AvailabilityCalendar` and into
`BookingSelectionProvider`, exposing them through `useBookingSelection()` alongside `selection` /
`setSelection` / `openSelection` / `setOpenSelection`. Add `selectDay(next: DayLocal)` and
`refreshDay(): Promise<void>` to the same context. `selectDay` owns the whole transition: set the day, set
`dayLoading` true, await `getDayAvailability(listingId, next)`, set `dayAvail` and clear the flags, or set
`dayError` on rejection. `refreshDay` repeats that for the CURRENT day and returns the promise so a caller
can await it — that is the seam plan 12-13 uses for the collision.

The provider therefore needs `listingId`, `initialDate` and `initialDay` as props. Take them, and keep
`AvailabilityCalendar`'s existing props intact so no external call site's prop list changes shape more than
it must; `AvailabilityCalendar` becomes a pure consumer that reads the four values and calls `selectDay`
instead of owning a fetch. Rename nothing that is exported.

Guard against a stale response overwriting a newer one: keep a mutable request token (a ref incremented per
call) and ignore any resolution whose token is not the latest. Two placements sharing one hook makes this a
real race rather than a theoretical one, and it is cheaper than an AbortController on a server action.

The five named exports stay: `BookingSelectionProvider`, `useBookingSelection`, `AvailabilityCalendar`,
`RailSelectionSummary`, `RailPassSummary`. Do not touch the money props, the `AllInTable` lookups, the
`Est.` labels, the day-cell classes or the slot skeleton — plans 12-04, 12-05, 12-06 and 12-09 own those,
and mixing them in here makes this refactor unreviewable.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser URL -> listing RSC | `date`, `start`, `end` are attacker-controllable strings that reach a `::date` cast and a slot-selection seed |
| client hook -> `getDayAvailability` server action | Server-action arguments are not runtime-typed; the action's own Zod schema is the only gate |
| client selection state -> hold creation | A seeded selection must never be treated as authorised; the hold action re-derives price and availability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02-PARAMTAMPER | Tampering | searched-window params | mitigate | `searchedWindowSchema` through `parsePickedDate` / `parseWindowHour`; a garbage value yields no window and the default view, never a throw; asserted by `tests/validation/search-window.test.ts` |
| T-12-02-FORMATMIX | Tampering | `start`/`end` dual format | mitigate | `slotSelectionSchema` stays byte-unchanged and `resume=1` stays the discriminator; the two schemas are asserted to reject each other's formats from both directions |
| T-12-02-SEEDTRUST | Elevation of Privilege | seeded slot selection | mitigate | The selection is seeded ONLY when the read model reports those hours free; `placeHold` re-derives availability and price server-side inside the transaction and remains the sole authority (D-130) |
| T-12-02-ENUM | Information disclosure | `getDayAvailability` | accept | Deliberately unauthenticated for a published listing (T-03-ENUM, accepted in v1.0). This plan does not widen its payload and adds no caller-supplied status; the published + non-deleted gate is re-enforced inside the action |
| T-12-02-RACE | Tampering | hoisted day fetch | mitigate | Per-call request token; a stale resolution is discarded rather than allowed to overwrite a newer day, asserted by a jsdom probe |
| T-12-02-SC | Tampering | npm/registry installs | mitigate | Zero packages. `git diff --stat package.json` must be empty |
</threat_model>
