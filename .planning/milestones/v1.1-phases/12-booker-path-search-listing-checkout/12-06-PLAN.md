THE RULE, stated once so no component re-derives it:

  1 the RESULT of something the user did        role="status" (implicit polite). NEVER assertive.
  2 a genuine failure needing a human           role="alert". Occupancy, expiry and sold-out are NOT failures.
  3 a ticking value                             role="timer" + aria-live="off" on the digits, plus a SEPARATE
                                                sr-only polite region changing only at declared thresholds
  4 loading                                     role="status" aria-busy="true" with a non-empty accessible
                                                name; every placeholder bar aria-hidden="true"
  5 any live region                             has an accessible name, or is inside a region that does
  6 any outcome                                 EXACTLY ONE live region announces it
  7 the whole booker path                       aria-live="assertive" is BANNED

⚠ THE MEASURED FACT THAT SHAPES EVERY REGION (from `tests/design/skeleton-a11y.test.tsx`): `role="status"`
is `nameFrom: author`, so a status div containing only an `sr-only` span computes an accessible name of
`""`. The `aria-label` is the NAME; the `sr-only` child is the region's CONTENT. They are different
mechanisms and both are wanted.

⚠ `dom-accessibility-api` is never imported directly anywhere in this repo — it is reached THROUGH
`@testing-library`'s `{ name }` option. Plan that idiom; do not add an import.

THE FILE-SPLIT DECISION (PATTERNS names this as a planner call, not an executor's): ONE file,
`tests/design/live-regions.test.tsx`, with `// @vitest-environment jsdom` on line 1. `skeleton-a11y.test.tsx`
is the precedent that a `tests/design/**` file may be `.tsx` with that pragma and still run under the
DB-free config. The SCAN half reads the nine files from disk with `node:fs` and asserts structure; the
RENDER half renders two tiny fixtures — a status div with an sr-only child only, and the same div plus an
`aria-label` — and asserts the computed names are `""` and the label respectively. The render half proves
WHY the scan demands `aria-label`; it deliberately does NOT import the domain components, because they
reach server modules and the design config is DB-free by construction.
