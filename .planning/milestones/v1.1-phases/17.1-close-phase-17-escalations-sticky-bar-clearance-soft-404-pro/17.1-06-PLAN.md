<objective>
Take the network out of `/host/payouts/refresh` without taking the measurement out.

Purpose: `[17-D18]` is *"the only assertion in this suite that leaves the machine"* — real POSTs to
`api.paymongo.com` carrying whatever `PAYMONGO_SECRET_KEY` the local `.env` holds, on every full e2e
run, consuming a rate-limit budget and writing audit rows. Its prescribed repair, `page.route` on the
PayMongo origin, **cannot work**: Playwright's network API is scoped to the browser and the POST is
issued in the Next server process. This is the second time this phase family has caught that error
class — `[17-D26]` prescribed `page.clock` against an RSC-computed value, was refuted by measurement,
and was replaced with a server seam. That server seam, `src/lib/dev/today-override.ts`, is the
template here.

**Keep the row.** Dropping it would leave the route unmeasured, which `[17-D18]` itself argues is
worse than the calls. The seam takes the network out; it does not take the measurement out — which is
why the substituted response must be the **gated-error shape** and nothing else.

**And keep it out of production.** This seam sits in the server boot path of a money-handling
marketplace. It is guarded the way the repo's one existing server seam is guarded, and pinned by the
same kind of test — inertness with a positive control, because a function that always returns nothing
passes an inertness test while asserting nothing at all.

Output: one guarded root file, one security test, two green spec rows, one closed ledger row.

    that it therefore does not widen the guard — this is the one reason the env-read assertion in Task
    2 admits two names instead of one.

    **THE IMPORT IS DYNAMIC AND IT COMES AFTER BOTH GUARDS.** `await import("undici")` inside the
    guarded body — never a top-level `import ... from "undici"`. Two reasons, both stated in the file:
    a top-level import puts a **devDependency** into the production server bundle, which
