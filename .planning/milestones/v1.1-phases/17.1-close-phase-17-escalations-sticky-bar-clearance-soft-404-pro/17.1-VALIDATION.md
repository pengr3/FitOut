## Sampling Rate

- **After every task commit:** `npm run build`, then `npx tsc --noEmit`, then the per-file e2e for
  whatever the task touched, `--project=chromium --workers=1`, **alone**.
- **After every plan wave:** `npm run build` → `npm test` **ALONE** → every e2e file the wave touched,
  per file, each failure compared against `e2e-baseline-reds.md`'s 10 declared rows.
- **Before `/gsd:verify-work`:** the full local set green, **plus** a green `ci` run whose
  `headSha == git rev-parse HEAD` with `gate-visual` included.
- **Max feedback latency:** ~120s (`npm run build`). See "Accepted latency exception" below.

**Nyquist note.** The four items' defect classes have very different natural frequencies. Item 4's
class (an inventory drifting from disk) is sampled **per commit** and is well-covered. Item 3's class
(an outbound call) is sampled at **zero** — nothing measures it today; this phase leaves behind a
standing net-connect policy in `instrumentation.ts` so the rate stops being zero (which policy —
`disableNetConnect()` or `enableNetConnect()` with a predicate — is decided by P3's census, not here). Item 1b's class (a class present but overridden)
was sampled at zero for the entire life of the constant; the band case raises it to "per manual e2e
run", and the computed-padding clause makes a future override fail on a pixel rather than survive on
luck.

### GAP-1 — RESOLVED

**Finding.** Item 2 closed on a *negative* result: § P1 measured 404 / 404 / 200 under a production
build, no repair was licensed, and no file changed. That is a legitimate closure — but it left the
finding's defect class with **no per-commit witness**. Items 1b, 3 and 4 each ended up with a

gone unobserved until a human ran `e2e/public-listing.spec.ts` by hand.

**Fill.** `tests/design/soft-404-status.test.ts` — a structural/AST gate, **10 assertions**, run
per-commit by `npm run test:design` (which `npm run build` and CI `gate-db-free` both invoke). It pins:

- `src/app/listings/[id]/(detail)/page.tsx` imports `notFound` from `next/navigation` and calls it
  as a real `CallExpression` — not a mention in a comment — guarded by an `if` whose condition
  mentions `isPubliclyViewable` (the D-13 rule);
- the exact 2-file `loading.tsx` (Suspense-boundary) inventory under `src/app/listings/[id]/`,
  compared against disk **in both directions** — a missing file fails *and* an extra file fails, so
  the gate is not green on an empty tree;
- vacuity guards and a positive control, including one that discriminates against a real second file
  (`book/page.tsx`, which calls `notFound()` four times for unrelated reasons).

It names `e2e/public-listing.spec.ts:385` as the counterpart **rendering** instrument in its header,
following the structure↔rendering pairing `tests/design/error-boundaries.test.ts` ↔
`e2e/error-leak.spec.ts` already establishes. It **takes no position on when the status line is
