- **D-01:** Item 1 is re-scoped. The ROADMAP's item-1 text describes a state that no longer exists.
  `[17-D9]` and `[17-D10]` were **fixed and closed** by quick `260830-r4b` at commit `4636206`
  (`STICKY_BAR_CLEARANCE` moved off `(detail)/page.tsx`'s `<main>` onto `(detail)/layout.tsx`'s
  `flex min-h-dvh flex-col` wrapper, gated `lg:pb-0`); both rows carry dated RESOLVED lines in
  `deferred-items.md`. The triage commit that inserted this phase landed 22 minutes later and did not
  absorb that. **Do not plan the clearance move.** Item 1 is exactly the two things that remain:
  **1a** the held `baselines.yml` dispatch, and **1b** the checkout route's overridden clearance.

- **D-02:** 1a — the held dispatch is authorised.
  `baseline-evidence.md` §7a ends *"DISPATCH HELD…
  That is a PM call, not an executor's."* The PM has made the call: dispatch. The operative prediction
  is **§7a's corrected one — 2 rows changed, not §4's 3**: `listing-detail-320-court-visual-linux.png`
  (+32px, 2986→3018) and `listing-detail-768-…` (+80px, 2408→2488); `listing-detail-1280-…` is
  byte-identical. 0 added, 0 deleted, disk stays 36. §4's original prediction is left standing verbatim
  in that file — it is the record of what the quick was authorised against — and the correction lives in
  §7a. Anything outside the corrected list moving is a stop, not a re-dispatch.

- **D-03:** 1a is the phase's FINAL wave, and nothing lands after it.
  `ci.yml` has **no
  `workflow_dispatch` trigger**, so the forced comparison run can only be reached by a new commit; and
  §7d requires the green comparison run's `headSha` to equal `git rev-parse HEAD`, so a later commit
  invalidates it. The generation run is **not** the evidence — a `GITHUB_TOKEN` push triggers no
  workflow, so at the moment it finishes nothing has ever compared against the PNGs it wrote. The
  deliverable is the comparison run, recorded per §7b/§7c/§7d.

- **D-04:** 1b — the repair lands even if the band probe measures nothing occluded.
  `sm:py-12` beats
  the unvariant `pb-20` (Tailwind v4 emits variant utilities after unvariant ones), so
  `STICKY_BAR_CLEARANCE` has **never** been in effect at or above 640px on either route. The listing
  route was fixed as a side effect of the wrapper move; `/listings/[id]/book` still carries the
  overridden spelling, giving a 64px bar over 48px of padding across **640–1023px** (both bars are
  `lg:hidden`). Whether a control is actually occluded there is **unmeasured** — measure first, then
  repair **regardless of the outcome**. This is `[17-D10]`'s own argument applied to the other route: an
  inert protection that reads as considered is the defect, and tolerating it "breaks the day the layout
  changes." Leave a **computed-padding assertion** behind so a future override is caught by the pixel
  and not by luck.

### Item 2 — the soft-404

- **D-05:** The probe runs first and the repair is conditional on it.
  Assumption `[A6]` — that the
  soft-404 behaves the same in a production build — has never been driven on this route. **The question
  has inverted** (RESEARCH C1): `[17-D1]`'s claim that the route directory did not move is false —
  `89fb451 fix(260826-l1o): /listings/[id] answers a real 404 again` landed 72 minutes after `[16-D6]`
  measured the 200, so 17-01 measured a **repaired** route, not a flaky one. The probe therefore asks
  *does the shipped layout-assert hold under `next build && next start`?* — expected **404 / 404 / 200**
  (draft / nonexistent / published control). A 200 on the draft is a **regression**, not a reproduction.
  **Do not restructure ten boundaries before knowing.** The published control is mandatory: without it a
  404 proves only that the server is broken.

- **D-06:** If and only if it reproduces, the Shape-A hoist must preserve the served document.
  Hoisting
  a guard into `(app)/bookings/[id]/layout.tsx` changes which document the **owner gate** returns
  (T-04-CONFIRMIDOR deliberately serves the same page for "missing" and "not yours"); falling through to
  the root not-found changes that response. Preserve the document, not merely the status code — or do
  not hoist on that segment.

### Item 3 — the PayMongo interception

- **D-07:** The ledger's prescribed `page.route` repair is REFUTED and must not be planned.
  The POST is
  issued by `paymongoFetch` in the Next **server** process; `page.route` only sees browser requests.
  This is the second time this phase family has caught the same error class — `[17-D26]` prescribed
  `page.clock` against an RSC-computed value and was refuted by measurement, then replaced with a server
  seam. Note also that **unsetting `PAYMONGO_SECRET_KEY` does not stop the call**: `authHeader()` falls
  back to `""` and still sends `Basic <base64 of ":">`. That removes the credential, not the network.

- **D-08:** The seam is D — `instrumentation.ts` + undici `MockAgent`.
  Process-level, in the Next
  server boot path. Chosen because it covers **both** endpoints — `POST /v1/linked_accounts/onboarding_links`
  (the `overflow-320` path) and `POST /v1/linked_accounts` (the account-CREATE path `axe-sweep` reaches
  with a bare-sign-up host) — **both** spec files, and a CI job nobody has written yet, which is item 3's
  own scoping sentence (D-35's boundary). Rejected: **seam A** (`PAYMONGO_BASE` override) puts an
  operator-settable base URL on the one module holding the secret key — a credential-exfiltration
  primitive, and the phase's only possible HIGH finding; **seam C** (page-level `?param`) is the exact
  repo precedent and has the smallest blast radius but covers one route only; **seam B** sits inside the
  rate-limited, audited money-adjacent action.

- **D-09:** The seam carries the `today-override.ts` control set.
  Build-time `NODE_ENV` constant as the
  **first statement** so the bundler prunes the branch — *not* an operator-settable env var, which can be
  flipped on a live deploy — pinned by an inertness test **with a positive control**, modelled on
  `tests/security/dev-today-override.test.ts` (17 assertions incl. a blast-radius walk). `.env.local`
  currently holds an `sk_test_` key, which lowers the urgency and changes nothing about the shape.

- **D-10:** KEEP THE ROW — both rows, in both specs.
  Dropping them would leave the route unmeasured,
  which `[17-D18]` argues is worse than the calls. The seam must return the **gated-error shape** — a
  non-2xx with `{ "errors": [ { "detail": "…" } ] }` — so the `audit` row
  (`action: "startPayoutOnboarding"`, `outcome: "error"`, `meta.reason: "paymongo_error"`), the
  rate-limit accounting and the rendered fallback (`h1: "Let's pick up where you left off"`) all stay
  byte-identical to today's. Otherwise the row stops measuring the branch it names.

- **D-11:** Census before seam.
  RESEARCH C4's second endpoint is **code-derived, not driven**. Task 1
  of item 3 measures method + full URL + count per run across both specs, read against the prediction
  (2 × `onboarding_links` from `overflow-320`; 2 × `linked_accounts` from `axe-sweep`). **An unpredicted
  endpoint or count is a finding**, in `deferred-items.md`'s format, before the seam is written.

### Item 4 — the unreachable boundary

- **D-12:** Delete `(detail)/not-found.tsx` and the header that claims the opposite, coupled to its inventory.
  The file cannot render in any state: `(detail)/layout.tsx` raises `notFound()` from a
  **layout**, so the parent segment's boundary wins and `src/app/listings/[id]/` has none — it falls
  through to the root, measured at 404 with **1** `empty-state` and this file's own copy appearing **0**
  times. The deletion **reds four instruments, two of them build-blocking** — every one must move in the
  same commit as the deletion, never after it. RESEARCH C2: this does **not** move
  `tests/design/loading-coverage.test.ts`'s pins (that gate counts `page.tsx`/`loading.tsx` only),
  contrary to what the row claims.
