## Accomplishments

- **The network is out of `/host/payouts/refresh` and the measurement is not.** All 10 PayMongo requests § P3 measured across the two spec files are now intercepted in-process; 0 reach the wire. All four spec rows still render `Let's pick up where you left off`, the `audit` rows are byte-identical (`action: "startPayoutOnboarding"`, `outcome: "error"`, `meta.reason: "paymongo_error"`), and the 5-per-60s rate-limit accounting is unchanged with no `denied` row anywhere.

## Decisions Made

- **Seam A stayed rejected and `src/lib/paymongo.ts` was not opened.** Making `PAYMONGO_BASE` settable would have been the one-line fix. It is also a credential-exfiltration primitive — `Authorization: Basic <secret key>` follows the base URL — so an operator-settable target on the one module holding the key is a way to post the key elsewhere. `git diff` on that file, on `paymongo-connect.ts`, on the refresh page and on `next.config.ts` is empty for this plan.
- **Catch-all rather than two path-specific interceptors.** § P3's census had already made this cheap to justify: a third endpoint (`[17-D27]`) existed that neither the finding nor the research named, on a different route. The catch-all covers the endpoint added next year on the day it is added.
- **Deny-of-one net-connect, not a blanket block.** `disableNetConnect()` was refuted by measurement, not by preference: `api.resend.com` is reached by shipped application code 14 times across these runs, and blanket-blocking it would change the behaviour of the very runs the audit uses to measure the product — which is `[17-D18]`'s own objection to dropping the row.
- **No escape hatch, and the cost is stated in the file.** The seam is unconditional outside production. That means local work against real PayMongo (the manual onboarding UAT) cannot be done while the file is present; the documented route is to move the file aside and clear `.next/` — a deliberate, git-visible act, never a flag. An operator-settable `E2E_*` variable is exactly what guard 1 exists to refuse.
- **The audit rows were read during the run, not counted after it.** A poller snapshotted the `audit` table throughout both drives, so the rows were captured before `overflow-320.spec.ts:3308`'s `DELETE` removed them. That is the harder of the two options the plan allowed, and it turns "the shape is unchanged" from an inference into a transcript.

None — plan executed exactly as written. No deviation rule fired: no bug, no missing critical functionality and no blocker was met, and no package was installed (`git diff --name-only -- package.json package-lock.json` is empty, as T-17.1-SC requires).

Three places where the plan left the choice open and it was resolved by measurement rather than by preference, recorded here because they were genuine forks:

2. **The watched-red mutation for the guard-position scan.** Swapping guards 1 and 2 — the plan's literal wording — also flips the env-read ORDER, so the env-read test would have reddened too and the reading would not have isolated the property under test. A statement was inserted *above* guard 1 instead, which is the same drift with a cleaner attribution: 1 failed / 12 passed, and it is the position test alone.
3. **Watched red 2 was predicted at 2 failed / 11 passed and measured 3 / 10.** The third row is the `.persist()` test, which also drives a real request. The correction is recorded in both the test header and `§ W3` rather than quietly adopted, per the evidence file's rule 2. The number moved in the safe direction.

## Issues Encountered

- **The `.next` staleness trap § P3 warned about was met and defused, twice.** Every boot in this plan was preceded by `rm -rf .next`, and the dev server was terminated before the file was touched. One `rm -rf .next` failed with `Directory not empty` because file handles had not yet been released after `taskkill`; a second immediate attempt succeeded. No `MODULE_UNPARSABLE` boot failure occurred and no red was misread.
- **Proving the seam LIVE inside the dev-server process needed an instrument, because the shipped seam prints nothing.** The swallowed `catch` in `startPayoutOnboarding` means the interception is invisible from outside: a green row looks the same whether the request was intercepted or really left the machine. Resolved with a throwaway addition placed strictly *below* `setGlobalDispatcher` (an equivalent logging reply callback + a boot self-test), so everything the guards claim is taken from byte-identical code; it was disposed and both specs re-driven together from the committed tree (`158 passed · 43 skipped · 0 failed`). The honest limit of that control is stated in `§ P3-AFTER` rather than absorbed.
- **`gsd-sdk state add-decision` needs `--summary`, not `--decision`**, and `state update-progress` reported `Progress field not found in STATE.md` (the same class of SDK quirk this repo has hit every phase). Decisions were added with the correct flag; the metric row's missing `min` suffix and the decision prefixes were normalised by hand to match their neighbours.
