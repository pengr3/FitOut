## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] A stale `next dev` server on :3000 was 500ing after `.next/` was cleared, and Playwright would have adopted it**

- **Found during:** Task 1 (before the acceptance-criterion e2e run)
- **Issue:** The plan requires clearing `.next/` before building — a stale `.next/dev/types` is the
  recorded cause of a class of false reds. But a long-running `next dev` server (Windows PID `11696`,
  `next/dist/server/lib/start-server.js`, ~2.1 GB RSS) was already listening on **:3000**, started
  before this session, serving the `.next/` that was deleted out from under it. It began answering
  **500 on every route**. Because `playwright.config.ts:113` sets
  `reuseExistingServer: !process.env.CI`, Playwright **adopts** whatever is on :3000 rather than
  starting its own — so the acceptance criterion *"`npx playwright test e2e/public-listing.spec.ts`
  still passes (8 passed)"* would have read as a wall of false reds attributable to nothing in this
  phase. This is `[17-D24]`'s adoption trap arriving from the **dev** side rather than the production
  side the plan's `<interfaces>` warns about.
- **Fix:** Terminated the stale server (`taskkill /PID 11696 /T /F`) so Playwright's `webServer` would
  boot a clean `next dev` against a freshly-generated `.next/`. Nothing was lost — the server's own
  state was already unrecoverable, since it was 500ing on every request.
- **Files modified:** none (a process action, not an edit)
- **Verification:** port 3000 refused connections after the kill; the subsequent
  `npx playwright test e2e/public-listing.spec.ts --project=chromium --workers=1` read **8 passed**,
  including `:385 › a draft listing 404s to the public`.
- **Committed in:** `cfac9c7` — recorded in `17.1-EVIDENCE.md` § P1 under *"One operational finding,
  recorded because it is the same trap from the other side"*, so the next plan that clears `.next/`
  inherits the rule rather than rediscovering it.
