<objective>
Measure what actually leaves this machine when the e2e suite touches `/host/payouts/refresh`, and
declare the one library the seam will need.

Purpose: `[17-D18]` records **2** outbound `POST /v1/linked_accounts/onboarding_links` per full run
from `overflow-320.spec.ts`. RESEARCH **C4** argues a **second, unrecorded** endpoint exists —
`axe-sweep.spec.ts` visits the same route twice with a bare-sign-up host that has no
`paymongo_account_id`, so `ensureLinkedAccount` falls through to `createLinkedAccount` and issues
**`POST /v1/linked_accounts` carrying the host's email address**. That is a resource-CREATE call, it
is not in the ledger, and **it is derived from code, not driven**. D-11 makes the census Task 1.

The census also answers a question the seam cannot be written without: **which other hosts does the
Next server process reach during those runs.** An interception that blocks everything would take out
`next/image`'s server-side fetches along with PayMongo's; an interception that blocks only
`api.paymongo.com` needs the host list to prove there is nothing else worth blocking.

Separately: **`undici` is not a declared dependency.** `npm ls undici` resolves it transitively through
`jsdom@29.1.1` only, and D-08's seam imports it. RESEARCH § Package Legitimacy Audit says this phase
needs **zero** new packages and calls adding one a *"scope alarm ... a supply-chain decision to raise
explicitly, not to absorb"*. It is raised here, at a blocking human checkpoint, and then declared the
way this repo has done it once before — quick `260828-qd5`, which promoted `tsx` to
`"tsx": "4.22.4"`, an exact pin, with the lockfile proving the resolved artefact did not change.

Output: one census transcript, any findings it produces, and one manifest line.
