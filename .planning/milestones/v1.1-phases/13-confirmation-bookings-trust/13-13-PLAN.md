<objective>
Prove the receipt three ways: that its number equals the database's, that it survives being printed,
and that its reference actually lines up.

Purpose: 13-PATTERNS § No Analog Found lists two of these three as genuinely new assertion shapes for
this repository — no spec in `e2e/` emulates print media, and the repo measures box geometry but has
never measured glyph advance width. 13-UI-SPEC closed Open Question 1 as a DECIDED call (the reference
is `font-mono tabular-nums`) and attached the measurement that makes it a decision rather than a
preference; that measurement also settles Assumption A1 for the whole app — if a `font-sans
tabular-nums` money pair does not render to equal width, the Google Fonts build of Geist ships no `tnum`
table, and that is a **finding for Phase 17**, not something to fix here.

Output: three specs, each measuring rather than describing, and each staying inside the CI secret
boundary.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI job → third-party secrets | GATE-05's e2e runs in a job that must never be granted a PayMongo key (D-35) |
| DOM number → DB number | The only assertion that catches a money surface drifting from its source |
| a passing spec → a real guarantee | A spec that emulates nothing, or reads the wrong element, is green and means nothing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-13-SECRETLEAK | Information Disclosure | CI job configuration | mitigate | All three specs take `DATABASE_URL` as their only environment input; a grep for `PAYMONGO` / `sk_test` / `SECRET` returning 0 is an acceptance criterion in each. A spec needing a secret has left D-35's boundary and must be split, not granted the key |
| T-13-13-HOOKAMBIGUITY | Tampering | `receipt-total` | mitigate | The exactly-one-hook guard runs BEFORE the equality assertion, with its own failure message naming the count. With two matches the parity spec would silently parse whichever came first in the DOM — the failure mode `price-breakdown.tsx:363-380` records |
| T-13-13-VACUOUSSPEC | Repudiation | all three specs | mitigate | Each carries a watched red and a control: parity is failed by a 1-centavo drift, print is failed by removing one `print:hidden`, and print asserts the screen direction too so an unemulated run cannot pass |
