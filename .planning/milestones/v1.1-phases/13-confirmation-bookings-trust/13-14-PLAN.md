<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live region → assistive technology | An over-announcing region trains a user to ignore the mechanism; a missing one loses an outcome entirely |
| scope-boundary exclusion → a claim of correctness | An exclusion says "not audited", and inheriting it silently converts that into "fine" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-14-TICKFLOOD | Denial of Service | `request-countdown.tsx` | mitigate | Rule 3 applied: `role="timer"` + `aria-live="off"` on the digits and one separate polite region changing only at a declared threshold. Proved by driving a clock and counting announcements, not by reading the markup |
| T-13-14-GHOSTREGION | Denial of Service | six static-content regions | mitigate | Removed rather than renamed. A region that announces nothing on every navigation is noise, and the module's own note says several of the ten were probably wrong |
| T-13-14-ASSERTIVE | Denial of Service | whole surface set | mitigate | `aria-live="assertive"` is banned by rule 7 and asserted absent tree-wide by grep; the replacement mechanism is a polite region plus moved focus, and on these surfaces even that is usually wrong because a fresh navigation already moves the reading position |
| T-13-14-SILENTINHERIT | Repudiation | `LIVE_REGION_EXCLUSIONS` | mitigate | All ten rows are removed and each file's verdict is landed in code; the type-level count alias is renamed to a MEASURED number so a guess is a compile error |
