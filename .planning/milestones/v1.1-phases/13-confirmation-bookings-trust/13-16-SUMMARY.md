### The four walks, written to be executed cold

#### WALK A — BFLOW-08's real hosted-checkout return

- **Prerequisites:** `npm run db:up`; `npm run dev`; a tunnel per `memory/paymongo-local-webhook-uat.md`
  with the tunnel URL registered at PayMongo Dashboard → Developers → Webhooks.
  ⚠ **The recorded gotcha:** the real-signature header is `te` XOR `li` — `li` is empty in test mode.
  Every confirm webhook 400s until that is handled.
- **Steps:** book a slot as a booker → pay on the **hosted PayMongo page** with a test instrument →
  let the webhook confirm it → land on the return URL.
- **Observe, in order:**
  1. The confirmation moment renders on the return — success mark, `<h1>`, arrival facts, the
     `FIT-XXXXXXXX` reference, the amount paid, `Confirmation sent to {full email}`.
  2. Within one frame, the URL bar reads `/bookings/{id}` with **no query string**.
  3. `page.reload()` (or F5) renders the **ordinary detail page** with no moment anywhere.
  4. **Back** leaves for the cross-origin PayMongo page — it does **not** return into the moment.
- **Why it cannot be automated:** no harness in this repository mints a real hosted-checkout return.
  `probeCheckoutSession` returns `null` for every synthetic `cs_e2e_…` id (13-15, measured).
- **A failure here is a BFLOW-08 defect**, not a test problem.

#### WALK B — TRUST-05's printed page, both themes

- **Route:** `/bookings/{id}/receipt` on a paid booking, once per theme (`court`, then `grove`).
- **Method:** the **browser's own print dialog** → Save as PDF, **Background graphics OFF** (the
  default). Not `emulateMedia` — that is what the automated spec already does.
- **Observe:**
  1. No solid flood — the panel flattens (`patterns/panel-card.tsx`'s unconditional print rule).
  2. The `FIT-XXXXXXXX` reference and the **Total** are both readable.
  3. The status appears as a **WORD**, never as a pill.
  4. **Zero** buttons or links on the page (`print:hidden` everywhere).
  5. The itemisation and the Total are **not split across a page break**.
- **Why it cannot be automated:** `emulateMedia({media:'print'})` proves the stylesheet **applies**. It
  cannot prove a grove-theme receipt is legible on paper.
- **This is the walk that keeps TRUST-05 at PARTIAL below.**

#### WALK C — STATE-05 / D-82 / D-83's manual-return copy

- **Setup:** a **QRPh** test payment, then trigger a gone-slot reversal (the D-58 backstop:
  booker paid, slot already taken, FitOut cancelled).
- **Observe:**
  1. A `needs_attention` audit row appears with `action: "auto_refund_manual"`
     (`npm run ops:alerts` lists it).
  2. The booker-facing copy **never uses the word "refunded"**.
  3. It says the amount is flagged to be returned **by hand**, and carries the reference.
  4. It **never** says *"cannot be reversed"* — D-82's accurate phrasing is *"not reversed
     automatically"*; the funds sit on the FitOut platform wallet and a human can move them.
  5. Then read the same screen **beside a real bank / e-wallet statement** and confirm the two do not
     contradict each other. That comparison is the entire point (13-CONTEXT § Specifics: *"If our
     screen and their statement disagree, our screen is wrong"*).
- **Why it cannot be automated:** the manual return is an operator action **outside the app**.
- ⚠ **A seeded row will NOT reach this branch.** `page.tsx` picks `manual` only when the D-84 probe
  returns a session AND `isApiRefundable(rail)` is false; a seeded reversed row lands on D-96's
  `indeterminate` branch instead. This walk needs a real QRPh test payment, which is exactly why
  `e2e/overflow-320.spec.ts`'s D-83 ordering case names it as blocker (2).

#### WALK D — D-81's standing re-verification of the QRPh refund probe

### The defects the plans did not anticipate — the phase's real yield

Every one of these was shipped, reviewed, and green under every gate that existed at the time.

1. **A discriminator that would have told *every ordinary cancellation* it had been reversed.**
   13-04: the plan's discriminator applied literally would have probed every `cancelled` row — and a

   booking** would have read *"We couldn't complete this booking — we've refunded ₱X in full."* Two
   row-level preconditions now run first; the common cancelled render also pays no round trip at all.

2. **The same branch, one question further out — D-96.** With the probe silent, the fallback row

   probe is deterministically unanswerable on every machine.

   13-15 measured `button[Yes, I'm coming] 256x22` and `button[Can't make it] 256x22` at 320px in both

   app's **most-shared public surface**, green under every existing gate. `share-link-box.tsx` carried
   the identical pattern.

   `sm:`-scoped steps recovering 8px below the breakpoint and changing nothing at or above it — 5px of
   headroom rather than the 1px a single step would have left.
