# Phase 13 — UI Design Contract

> Visual and interaction contract for everything a booker sees about a booking **after they pay**.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## What this document is, and what it deliberately does not touch

**Phases 10, 11 and 12 shipped a complete, gated design system, a pattern layer and the booker path.**
Colour, type, focus, status tones, elevation, z-index, motion, the contrast inventory, the three card
patterns, the four state families, the app shell, the one overlay primitive and the five typed inventories
(`contrast-pairs.ts`, `measurements.ts`, `selector-contract.ts`, `status-tones.ts`, `live-regions.ts`) are
**LOCKED**. `npm run build` = `lint && test:design && next build`, so a raw hex, an arbitrary type size, an
undeclared `data-testid`, a raw `<Card>` in a new file or a skeleton with a literal box class already fails
the build today.

**This document re-decides none of that.** Everything below either *consumes* an existing token, pattern or
recipe, or names precisely where a declared inventory must be **EXTENDED** — and an extension is always
"add a measured row to the declared inventory", never "invent a value at the call site."

Read `10-UI-SPEC.md` for the foundation, `11-UI-SPEC.md` for the shell/states/patterns, `12-UI-SPEC.md` for
the booker path. This file adds six things on top of them:

| # | Adds | Requirements |
|---|------|--------------|
| 1 | **The confirmation moment** — a full-page first screen that decays, inside the same route | BFLOW-08 |
| 2 | **The booking detail page across every status** — one shell, one trust block, one reference | TRUST-01, TRUST-02, TRUST-03, TRUST-04 |
| 3 | **The three payment states** — and the one money sentence that owns all of them | STATE-05, STATE-06 |
| 4 | **The receipt** — a net-new route, designed for screen **and** for paper | TRUST-05 |
| 5 | **The alert/toast split** — what a booker must READ never travels in a toast | STATE-08 |
| 6 | **The group surfaces' design-system pass** — patterns and states only, zero net-new capability | (D-79) |

**The standard, restated because it shaped every criterion below.** Phase 11: *"a gate that has silently
never failed is worse than no gate."* Phase 12: **12-CONTEXT D-59 — when two options both satisfy a
requirement, choose the one that costs the booker less.** Phase 13 adds the one its own CONTEXT names:
**the reversed-payment copy must survive the booker looking at their bank app. If our screen and their
statement disagree, our screen is wrong.**

**The colour authority remains `tests/design/contrast.test.ts` (D-12).** No ratio is re-derived here; this
phase renders **zero undeclared pairings** (§ Color).

**GATE-06 binds. ZERO schema migrations (13-CONTEXT D-80).** `drizzle/` stays at `0025_audit_resolved_by.sql`.
Every surface below is deliverable without a column. A migration proposed under this spec is a scope alarm.

**Decision-ID namespace.** Bare `D-NN` in this file means **13-CONTEXT D-60…D-89**. PROJECT-namespace
numbers are written `PROJECT D-57`, `PROJECT D-79`. Phase-12 numbers are written `12-CONTEXT D-59`.

## Spacing Scale

**Inherited unchanged from Phase 10 (D-05, global — identical in both themes).** The declared legal set:
4 (`*-1`) · 8 (`*-2`) · 12 (`*-3`) · 16 (`*-4`) · 24 (`*-6`) · 32 (`*-8`) · 48 (`*-12`) · 64 (`*-16`).

Phase 11's four exceptions (56px header, 176px auth slot, 80px sticky offset, 85dvh sheet bound) and
Phase 12's six (44px targets, 80px bar clearance, 96px countdown box, the fluid ~41px calendar cell, the
2px optical nudge, and `gap-5`'s retirement) carry forward unchanged.

### Phase 13 declares exactly ONE exception

| Value | Class | Where | Why it is not a ladder step |
|-------|-------|-------|------------------------------|
| **viewport-minus-header** | `min-h-[calc(100svh-3.5rem)] sm:min-h-[calc(100svh-4rem)]` | The confirmation moment's container only | It is not a spacing value; it is the **only way BFLOW-08's "distinct confirmation moment" becomes a measurement instead of an adjective.** `3.5rem`/`4rem` are the *declared* header heights (`HEADER_HEIGHT = "h-14 sm:h-16"` = 56/64px), so the moment fills the viewport below the chrome and the ordinary detail necessarily begins below the fold. **`svh`, not `vh` and not `dvh`:** `vh` includes the retracted iOS URL bar and overshoots; `dvh` re-resolves as the bar retracts, so a `min-height` in `dvh` **grows mid-scroll and reflows the page under the reader's thumb**. Phase 11's "`dvh`, never `vh`" rule was written for a `max-height` on a sheet, where following the live viewport is correct; a `min-height` promise needs the smallest viewport. Different unit, same reasoning, stated so it does not read as a violation. |

**Stored as a constant, never as a call-site literal:** `CONFIRMATION_MOMENT_MIN_H` in
`src/lib/design/measurements.ts`, beside `HEADER_HEIGHT` whose two values it is derived from. A future
header-height change must break in one place.

### One duplication this phase ends, mechanically

`mx-auto w-full max-w-2xl px-4 py-8 sm:py-12` is hand-typed on **six** status branches of
`bookings/[id]/page.tsx`, in `pending-payment-state.tsx`, `payment-reversed-state.tsx`,
`expired-approval-state.tsx`, `cancel/page.tsx` and `bookings/[id]/loading.tsx` — eleven copies of one
string, and `page.tsx`'s own header instructs the next author to "copy the container from `loading.tsx`."
An instruction is not a mechanism.

**Resolution: `BOOKING_SHELL = "mx-auto w-full max-w-2xl px-4 py-8 sm:py-12"` in `measurements.ts`,
imported by every one of them, including the net-new receipt route and its `loading.tsx`.** Every value in
it is already a declared ladder step; nothing about the rendering changes. This is the same argument
`RESULT_GRID_GAP` made in Phase 12, applied to the string that had eleven copies instead of two.

## Typography

**Inherited unchanged.** Four named roles (`text-display` / `text-heading` / `text-body` / `text-label`),
per-theme, pinned by `tests/design/type-scale.test.ts`. Tailwind's re-declared `text-xs…2xl` ladder is legal
and is not a fifth role. Arbitrary `text-[NNpx]` is banned by ESLint **and** a Vitest gate — **including
inside `print:` variants.**

| Role | court | grove | Phase 13 uses it for |
|------|-------|-------|----------------------|
| Display | 28 / 1.15 / 600 / -0.02em | 34 / 1.20 / 700 / -0.005em | The confirmation moment's `<h1>`; the detail page's `<h1>` on later visits |
| Heading | 20 / 1.30 / 600 / -0.01em | 24 / 1.30 / 700 / 0 | The reference on the moment; every `<h2>` section title below the moment; `PanelCard` titles; the receipt `<h1>` |
| Body | 16 / 1.50 / 400 / 0 | 17 / 1.60 / 400 / 0 | The money sentence's first line; the reference on the detail page and the receipt; receipt itemisation values |
| Label | 14 / 1.43 / 400 / 0 | 15 / 1.50 / 400 / 0 | Every muted meta line; the money sentence's second line; trust-block rows; receipt row labels; the tz note |

### Three type rules this phase adds

**1. The booking reference renders in `font-mono`, and this closes RESEARCH Open Question 1 as a
*decided* call rather than a default.**

TRUST-02 asks for "tabular figures". `tabular-nums` normalises **digits only** — and a
`FIT-9K3MP7QZ` reference drawn from Crockford base32 is *mostly letters*, so tabular figures alone do not
make it line up, which is the entire point of the requirement (a string a booker reads back over the phone
or lines up against an email subject). Geist **Mono** is already loaded, already exposed as `--font-mono`,
and has **zero call sites** — so the correct tool is present and unused.

> **Decision: the reference is `font-mono tabular-nums`.** `font-mono` gives every glyph a fixed advance
> width (letters included); `tabular-nums` is retained so the requirement's literal wording is satisfied and
> any all-digit reference stays aligned with the money column above it. It is a **font-family** utility, not
> a fifth size step — the size still comes from a named role (`text-heading` on the moment, `text-body`
> everywhere else). No `tracking-*` override: mono advance widths already own the rhythm, and
> `tracking-tight` on a monospace string is the one place negative tracking reads as a defect.

**Falsifiable, and it settles Assumption A1 for the whole app in the same test** (`e2e/tabular-figures.spec.ts`):
(a) the reference element's computed `font-family` resolves to the Geist Mono stack; (b) two references of
equal character length render to **equal `boundingBox().width`**; (c) separately, a money figure rendered
`font-sans tabular-nums` gives `"₱11,111.11"` and `"₱00,000.00"` **equal width** — if (c) fails, the Google
Fonts build of Geist ships no `tnum` table and that is a **finding for Phase 17**, not something to fix
here. Run in both themes.

**2. Print reuses the four roles and introduces no size of its own.** No `print:text-[NNpx]`, no
`print:text-*` step outside the declared ladder. A printed page whose type came from a fifth scale is a
second, un-gated type system wearing a media query.

**3. No `<p className="font-semibold">` standing in for a heading.** Phase 11 fixed this in the empty
states, Phase 12 in the key-facts strip. This phase's new surfaces are the next place the shortcut is
available: the money statement's first line is a `<p>` (it is a sentence, not an outline entry), the trust
block's rows are `<dt>`/`<dd>` inside a `<dl>` (they are a fact list), and every receipt section opens with
a real `<h2>`.

**Exactly one `<h1>` per rendered document, on every branch.** On `?paid=1` it is the moment's; on every
later visit it is the detail's. **Falsifiable:** `getByRole("heading", { level: 1 })` resolves to exactly
**1** on each of the eight status renders and on the receipt.

### `--destructive` renders nowhere in this phase, and that is the contract

A reversed payment, a failed checkout, a settling webhook and a cancelled booking are **not errors the

that human — the operator alert already raised by `handleGoneSlot` is. Colour-as-alarm on a money surface
tells a booker they did something wrong at the exact moment they did not.

**Falsifiable, as a source scan over the Phase-13 file set:** zero `destructive` tokens
(`text-destructive`, `bg-destructive`, `variant="destructive"`, `--destructive`) under
`src/app/(app)/bookings/**`, `src/components/booking/**` and `src/components/group/**`. This extends the
grep-tripwire idiom `rsvp-confirmation.tsx` and `top-up-nudge.tsx` already use, and it must be written with
the **two-piece string idiom** so the test cannot trip its own scan.

## The Confirmation Moment (BFLOW-08 · D-60, D-61, D-62, D-63)

### Geometry — the decay, stated as a measurement

| Property | Value |
|---|---|
| Route | `/bookings/[id]` — **no second URL** (D-61; a second URL costs the booker a navigation, 12-CONTEXT D-59) |
| Trigger | `searchParams.paid === "1"` **AND** `booking.status === "confirmed"` — both, always. The param alone never moves a branch (PROJECT D-57) |
| Element | `<section data-testid="confirmation-moment">` — a section, not a `<main>` (D-88.1); the layout owns the one `main` landmark |
| Box | `CONFIRMATION_MOMENT_MIN_H` + `flex flex-col items-center justify-center text-center` + `BOOKING_SHELL`'s measure |
| Below it | `<Separator />` then `<section data-testid="booking-detail">` — the ordinary detail page, unchanged, in full |
| Consumption | `window.history.replaceState(null, "", pathname)` in a mount effect, **on the confirmed branch only** (D-89 / Pitfall 2). Never `router.replace`. Never `pushState` |
| Later visits | The same URL renders `booking-detail` alone, with `confirmation-moment` **absent from the DOM** |

**Falsifiable (`e2e/confirmation-decay.spec.ts`):**

1. On `?paid=1` + confirmed: `confirmation-moment` exists; its `boundingBox().height >= viewport.height − 64`.
2. `booking-detail`'s `boundingBox().y >= viewport.height` — the ordinary page starts **below the fold** at
   320×568, 375×667 and 1280×800, in both themes.
3. The URL bar reads `/bookings/{id}` (no query) within one frame of paint; `page.reload()` renders
   `booking-detail` and **zero** `confirmation-moment`.
4. Back goes to the cross-origin PayMongo page, never into the moment.
5. **Seeded `pending`:** the poller runs its full 8 attempts and the URL **never changes** and the page
   **never navigates** — D-89's whole reason for existing.

### What is in the moment, in order

1. **Success mark** — `CheckCircle2`, `size-10`, `text-success`, `aria-hidden`. **Never a filled green
   badge** (retired by DS-10 at 3.24:1); green retreats to the icon.
2. **`<h1>`** — `text-display`. Copy branches on mode, § Copywriting.
3. **The arrival facts** (`instant`) or **the approval fact** (`request`) — venue name, **full address**,
   venue-local date/time with the named timezone, composed by `composeWhenLabel` / `venueTzNote`. No fifth
   date format.
4. **The reference** — labelled `Booking reference`, `text-heading font-mono tabular-nums`, with its copy
   control.
5. **The amount paid** — `formatMoney`, `tabular-nums`, labelled `Paid`.
6. **`Confirmation sent to {full email}`** (D-63) — the **full, unmasked** address. `text-label
   text-muted-foreground`. Masking is rejected: catching a typo is the only reason the line exists.
7. **The condensed trust block** (D-67) — two of the four signals; § The Trust Block.
8. **The cancellation policy** — the existing `CancellationPolicyDisclosure`, whose collapsed `<summary>`
   already carries the concrete-date statement (TRUST-03). Composition, not construction.

**There is no CTA in the moment.** A terminal success screen that immediately asks for another action is
selling, not confirming. Every action (receipt, group, cancel, find another space) lives in the detail
below, which is one scroll away and permanently there.

### Motion — the obvious place to get reduced-motion wrong

| Rule | Value |
|---|---|
| Allowed | **One** non-looping fade+scale on the success mark, `duration-(--motion-slow)` (320ms), `--ease-standard`, one iteration |
| Banned | Confetti, sound, auto-scroll, a number that counts up, a checkmark that draws itself over more than one beat, any `animate-*` with `iteration-count: infinite` |
| Reduced motion | Honoured by the **global `@layer base` reset only** (Phase 10). **No per-component `@media (prefers-reduced-motion)`** — DS-04 requires one global reset and a second mechanism is how the two drift |

**Falsifiable:** under `prefers-reduced-motion: reduce`, every animated element inside
`confirmation-moment` reports `animation-duration <= 0.01ms`; and in **either** motion mode, zero elements
inside it report `animation-iteration-count: infinite`.

### Nothing important lives only in the moment

**Every fact in the list above is repeated inside `booking-detail`** — that is what makes D-60's decay
safe, and it is the acceptance criterion, not a hope. **Falsifiable
(`tests/booking/detail-completeness.test.tsx`):** render the confirmed detail **without** `?paid=1` and
assert the presence of status + meaning, venue name, full address, venue-local time with the named
timezone, host, itemised total, the cancellation deadline as a concrete date with today's refund amount,
the reference, and (guard-open) the support path. The moment adds *prominence*, never *information*.

⚠ **D-87 is part of this criterion, not adjacent to it.** The reversed state is currently reachable only
via `status === 'cancelled' && paid === '1'`. Consuming the param is only safe once the reversed state
renders from **DB state plus the D-84 probe**, with no dependence on the query string. Until that is true,
D-60's safety argument is false for that one state and the param must not be consumed. Order the work
accordingly.

## The Booking Detail Page, Every Status (TRUST-01 · D-67, D-78)

### One shell, eight renders

Every status branch renders the same skeleton, so a booker who has seen one has learned all of them:

```
<div className={BOOKING_SHELL}>            ← div, never <main> (D-88.1)
  [confirmation-moment]                    ← only on ?paid=1 + confirmed
  <section data-testid="booking-detail" className="space-y-6">
     status badge + <h1> + one plain sentence saying what the status MEANS
     <MoneyStatement/>                     ← where the money is, in words  (STATE-06)
     <PanelCard> the facts <dl>            ← venue, full address, when + tz, host, itemised total
     <PanelCard> reference + copy          ← TRUST-02, every status
     CancellationPolicyDisclosure          ← TRUST-03, concrete dates, when a policy applies
     <TrustBlock variant="full"/>          ← TRUST-04, every status (D-67)
     <Separator/> actions block            ← at most ONE coral
  </section>
</div>
```

**The outer `<Card>` that wraps every branch today is removed.** Nesting `PanelCard` inside a container
that already supplies `bg-card ring-1 rounded-xl` pays the block padding twice (measured at 112px vs 80px —
the trap `card-pattern-coverage.test.ts`'s own header records). The page becomes a **stack of panels on the
page ground**, which is what the pattern layer is for. `PriceBreakdown` stays a bare `div` and is **not**
wrapped — the same rule, from the other direction.

**Falsifiable:** every card container on `/bookings/**` renders `data-testid` of `panel-card` or `row-card`;
`card-pattern-coverage.test.ts` stays green with **zero new `ALLOWED_RAW_CARD` rows** and its
`EXPECTED_SURFACES` pin re-measured in the same commit.

### The status must state what it MEANS, not only what it is

TRUST-01's first clause is the one most likely to be waved through, so it is written as a table. One
sentence, `text-body text-muted-foreground`, directly under the `<h1>`. The **badge vocabulary does not
change** — DS-10 owns the words; this adds the sentence beside them.

| Status | Means (the sentence) |
|---|---|
| `requested` | *"The host has this request. You'll hear back before {deadline} — nothing is charged until they approve."* |
| `approved` | *"The host said yes. Pay within {window} to lock in this time."* |
| `pending` (settling) | *"We're waiting on your payment provider to confirm it. This page updates on its own — you don't need to refresh it."* ⚠ **superseded by 13-CONTEXT D-102** — the shipped wording asserted receipt of a payment the webhook has not confirmed |
| `pending` (not completed) | *"This checkout didn't finish. Your slot is still held."* |
| `confirmed` | *"This time is yours. Show this page (or your email) when you arrive."* |
| `completed` (derived) | *"This session is finished. This page stays as your record."* |
| `declined` | the shipped `declinedCopy(cancelledBy)` — **unchanged** |
| `cancelled` (party) | *"This booking was cancelled. It's no longer held."* |
| `cancelled` (lapsed approval) | the shipped `ExpiredApprovalState` copy — **unchanged** |
| `cancelled` (reversed) | *"We couldn't confirm this booking, so it was cancelled."* |

### The address rule — and it is a product fork, flagged

>

### The Print Contract (D-74 · Pitfall 3)

**Print is a real medium here, and the failure it must prevent is specific: `print-color-adjust`'s initial
value is `economy`, Chrome's "Background graphics" box is off by default, so backgrounds drop — and any
near-white ink on a filled surface prints as near-white ink on white paper. Invisible.**

> **Design the printed receipt as ink on white. Do not force colour.**

| Rule | Mechanism |
|---|---|
| Chrome disappears | `print:hidden` on `site-chrome.tsx`'s `<header>` and `site-footer.tsx`'s `<footer>` |
| Controls disappear | `print:hidden` on every `<Button>` and link on the route: the copy control, `View receipt`'s siblings, the cancel entry, the group entry, the trust block, the support control |
| Status survives as a **word** | `print:hidden` on the badge; `hidden print:inline` on `<span>Confirmed</span>` beside it. The pill's meaning is in its shape and fill; the word's meaning is in the word |
| Panels flatten | `print:bg-transparent print:ring-0 print:shadow-none` on every `PanelCard` on the route |
| Measure opens up | `print:max-w-none print:px-0 print:py-0` on the article container |
| Pagination | `print:break-inside-avoid` on the itemisation block and on the Total row — a total split across a page break is the one thing a receipt may not do |
| **Never** | `[print-color-adjust:exact]`, `-webkit-print-color-adjust`, or an `@media print` block in `globals.css`. Forcing exact colour costs the booker ink and buys nothing on a document whose job is to be legible |
| Both themes | `--card` is `#ffffff` in **court and grove**, so the receipt degrades to ink-on-white identically. `--foreground` on white is 19.80 / 18.42 |
| Forward rule | If `.dark` is ever activated, this contract still holds **because the receipt never relies on a painted background.** That is the property to preserve, not a value to re-tune |

⚠ **`print:` utilities compile only inside `@media print`, so screen rendering is byte-identical** — no
`globals.css` edit, so `token-drift.test.ts`'s brace-depth parser and `leak.test.ts` are both out of the

## STATE-08 — What a booker must READ never travels in a toast

**The rule:** terminal success is a **full-page moment**; non-terminal success is a **toast**; anything the
user must actually read — *a refund amount, a reduced headcount, a voided invite* — is an **in-page alert**,
never a toast. A toast is dismissible, timed, unaddressable and gone on refresh. Those three facts are none
of those things.

### The three corrections this phase owes (each is one of STATE-08's own named examples)

| Site | Today | Phase 13 |
|---|---|---|
| `cancel-confirm.tsx` | `toast.success("Booking cancelled. Your refund is on its way.")` | Toast becomes **"Booking cancelled."** The refund fact lands on the destination as a `MoneyStatement` on the cancelled branch, wording preserved per PROJECT D-79 |
| `remove-attendee-button.tsx` | `toast.success("Removed. Their spot is free again.")` | **No toast.** An in-page alert above the roster: *"{Name} removed — {N} coming, {M} spots free."* |
| `regenerate-link-button.tsx` | `toast.success("New link ready. Copy it and share it again.")` | **No toast.** An in-page alert above the share box: *"The old invite link no longer works. Copy the new one below and share it again."* |

**No toast + alert pair.** Two regions announcing one outcome is GATE-03 rule 6's defect; the alert is the
single announcement.

**The in-page alert's form is already declared:** `PanelCard tone="muted"` + `role="status"` + a
non-empty accessible name. **Not** a new pattern, **not** `attention` tone (DS-10 reserves that for genuine
failure needing a human), **not** `--destructive`.

### Toasts that legitimately stay

`cancel-request-dialog.tsx` · every server-refusal `toast.error` (calm sentences, never a stack trace).

**Falsifiable — extend `tests/design/status-vocab.test.ts` with an AST scan** over

## Anti-Patterns — reject these in plan review

- **Consuming `?paid=1` anywhere but the confirmed branch.** `router.refresh()` re-renders the RSC for the
  current URL; on the pending branch the next poll falls into the existing `redirect(…/book?hold=…)` and
  bounces a paying booker back to checkout mid-webhook (D-89 / Pitfall 2).
- **`router.replace` instead of `window.history.replaceState`.** A server round-trip and a second source of
  truth for a URL that has one.
- **`pushState`** — it lets the booker Back *into* the moment. D-60 rules that out.
- **Branching any UI on `?paid=1` beyond the moment itself.** The param is forgeable; the DB status is not
  (PROJECT D-57).
- **A refund amount, a headcount or a voided invite in a toast.** STATE-08, by name.
- **An error affordance on the pending state — at any threshold.** D-71. The webhook is still the
  outstanding authority.
- **The word "refunded" in the manual-return branch.** The money has not been sent back; a human has to
  send it. Two grep tripwires guard this.
- **"cannot be reversed".** D-82: the accurate phrasing is *"not reversed automatically"*. The funds sit on
  the platform wallet and a human can move them.
- **"you haven't been charged" on the reversed state.** It is STATE-05's *not-completed* language and it
  contradicts the booker's own bank app.
- **Any refund window other than the three verified ones** (card 30 days, GCash 24h, Maya 24h) — and **no**
  window at all for QR Ph.
- **Widening `REFUNDABLE_RAILS` to include `qrph`** because the vendor's docs say it is refundable.
  Re-probed 2026-08-20; identical `HTTP 400`. Observed behaviour is authoritative.
- **A fifth trust signal.** No verification badge, no superhost chrome, no rating, no "responds within".
  There is no column and the answer is not a column (D-80).
- **The not-completed state rendering for an expired hold.** `hold-expired-state.tsx` owns that landing.
- **A second checkout-minting path for the retry.** PayMongo does not honour `Idempotency-Key` on
  `POST /v1/checkout_sessions` — probed, and it cost a real double charge. Expire-before-create only.
- **`[print-color-adjust:exact]`, or an `@media print` block in `globals.css`.** Design for ink on white;
  a `globals.css` block also puts `token-drift.test.ts`'s brace-depth parser in the blast radius.
- **A PDF library or a server-side render pipeline.** The browser's print dialog is the deliverable (D-74).
- **Serial numbers, TIN fields, "Official Receipt" wording or BIR styling.** D-75 — that is a business
  decision the PM has not made.
- **Attendee names on a receipt.** Other people's names on a printable financial document, and RSVP state
  changes after payment.
- **Dividing a frozen total to recover a per-head unit.** Positive match or no unit line (D-86).
- **A per-head line on an exclusive group booking.** It prints a number that never equalled the charge, and
  no existing gate would catch it.
- **A raw `<Card>` in a new file**, or a `PanelCard` nested inside a container that already supplies
  `bg-card ring-1 rounded-xl` — 112px of padding where 80px was designed.
- **A second `<main>` landmark.** Three components on this very route still ship one; fix them while there
  (D-88.1).
- **`aria-live="assertive"`**, or a live region on a freshly navigated static page.
- **Weakening, skipping or inverting `tests/design/site-contacts.test.ts`**, or setting `SUPPORT_EMAIL` to
  a placeholder to make a surface pass. D-64 forbids it in three separate sentences.
- **Passing `SUPPORT_EMAIL` down as a prop.** The guard must be lexical and local, or the scanner sees an
  unguarded `mailto:`.
- **A new accent use.** The list stays at 10.
- **Inventing a colour pairing at a call site.** This phase needs none.
- **A schema migration.** GATE-06 binds; `drizzle/` stays at `0025`.

## Open Questions — flagged for the PM, not blocking

Each was decided so the phase can proceed (12-CONTEXT D-59 as the tie-break). Each is a **product** call the
PM may reverse.

1. **D-62's request-mode branch describes a charge that never happens.** D-62 says the request branch should
   lead with *"the booker has been charged, and is refunded in full automatically if the host declines."*
   The shipped flow is **pay-on-approval** (BOOK-06 / D-66): a `requested` booking charges nothing, and the
   detail page's own label is *"You'll pay if approved"*. A request-mode booking only reaches `?paid=1`
   **after** the host approved and the booker paid — so at the moment, nothing is at risk.
   **Decision taken:** describe what is true. The moment's request branch leads with the approval fact and
   the money answer that is real (*"You've paid ₱X in full. FitOut holds it until after your session."*),
   and the **`requested`** status branch carries the risk answer above the fold (*"You haven't been charged.
   You'll pay only if {Host} approves."*). Telling a booker they were charged when they were not is the
   failure mode this phase exists to prevent. **If capture-now for request-to-book is on the roadmap, this
   copy changes with it — it is not a copy fix, it is a flow change.**

2. **The full address on a `showExactAddress = false` listing.** TRUST-01 and BFLOW-08 both require the full
   address; the host chose "approximate" for the public page. **Decision taken:** reveal on `confirmed` and
   derived-`completed` only, through a named `bookedListingAddress()` boundary. This is standard marketplace
   behaviour, but it is a promise to hosts and the PM owns those.

3. **`src/lib/email.ts:341`'s unsourced refund window.** It is a copy constant, not a send trigger, so
   changing it does not touch Phase 15's SC#3. **Decision taken:** change it here, because the screen and
   the email must not disagree about when money comes back. Move it to Phase 15 if the PM prefers a hard
   file boundary.

4. **The support-escalation threshold on the pending state.** 13-CONTEXT D-90 puts poll thresholds at the
   executor's discretion. **Recommended: ~2 minutes on the page** before the guarded support line appears —
   long enough that it never fires on a healthy webhook, short enough to matter. Non-binding.

5. **Official BIR receipts** remain a parked business question (13-CONTEXT § Deferred). D-75 ships an
   explicitly informal record in the meantime. Recorded, not scheduled.
