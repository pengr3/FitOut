<objective>
Make the server stop re-framing what the user just chose — and say so truthfully in the two places that
currently say the opposite.

Purpose: `src/lib/cloudinary.ts:29` runs `{ width: 400, height: 400, crop: "fill", gravity: "face" }` on
every avatar. On a source with no face, Cloudinary picks a region for the user — literally the complaint
that created this phase. D-171 changes one word and keeps the transform, and 999.2 § 4 gives the four
reasons why deleting it would open a hole.

Output: one word, two corrected comments, one narrowed Zod refine, and four new assertions.

**"Identity" is a claim about GEOMETRY, not about bytes (RESEARCH §C12).** An upload `transformation` is an
incoming transformation: Cloudinary decodes and re-encodes to produce the stored derivative. So the stored
JPEG is NOT byte-identical to the blob the client produced, and a test asserting
`storedBytes === uploadedBytes` would fail and would be the wrong test to write. Nothing in this plan may
assert byte equality in either direction.
</objective>
