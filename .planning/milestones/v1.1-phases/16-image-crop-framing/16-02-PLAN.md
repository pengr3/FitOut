<objective>
Author the phase's contract module: the copy, the four constants and the one piece of arithmetic
everything downstream reads.

Purpose: this module is the reason the crop dialog, the guard chain, the Zod schema and the tests can
all be right about the same thing. It is directive-free on purpose — `src/app/actions/avatar.ts` is
`"use server"` and exporting a value from it once left avatar upload dead in the browser for a whole
phase while the tests stayed green (`actions/avatar.ts:19-27`).

`tests/profile/avatar-zoom.test.ts` and calls it "design config, no DB". `16-PATTERNS.md` § Measured
corrections #3 proved that impossible: `vitest.design.config.ts:53` includes `tests/design/**` ONLY, so
a spec at `tests/profile/` is collected by `vitest.config.ts`, which declares
`globalSetup: ["tests/global-setup.ts"]` and hard-fails without Docker + Postgres even for a single
file. The repo's only prior answer was a throwaway config deleted after use, which is not a standing
gate. The zoom bound is a CONTRACT asserted against a pure module — the same kind of thing
`tests/design/` already holds — so it goes to `tests/design/avatar-zoom.test.ts`, where it is DB-free,
runs in ~1s, and is build-blocking through `npm run build`.

IC-05's seven worked rows, confirmed against `react-easy-crop`'s own `computeCroppedArea` in
RESEARCH §A4 (`croppedAreaPixels` is a `min(natW,natH)/zoom` square, so requiring >= 400 real source

  1200 x  900 -> shorter  900 -> 2.25
   600 x  800 -> shorter  600 -> 1.5
   400 x  400 -> shorter  400 -> 1.0   (zoom row disabled + soft note)
   300 x  300 -> shorter  300 -> 1.0   (clamped up; output upscales 300 -> 400)
   180 x  240 -> shorter  180 -> refused before the dialog (below AVATAR_MIN_SOURCE_PX)
  4000 x  500 -> shorter  500 -> 1.25
