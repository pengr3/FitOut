    What CANNOT be automated, and why — four things, each a different kind of unreachable:
    - **Safari's `gesturestart` / `gesturechange` path.** `componentDidMount` registers it separately from
      the two-finger touch path; it is a genuinely different branch of the library, and no emulator fires it.
      Android Chrome runs the OTHER branch. That is why one device does not discharge this.
    - **A finger on a 183px stage.** On a 320x568 phone the stage is 183px; a fingertip occludes a
      meaningful fraction of it. No headless run can tell you whether that is workable.
    - **iOS momentum and rubber-banding** during a vertical drag, which is exactly what Delta-4's
      `touch-action: none` guard exists to prevent from becoming a sheet scroll.
    - **The OS file picker.** D-174's re-pick bug lives in the browser's `change`-event behaviour for a
      re-selected identical file, and `setInputFiles` sets the value programmatically — a different event
      sequence.
  </what-built>
