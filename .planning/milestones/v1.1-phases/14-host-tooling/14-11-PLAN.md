<objective>
Tell the host whether their work is saved, using the only thing that knows — the server's answer.

Purpose: the wizard already autosaves on every advance and says nothing about it, and when a save fails the
sentence explaining why arrives in a dismissible overlay that is gone on refresh. D-150 fixes both with one
region, and forbids the two shortcuts that would make it a lie: an optimistic string, and a timer. The
non-obvious cost is that the save helper currently fires the toast itself and returns a boolean, so the
server's sentence is already gone by the time the caller sees a failure — the signature has to change.

Output: a three-state region beside the control that triggers the save, a helper that returns what the server
said, and a test that fails if a timer ever appears on the save path.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server action result → the indicator | The only authority on whether a draft is persisted; an optimistic string or a timer substitutes a guess for it |
| server refusal sentence → the host | Rendered verbatim; a re-authored sentence is a second thing that must agree with the server |
| one outcome → one announcement | A region and a toast for the same save is two announcements for one outcome |
| status role → its accessible name | That role takes no name from its own text, so a region without an author-supplied label is unnamed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-11-FALSESAVE | Repudiation | the save indicator | mitigate | Every transition is driven by the action's returned result; zero scheduled callbacks on the save path, asserted both as a rendered behaviour under a fake clock and as a source scan |
| T-14-11-LOSTERROR | Repudiation | failed autosave | mitigate | The helper returns the result instead of swallowing it; the region carries the server's sentence and survives a refresh, and the error toast is deleted |
| T-14-11-DOUBLEANNOUNCE | Denial of service | assistive-technology surface | mitigate | One region; the two autosave toasts are removed and only the two navigation-preceding toasts remain, asserted by exact grep counts |
| T-14-11-UNNAMED | Denial of service | the status region | mitigate | An author-supplied label from a named constant; the accessible name is asserted with the accessibility-name library, and the row is declared in the live-region inventory in plan 14-14 |
| T-14-11-SEMANTICS | Tampering | the save action | mitigate | No server file is opened; `git diff src/app/actions/` empty, and the action still re-validates with the same shared schema |
| T-14-11-SC | Tampering | npm/pip/cargo installs | mitigate | **No package is installed.** Any proposed install is a scope alarm |
</threat_model>
