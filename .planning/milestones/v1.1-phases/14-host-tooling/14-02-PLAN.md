<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host session id → SQL `WHERE` | The only place ownership is decided. A page branch can be bypassed by a crafted parameter; a `WHERE` cannot |
| database clock → "today" | The clock is read once, server-side, and bound into the statement. A browser clock or a drifting server clock must not be able to change what a day means |
| `listing.timezone` → the day boundary | A per-row column, not a bound string and not a server locale. Two hosts' venues resolve to two different local days from one instant |
| `sql.raw` → column names only | The module's one raw seam takes an identifier, never a value |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-02-IDOR | Information disclosure | `queryHostAgenda` | mitigate | Ownership is a bound `WHERE` clause on the joined listing's host column; proved by the crossed-fixture symmetry cases added to `tests/security/bookings-owner-scope.test.ts` in Task 3 |
| T-14-02-SQLI | Tampering | the `sql` template | mitigate | Every caller-supplied value is a bound parameter; `sql.raw` is used only for the existing column-name boundary. Grep the diff for any `sql.raw` taking a variable |
| T-14-02-CLOCK | Tampering | the "today" predicate | mitigate | The clock instant is read from Postgres once per request and bound in; zero `new Date()` added to the read path, asserted by grep |
| T-14-02-ZONE | Repudiation | two-timezone hosts | mitigate | The predicate projects into the per-row venue timezone; the Manila straddling-midnight fixture is the falsifying case and is observed failing against a UTC comparison |
| T-14-02-PII | Information disclosure | the projection | mitigate | The projection carries the booker's FIRST NAME only, matching the two shipped host row shapes. No email, no surname, no phone is added |
