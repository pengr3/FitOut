## Decisions Made

**The `fetch_format` absence was settled by experiment, not by charity.** `presetDrift` cannot distinguish "the vendor drops a key it still honours" from "the transformation you believe you applied was never applied" — identical GET, opposite consequences. Six probe uploads (all six destroyed afterwards, zero residue) resolved it: the same real HEIC stored `png` **with** the preset and `heic` **without** any transformation. The transformation is applied; the vendor normalises the component out of the persisted representation.

**The exemption is absence-only and pinned as such.** A present-but-wrong `fetch_format` is still drift, and the key stays in `KNOWN_LONG_KEYS` so it can never be reported unrecognised. An exemption with an unpinned edge is how a narrow measured allowance becomes a blanket skip in a later edit.

**What the fix costs is stated in-file rather than implied away.** The reconciler can no longer prove the format conversion is set, because the vendor gives it no way to. What proves it is Check 4, a product check on a human's screen — a weaker mechanism than a scripted diff, recorded as such.

**Check 8 was refused on an interim green.** A `--verify` exit 0 taken *before* the uploads answers a different question from the one R-1.6 layer 5 asks. It was recorded as an interim with the reason it was insufficient, and re-run at the true end.

**Check 6 is recorded as two halves with different strengths.** The delivered file is byte-verified with Pillow from the downloaded `res.cloudinary.com` URL — `exif {}`, `gps {}`. The source's GPS is **operator-attested, not byte-read**: the original never reached this machine. A row that overstates its own evidence is worth less than one that admits its edge.

**1. [Rule 1 - Bug] `f_auto` is dropped from the persisted preset, not renamed — the verifier's row was a false alarm**
- **Found during:** Task 2 (the operator-run `--apply` + `--verify` gate)
- **Issue:** The plan anticipated the `f_` row being a *rename* and budgeted "one line plus its two pins". - **Fix:** `VENDOR_NORMALISES_AWAY`, a guard in `presetDrift`'s absent branch, and a matching branch in `runVerify`'s echo so the printed row and the authoritative drift list cannot contradict each other. **Three code lines and a third pin, not one line and two** — flagged at the gate rather than filed silently.
- **Files modified:** `scripts/cloudinary-preset.ts`, `tests/design/cloudinary-preset-script.test.ts`

**5. [Rule 1 - Bug] The reconciler's 404 branch exits 127 instead of 1**
- **Found during:** Task 2 (Finding 3)
- **Issue:** `process.exit()` fires synchronously while an undici socket is still closing — libuv aborts (`Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`, Node v24.13.0, Windows) and the shell sees **127**, conventionally *command not found*. Confirmed twice. **The verdict text was correct every time; only the status was clobbered** — the worst shape the bug could take, and on the one branch that fires when the security control is missing.
- **Fix:** Every exit in `main()` is `process.exitCode` plus a return; the assertion text and the reason are written above the first one.
- **Files modified:** `scripts/cloudinary-preset.ts`
- **Verification:** no mode / `--bogus` / both modes → `1,1,1`; rejected credential after a live GET → `3` with no abort; real `--verify` → `0` in 3s, no lingering handle.
- **Committed in:** `b198f5f`

**6. [Rule 3 - Blocking] The walk had no server to walk against**
- **Found during:** Task 3 prep
- **Issue:** The checkpoint protocol requires the verification environment to be ready before a human gate. No dev server was running.
- **Fix:** A detached dev server was started and its log added to `.gitignore` rather than left untracked. The ready-to-walk header removed the remaining setup by naming two empty non-seeded draft listings as valid targets.
- **Committed in:** `915985e`, `c015252`
