> ⚠ **Two commands, not one — this phase's pure-unit files live under `tests/design/`.**
> `upload-policy.test.ts`, `upload-refusal.test.ts`, `cloudinary-preset-script.test.ts` and
> `photo-uploader-options.test.ts` are collected by `vitest.design.config.ts`, **not** by
> `vitest.config.ts`, so `npx vitest run tests/listing` will not run them and reports coverage that
> isn't there. The placement is deliberate (PATTERNS § C-2, the litigated
> `tests/design/avatar-zoom.test.ts:13-20` precedent: all four are pure, `vitest.config.ts`'s
> `globalSetup` would make them pay a Postgres preflight, and `tests/design/**` is what runs inside
> `npm run build`). Note `vitest.design.config.ts` carries **no `setupFiles`**, so nothing placed
> there may depend on the cloudinary mock.

**CI reality — this constrains every row below.** The Vitest job runs with a Postgres service and
**no Cloudinary credential** (`cloudinary` is mocked in `tests/setup.ts`); the invariant is deliberate
and recorded as `T-11-CISECRET` at `.github/workflows/ci.yml:151`/`:875`. The e2e job runs
`price-parity.spec.ts` plus the visual job; `avatar-crop.spec.ts` is excluded by decision.

> **The honest limit, stated once so no plan has to re-argue it:** CI can prove *every decision our
> code makes* — the equality gate, the destroy ordering, the shared arrays, the refusal matcher. CI can
> prove **nothing** about what Cloudinary actually stores. The credential-bearing checks in
> § Manual-Only Verifications are not a gap to be closed; they are the phase's real gate.

## Validation Audit 2026-08-28

Audited against the executed tree. Every command in the map was re-run; `scripts/cloudinary-preset.ts`
was **not** modified (`git diff --exit-code scripts/` → 0).

| Metric | Count |
|--------|-------|

| Gaps found | 3 |

| Escalated to Manual-Only | 1 — WR-07 |

| Mutations observed RED | 6, transcribed verbatim at `tests/design/cloudinary-preset-script.test.ts:39-96` |

**What the audit found.** The plan-time contract was never updated during execution — its Per-Task
Verification Map was still `*TBD*` and its frontmatter still `draft` / `nyquist_compliant: false`.
Against that stale document the phase's *original* criteria turned out to be fully covered; the real
gaps were three **post-code-review fixes** that shipped with no test at all. `git show --stat` on
`7ec1f28` and `7d2add5` shows each touching `scripts/cloudinary-preset.ts` and nothing else — WR-01
through WR-04 all shipped their tests, WR-05 and WR-06 did not.

That mattered because this script's **only product is a machine-readable exit code**, and the
exit-code contract is load-bearing to the phase's own criteria: 16.1-03-PLAN Task 1's automated verify
is literally `test $? -eq 1`, and the cross-cutting row is `--verify` → exit 0. WR-06 is narrower and
sharper still: it re-inverted a predicate from `=== true` to `!== false` on the account-wide unsigned
scan — the control the file itself calls a standing upload hole — where the wrong polarity yields
"a green indistinguishable from a real one".

**WR-07 was escalated rather than faked.** Its teardown is verifiable only by counting live
`fitout/avatars` assets across a local Playwright run, and `T-11-CISECRET` makes "CI holds no
Cloudinary credential" a deliberate invariant. A test that could run it would need the credential the
invariant exists to withhold. It is now Manual-Only row 8, and it is the one row in this document that
has **not** been walked.
