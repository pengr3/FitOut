Measure the ink-on-ground pairs the four auth screens actually render — in BOTH themes — and make
that measurement a standing, build-blocking gate that goes red when a surface invents a pairing
nobody declared.

Purpose: AUTHUI-03's **AA** clause is unevidenced. `tests/design/contrast.test.ts` is a TOKEN-LAYER
gate and says so in its own header: it "cannot see a pairing a component invents". Phase 15's only

which asserts that *no new pairing was declared* — a negative check, not a measurement. This matters
specifically because D-162 changed the composition underneath: the wordmark now sits directly on

`foreground` on `muted` at 18.16 court / 16.89 grove — but that pairing was declared and measured in
an earlier phase, against a different composition.

`pair-drift.test.ts` recovers SAME-STRING pairings tree-wide and names its own blind spot in its
header: "a `text-brand` child rendered inside a `bg-muted` parent is a real pairing that no string
comparison can see, because the two class names never appear together." That blind spot is exactly
the shape of D-162's composition. This plan closes it for the auth surface.

Output: one shared maths module, one new build-blocking gate, a measured table of every auth pair in
both themes, and — only if the measurement finds one — a new row in `contrast-pairs.ts`.

⚠ THIS PLAN MOVES NO PIXEL. It adds a test, moves functions between test files, and may add a data
row to a module that nothing under `src/` renders. No component, class string, sentence or baseline
is touched, and no CI baseline dispatch is needed.

say so with the measured numbers and stop. Do NOT invent a row so the plan has something to add — a
declared pairing nothing renders is the inverse defect, and `pair-drift.test.ts` is one-directional

`tests/design/contrast.test.ts` (287 lines) holds, module-local, the maths the whole design suite
depends on and deliberately hand-rolls so no assertion depends on one library being right twice:
  hexOf(cssValue) → "#rrggbb"                 (via culori `converter("rgb")` + `formatHex` + `parse`)
  channelsOf(hex) → [r,g,b]                   8-bit, parsed from the hex — never from the float
  luminance(hex) → number                     WCAG 2.x relative luminance
  contrast(aHex,bHex) → number                (hi+0.05)/(lo+0.05)
  composite(fgHex, alpha, bgHex) → hex        gamma-space, 8-bit — COMPOSITE FIRST, MEASURE SECOND
  mixInOklch(aValue,bValue,pct) → hex         models `color-mix(in oklch, …)`, the shipped hover idiom
  resolve(theme,name) → hex                   a real token OR a `DERIVED_SURFACES` mix; THROWS on an
                                              unknown name rather than defaulting to something green
Its constants come from `src/lib/design/contrast-pairs.ts`: `AA_EPSILON = 0.05`, `TEXT_BAR = 4.5`,
`NON_TEXT_BAR = 3.0`, `CONTRAST_PAIRS` (39 rows today), `EXCLUDED_PAIRS` (7+ rows), `DERIVED_SURFACES`.

own note says that is the ONE import site for token data across the design suite (D-16), so no test
hand-rolls a second parser. This plan applies the same rule one level down, to the maths.

Its three guard-the-guard floors, which move WITH the inventory and never ahead of it:

`src/lib/design/contrast-pairs.ts` row shape:

`fg`/`bg` are token names WITHOUT the leading `--`. `alpha` describes the BACKGROUND's opacity over
`over`; `fgAlpha` the INK's own opacity, composited over the ALREADY-COMPOSITED background.
