<objective>
Reconcile the two status tone vocabularies that exist today into one closed union of four tones, and
retire the filled green badge.

Purpose: `src/components/booking/booking-status.ts:33` declares `tone: "muted" | "outline" | "success"`
while `src/components/host/payout-ledger-status.ts:19` declares
`"muted" | "outline" | "success" | "attention"`. Two vocabularies exist, neither is DS-10's, and the one
they share — the filled `bg-success text-success-foreground` badge — measures 3.24:1 and is exactly the
colour-carries-meaning pattern the requirement pushes back on. The repo already implements "icon + text,
never colour-only"; what changes is the tone treatment, not the structure.

Output: one tone module, both view types retyped against it, five call sites re-treated, one green test.
</objective>

| Boundary | Description |
|----------|-------------|
| status derivation → rendered badge | The tone drives a colour that carries meaning to a user |
| component → assistive technology | Colour-only status is invisible to a colour-blind or screen-reader user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-21 | Repudiation | status tone union | mitigate | An open string tone would let a new status ship with no icon and no declared pairing. `STATUS_TONE_RECIPES` is a `Record` over a closed union, so the gap is a compile error, and `tests/design/status-vocab.test.ts` drives every derive function over every status. |
| T-10-22 | Information disclosure | status labels | accept | The tone change touches presentation only; the words are unchanged and are already derived server-side by `deriveBookingStatusView` / `derivePayoutLedgerView`. No new data reaches the client (D-130 holds). |
| T-10-23 | Tampering | `--success-foreground` | mitigate | It survives with exactly one legal pairing and the source scan pins the surviving occurrence to a single named file, so a second filled green badge goes red. |
</threat_model>
