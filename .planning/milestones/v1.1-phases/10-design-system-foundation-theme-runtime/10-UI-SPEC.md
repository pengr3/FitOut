# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This phase does not build a product screen.** The "UI" being specified is the token contract itself,
the component recipes the contract forces, and one internal surface (`/dev/theme`). Every product surface
is Phases 11–15. Nothing below invents a booker or host screen.

**Colour authority.** Every ratio in this document was computed in this session with an independently
implemented OKLab→sRGB (Ottosson) + WCAG 2.x solver with 8-bit rounding and gamma-space alpha compositing.
It reproduces `10-RESEARCH.md` § Computed Palette exactly — shipped `--brand` renders `#ef4445`, brand-fg
on brand **3.60**, success-fg on success **3.24**, muted-fg on muted **4.35**, brand on muted **3.45**,
success on background **3.39**, ring on background **2.58**, `ring/50` composited **1.54**,
destructive on its own `/10` tint **4.01**, fg on background **19.80**, max in-gamut chroma at
`--destructive`'s L/H **0.2354**. Same method, same numbers. The values below are therefore derived, not picked.

**The `culori` test remains the authority at execution time** (D-12). If it disagrees with a number here,
the test wins and this file is corrected — but it should not disagree, because it is the same computation.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialised — `components.json` present) |
| Preset | `style: "radix-nova"`, `baseColor: "neutral"`, `cssVariables: true`, `tailwind.config: ""` (CSS-first, no JS config) |
| Component library | Radix (`radix-ui` package) via 30 vendored primitives in `src/components/ui/**` |
| Icon library | `lucide-react` |
| Font | Geist Sans (`--font-geist-sans`) + Geist Mono (`--font-geist-mono`), both already loaded by `next/font/google` in `src/app/layout.tsx:5-13`. **No new typeface is chosen (D-127).** `--font-heading` stays an alias of `--font-sans` (D-20) — the seam is kept, not exercised. |
| Styling engine | Tailwind CSS 4.3.0, `@theme inline` in `src/app/globals.css:7` |
| Theme runtime | `next-themes@0.4.6`, `attribute="data-theme"`, themes `["court","grove"]`, default `court`, `enableSystem={false}` |

**Two mechanisms are load-bearing and must never be "cleaned up":**

1. **`@theme inline` stays.** Verified by compilation: it makes every utility emit `var(--background)` rather
   than `var(--color-background)`, which is the only reason a nested `[data-theme="grove"]` subtree re-skins.
   Drop `inline` and the `<html>`-level switch keeps working while THEME-04 silently dies.
2. **Theme blocks are unlayered, equal-specificity, source-ordered.** `:root, [data-theme="court"] { … }`
   then `[data-theme="grove"] { … }`. **Never** `:root[data-theme="grove"]` or `html[data-theme="grove"]` —
   it raises specificity but stops matching a nested `<div data-theme="grove">`, same failure class.

## Spacing Scale

**Global — identical in both themes (D-05).** A constant grid is what keeps a two-theme visual diff
interpretable; only colour, type, radius and elevation travel.

Tailwind's `--spacing: 0.25rem` already yields this ladder (`p-4` → `calc(var(--spacing) * 4)` → 16px).
No new spacing tokens are authored; the scale below is the **declared legal set**.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`*-1`) | Icon-to-label gaps inside a chip or badge |
| sm | 8px (`*-2`) | Compact element spacing; button internal gaps |
| — | 12px (`*-3`) | Dense row padding, table cells (retained, in wide use, a multiple of 4) |
| md | 16px (`*-4`) | Default element spacing; card padding |
| lg | 24px (`*-6`) | Section padding |
| xl | 32px (`*-8`) | Layout gaps |
| 2xl | 48px (`*-12`) | Major section breaks |
| 3xl | 64px (`*-16`) | Page-level spacing |

**Exceptions: none.** The 44px touch target (DS-09) is `h-11` = 4 × 11 — already on the grid, so it needs
no exception and no arbitrary value.

## Typography

**Per-theme (D-01/D-05).** Four declared semantic roles, exactly two weights per theme.

### Declared roles

| Role | court size / line-height / weight / tracking | grove size / line-height / weight / tracking | Used for |
|------|---------------------------------------------|---------------------------------------------|----------|
| Display | 28px / 1.15 / semibold / -0.02em | 34px / 1.20 / bold / -0.005em | Page titles; money figures. **Replaces all 12 `sm:text-[28px]` sites.** |
| Heading | 20px / 1.30 / semibold / -0.01em | 24px / 1.30 / bold / 0 | Section headings, card titles |
| Body | 16px / 1.50 / regular / 0 | 17px / 1.60 / regular / 0 | Prose, descriptions |
| Label | 14px / 1.43 / regular / 0 | 15px / 1.50 / regular / 0 | Dense UI text, table cells, chips, buttons (today's `text-sm`, 265 sites) |

### Weights — exactly two per theme

| Token | court | grove | Note |
|-------|-------|-------|------|
| `--font-weight-normal` | 400 | 400 | Body, label |
| `--font-weight-semibold` | 600 | **700** | The single emphasis weight |
| `--font-weight-medium` | **600** | **700** | **Deliberately aliased to the emphasis weight** — see below |

`--font-weight-medium` is collapsed onto the emphasis weight rather than kept as a third step. Two weights
is the contract; the 70 shipped `font-medium` call sites then need **zero edits** and simply render at the
theme's emphasis weight. This is a visible change (500 → 600 in court) and is accepted, on the same footing
as the accent deepening.

### The two traps this contract exists to avoid

- **A co-located utility beats a `--text-*` step's modifier.** `font-semibold` sets `--tw-font-weight`,
  `tracking-tight` sets `--tw-tracking`, `leading-tight` sets `--tw-leading` — and there are 98 / 34 / 24
  of them. **Therefore `--font-weight-*`, `--tracking-*` and `--leading-*` are themselves per-theme tokens.**
  A grove block that defines display weight but not `--font-weight-semibold` produces two themes with
  identical headings. Required per-theme: `--font-weight-normal`, `--font-weight-medium`,
  `--font-weight-semibold`, `--tracking-tight` (court -0.02em / grove -0.005em), `--tracking-normal`,
  `--tracking-widest`, `--leading-none`, `--leading-tight` (court 1.2 / grove 1.25), `--leading-snug`,
  `--leading-relaxed`.
- **Never use the `/` modifier on a named step.** `text-display/tight` compiles to font-size + line-height
  only; letter-spacing and font-weight vanish.

### The built-in ladder travels too

Tailwind's `--text-xs/sm/base/lg/xl/2xl` are var-referencing, so re-declaring them per theme re-skins all
399 existing call sites with zero component edits. Declare all six in both blocks:

| | xs | sm | base | lg | xl | 2xl |
|---|---|---|---|---|---|---|
| **court** | 12px | 14px | 16px | 18px | 20px | 24px |
| **grove** | 13px | 15px | 17px | 19px | 22px | 27px |

`text-xs` is the sub-label utility step for numerals and counters — **the two arbitrary sites
(`text-[10px]` at `booking-row.tsx:69`, `text-[11px]` at `notification-bell.tsx:117`) migrate to it.**
It is not a fifth semantic role.

## Resolved Open Questions

The research flagged four items as design judgements to be closed here. All four are closed, with the
computation that closed them. **These are design decisions made by this document, stated as such.**

### 1. Grove's `--success` hue (research L13 / OQ1) — RESOLVED: shift grove's brand teal-ward

Grove's brand moves to **hue 190 (`oklch(0.5445 0.09 190)` = `#13807c`)** and `--success` stays at hue 150
in **both** themes. This is the research's own default recommendation, and it is the right one: the hue gap
is created by the token that is *supposed* to travel (D-02 explicitly names "forest/**teal**"), it needs no
per-theme `--success`, and it puts 40° between brand and positive-status rather than the 10° that a hue-160
grove brand would have left.

Computed at hue 190, the maximum practical chroma is **0.09** — solving for the lightest brand at C 0.11 /
0.12 / 0.13 (hues 190 / 185 / 180) returns **no in-gamut solution** at the 4.55 bar. `#13807c` is therefore
not a soft choice; it is the constraint boundary. Grove's neutrals are re-tinted from the research's hue
160/165 to **hue 190** so the theme is hue-coherent with its own accent; all neutral pairs were re-verified
above and every one passes.

### 2. Arbitrary-text leak pattern: px-only or rem-inclusive (OQ2) — RESOLVED: **px-only**

`text-\[[0-9.]+px\]`. This matches DS-13's literal wording and the measured baseline (14 app / 0 vendored).
D-15 already widened DS-13 once with a stated reason; widening it twice without one erodes the discipline.
**The 4 × `text-[0.8rem]` sites (`ui/button.tsx:27`, `ui/calendar.tsx:93,102`, `ui/toggle.tsx:20`) are
recorded here as known, tolerated vendored debt** — not silently missed.

### 3. `--success` margin (OQ3) — RESOLVED: **`--success` moves to `oklch(0.58 0.15 150)` = `#1b9247`**

The research left grove's `--success` uncomputed. Computed here: the shipped `oklch(0.62 0.17 150)` = `#03a14a`
lands at **3.01:1 on grove's `--muted`** — it *fails* the 3.0 bar with epsilon and sits essentially on the
line even without one. Keeping it was never viable once grove exists.

Applying the same `AA_EPSILON` rule the brand derivation uses, and taking the research's own named in-gamut
path (reduce chroma alongside lightness, because every darkening at the shipped chroma is out of gamut):
`oklch(0.58 0.15 150)` = `#1b9247`, in gamut, **court 4.00 / 4.00 / 3.67** and **grove 3.86 / 4.00 / 3.54**
on background / card / muted. One rule, applied uniformly, and the 0.11-margin inconsistency the research
flagged is gone.

### 4. Per-theme `--destructive`? (OQ4) — RESOLVED: **global, and re-derived**

`oklch(0.546 0.22 27.325)` gives **exactly 4.50** on grove's `/10` tint over grove's background — which
*fails* `bar + 0.05`. Accepting it would have re-created the 0.02-margin problem the brand derivation
explicitly rejected. Re-solved at the gamut ceiling: **`oklch(0.535 0.215 27.325)` = `#cd0916`**, in gamut
(ceiling at that L/H is 0.2182), giving **court 4.81 / grove 4.67** on the `/10` tint and **5.76 / 5.56** on
background. It stays a **single global value declared identically in both theme blocks** — declared in both
so THEME-02's key-set equality holds, identical in value because nothing in the derivation requires it to move.

## Button Hierarchy (DS-08)

**The hierarchy: `brand` → `default` → `outline` → `secondary` → `ghost` → `link`, with `destructive`
edge-only.** An un-varianted `<Button>` stays neutral `--primary` near-black (D-21). Coral appears only
where someone asked for it — this is what protects the 10% accent budget.

### The 29 / 20 / 9 split — name it or the calendar breaks

There are **29 distinct source lines** containing `bg-brand` (53 raw grep hits, because most also carry
`hover:bg-brand/90`). **Exactly 20 are on a `<Button>` and convert to `variant="brand"`. The other 9 are
not buttons, are not leaks, and MUST NOT be converted.**

**Convert (20 — `<Button>` call sites):**
`bookings/[id]/page.tsx:374,421,517` · `bookings/page.tsx:145,211` · `host/listings/[id]/edit/wizard.tsx:1416` ·
`host/listings/page.tsx:81,93` · `host/page.tsx:123,155` · `booking/book-cta.tsx:222` ·

`booking/reserve-actions.tsx:81` · `group/create-group-button.tsx:63` · `group/rsvp-form.tsx:327` ·

(step markers)

A task that says "replace all 29 with `variant='brand'`" breaks the availability calendar and the slot
picker — the two surfaces the sketch direction is built around.

### The variant recipes

```
default:     bg-primary text-primary-foreground
             hover:bg-[color-mix(in_oklch,var(--primary),var(--foreground)_10%)]
brand:       bg-brand text-brand-foreground
             hover:bg-[color-mix(in_oklch,var(--brand),var(--foreground)_10%)]
destructive: bg-destructive/10 text-destructive
             hover:bg-destructive hover:text-destructive-foreground
```

**The `hover:bg-brand/90` in `10-RESEARCH.md` § Code Examples must not be copied** — it is 4.04:1 (court) /
3.87:1 (grove). The `color-mix` form darkens instead of lightening: court `#c32b37` at **5.41:1**, grove
`#137470` at **5.36:1**. This is not a new vocabulary — it is the idiom already shipped at `button.tsx:16`
for the `secondary` variant, and it is theme-portable because `--foreground` is per-theme.

**This is not a `--brand-strong` escape hatch** (rejected in CONTEXT § Specific Ideas). There is still exactly
one brand value and zero per-call-site judgement; the hover lives once, inside the CVA variant.

The destructive hover flips to a solid fill with `--destructive-foreground` (5.52:1 in both themes) rather
than deepening the tint — deepening the tint moves the surface *toward* the text colour, which is the wrong
direction and is why `/20` measures 4.01. `--destructive-foreground` is a new token in both theme blocks.

`default`'s hover is changed from `hover:bg-primary/80` for consistency of mechanism only; the shipped
`/80` measures 9.19:1 and was never failing.

## Focus Recipe (DS-05)

**One recipe, app-wide. No control may rely on a 50%-alpha ring.**

```
focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background
```

Plus `globals.css:137`'s `outline-ring/50` → `outline-ring` (it sets `outline-color` only, so it renders
nothing alone — but it is the colour source for the 3 `focus-visible:outline-1` sites).

**Why the token change alone is insufficient — this is arithmetic, not preference.** `ring-ring/50` compiles
to `color-mix(in oklab, var(--ring) 50%, transparent)`. Composited over white, a `#555555` ring is **2.32:1**.
The lightest neutral that reaches 3:1 at 50% alpha is ≈ `oklch(0.2825 0 0)`, and even that fails on `--muted`
(2.93:1). **No value of `--ring` fixes `/50`.** All **13 `focus-visible:ring-ring/50` occurrences (11 of them
vendored) lose the `/50`.**

The `ring-offset-2` band is `--background`-coloured, guaranteeing the indicator has a verified ≥3:1 surface
on both sides (ring on background 7.46 / 7.11; on card 7.46 / 7.36; on muted 6.84 / 6.52). Declaring
`ring-offset-background` explicitly is required — Tailwind's default `--tw-ring-offset-color` is a literal
`#fff`, which is a leak in all but name and would be wrong on grove's tinted background.

Grove's `--background` and `--card` differ (`#f7fcfc` vs `#ffffff`), so a focused control on a card shows a
2px band one shade off the card. That is deliberate: **one recipe, app-wide** (DS-05's literal wording) beats
a per-surface offset colour, which would reintroduce exactly the per-call-site judgement this phase removes.

**Do not plan a `@layer base` `*:focus-visible { outline: … }` fallback** — shadcn's base recipe sets
`outline-none` in the utilities layer, which outranks any base-layer outline. Considered and rejected.

## Status Vocabulary (DS-10)

**A closed union of exactly four tones. Every status declares an icon. Never colour-only. Never red or green
as decoration.** This implements the sketch manifest's binding rule directly: *occupancy and unavailability
are normal states, never errors, never red.*

| Tone | Surface | Text | Icon | Meaning |
|------|---------|------|------|---------|
| `neutral` | `bg-muted` | `text-foreground` | `text-muted-foreground` | In-flight or closed lifecycle: pending, requested, completed, declined, cancelled, held, refunded |
| `positive` | `bg-muted` | `text-foreground` | `text-success` | The one confirmed/paid signal |
| `attention` | `bg-muted` | `text-foreground` | `text-destructive` | Genuine failure needing a human: payout failed |
| `soft-accent` | `bg-brand/10` | `text-foreground` | `text-brand` | Brand-relevant informational chip: spots-left |

**"Green retreats to the icon" (D-14) is enforced structurally, not by convention.** Status *text* is always
`--foreground` ink on a neutral tint (18.16 / 16.89) and the hue lives only in the icon, which needs to clear
the 3:1 non-text bar (success on muted 3.67 / 3.54). The shipped filled green badge
(`bg-success text-success-foreground`, **3.24:1**) is **retired** — it is both the failing pair and the
colour-carries-meaning pattern DS-10 pushes back on.

**Five shipped call sites change:** `booking/booking-status-badge.tsx:47` (confirmed) ·
`host/payout-state-badge.tsx:34` (paid) · `host/payout-banner.tsx:48` ("Payouts enabled") ·
`listing/listing-card.tsx:80` (published) · `host/listings/[id]/edit/wizard.tsx:1351` (completed step).

`--success-foreground` is **retained with exactly one legal pairing: a non-text glyph on a filled `--success`
surface** (3.83 / 3.84 ≥ 3.05) — the wizard's completed-step marker, which is a progress indicator, not a
status badge. It is **illegal as text**, and the pair-drift check must reject `text-success-foreground` on
any text node.

**The vocabulary is a type, not a convention.** The four tones are a closed union; the per-status recipe map
must be `Record<Status, { tone, Icon, label }>` so a new status without an icon is a compile error. The
existing icon assignments in `booking-status-badge.tsx` and `payout-state-badge.tsx` are correct and are
preserved — the tone/surface treatment is what changes.

Genuine failure *messages* (not chips) keep the destructive `Alert` pattern, which is `bg-card text-destructive`
(**5.76 / 5.76**) with `text-destructive/90` on card (**5.24**). Both are declared pairings.

## Elevation, Z-Index and Motion

### Elevation — exactly 3 steps, per-theme (DS-03)

Tailwind's default `shadow-*` compile to **literal** values, not `var()` references, so they are *not*
theme-swappable. Named `@theme inline` steps are mandatory, not stylistic — and are the only way grove's
"pronounced elevation" (D-02) can exist at all.

| Step | court | grove | Collapses today's |
|------|-------|-------|-------------------|
| `shadow-raised` | `0 1px 2px 0 oklch(0 0 0 / 0.05)` | `0 2px 6px -1px oklch(0.17 0.02 190 / 0.10)` | `shadow-xs` ×1, `shadow-sm` ×3 |
| `shadow-overlay` | `0 8px 24px -6px oklch(0 0 0 / 0.12)` | `0 16px 40px -8px oklch(0.17 0.02 190 / 0.20)` | `shadow-md` ×4, `shadow-lg` ×1 |
| `shadow-sticky` | `0 -1px 12px -2px oklch(0 0 0 / 0.08)` | `0 -2px 20px -4px oklch(0.17 0.02 190 / 0.14)` | (new — for bottom-anchored bars) |

`shadow-none` ×5 stays `shadow-none`. All 14 shadow call sites migrate; five distinct values collapse into
three, so some surfaces visibly gain or lose depth — that is the point of a three-step scale.

### Z-index — exactly 4 steps, global

| Token | Value | Layer |
|-------|-------|-------|
| `--z-sticky` | 10 | Sticky bars, sticky table headers (today's `z-10` ×12) |
| `--z-sheet` | 20 | Mobile overlay / sheet |
| `--z-dialog` | 30 | Dialog, popover, dropdown (today's `z-50` ×9) |
| `--z-toast` | 40 | Toast — always on top |

`z-0` ×2 stays 0. **Rule the scale carries for Phase 18:** any third-party widget with its own internal
z-index (Leaflet's control corners sit at 1000, its panes at 400–700) must be wrapped in a CSS stacking
context (`isolate`) by the phase that introduces it. The app scale is the arbiter and does not inflate to
out-run a vendor.

### Motion — global, every token ≤ 320ms (DS-04)

| Token | Value |
|-------|-------|
| `--motion-fast` | 120ms |
| `--motion-base` | 200ms |
| `--motion-slow` | 320ms |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` |
| `--default-transition-duration` | `var(--motion-fast)` |
| `--default-transition-timing-function` | `var(--ease-standard)` |

Motion is a **budget, not a brand expression** (D-05) — global, so no theme can blow the cap.
Setting the two `--default-transition-*` variables retunes every bare `transition-*` utility with zero edits.
**There is no `--duration-*` namespace in Tailwind v4** — `duration-base` does not compile. Named durations
are written `duration-(--motion-base)`, which emits `--tw-duration: var(--motion-base)` and stays theme- and
media-aware. `tw-animate-css` honours the same variables.

**Cap wording, so the test is writable:** *no transition or enter/exit animation exceeds 320ms; continuous
loading indicators (`animate-spin`, `animate-pulse`) are exempt by design and are covered by the reduced-motion
reset instead.* Without that clause the budget test cannot be written without failing on the spinner.

### Reduced motion — a global property, never per-component

There is currently **zero** `prefers-reduced-motion` handling anywhere in the repo. One reset, in
`@layer base`, with `!important` so it beats utilities:

```css
@layer base {
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      animation-iteration-count: 1 !important;
      transition-duration: 0.01ms !important;
      scroll-behavior: auto !important;
    }
  }
}
```

This is the only form that also neutralises `tw-animate-css` keyframes (`animate-in` ×8, `zoom-in-95` ×7,
`slide-in-from-*` ×20) and Radix `data-state` animations. Redefining `--motion-*` inside the media query
reaches only utilities that read those variables and **misses every keyframe animation** — do not do that.
Per-component `@media` blocks are explicitly out (DS-04 says "a global reset is in force").

## The `/dev/theme` Surface

**The one real screen this phase builds.** Success criterion 3 is that a brand direction can be judged
*on real components rather than swatches* — so the layout is ordered to make that true.

| Property | Value |
|----------|-------|
| Route | `/dev/theme` (single route; not a `(dev)` route group — D-09) |
| Production guard | `if (process.env.NODE_ENV === "production") notFound()` **inside the page component** — a build-time constant the bundler can prune; never an operator-settable env var |
| Data | Static fixture props typed `ComponentProps<typeof X>` so fixture drift is a compile error (D-10). **No DB, no network, no seed dependency** — Phase 11 and Phase 17 screenshot this page and must work on a fresh clone and in CI |
| Loading / empty / error states | **None, by construction.** The page is static; the only "error" path is the production `notFound()`. The STATE-\* families are Phase 11 and must not be invented here |

### Layout

- **Header strip, rendered outside both panes** (root theme): the title, a one-line note that the route does
  not ship, the AA bar legend (4.5 text / 3.0 non-text / +0.05 epsilon), and each theme's live `--brand` hex
  read from the generated token module so the page cannot lie about what it is showing.
- **Body: two equal columns side by side at ≥1024px, stacked below.** Left `<div data-theme="court">`,
  right `<div data-theme="grove">`. Each pane is `bg-background text-foreground` and fills its column, so
  each theme's own background is visible rather than sitting on the root theme's.
- **Both panes render the identical ordered section sequence fed by identical fixture props**, so a
  horizontal scan compares like with like. Section headings render inside the pane, in the pane's own theme.
- Responsive floor: **320px** (D-131) — below 1024px the panes stack, court first.

### Section order — real components first, swatches last

1. **Type ladder** — display / heading / body / label, each labelled with its role and rendered with real
   product copy, so the per-theme weight and tracking difference (D-20) is visible.
2. **Button hierarchy** — `brand`, `default`, `outline`, `secondary`, `ghost`, `destructive`, `link`; each at
   `default` and `touch` size; plus one disabled and one with focus forced, so the DS-05 recipe is visible
   without tabbing.
3. **Status vocabulary** — every declared status rendered through the real `BookingStatusBadge` and
   `PayoutStateBadge`, covering all four tones. This is where "occupancy is never an error" is checkable.
4. **Availability surface** — the real `SlotPicker` on a fixture day: available hours, one struck-through
   unavailable run, and one selected contiguous run. **The canonical accent-carries-meaning surface** and the
   single most useful thing on the page for judging a brand direction.
5. **Result card** — the real listing/search result card with a placeholder photo, title, price and a
   spots-left `soft-accent` chip.
6. **Form row** — Input + Label + Select + Checkbox, one field in `aria-invalid` state, showing the focus
   recipe and the destructive border treatment on a real control.
7. **Elevation ladder** — the three named steps as three cards.
8. **Radius ladder** — the seven `calc()`-derived steps from the theme's single `--radius`.
9. **Surface swatches** — background / card / muted / border, each labelled with its role. **Deliberately
   last**, because swatches are the least useful comparison and putting them first is how a design-system
   page ends up being read as a palette instead of a product.

### Theme override paths (both must exist and be documented here)

| Consumer | Mechanism |
|----------|-----------|
| **Tests** | Playwright seeds next-themes' storage key (`localStorage["theme"]`) via `context.addInitScript` before navigation. No app surface, nothing to gate, works on every route. **This is the seam Phase 11's theme-swap smoke and Phase 17's two-theme axe pass both depend on.** |
| **Humans** | `?theme=` honoured **only outside production**, read from `window.location.search` inside a client effect — root layouts receive no `searchParams` and `useSearchParams()` would force dynamic rendering. The value is checked against the `THEMES` allowlist with `.includes()` and **never** cast with `as` — it reaches a DOM attribute. |

`disableTransitionOnChange` is set on the provider so the Phase-11 swap screenshots are deterministic.
`suppressHydrationWarning` on `<html>` is **load-bearing**, not belt-and-braces: next-themes' inline script
mutates `documentElement` before React hydrates.

## Anti-Patterns — reject these in plan review

- **Dropping or replacing `@theme inline`** — silently kills THEME-04 while the `<html>` switcher keeps working.
- **`:root[data-theme="grove"]` or `html[data-theme="grove"]`** — stops matching nested subtrees; same failure class.
- **Renaming shadcn's semantic token names** — 30 vendored primitives and five approved UI-SPECs speak
  `bg-background` / `text-muted-foreground`. Do not invent a parallel vocabulary.
- **Converting all 29 `bg-brand` lines to `variant="brand"`** — 9 are not buttons; it breaks the calendar and slot picker.
- **`hover:bg-brand/90`** — 4.04 / 3.87. Use the `color-mix` hover.
- **Fixing the focus ring by token value alone** — arithmetically impossible; the `/50` must go.
- **Reintroducing `--brand-strong`** — considered and rejected; the accent deepening everywhere is accepted.
- **A filled `bg-success text-success-foreground` badge** — 3.24:1 and colour-carries-meaning; retired by DS-10.
- **Per-component `@media (prefers-reduced-motion)`** — DS-04 requires one global reset.
- **Capturing any visual-regression baseline in this phase** — GATE-01 is Phase 11 and DS-01 invalidates
  anything shot before it. A `toHaveScreenshot` in a Phase 10 plan is a scope alarm.
- **Proposing a schema migration** — GATE-06 binds from this phase; `drizzle/` stays at `0025`.
