<objective>
Close UAT gap **G-01** — notification rows (and any other ScrollArea child) lay out at their natural
width inside the panel and are clipped.

Radix renders `ScrollArea.Viewport`'s children inside one wrapper div carrying an **inline**
`style={{ minWidth: "100%", display: "table" }}`. `display: table` shrink-wraps to max-content, so
`min-width: 100%` is a **floor with no ceiling**: long unbreakable content expands the wrapper past
the panel and the overflow is clipped. Measured in Chromium, signed in, panel open — viewport
**384.0px**, wrapper and row **976.9px**, overflowing right by **592.9px**, flush left at 0. Forcing
that wrapper to `display: block` takes both to exactly **384.0px** (probed live).

Purpose: the defect is in the primitive, so it is fixed in the primitive — both shipped call sites
(`notification-bell.tsx` max-h-96, `slot-picker.tsx` max-h-72) inherit the fix and nothing else has
to know. It is **not** an IN-14 regression: removing `max-h-[inherit]` leaves the row at 976.9px
unchanged. IN-14 is only what made the list long enough to read, and therefore long enough to notice.

Output: a one-class fix, a comment that hands the next person the horizontal caveat, and **two**
gates at two different layers — one that blocks `npm run build`, one that measures real pixels in
real Chromium — each watched failing before it passed.
</objective>

<facts_already_established>
These were verified while planning. Do NOT re-derive them; they are the reason the tasks are shaped
this way.

**1. Radix renders exactly one direct div child of the Viewport, and its style is inline.**
`node_modules/@radix-ui/react-scroll-area/dist/index.mjs:130` —
`jsx("div", { ref: context.onContentChange, style: { minWidth: "100%", display: "table" }, children })`.
So `[&>div]` targets precisely that wrapper and nothing else (the app's own children are nested one
level deeper, inside it). Inline style ⇒ `!important` is REQUIRED; a plain `[&>div]:block` loses.
There is no Radix prop that configures this away — CSS is the only lever.

**2. BOTH important-modifier spellings compile under this repo's Tailwind (4.3.0).** Probed by
compiling `@source inline(...)` through the repo's own `@tailwindcss/postcss`:

```
.\[\&\>div\]\:\!block { &>div { display: block !important; } }     <- v3 prefix form
.\[\&\>div\]\:block\! { &>div { display: block !important; } }     <- v4 suffix form
.\[\&\>div\]\:block   { &>div { display: block; } }                <- control, no !important
```

So the prefix form in the gap report is not *wrong*; it is off-convention. `src/` contains **zero**
prefix-form occurrences and ~9 suffix-form ones (`ui/command.tsx`, `ui/badge.tsx:19 [&>svg]:size-3!`).
**Use the suffix form `[&>div]:block!`.** Note the emitted shape: Tailwind v4 emits **NESTED** CSS
(`&>div` inside the escaped class rule), NOT a flattened `.cls > div` selector. An assertion written
against the flattened form will read "missing" against a correct stylesheet.

**3. `orientation="horizontal"` appears nowhere in `src/` (grep: 0 hits), and `ScrollArea` hardcodes
`<ScrollBar />` whose `orientation` defaults to `"vertical"`.** A horizontal scrollbar is therefore
unreachable through this wrapper. This is why the caveat is a COMMENT and not a conditional.

**4. Both ScrollArea call sites are vertical-only:** `slot-picker.tsx:155` (`max-h-72 w-full`, a
`flex-wrap` ToggleGroup of short time chips) and `notification-bell.tsx:150` (`max-h-96`, a
`<ul className="divide-y">` of `NotificationItem`).

**5. `/dev/theme` renders TWO `SlotPicker`s** (court + grove panes, `src/app/dev/theme/page.tsx:260`
via `slot-picker-preview.tsx`), from static fixtures — **no auth, no database**. It is also the page
`e2e/reduced-motion.spec.ts` already drives.
</facts_already_established>

<decision_the_row_is_not_changed>
The UAT gap's third `missing` bullet asks for `min-w-0` + truncation on the notification row. **It is
already there, and it was already correct — it was INERT, not absent.** Deciding this on evidence
rather than adding belt-and-braces classes:

- `notification-item.tsx:268` — the text column is already `min-w-0 flex-1`.
- `notification-item.tsx:270` — the body line, the ONLY line carrying user-controlled text
  (`listingTitle`, `bookerLabel`, `attendeeLabel`, `refundLabel`, `whenLabel`), is already `truncate`.
- Every `title` returned by `describeNotification` is a hardcoded string literal from the closed
  union — 15 cases, and the two branching ones choose between two literals. **No user input reaches
  the title line**, and the longest ("Request approved — pay to confirm") wraps normally at 384px.
- `truncate` implies `white-space: nowrap`, which is consistent with *causing* the 976.9px
  max-content in the first place. **More truncation would have made the wrapper wider, not narrower.**
  Once the wrapper is `block`, `min-w-0` lets the flex child shrink and the existing `truncate`
  engages — Task 2 measures that ellipsis rather than assuming it.
- `slot-picker.tsx` renders short time labels in a `flex-wrap` container. Nothing to truncate.

**So `notification-item.tsx` and `slot-picker.tsx` are not touched by this plan.** If Task 2's
measurement shows a row still exceeding the viewport after the wrapper fix, that finding overrides
this paragraph — report it and stop rather than papering over it with classes.
</decision_the_row_is_not_changed>

<decision_two_gates_not_one>
The gate constraint was decided deliberately; both layers ship, because each closes the other's hole
and this is the same two-layer argument `e2e/reduced-motion.spec.ts` already makes in its own header.

- **A source-scan gate alone is refused.** It asserts a *string*. The whole trap in this task is that
  a class name can be present and spelled plausibly while producing nothing — this repo has now been
  bitten by that twice (`z-dialog` compiling to silence, `text-label` deleted by tailwind-merge). A
  gate that reads source is protection this fix specifically does not get from source.
- **The build-layer gate is therefore written against the COMPILED stylesheet** (`compileGlobalsCss()`
  scans `src/`, so it emits what the app really references). That upgrade is nearly free and it is
  the layer that would have caught a non-compiling spelling. It runs inside `npm run build`
  (`build = lint && test:design && next build`) — the only gate that can block a build, since
  Playwright is not in that chain.
- **The Playwright gate exists because widths are the actual claim.** jsdom performs no layout;
  `getBoundingClientRect()` returns zeros, so a width assertion cannot live in the design suite at
  all. Playwright is already installed, and is the tool that produced the 384.0/976.9 diagnosis —
  declining to measure the fix with the instrument that measured the defect would be indefensible.
- **Target `/dev/theme`, not the notification panel.** The panel needs an authenticated session and
  20 seeded rows; a gate with those dependencies is a gate that stops running. `/dev/theme` needs
  neither, renders the same primitive twice, and is the existing e2e precedent. The real panel is
  confirmed once, by hand, in Task 2 — recorded, not committed.
</decision_two_gates_not_one>

**2a. The spec.** New `e2e/scroll-area-overflow.spec.ts`, modelled on `e2e/reduced-motion.spec.ts`

  2. **Mechanism.** The wrapper — `viewport.firstElementChild`, the div Radix hardcodes — computes
     `display === "block"`. This is the assertion that catches a class that is present but never
     compiled or never applied, which is the failure mode a source scan cannot see.
  3. **Width.** `wrapper.getBoundingClientRect().width <= viewport.clientWidth + 0.5` (subpixel
     tolerance; the diagnosis measured 976.9 vs 384.0, so the tolerance is nowhere near the signal).
  4. **Real content.** Every direct child of the wrapper is also within `viewport.clientWidth + 0.5`.
  5. **Oversized-content probe — the deterministic red-maker.** In the same spirit as
     `reduced-motion.spec.ts`'s synthetic `animate-pulse` probe: inject a child INTO the wrapper (not
     as a sibling of it) carrying ~300 unbreakable characters and `white-space: nowrap`; then
       - assert the probe is genuinely oversized (`probe.scrollWidth > viewport.clientWidth`) —
         without this the probe could be inert and the next assertion vacuous, which is the exact trap
         `readPulse` returns `animationName` to avoid;
       - assert the wrapper width is STILL within the viewport;
       - remove the probe.

     regardless of what the fixtures happen to render. That is what makes this gate independent of
     seed data and of how long a listing title happens to be.
