# Quick: stop the e2e suite sending 14 real emails per run, and pin the zero

## What is being closed

`[17-D28]` (`deferred-items.md:1265-1318`). Measured under the § P3 census at `9683ad9`, both spec
files driven alone at `--project=chromium --workers=1`:

| spec | request | per full run |
|---|---|---|
| `e2e/overflow-320.spec.ts` | `POST https://api.resend.com/emails` | **12** |
| `e2e/axe-sweep.spec.ts` | `POST https://api.resend.com/emails` | **2** |

All 14 left the machine: the census substituted only `api.paymongo.com` and delegated Resend untouched.
Recipients are synthetic addresses minted by the `signUp` fixtures, so these are near-certain bounces on
a shared sending domain. And `playwright.config.ts`'s `webServer` has **no `env:` key at all** — the day
this suite runs in CI with real secrets, CI sends real email on every push.

---

## THE DECISION, AND WHY THE OTHER OPTION LOSES

**Chosen: silence Resend at the Playwright boundary via `webServer.env`, and make that silence
self-enforcing by DELETING the adoption case (`reuseExistingServer: false`) rather than tolerating it.
`src/lib/email.ts` is not touched. `instrumentation.ts` does NOT grow a Resend interception.**

### Why not extend the `instrumentation.ts` seam — the load-bearing asymmetry

The seam is the tempting answer because it is proven, process-side, and immune to which server Playwright
adopts. It is still the wrong tool here, and the reason is mechanical rather than stylistic:

> `instrumentation.ts:20-22` — *"AND UNSETTING THE KEY IS NOT A SUBSTITUTE. `authHeader()` in
> `src/lib/paymongo.ts` falls back to `""` and still sends `Basic <base64 of ":">`. Clearing the
> credential removes the credential, not the network. Only an interception removes the network."*

**Resend is the exact inverse.** `src/lib/email.ts:34-35` binds `resend = key ? new Resend(key) : null`
at module load, and `send()` at `:38-53` returns on the `!resend` branch **before any transport object
exists**. For PayMongo the key is a credential and the request happens anyway; for Resend the key **is
the switch**. Same-looking finding, opposite mechanism, therefore a different correct answer. `[17-D28]`
says the same thing in its own words: *"the e2e environment already has the correct switch built into
it."*

Three further costs the seam would carry and the env fix does not:

1. **It changes every dev boot, not just Playwright runs.** `register()` is unconditional outside
   production by design (`instrumentation.ts:31-42` refuses an operator-settable escape hatch on
   purpose). An operator with a key in `.env.local` would get a fabricated success, no email, **and** no
   `[email:dev]` console link — strictly worse than today in both directions. That is the § P3 objection
   (*"changing the behaviour of a shipped code path inside the very runs the audit uses to measure the
   product"*) generalised past `disableNetConnect`.
2. **It would put `resend.emails.send` on a fabricated path in every measured run.** The `[email:dev]`
   fallback is this module's own designed test posture, documented at `email.ts:2-5` and `:547-548`, and
   already pinned by `tests/auth/email-dev-fallback.test.ts`. Substituting a wire response invents a new
   posture nothing else in the repo asserts.
3. **The e2e suite has zero dependency on real delivery — measured, not assumed.** Both specs that need
   an emailed token read it from Postgres and say why:
   `e2e/stale-session-selfheal.spec.ts:44-50` — *"Reading the DB … is also the only strategy that
   survives `RESEND_API_KEY` being set"*; `e2e/password-reset.spec.ts:8-10` says the same. Silencing
   Resend changes **no** spec's behaviour. Verify this holds by re-reading both headers before shipping.

### The `[17-D24]` adoption trap — resolved by deletion, not by detection

`reuseExistingServer: !process.env.CI` means an env var in `webServer` is silently ignored whenever a
dev server is already on :3000. This has produced false results twice already (17.1 waves 1 and 2).

Two facts decide the resolution:

- **On CI the trap does not exist.** `!process.env.CI` is already `false` there, so Playwright always
  boots its own server and `env` always applies. The exposure that actually matters — real secrets, every
  push, `[17-D28]`'s "Credential exposure" paragraph — was never subject to the trap.
- **Locally, a detector is more machinery than the case it detects.** A marker-file + pid-liveness probe
  can itself go vacuous; that is the failure class this repo keeps paying for.

So: **`reuseExistingServer: false`, unconditional.** The adopted-server case stops existing, which is why
the guard can be a *static property of the config* instead of a runtime probe that must itself be trusted.

**The cost, stated rather than hidden:** `npx playwright test` now FAILS when anything holds :3000
(Playwright's own error names the port). Free the port first. This is loud where the old behaviour was
silent, and it closes the `[17-D24]` trap for every future `webServer` guarantee, not just this one.
Turbopack's `.next` compile cache survives boots, so the price is a boot (~0.7s observed in § P3), not a
rebuild.

### The named opt-in

`FITOUT_E2E_REAL_EMAIL=1` makes the config emit **no** `RESEND_API_KEY` entry at all, so the merge
inherits the operator's own environment. The config therefore **never reads the secret's value** in
either branch — which is how constraint 1 is satisfied structurally rather than by remembering.

### Mechanics verified by source reading — RE-MEASURE, do not trust

| Claim | Where | Why it matters |
|---|---|---|
| `webServer.env` MERGES over `process.env` (`...this._options.env`) | `node_modules/playwright/lib/…/webServerPlugin.js:835`, Playwright **1.60.0** | Omitting the key inherits the live one. It must be set to `""` explicitly. |
| `@next/env` applies a `.env.local` value **only** when `typeof initialEnv[key] === "undefined"` | `node_modules/@next/env/dist/index.js`, `processEnv` | `""` is a defined string, so `.env.local`'s live key is **not** re-applied over it. This is why `""` is the correct spelling and "unset" is not — a deleted var would be re-supplied at boot. |
| The client binds at **module load** | `src/lib/email.ts:34-35` | The var must be `""` at server boot, which only a Playwright-booted server can guarantee. |

## Constraints on every task below

- **Never read, print, echo, log or commit the value of `RESEND_API_KEY`.** Prefix and length only, as
  the census did.
- **Never edit or delete `.env.local`.** It is the operator's file.
- **`src/lib/email.ts` must end byte-identical.** The WR-02 production guard at `:44-49` is untouched.
- **This task sends ZERO real emails, including during measurement.** Both census drives INTERCEPT
  `api.resend.com` and count; they do not delegate. § P3 already recorded that the 14 really left — that
  record stands and does not need re-purchasing.
- **`.next` hygiene, every boot:** any change to `instrumentation.ts` wedges the next dev boot with
  `MODULE_UNPARSABLE` (`instrumentation.ts:107-111`), and Playwright reports that only as *"webServer was
  not able to start"*. Terminate anything on :3000, then `rm -rf .next`, then boot.
