# Quick 260831-99f — make the checkout clearance's argument order enforceable · SUMMARY

## One-liner

An AST-derived design gate that runs the REAL `cn()` argument list of every site composing
`STICKY_BAR_CLEARANCE` through the REAL `cn` and fails when tailwind-merge deletes a `pb-*` —
watched red three ways, and changing no rendered pixel.

## What shipped

**Nothing was broken, and nothing rendered differently afterwards.**
`src/app/listings/[id]/book/page.tsx:546-552` was correct and measured before this task — 80px at
320 / 639 / 640 / 768 / 1023 and 48px at 1024 / 1280, both themes (`17.1-EVIDENCE.md` § P4). What was
missing was any instrument that would notice the reorder that breaks it. The task closes the gap
between *correct* and *hard to break*.

The mechanism, which nothing in the ~30 lines of comment above that call had ever named: `cn` is
`clsx` + `extendTailwindMerge` (`src/lib/utils.ts:41-47`), and tailwind-merge resolves a `py-*` /
`pb-*` conflict by **deleting the earlier class before any CSS exists**. All three ⚠ paragraphs above
the call reason about Tailwind v4's *cascade layers* — a different mechanism at a later stage, where
both classes reach the stylesheet and one wins. Here the loser never reaches the DOM.

Re-probed at HEAD through this repo's own `cn` before writing anything (every row of the plan's table
reproduced byte-for-byte):

| order | `cn(...)` output |
|---|---|
| SHIPPED `cn(P, K, T)` | `mx-auto w-full max-w-4xl px-4 py-8 sm:py-12 pb-20 sm:pb-20 lg:pb-12` |
| HOISTED `cn(K, P, T)` | `… py-8 sm:py-12 sm:pb-20 lg:pb-12` — **`pb-20` GONE** |
| FLATTENED into one string | `… py-8 sm:py-12 lg:pb-12` — **both clearance terms GONE** |
| Shape A hoisted (`K = "pb-20 sm:pb-20"`) | `… py-8 sm:py-12 lg:pb-12` — **BOTH GONE** |

The hoist leaves `<main>` reserving **32px (`py-8`) under a 64px bar below 640px** — strictly worse
than the defect phase 17.1 just repaired, which was 80px below 640px and only failed from 640px up.

### Task 1 — `tests/design/clearance-merge-order.test.ts` (new, 15 tests)

A **rule, not a path inventory, and not a copy of the argument list.** It walks `src/`, comment-strips
each module, parses it with the TypeScript AST, and matches every `CallExpression` whose callee is
`cn` and whose arguments contain the identifier `STICKY_BAR_CLEARANCE`. String literals resolve to
their text; the identifier resolves through the **real import**; **any other argument shape is a
violation, not a skip** (fail-closed, the direction `sticky-offset.test.ts` takes with an offset it
cannot parse).

For each site it collects the `pb-*` terms per variant in argument order (last-wins — what a
deliberate override means), runs the resolved list through the **real `cn`**, and reports any variant
whose expected survivor is missing or replaced, naming the file, the line, the class that vanished and
the merged output string.

Why an AST rule and not the obvious version: importing `cn` and retyping the three arguments in the
test is a **second copy** that stays green forever while the real file is reordered. This repository
has paid for that defect class twice, in writing — `helpers/strip-comments.ts:12-26` (brand recipe
reported **21/21 passed** while the primary booker CTA was no longer coral) and
`sticky-offset.test.ts:9-13`.

Guard-the-guard, all asserted before the rule:

| pin | value | what a change means |
|---|---|---|
| files walked | ≥ 50 | a scan that opened nothing satisfies `toEqual([])` perfectly |
| both real files reached, by name | — | a count of 2 must not come from two other files |
| stripper non-vacuous | — | `(detail)/page.tsx` names the constant in **prose only**; raw contains it, stripped must not |
| files importing the constant | **2** | dropping WITH the site count = a call site abandoned it |
| `cn()` sites composing it | **2** | dropping ALONE = still imported, no longer composed → the rule silently stops covering it |
| surviving `pb-*` per variant, per site | pinned table | the positive half; fires from the other direction on the same edit |

The pinned positive table:

- `src/app/listings/[id]/book/page.tsx` → `{ "": "pb-20", sm: "sm:pb-20", lg: "lg:pb-12" }`
- `src/app/listings/[id]/(detail)/layout.tsx` → `{ "": "pb-20", lg: "lg:pb-0" }`

**CI reachability, read end to end rather than assumed:** `ci.yml:601-602` (job 1 `gate-db-free`) runs
`npm run build` → `package.json:11` → `npm run test:design` → `vitest.design.config.ts:50`, which has
no `globalSetup` and no `setupFiles` (the DB-free guarantee, D-16). So this gate runs on every push
with no Postgres and no browser. The instrument that actually measures this padding —
`e2e/mobile-booker-path.spec.ts`'s `expectDocumentEndClearsBar` — **never runs in CI**, because
`ci.yml:841` runs exactly `e2e/price-parity.spec.ts`. That asymmetry is why the gate lives in
`tests/design/` and why the call-site comment now names two instruments.

## Blind spots this gate does NOT close (stated in the test file too)

- It reads **source**, not computed geometry. It proves the class survives the merge, not that the box
  renders 80px. That measurement is the e2e band case CI does not run.
- It understands `pb-*` only. A clearance as `mb-*`, an inline style, or an arbitrary property is
  invisible.
- It follows the **constant**. A clearance hard-coded as a bare `pb-20` literal is out of subject by
  construction.
- Variants split at the last `:`; an arbitrary variant containing a bracketed colon would be
  mis-bucketed — loudly (as a deleted class), not silently. None exists in the tree.
