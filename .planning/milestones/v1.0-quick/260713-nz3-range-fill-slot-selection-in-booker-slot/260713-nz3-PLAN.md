<objective>
Replace the booker SlotPicker's shipped interaction — "click each hour; adjacent clicks extend the run" — with the APPROVED range-fill model from sketch 001 variant A (winner). The new gesture: click a START hour (coral-ring anchor, selection not yet complete), then click an END hour to fill the CONTIGUOUS available run between them (either direction). If the run would cross an unavailable hour it TRUNCATES at the last available hour before the gap and shows a soft, non-error inline hint naming the blocking hour. Clicking the same anchor again = a 1-hour block; a click after a completed run re-anchors a fresh start.

This is a UAT-discovered UX refinement of Phase-3 plan 03-05. The picker stays ADVISORY only (Pitfall 6): the DB `booking_no_overlap` EXCLUDE constraint remains the sole booking authority. NO schema / DB / server-action changes.

Purpose: the shipped consecutive-click model cannot express a multi-hour window in two clicks and gives no guidance when a booked/blocked hour interrupts a range — the range-fill model (fewest clicks, hour grid stays the availability map) is the approved design.
Output: a pure gesture core + the rewritten SlotPicker + unit coverage of the core + the updated E2E; full Vitest + Playwright `availability.spec.ts` + `tsc --noEmit` + `eslint` all GREEN.
</objective>

<approved_design>
The winner is sketch 001 variant A ("Range fill"). The exact, approved gesture state machine is the
`rangefill` branch of `onClick(i)` in .planning/sketches/001-timeslot-selector/index.html (lines
232-357). Port that logic verbatim in behavior. The two pure helpers to port:

- `contiguousEnd(lo, hi)` — `let j = lo; while (j < hi && isAvail(j + 1)) j++; return j;`
  (the last available index reachable from `lo` going forward, capped at `hi`; `lo` is always available).
- `firstGap(lo, hi)`  — `for (let k = lo; k <= hi; k++) if (!isAvail(k)) return k; return -1;`

Gesture (rangefill onClick, index `i` into `slots`, only reachable for AVAILABLE chips):
1. if fullDay → set fullDay=false, then continue.
2. if a run is committed → RESET: run=null, anchor=i, gap cleared. (fresh start after a completed run)
3. else if anchor===null → SET START: anchor=i, gap cleared.
4. else (second click = end): `lo=min(anchor,i)`, `hi=max(anchor,i)`, `end=contiguousEnd(lo,hi)`,
   run={lo, hi:end}, anchor=null; if `end < hi` set gapIndex=`firstGap(lo,hi)` (truncated) else clear gap.
   Same-anchor click (i===anchor) → lo=hi=i → end=i → run={i,i} = a 1-hour block.

The sketch's HINT copy: `${SLOTS[gapIdx].label} is ${reasonFor(state).toLowerCase()} — pick a later start
for a block after it.` NOTE the shipped read model only exposes state "available|unavailable|past|
beyond_horizon" (NO booked-vs-blocked distinction — that would be a server change, OUT of scope), so the
shipped reason word is "unavailable" (e.g. "8:00 AM is unavailable — pick a later start for a block after
it."). The sketch's PENDING rail copy ("Now pick an end hour") maps to an inline picker helper here.
</approved_design>

Proposed pure core — src/components/availability/slot-selection.ts (new; imports ONLY the AvailabilitySlot
type, so it is DOM/React/Radix-free and unit-testable in node):
```ts
export type Run = { lo: number; hi: number };
export type SelectionState = { run: Run | null; anchor: number | null; fullDay: boolean; gapIndex: number | null };
export type SlotSelectionValue = { startUtc: string; endUtc: string; fullDay: boolean };
export const EMPTY_SELECTION: SelectionState;
export function isAvailable(slots: AvailabilitySlot[], i: number): boolean;      // slots[i]?.state === "available"
export function contiguousEnd(slots: AvailabilitySlot[], lo: number, hi: number): number;
export function firstGap(slots: AvailabilitySlot[], lo: number, hi: number): number;  // -1 if none
export function resolveClick(state: SelectionState, index: number, slots: AvailabilitySlot[]): SelectionState;
export function resolveFullDay(state: SelectionState): SelectionState;           // toggle fullDay, clear run/anchor/gap
export function selectionValue(state: SelectionState, slots: AvailabilitySlot[]): SlotSelectionValue | null;
```
