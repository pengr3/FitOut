<objective>
Close finding #4 of the v1.0 milestone audit: `publishListing` never requires operating hours, so a host
can go "Live" with an empty calendar, be told nothing, and send every booker to a dead end where each
date renders Closed.

This plan adds the missing SIGNAL, on the host side only. It is presentation plus one read.

Purpose: the host currently has no way to learn that their live listing is unbookable. Give them the
fact, the reason, and the way out — on both surfaces where they manage listings.
Output: one shared read+copy module, an optional card prop, two wired host surfaces, and tests that
pin the derived state in both directions.
</objective>

<constraints_the_executor_cannot_violate>

   `statusBadge()` function in `listing-card.tsx` is not touched.

4. **Do not touch the booker side.** `src/lib/search/query.ts`, `src/components/availability/*`, and
   the public listing page are all out of scope.

5. **Do not restyle the card.** The change to `listing-card.tsx` is additive: one optional prop and
   one muted paragraph. Layout, spacing, badge, price line, and footer actions stay as they are.

6. **Reuse the existing route.** `ListingCard` already receives
   `availabilityHref={`/host/listings/${r.id}/availability`}` (listings/page.tsx:109). The signal's
   link uses that prop. Do not invent a new route or a new server action.

7. **One grouped query, never N+1.** Follow the `coverByListing` idiom already in
   `listings/page.tsx:43-50`: one query for all of the host's listings, results collapsed into a `Set`
   / `Map` the render reads from.
