<current_state>
This session did no code changes. It was a full design discussion about replacing Inngest
(D-56) with an in-house Postgres transactional outbox + a single worker process, to take the
third-party vendor out of the money/notification path. The analysis — design, performance,
cost, and a capacity/metrics model — is captured in full in `inngest-in-housing.md` (same
directory). The decision LEAN is: do it, but formalize as an ADR superseding D-56 and schedule
it BETWEEN phases (not mid-Phase-7).

<decisions_made>
- Lean: in-house the layer (vendor independence + closes the documented dropped-event gap at
  `src/lib/notifications.ts:106`). Cost is roughly neutral and is NOT the deciding factor.
- Design defaults: `LISTEN/NOTIFY` (zero idle query load) + a single worker (2 for HA).
- The crux is the `emitNotify` inversion — from a post-commit `inngest.send` HTTP call to an
  in-transaction outbox INSERT (`notifications.ts:100`'s "never in a transaction" rule flips).
</decisions_made>
