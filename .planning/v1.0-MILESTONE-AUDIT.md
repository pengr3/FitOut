# Milestone v1.0 — Audit Report

**Project:** FitOut — Airbnb-style marketplace for fitness & recreational spaces
**Milestone:** v1.0 (9 phases, 107 plans)
**Audited:** 2026-08-01 · **Reconciled:** 2026-08-01
**Status:** `tech_debt` — no blockers; accumulated deferred items warrant a read before archiving

## Verdict

**49/49 requirements satisfied. 9/9 phases verified. 7/7 cross-phase seams and 7/7 E2E flows wired.
Nyquist 9/9. No blocking gaps.**

The first pass of this audit returned `gaps_found` for one reason: Phase 2 — the phase that owns
listings and the payout-onboarding bookability gate — had shipped without ever running its verification
gate, so seven requirements (LIST-01…06, PAY-04) existed in the traceability table and in working,
independently-traced code but in **no VERIFICATION.md anywhere in the milestone**. That, plus a set of
bookkeeping drifts, has been closed. The characterization held up: it was a **verification-artifact
gap, not a product gap** — the retroactive Phase 2 verification found 4/4 success criteria and 7/7
requirements satisfied, with 144 Phase-2 tests and 3/3 LIST-06 browser E2E re-run first-hand.

What remains is genuine tech debt, and one item on it deserves to be read before anyone calls v1.0
shippable: **real host payouts have never moved real money.** PayMongo's `/v2` money-movement beta is
sales-gated and not enabled on the account, so the sweep and reconcile that pay hosts are proven only
against mocks. The booker-side money path is proven against the real API — real `sk_test_` hosted
checkouts were paid by hand in Phases 6, 8 and 9 — but the host-side leg is not. That is an external
dependency, not unfinished work, and it has been correctly and continuously disclosed since Phase 5.

## Tech Debt Summary

**Blocking: none.**

Ranked by consequence:

1. **Real host payouts have never moved real money.** PayMongo's `/v2` money-movement beta is
   sales-gated. Sweep and reconcile are proven only against `mockPayMongo`. The booker-side rail *is*
   proven against the real API (hand-paid `sk_test_` checkouts in Phases 6, 8 and 9). External.

   fully proven structurally; the third party's hosted flow is not reachable. External.
3. **Three phases at `human_needed`** (01, 02, 05) — entirely external-credential, third-party-beta,
   or product-sign-off items.
4. **`publishListing` allows a live listing with no operating hours.** The one genuine product-
   completeness finding in the whole audit, and the only one that is fixable today.
5. **Phase 8 accepted residuals** — truly concurrent double-click on Confirm & pay (T-08-79), the
   already-captured qrph overcharge (T-08-74), and `expireCheckoutSession`'s string-matched
   already-expired tolerance (LW-01, fails safe).
6. **Phase 9 product copy** — "Drop-in" is unexplained on the search card (conversion risk); the
   small-cap scarcity chip behaviour is an explicitly accepted design decision, not a defect.
7. **Absent dev credentials** — `GOOGLE_CLIENT_*` and server-side `CLOUDINARY_*` are missing from
   `.env.local`, which is why three Phase-1/2 human items cannot be re-exercised locally.
