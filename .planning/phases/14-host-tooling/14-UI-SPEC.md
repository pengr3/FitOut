# Phase 14 — UI Design Contract

> Visual and interaction contract for the five surfaces a **host** works on.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## What this document is, and what it deliberately does not touch

**Phases 10–13 shipped a gated design system, a pattern layer, an app shell and the whole booker path.**
Colour, the four type roles, focus, status tones, elevation, z-index, motion, the contrast inventory, the
three card patterns, the four state families, the one overlay primitive and the six typed inventories
(`contrast-pairs.ts`, `measurements.ts`, `selector-contract.ts`, `status-tones.ts`, `live-regions.ts`,
`accent-uses.ts`) are **LOCKED**. `npm run build` = `lint && test:design && next build`, so a raw hex, an
arbitrary type size, an undeclared `data-testid`, a raw `<Card>` in an unlisted file, a fourth accent use or
a skeleton with a literal box class already fails the build today.

**This document re-decides none of that.** Everything below either *consumes* an existing token, pattern or
recipe, or names precisely where a declared inventory must be **EXTENDED** — and an extension is always
"add or amend a row in the declared inventory, with its reason", never "invent a value at the call site."

Read `10-UI-SPEC.md` for the foundation, `11-UI-SPEC.md` for the shell/states/patterns, `12-UI-SPEC.md` and
`13-UI-SPEC.md` for the booker precedent this phase is asked to match. This file adds five things:

| # | Adds | Requirement |
|---|------|-------------|
| 1 | **The dashboard as an agenda** — today's real sessions, then three signal rows | HFLOW-03 |
| 2 | **The requests inbox as a triage queue** — the SLA countdown as the loudest element on the row | HFLOW-01 |
| 3 | **The wizard's rail, save state and persistent checklist** | HFLOW-02 |
| 4 | **The bookings table's design-system pass + the week-at-a-glance bar strip** | HFLOW-04 |
| 5 | **Earnings and payouts — a token pass, and nothing else** | HFLOW-05 |

**The standard, restated because it shaped every criterion below.** Phase 11: *"a gate that has silently
never failed is worse than no gate."* Phase 12 (12-CONTEXT D-59): *when two options both satisfy a
requirement, choose the one that costs the user less.* Phase 13: *if our screen and the user's own record
disagree, our screen is wrong.* Phase 14 adds the one its own CONTEXT names, and it applies to five
surfaces at once: **an absence must never be dressed as a failure** (`T-11-FALSEALARM`). An empty inbox, a
quiet day, a week with no hours set and a host with no payouts are all NORMAL states of a working product.

**PROJECT D-138 binds: `court` is the SINGLE product theme.** `grove` is a token-contract probe, proved by
the existing 24-name parity check, the contrast table and the one fixed four-surface contract spec. **Every
new baseline in this phase is court-only.** No Phase-14 surface owes grove a screenshot pair. Every colour
figure quoted below is nevertheless still *measured in both themes* by `contrast.test.ts`, because the token
contract did not change — only the baseline matrix did.

**PROJECT D-130 binds. Polish may reshape layout and hierarchy; it may not move logic client-side or weaken
a v1.0 invariant.** Owner-scoping stays in the SQL `WHERE`. Money stays the server-frozen
`quotedTotalCents` and every host surface here performs **zero** arithmetic on it. Time stays `readDbNow(db)`
read once per request and threaded, rendered venue-local through `composeWhenLabelShort`.

**PROJECT D-136 binds. ZERO schema migrations.** Every surface below is deliverable without a column. A
migration proposed under this spec is a scope alarm, not a design cost to absorb.

**Decision-ID namespace.** Bare `D-NN` in this file means **14-CONTEXT D-140…D-156**. PROJECT-namespace
numbers are written `PROJECT D-130`. Earlier phases are written `11-CONTEXT`, `13-CONTEXT`.

⚠ **A comment containing a banned token trips the design greps.** Three plans in this repo have been burned
by quoting a banned class name inside an explanatory comment. Everywhere this document instructs source
prose, it instructs **descriptive naming**, never quotation.

## Spacing Scale

**Inherited unchanged from Phase 10 (D-05, global).** The declared legal set:
4 (`*-1`) · 8 (`*-2`) · 12 (`*-3`) · 16 (`*-4`) · 24 (`*-6`) · 32 (`*-8`) · 48 (`*-12`) · 64 (`*-16`).

Phase 11's four exceptions (56/64px header, 176px auth slot, 80px sticky offset, 85dvh sheet bound),
Phase 12's six (44px targets, 80px bar clearance, 96px countdown box, the fluid ~41px calendar cell, the
2px optical nudge, `gap-5`'s retirement) and Phase 13's one (`CONFIRMATION_MOMENT_MIN_H`) all carry forward
unchanged. **Phase 14 renders none of them except the 44px touch target.**

### Phase 14 declares exactly THREE box exceptions, all stored as constants

Box dimensions are not spacing steps — the same distinction `SLOT_CHIP_BOX`, `CALENDAR_CELL` and
`PANEL_MIN_HEIGHT` already make. Each goes in `src/lib/design/measurements.ts` with its derivation, and
**never as a call-site literal**.

| Constant | Value | Where | Derivation |
|---|---|---|---|
| `HOURS_STRIP_TRACK` | `"h-40"` (160px) | The week-at-a-glance track, one per weekday column | 160 ÷ 24 = **6.67px per hour**, so a one-hour window renders as a bar a reader can actually see. The two ladder candidates fail on arithmetic, not taste: `h-16` gives 2.67px/hour and `h-12` gives 2px/hour — a one-hour window would be a hairline and the preview would not do the job D-152 gives it. `min-h-40` is already precedented in this file as `PANEL_MIN_HEIGHT`. |
| `STEP_MARKER_BOX` | `"size-6"` (24px) | Every marker in the wizard step rail | The shipped value, retained and now load-bearing: D-148 turns the visited markers into real controls, and 24px is the **WCAG 2.5.8 AA target-size bar** that `e2e/overflow-320.spec.ts`'s `TARGET_FLOOR_PX` asserts. With `gap-2` the adjacent centres sit 32px apart, so the spacing exception is not even needed — the bar is met directly. |
| `WIZARD_CHECKLIST_COL` | `"lg:w-72"` (288px) | The publish-checklist side panel from `lg` up | The wizard shell widens from `max-w-3xl` to `max-w-5xl` at `lg` (see § The Wizard). 1024 − 32 (`px-4` both sides) − 288 − 32 (`gap-8`) = **672px** of form column, against the 736px it has today — the narrowest the address step's two-column fields survive without wrapping. |

**No other new box value.** In particular: the strip's bar geometry is a **percentage in `style`**, never an
arbitrary Tailwind class. Twenty-four `h-[N%]` variants would be twenty-four undeclared values and would put
this surface permanently at odds with the arbitrary-value gate. See § The Week-at-a-Glance Strip.

### One duplication this phase ends, mechanically

`mx-auto w-full max-w-4xl px-4 py-10` is hand-typed on `/host/requests`, `/host/bookings`, `/host/earnings`
and their three `loading.tsx` plates — six copies of one string, and the plates are the only reason the
loading and loaded shells agree today. `mx-auto w-full max-w-3xl px-4 py-12` and
`mx-auto w-full max-w-3xl px-4 py-8` are two more near-twins on `/host` and the availability page.

**Resolution: two constants in `measurements.ts`, imported by every page AND its plate.**

| Constant | Value | Consumers |
|---|---|---|
| `HOST_LIST_SHELL` | `"mx-auto w-full max-w-4xl px-4 py-10"` | `/host/requests`, `/host/bookings`, `/host/earnings` + their three `loading.tsx` |
| `HOST_PANEL_SHELL` | `"mx-auto w-full max-w-3xl px-4 py-8"` | `/host` + its plate, `/host/listings/[id]/availability` + its plate, the wizard's `edit`/`new` pages + their plates |

Every value in both is already a declared ladder step; **nothing about the rendering changes except `/host`,
which moves from `py-12` (48px) to `py-8` (32px)** and thereby stops being the one host page with its own
vertical rhythm. This is the argument `BOOKING_SHELL` made in Phase 13 and `RESULT_GRID_GAP` made in Phase
12, applied to the strings that had six copies and three.

## Typography

**Inherited unchanged.** Four named roles (`text-display` / `text-heading` / `text-body` / `text-label`),
per-theme, pinned by `tests/design/type-scale.test.ts`. Tailwind's re-declared `text-xs…2xl` ladder is legal
and is not a fifth role. Arbitrary `text-[NNpx]` is banned by ESLint **and** a Vitest gate.

| Role | court | Phase 14 uses it for |
|------|-------|----------------------|
| Display | 28 / 1.15 / 600 / -0.02em | **Nowhere.** No host surface in this phase carries a display-scale heading; the wizard's shipped `text-2xl` step title is the only near-neighbour and it is retired (below) |
| Heading | 20 / 1.30 / 600 / -0.01em | `PageHeader`'s `<h1>` on all five surfaces (via the pattern's own `text-xl font-semibold tracking-tight`); the wizard step title; every `<h2>` section title; `PanelCard` titles; **the SLA countdown's digits in `lead` form** |
| Body | 16 / 1.50 / 400 / 0 | Agenda row titles; row card titles; the quiet-day sentence; the signal rows' state clause; checklist row labels |
| Label | 14 / 1.43 / 400 / 0 | Every muted meta line; venue-local window labels; `<dl>` term/value pairs; money figures on host rows; the strip's caption and day abbreviations; the save-state line |

### Four type rules this phase adds

**1. The wizard's step title stops being the largest thing on a host page.** `wizard.tsx` renders
`<h1 className="text-2xl font-semibold tracking-tight">` (24px) for the step question, while every other
host `<h1>` is `text-xl` (20px). Two different `<h1>` scales in one product is drift, and the wizard's is
the outlier. **Decision: the step title becomes `PageHeader`'s `<h1>`,** at the same 20px every other host
page uses. The listing's name is not on this page today and does not become one — the question *is* the
title. **Falsifiable:** every `<h1>` on the five Phase-14 surfaces computes an identical `font-size` at
320 / 768 / 1280.

**2. The SLA countdown's digits are the only text on a request row above 16px, and that is how D-146
becomes a measurement.** § The Requests Inbox states the whole hierarchy as a table plus a Playwright
assertion over computed `font-size`. "Loudest" is a comparison, so it is written as one.

**3. No `<p className="font-semibold">` standing in for a heading.** The pattern layer already fixed this in
the empty states, Phase 12 in the key-facts strip, Phase 13 on the booking surfaces. This phase's new
regions are the next place the shortcut is available: the agenda's *"Today"* is a real `<h2>`, the
checklist's *"Almost there — finish these to publish:"* is a real `<h2>` inside the panel, the strip's
*"Your week at a glance"* is `PanelCard`'s own `title` prop (which renders `<h2 className="text-heading">`),
and the signal rows are `<p>` sentences because they are sentences.

**4. Exactly one `<h1>` per rendered document, on every branch.** `PageHeader` supplies it on all five
surfaces. **Falsifiable:** `getByRole("heading", { level: 1 })` resolves to exactly **1** on
`/host` (all four states), `/host/requests` (both states), `/host/bookings` (both tabs, both states),
the wizard (every step, both occupancy modes) and the availability page.

## The Dashboard (HFLOW-03 · D-140, D-141, D-142, D-143)

### The shell, and the four states it renders

```
<div className={HOST_PANEL_SHELL} data-host-dashboard>
  <PageHeader                                   ← D-143: the greeting is a title, not the subject
     title="Your hosting, {First}"
     lede={ONLY in the no-listings state}
     actions={[ Create listing (brand) , Your listings (outline) ]} />

  <section aria-labelledby="today">             ← the AGENDA. States A / B / C below
     <h2 id="today">Today</h2>  +  View all bookings →
     …
  </section>

  <section aria-labelledby="setup">             ← the SIGNALS, in D-140's order
     <h2 id="setup" className="sr-only">What needs you</h2>
     [1] requests owed        — PanelCard tone="muted", hidden at 0
     [2] payout state         — PayoutBanner, UNCHANGED (D-156)
     [3] published-without-hours — PanelCard tone="muted", hidden at 0
  </section>
</div>
```

**Rhythm:** `space-y-8` between the header, the agenda and the signals; `space-y-3` between rows inside the
agenda; `space-y-4` between the three signals.

### The header cluster loses two buttons, and that is a deliberate subtraction

The shipped cluster is `Create listing` · `Your listings` · `Earnings` · `Requests {N}`. **`Earnings` and
`Requests` are both permanent slots in the host nav** (`HOST_NAV_IDS = ["earnings", "requests"]`), rendered
on every host screen including this one, and the requests count now has its own signal row three inches
below. Two buttons that duplicate persistent navigation are two competitors for the one accent.

**Decision: the cluster becomes `Create listing` (brand) + `Your listings` (outline).** `/host/listings` and
`/host/bookings` are the two host destinations that are **not** in the nav; the first keeps its button and
the second gains a `View all bookings` link in the agenda's own heading row — a route-out the dashboard does
not have today at all. **Falsifiable:** exactly one accent-filled element in the `/host` viewport at
320 / 768 / 1280; `/host/bookings` is reachable from `/host` by an accessible-name query. Flagged in
§ Open Questions — the PM may want the two buttons back.

### The agenda's three states

| | **A — sessions today** | **B — quiet day** | **C — nothing booked** |
|---|---|---|---|
| Condition | ≥ 1 session whose venue-local day is today | 0 today, ≥ 1 upcoming | 0 today, 0 upcoming |
| Hook | `data-testid="host-agenda"` on the `<section>`, present in **all three** | same | same |
| Body | `<ul className="space-y-3">` of `RowCard`s | one `PanelCard tone="muted"`, one sentence | one `EmptyState` |
| Copy | § Copywriting | **`Nothing today — next: {Sat, Aug 29} · {10:00 AM} · {Court A}`** | title **`Nothing booked yet`** + body |
| Never | A count. A tile. A percentage | A dead box. An alarm. A retry | An error vocabulary. A "something went wrong". A retry affordance |

**The hook is present in all three states on purpose.** An assertion of the form *"the agenda renders"* that
can be satisfied by an absent section is the vacuity shape this repo has recorded a dozen times. The three
states are then distinguished by their contents, each with its own hook:
`agenda-rows` / `agenda-next` / `agenda-none`.

**State C's body must not assert bookability.** *"Your spaces are live and bookable"* is false for a host
whose payouts are not enabled, and false for a listing with no hours — both of which the signal rows below
are simultaneously saying. The sentence describes the **mechanism** instead:

## The Week-at-a-Glance Strip (HFLOW-04 · D-152, D-153)

### What it is, and what it deliberately is not

**A seven-column bar strip of the weekly PATTERN, drawn against a 24-hour scale, updating live from form
state before anything is saved.**

**Date-specific blocks and closures are NOT overlaid.** They are what `BlocksEditor` below controls, and a
preview must describe exactly what the editor above it sets. Conflating "my weekly pattern" with "this
specific week" is wrong the moment a one-off block exists, and it is wrong silently.

### Geometry

| Property | Value |
|---|---|
| Container | `PanelCard title="Your week at a glance"` — **`tone="default"`**, so the `bg-muted` track has a `bg-card` ground to be visible against |
| Grid | `grid grid-cols-7 gap-1` — seven equal columns at every width. At 320px: (288 − 6×4) ÷ 7 ≈ **37.7px** per column |
| Track | `relative overflow-hidden rounded-md bg-muted` + `HOURS_STRIP_TRACK` (`h-40`, 160px) |
| Segment | `absolute inset-x-0 rounded-sm bg-foreground`, positioned by **inline percentage**: `top = (openHour / 24) × 100%`, `height = ((closeHour − openHour) / 24) × 100%` |
| Day label | Beneath each column: `Sun` … `Sat` at `text-xs text-muted-foreground`, `aria-hidden` |
| Caption | Beneath the grid: **`Midnight to midnight · {City} time`**, `text-label text-muted-foreground` |
| Axis | **None.** No gridlines, no hour ticks, no left gutter |
| Colour | `bg-foreground` bar on `bg-muted` track — `foreground on muted`, **18.16 court**, declared. Never the accent |

> **Why the geometry is an inline percentage and not a Tailwind class.** Twenty-four `top-[N%]` and
> twenty-four `h-[N%]` variants are forty-eight undeclared arbitrary values in a repository whose build fails
> on one. A `style` object carrying two computed percentages carries **no colour and no type size**, so it is
> outside every leak scan by construction, and the values are derived from the same array that draws the
> sentences. This is stated so nobody "fixes" it into arbitrary classes.

> **Why there is no axis, and why the strip still does its job.** The strip's purpose (D-152) is that *a
> mistyped window is visible immediately*. A host who types 9 AM where they meant 9 PM sees the bar jump
> from the bottom third of the column to the top third — a **shape** change, legible with no scale to read.
> Precision is not the strip's job: the exact times are in the selects six inches below, and in the text
> equivalent. Adding gridlines would also add an undeclared hairline pairing to a surface whose entire
> justification is that it carries no information (§ Color). The strip trades precision it does not need for
> a contract it can keep.

> **Why the columns are vertical.** A weekly pattern is read across days at the same hour — *"Mon–Fri open at
> six, Saturday opens at eight"*. Vertical tracks put the same hour on the same horizontal line across all
> seven columns, so that reading is a glance. Horizontal rows would put it on a diagonal.

### The four renderings

| Case | Draws | Announces |
|---|---|---|
| **One window** | One segment | `Monday: 6:00 AM to 10:00 PM` |
| **Multiple windows** | One segment per window, each absolutely positioned. **Touching windows (09:00–12:00 and 12:00–15:00) visually merge into one bar, and that is correct** — the space *is* open continuously across the boundary, which is exactly what the `'[)'` half-open schema means. Do not insert a forced gap | `Tuesday: 6:00 AM to 9:00 AM, and 5:00 PM to 10:00 PM` |
| **Closed day** | An empty track. No marker, no glyph, no strike | `Sunday: closed` |
| **No hours at all** | Seven empty tracks, plus one line beneath the caption: **`Closed every day — no hours set yet.`** at `text-label text-muted-foreground` | seven `closed` sentences |

**The all-closed week is not an error state and carries no alarm.** It is the truthful picture of a listing
that has not been set up yet, and the shipped hours-missing signal (which the dashboard and the listings grid
already render from `hours-signal.ts`) is where that fact becomes actionable.

### One derivation, two consumers (D-153)

```
deriveWeekStrip(windows: WeeklyHoursWindow[]): WeekStripDay[]
  // WeekStripDay = { dayOfWeek, dayLabel, segments: {openHour, closeHour}[], sentence: string }
```

- **Pure, exported, and the ONLY source of both halves.** The bars are drawn from `segments`; the sr-only
  list is `sentence`. The seen and the announced cannot drift because there is one function.
- **Input is the live form array** — the `useWatch({ name: "windows" })` value the editor already holds as
  `liveWindows`, **not** `initialWindows` and **not** a re-read after save. D-152's whole point is that the
  preview updates *before* the round-trip.
- **Times are formatted with the SAME map the selects render** (`HOUR_OPTIONS`'s `"6:00 AM"` labels), so the
  announced string matches what the host picked, glyph for glyph.
- **Days are ordered `0=Sun … 6=Sat`**, the `operating_hours.day_of_week` convention the editor and the lock
  state already use. Seven entries, always — a closed day is a row with zero segments, never a missing row.

### Accessibility

| Rule | Value |
|---|---|
| The bars | The **entire** seven-column grid is `aria-hidden="true"`. It is decoration |
| The equivalent | `<ul className="sr-only">` with exactly **seven** `<li>`, one per weekday, in the same order |
| Live region | **None.** The sentences are static text that re-renders with the form; the select the host just changed already announces its own new value, and a second announcement for one action is GATE-03 rule 6's defect |
| `aria-live="assertive"` | **Banned**, as everywhere else |

**Falsifiable (`tests/availability/week-strip.test.tsx`):**
1. `deriveWeekStrip` returns exactly 7 entries for every input including `[]`.
2. For every input, `segments.length` equals the number of time ranges named in `sentence` (and `sentence`
   ends in `closed` iff `segments` is empty).
3. Rendering the editor, changing one `openTime` select, and asserting the sr-only sentence for that day
   changes — **with zero network calls made**.
4. The strip container computes `aria-hidden="true"`; the accessibility tree contains the seven sentences
   and **zero** of the bars.
5. Two windows that touch at an endpoint render two segments whose boxes are adjacent with a 0px gap.

## Anti-Patterns — reject these in plan review

- **A schema migration.** PROJECT D-136 binds; `drizzle/` does not move. A Phase-14 plan proposing one is a
  scope alarm to be raised, not absorbed.
- **A grove baseline for any Phase-14 surface.** PROJECT D-138 supersedes the two-theme half of D-133/D-135.
- **Coral on `/host/requests`, `/host/bookings`, `/host/earnings` or the availability editors.** Those three
  carry none today and must carry none after.
- **Converting the wizard's step marker to `variant="brand"`.** It takes `brand-recipe.test.ts`'s pinned
  count to zero and the gate goes red for a reason with nothing to do with the design.
- **Making the current step marker a control.** It is where the host already is, and it would put a second
  reachable accent fill in the viewport.
- **Tracking visited-ness by numeric index.** The walked list is mode-dependent; an index-keyed set
  silently repoints every marker after `occupancy` the moment the mode changes.
- **A `data-testid` that is not in `selector-contract.ts`.** It is a compile error, not a review comment.
- **A fourth card container.** DS-11 says three. A hand-rolled `<div className="bg-card ring-1 rounded-xl">`
  is invisible to `card-pattern-coverage.test.ts` and is the same defect wearing a disguise.
- **Nesting a `RowCard` inside a `PanelCard`.** 112px of padding where 80px was designed — the trap
  `card-pattern-coverage.test.ts`'s own header records, and the reason the dashboard's agenda is a heading
  plus rows on the page ground rather than a panel full of cards.
- **Giving `request-row.tsx` an `href`.** D-144 closes that question; a triage queue that browses is no
  longer a triage queue, and two places carrying approve/decline is two places that must be kept in
  agreement.
- **An error affordance on inbox-zero, or on the quiet-day dashboard, or on a week with no hours set.** All
  three are absences, and `T-11-FALSEALARM` binds.
- **A retry, a red, or the word "error" anywhere a host has simply not finished setting something up.**
- **Overlaying date-specific blocks on the week strip.** D-152 forbids it by name: the preview must describe
  exactly what the editor above it sets, and a one-off block turns "my weekly pattern" into "this specific
  week" silently.
- **A live region on the strip.** The select the host just changed already announces itself; a second
  announcement for one action is GATE-03 rule 6's defect.
- **Drawing the strip's bars with arbitrary Tailwind percentages.** Forty-eight undeclared values in a repo
  whose build fails on one.
- **A gridline, an hour tick or an axis label on the strip.** Each adds an undeclared hairline pairing to a
  surface whose entire justification is that it carries no information.
- **A timer driving the save state.** D-150: the indicator reads the actual `saveListingStep` result, and a
  `setTimeout` that clears it is an optimistic string wearing a delay.
- **A toast and an in-page region for one outcome.** Pick the one that survives a refresh.
- **Restructuring earnings, adding a chart, a date range, a filter or a new payout state.** D-156, and
  HFLOW-05's own words: those numbers have never been real.
- **Converting `PayoutBanner` to a `PanelCard`.** It is a payout surface and D-156 freezes it structurally.
- **A second filled-success surface.** The review checklist's done marker is the one survivor in the repo
  and it survives only because it holds a glyph and nothing else.
- **Adding an action to the availability editor.** Copy-to-all is Phase 19 (PROJECT D-136). Leave the row
  friendly to it; add nothing.
- **Merging the host and booker shells**, or merging the `Requests` badge with the notification bell.
- **Moving owner-scoping out of the `WHERE` clause into a page branch.** A branch can be bypassed by a
  crafted parameter; a `WHERE` cannot. This is the class Security V4 warns about and D-101 already rejected
  once.
- **`new Date()` in any render path.** The DB clock is the authority and it is read once per request.
- **Quoting a banned class name inside an explanatory comment.** Three plans in this repo have been burned
  by it. Name tokens descriptively.

## Open Questions — flagged for the PM, not blocking

Each was decided so the phase can proceed (12-CONTEXT D-59 as the tie-break). Each is a **product** call the
PM may reverse without re-planning the phase.

1. **The dashboard's header cluster loses `Earnings` and `Requests`.** Both are permanent slots in the host
   nav, rendered on this very page, and the requests count now has a signal row three inches below. Two
   buttons that duplicate persistent navigation are two competitors for the one accent.
   **Decision taken:** the cluster becomes `Create listing` + `Your listings`, and the agenda's heading row
   gains `View all bookings` — a route-out `/host` does not have at all today. Reversible by re-adding two
   `variant="outline"` buttons; nothing else in the spec depends on it.

2. **D-148's "forward steps stay inert" is read strictly:** a marker is interactive iff its key is visited
   **and** its index is below the current step. A host who walks to step 6, returns to step 2, and then wants
   step 5 uses `Save and continue` — the path that re-validates and autosaves.
   **The alternative reading** is that any visited step is clickable in either direction, which is
   technically safe because every step autosaves independently. It is not taken because it reintroduces
   exactly the case D-148 rejects free jumping over — landing on a step whose earlier answers are blank —
   for a host who backed out mid-flow. One-line change if the PM prefers the wider rule.

3. **The `(host)` error boundary's `routeOut` is `/host`, which is a self-link on the dashboard.** A host
   whose dashboard throws is offered a button back to the dashboard.
   **Not changed here, deliberately:** it is the shared boundary for all twelve host routes and `/host` is
   the correct destination for the other eleven. The fix is a per-route boundary or a route-out that reads
   the pathname, both of which are changes to Phase-11 shell work on a surface this phase is restyling
   rather than rebuilding. Recorded so it is found rather than rediscovered.

4. **The agenda heading carries no date** because a host with venues in two timezones has two "todays" and a
   single date would be silently false for one of them. If the PM would rather see the date and accept that
   it is the *first* listing's day, that is one line — but it should be an explicit choice, not a default.

5. **A refused approve or decline moves from a toast to an in-row line.** It is a small behaviour change on
   the inbox, made because a refusal is a sentence the host must read and a toast is dismissible, timed and
   gone on refresh. The success toasts are unchanged.

6. **`D-141`'s day-boundary predicate is handed to planning with a recommendation, not a decision.** The
   recommended rule — a session is "today" iff its venue-local calendar date equals the venue-local calendar
   date of the DB clock, evaluated per row in that row's own `listing.timezone` — is the only reading under
   which a two-zone host sees each venue's real day. D-141 requires the answer to be **written down and
   tested**, whichever way it lands.

7. **The 11-UI-SPEC's `ResultCard` *Replaces* list is corrected rather than obeyed** (14-CONTEXT's
   discretion item for `[11-16]`). `listing/listing-card.tsx` is dropped from that list: the host listing
   tile is a **management** tile carrying four controls, and a tile that is one whole-card anchor cannot hold
   interactive children without nested-interactive accessibility problems. **No fourth container is added** —
   DS-11 still says three, and `ALLOWED_RAW_CARD` already carries the tile with that measured reason. This is
   a spec correction, not a container swap.
