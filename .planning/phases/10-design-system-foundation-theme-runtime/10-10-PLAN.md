<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| codegen script → repository filesystem | The generator writes into `src/lib/design/` and `public/` |
| theme value → DOM `<link href>` | `FaviconSwap` puts a theme-derived string into a document attribute |
| committed generated artifact → reviewer trust | A generated file that drifts from its source is a lie a reviewer will believe |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03 | Tampering | `scripts/generate-design-tokens.mjs` | mitigate | Both read and write paths are hard-coded `resolve(process.cwd(), "<literal>")` constants and the script accepts no arguments; `grep -c "argv"` returning 0 is an acceptance criterion (ASVS V12). |
| T-10-30 | Repudiation | `src/lib/design/tokens.generated.ts` | mitigate | D-18's regen-diff test asserts byte equality and is wired into `test:design`, which plan 10-12 wires into `build`. Its own guard-the-guard rejects an empty render matching an empty file, and the executor observes it going red on a one-character edit before closing the task. |
| T-10-04 | Tampering | `FaviconSwap` href | mitigate | The theme value is checked against the `THEMES` allowlist with `.includes()` and mapped to one of two literal paths; nothing user-controlled is interpolated into the `href` (ASVS V5). |
| T-10-31 | Information disclosure | deleted assets | accept | The five starter SVGs and `favicon.ico` are create-next-app scaffold assets containing no project data; they are verified unreferenced before deletion. |
</threat_model>
