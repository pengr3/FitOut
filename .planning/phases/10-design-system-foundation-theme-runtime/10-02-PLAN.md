<objective>
Build the two shared primitives every later gate reads from — the leak-pattern list and the
`globals.css` token parser — plus the helper that compiles `globals.css` programmatically, and settle
THEME-04's assertion layer with a recorded spike.

Purpose: D-16 requires ESLint and Vitest to enforce one list, not two. `eslint.config.mjs` is ESM
JavaScript and cannot import a `.ts` module, and any module holding the hex/palette regexes would trip its
own gate if it sat under `src/**`. Both shared modules therefore live in a new plain-ESM `config/`
directory outside the scanned tree.

Output: `config/design-leak-patterns.mjs`, `config/design-tokens-source.mjs`,
`tests/design/helpers/compile-css.ts`, and a self-test that proves both the true positives and the two
known false-positive classes.
</objective>

      does not. Recommended source:

      without it the pattern matches `in_oklch,` inside `button.tsx:16`'s `color-mix`. Do NOT add
      `color-mix(` to the ban list — a `color-mix` over two tokens is not a leak, it is the phase's
      prescribed hover idiom.
    - `arbitrary-text-px` — `/text-\[[0-9.]+px\]/`. **px-only**, per UI-SPEC Resolved Q2: it matches
      DS-13's literal wording and the measured baseline (14 app / 0 vendored). Record in the `why` field
