<objective>
Wire the capacity claim into the booking mutation: a new `placeOpenHold` server action that takes a DATE and
a pass count, forks on the listing's persisted occupancy mode, mints the hold through
`createOpenCapacityHold`, and hands the granted count to the reserve page. Close the step-up hole
(`updateDeclaredPax`) and prove the payment rail is unchanged.

Purpose: OPEN-02's entry point and the mode-fork half of OPEN-03. The security core is that **both**
mutations refuse the other mode: without that, an exclusive-shaped payload against an open listing would
mint a booking through `createPendingHold` — bypassing the admissions counter entirely and, because the
EXCLUDE no longer sees open rows, arbitrated by nothing at all.

Output: `openHoldSchema`, `placeOpenHold`, two mode refusals, the D-126 step-up refusal, and three test sets.
</objective>

```typescript
/**
 * The OPEN-CAPACITY hold payload (OC-02/OC-06). A drop-in booker picks a DATE — never a time window — and a
 * number of passes. There is deliberately no `startUtc`/`endUtc`/`fullDay` here: the entry window is derived
 * SERVER-SIDE from the listing's operating hours for that date (OC-03), so the client cannot choose, widen
 * or shift the window the refund ladder and payout sweep will later key on.
 *
 * `date` is a venue-local calendar day. It is re-parsed by `parsePickedDate` in the action, which
 * canonicalizes it and round-trip-guards impossible dates (2026-02-31) before anything reaches SQL.
 *
 * CR-03 restated for passes: the `.max()` is a SHAPE ceiling, not the cap. It exists so no accepted value
 * can multiply through `per_head_price_cents × passes` into the `integer` money columns and raise a
 * Postgres 22003 that `mapBookingError` would re-throw as a raw 500 (T-03-500). The REAL cap is the
 * listing's own `max_occupancy`, read inside `createOpenCapacityHold`'s transaction and applied there
 * against the live admissions SUM (D-124 / Security V4) — never a client-supplied bound.
 */
export const openHoldSchema = z.object({
  listingId: z.string().min(1),
  date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/, "Pick a day to book."),
  requestedPasses: z.coerce.number().int().min(1).max(10_000),
  idempotencyKey: z.string().max(200).optional(),
});
export type OpenHoldInput = z.infer<typeof openHoldSchema>;
```
