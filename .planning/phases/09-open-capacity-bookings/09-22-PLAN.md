<objective>
Close **CR-05** (reported, NOT independently verified): `createGroup` never checks occupancy mode. Four files
hard-code `openCapacity: false` into `composeWhenLabel` on the strength of "a group can only ever be created
on an exclusive booking (D-110)", and the only thing implementing that rule is a **UI condition** on the
booking detail page — whose own comment claims the server re-checks:

> "ALL THREE ARE COURTESIES. `createGroup` re-checks ownership and confirmation server-side before it writes
> anything, so a hand-crafted POST that skipped this UI gains nothing (Security V4)."

`createGroup`'s gate (`group.ts:236-243`) and its defence-in-depth INSERT predicate (`:292-296`) check
`booker_id`, `status = 'confirmed'` and `max_occupancy >= 2`. **Neither checks `occupancy_mode`.** The quoted
sentence is false for exactly one of the three conditions, and it is the one Phase 9 added.

Purpose: the failure is a capacity lie sent to third parties. A booker buys **one** drop-in pass on a 30-cap
gym, pays, then POSTs `createGroup(bookingId)` directly. The insert succeeds with
`capacity_snapshot = GREATEST(max_occupancy − 1, 0) = 29` — the **daily admissions cap**, which has nothing to
do with the one pass that was paid for. Up to 29 people RSVP yes and are told they are coming; every group
surface renders the pass through `composeWhenLabel({ openCapacity: false })`, i.e. the sixteen-hour-reservation
line 09-08 forked the formatter to prevent, now emailed to strangers; and the venue sees 30 people arrive
against 1 paid admission the counter never saw.

**This plan is CONFIRM-THEN-FIX.** Task 1 must independently reproduce the defect against the current code
before Task 2 changes a line of `src/`.

The `depends_on: ["09-17"]` is a **sequencing** constraint, not an artifact one — this plan shares no file
with 09-17. It exists because the gap-closure mandate puts the two orchestrator-verified blockers first, and
`workflow.use_worktrees` is false so plans serialise in plan order regardless.

Output: the guard in both places it must exist, the page comment made true, and a test that begins as the
confirmation and ends as the regression guard.
</objective>

```ts
    WHERE b.id = ${parsed.data.bookingId}
```
