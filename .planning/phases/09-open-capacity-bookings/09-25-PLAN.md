<objective>
Close **WR-05** and the `cancel-booking.ts` half of **NT-01**.

**WR-05.** `cancelBookingAsBooker`'s flip is scoped `AND starts_at > now()`. For a drop-in pass that instant
is the venue's **opening** time, so the entire day a pass is valid for is a day on which it cannot be
cancelled or refunded — even though the pass is still fully usable. Today this is masked by CR-01 (a same-day
pass cannot be bought at all); **09-17 removes that mask and exposes it directly**: a pass bought at 15:00 for
today is instantly non-cancellable and non-refundable, and nothing on the reserve page says so.

**NT-01.** Both refusals read "This session has already started" — the exact framing 09-08 forked
`when-label.ts` to eliminate for passes, and which the anchor `CancellationPolicyDisclosure` already renames
("before the space opens"). 09-17 forked the `booking.ts` copy; this plan forks the `cancel-booking.ts` one.

Purpose: shipping "you bought it, it's final, and nothing told you" is the worst of the reviewer's options.
This plan takes the other one — **allow cancellation while the pass window is live** — because it is better
for all three parties and because it is safe for exactly the reason CR-01's divergence was safe:

- the refund is whatever the ladder already says. `quoteRefund` handles a negative `hoursToStart` by design
  ("Nothing satisfied — which includes every negative `hoursToStart` … falls through to 0",
  `src/lib/payments/cancellation.ts:92-96`), so a same-day cancel retains the full space price. **No money
  math changes.**
- the D-94 clawback property is preserved. Its stated rationale is that payout is not eligible until
  `ends_at + 24h` (D-55), so a refund is always a platform-wallet reversal with the host never yet paid —
  and while a pass window is live, `ends_at + 24h` is still in the future. Moving the guard from `starts_at`
  to `ends_at` for open rows keeps that property intact; it does not weaken it.
- the spot returns to the pool with no release code (`remaining` is a live SUM), so a booker who cannot come
  frees a head that would otherwise be a paid no-show.

**Scope note — the HOST cancel path is deliberately unchanged.** WR-05 cites the booker flip
(`cancel-booking.ts:557-570`). `cancelBookingAsHost`'s own `AND starts_at > now()` at `:991` stays: a host
withdrawing a pass a guest may already be using is a support case, not a self-serve one, and widening it would
be a product decision nobody asked for. Say so in the code comment so the asymmetry reads as a choice.

Output: the forked window, the forked refusals, a required disclosure prop with a two-site census, and cases
in the existing 09-09 test file.
</objective>
