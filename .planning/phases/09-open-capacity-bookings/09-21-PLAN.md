<objective>
Close **CR-04** (reported, NOT independently verified) and **WR-04** (warning) — two halves of the same
sentence: *a bad money input on the drop-in path must produce a calm refusal, never a raw 500.*

**CR-04.** `publishSchema`'s open branch correctly requires `per_head_price_cents`, `maxOccupancy`,
`bookingMode === "instant"` and `unitCount === 1`. But `saveListingStep` writes `occupancyMode` and every
other field straight to the live row and **never re-runs `publishSchema` for a `published` listing** — the
only edit-path re-gate that exists is the HG-01 surcharge-reachability check at `listing.ts:133-144`, added
for exactly this reason and never extended to the Phase-9 fields. The wizard makes this the *normal* path:
`STEPS` puts `occupancy` **before** `pricing`, and `saveAndContinue` persists the whole form on every step. A
host picking "Drop-in passes" and clicking *Save and continue* leaves a published, bookable listing in
`open_capacity` with `per_head_price_cents = NULL`. A booker's click then reaches
`quoteOpenCapacity({ perHeadPriceCents: null })`, which **throws**; `mapBookingError` re-throws anything that
is not `NoUnitAvailableError`/23P01/40P01; the exception escapes `placeOpenHold` as an unhandled server-action
error — the exact `T-03-500` outcome `mapBookingError`'s own docblock promises never happens.

**WR-04.** The `.max(10_000)` docblocks in `src/lib/validation/booking.ts:100-108` and `:126-136` assert a
protection that is not there: `granted` is bounded by `remaining = cap − taken` where `cap` is the **host's**
`max_occupancy` (only `.int().positive()` at publish), and `per_head_price_cents` is likewise unbounded above.
The product can exceed int4 and raise a Postgres 22003 on the money columns — again re-thrown as a raw 500.
A comment asserting a protection that does not exist is how the next reader stops thinking about it.

**This plan is CONFIRM-THEN-FIX.** Task 1 must independently reproduce CR-04 against the current code before
any `src/` change, and must state what happens if it does not.

Output: the published-row re-gate reusing the publish path's own sentences, a fail-closed claim, real numeric
ceilings that make the docblocks true, and a test file that begins as the confirmation and ends as the guard.
</objective>
