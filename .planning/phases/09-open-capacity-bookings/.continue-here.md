## Critical Anti-Patterns (do NOT repeat these)

- **ANTI-PATTERN: treating a green suite as coverage of the same-day path** → both proof layers avoided it
  (e2e books ≥3 days out; the UAT ran before opening hour). Add the case, mutate it, prove it fails.
- **ANTI-PATTERN: inferring occupancy mode from null rates** → a drop-in listing can legally still carry
  `hourly_rate_cents` / `day_rate_cents` / `included` / `extra_head_fee`. 09-06 requires a per-head price but
  never clears the exclusive columns, and OC-17 permits the switch. Always read the persisted
  `occupancy_mode`. Several fixtures deliberately keep those columns so a fork can only pass by keying on mode.
- **ANTI-PATTERN: adding a raw-SQL booking projection without the `open_capacity` alias** → `tsc` cannot check
  it; a dropped alias yields `undefined` → falsy → the drop-in pass renders as a 16-hour reservation.
  `bookings-query.ts` (both SELECTs) and `reminders.ts` have DB-backed mutation-verified cases; any new raw
  projection owes the same.
