<objective>
Teach search about drop-in listings: an all-in `₱/person` rate, a price filter and sort that do not exclude
them, and a Stage-2 branch that keeps an open listing only when the picked date still has a spot — carrying
the server-derived scarcity state onto the row.

Purpose: OPEN-04's search half and OC-12. This plan also closes a **latent trap the pattern mapper found**:
Stage-1's `priceMax` predicate tests `l.hourly_rate_cents`, which is NULL on every open listing, so today a
price filter would silently delete drop-in listings from results. The same expression governs the price
sort, which would otherwise bury every drop-in listing at the end of the list.

Output: `allInRateParts`'s `/person` branch, the Stage-1/Stage-2 forks, and a search test file.
</objective>

```typescript
// Phase-9: the listing's ADVERTISED unit price, whichever unit it sells in — hourly for an exclusive
// listing, per-person for a drop-in (D-125). Written once and used by BOTH the price filter and the price
// sort, so a drop-in listing can never be invisible to one and mis-ranked by the other. Comparing an
// hourly rate against a per-person day pass is imperfect, and deliberately so: silently DELETING every
// drop-in listing from a filtered search is strictly worse than ranking it approximately.
const effectivePriceSql = sql`(CASE WHEN l.occupancy_mode::text = 'open_capacity'
                                    THEN l.per_head_price_cents ELSE l.hourly_rate_cents END)`;
```
