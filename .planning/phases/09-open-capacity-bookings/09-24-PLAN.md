<objective>
Close the three read-model findings from 09-REVIEW that share one file pair and no dependency on each other:

**WR-02 — a split-shift day that crosses midnight gets a truncated pass window.** `loadOpenDayWindow` takes
`MIN(open_time)` / `MAX(close_time)` across the weekday's rows to build "the outer envelope"
(`open-capacity.ts:158-170`). `MAX` on a wall-clock `time` cannot express a shift that rolls past midnight. A
gym storing Saturday as `06:00–12:00` and `18:00–02:00` yields `MIN(open) = 06:00`, `MAX(close) = 12:00`
(because `'12:00' > '02:00'`), so `rollsPastMidnight` is false and the pass window becomes **06:00–12:00**.
The evening session vanishes; the day panel says "Open 6:00 AM – 12:00 PM"; `ends_at` is noon; and because
`expires_at = LEAST(now + 15min, ends_at)` an afternoon claim mints a hold that is **born already expired**,
while `day_open_ok` refuses claims after noon on a day the venue is open until 2 AM. This is the same
unpayable-hold shape as CR-01, reached by a different route.

**WR-03 — `OPEN_LOW_STOCK_MAX` is an unvalidated `Number(env)`.** `Math.min(x, NaN)` is `NaN` and
`remaining <= NaN` is always false, so `OPEN_LOW_STOCK_MAX=five` (or a trailing space, or an empty string
coercing to `0`) makes `spotsState` never return `"low"` and every date renders the digit-free
"Spots available" chip right up to "Fully booked" — the OPEN-04 scarcity signal silently off, on a server-only
constant nobody looks at.

**NT-02 — the month grid and the day panel disagree when `max_occupancy` is NULL.**
`getOpenMonthAvailability` uses `cap = maxOccupancy ?? 0` and marks a date full only when `taken >= cap`;
with `cap = 0` a date with **no** bookings produces no row at all and stays *selectable*, while `getOpenDay`
computes `remaining = 0` and renders "Fully booked". A mis-configured or mid-edit listing offers dates the
panel then refuses.

Purpose: each is a small, well-understood defect in the two files that own the open read model, and each has
a booker-visible consequence. Grouping them is a context decision, not a coupling one — every task is
independently revertible.

Output: three targeted fixes and three cases in the existing read-model test file.
</objective>
