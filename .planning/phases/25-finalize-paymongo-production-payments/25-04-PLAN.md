<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PayMongo merchant/wallet state → payout sweep | Provider entitlement and wallet correlation determine whether an external transfer may be attempted. |
| payout transfer provider response → durable ledger | A request acknowledgement is not a terminal payout; reconciliation maps provider state into the durable ledger. |
| release authority → customer and host traffic | Broad availability and rollback are external financial decisions that need accountable authorization. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-10 | Spoofing | Merchant activation and recipient wallet | critical | mitigate | Require provider evidence, activated-wallet correlation, and authorized recipient boundary; never infer a default wallet. |
| T-25-11 | Tampering | Payout transfer lifecycle | critical | mitigate | Preserve held-to-processing claim and processing-only reconciliation; use provider-derived terminal status and alert ownership. |
| T-25-12 | Repudiation | Manual return and alert response | high | mitigate | Require named monitored recipient, response owner, SLA, and redacted reconciliation record for every exception path. |
| T-25-13 | Denial of service | Broad-release rollback | high | mitigate | Require a documented provider-side stop method and authority; any missing executable boundary forces HOLD. |
| T-25-SC | Tampering | Package-manager supply chain | high | mitigate | Keep package files unchanged; any proposal to install a package stops for legitimacy review. |
</threat_model>
