<objective>
Write the two build-blocking design gates that make the shell's claims falsifiable, in the config that
runs inside `npm run build`.

Purpose: `npm run build` is `lint && test:design && next build`, so a gate placed in `tests/design/**`
blocks the build. But `vitest.design.config.ts` declares **no `globalSetup` and no `setupFiles`** by
contract — the global `vi.mock("resend")` does not exist there. A gate that asserts on a captured send
cannot run in that config. Both gates therefore assert on the pure exported `renderEmail`, which is why
plan 15-01 built it that way. This is the first "assert on a pure exported renderer" test in the
repository — the precedent 15-RESEARCH cites does not actually exist yet (measured: zero test files
import `renderOpsAlertDigest`), so this plan is creating the pattern, not copying one.

Output: two pure node test files, each carrying guard-the-guard assertions first and a positive-control
fixture, each watched red by mutation before it is trusted.
</objective>

  <name>Task 1: The EMAIL-01 structural and parity gate</name>

  <behavior>
    - A rendered email with a CTA contains exactly one preheader div, exactly one `width="600"` table, exactly one `font-family` declaration.
    - A rendered email contains zero `display:flex`, zero `display:grid`, zero `float:`, zero `<img`, zero `class=`, zero `<style`, zero `xmlns`, zero `DOCTYPE html PUBLIC`.
    - Every layout `<table` carries `role="presentation"`.
    - With a CTA present, the index of the first `https?://` match in the HTML equals the index of the CTA href — no absolute URL precedes it.
    - With no CTA present, the HTML contains zero `https?://` matches.
    - Every paragraph string appears verbatim in `text` and escaped in `html`; the heading likewise; the text part carries a `{label}: {raw href}` line.
    - A payload containing quote-and-markup characters appears nowhere raw in the HTML — including inside the preheader div.
    - While `SUPPORT_EMAIL` is null the rendered HTML contains zero `mailto:`.
    - The set of `font-size:` values in a rendered email is exactly the five the spec declares.
  </behavior>

    absence, and an empty string satisfies all of them: assert the rendered HTML length exceeds a floor

    that the rendered `text` length exceeds a floor and contains the heading. Copy `token-drift.test.ts`'s

    one preheader div; one `width="600"`; exactly one occurrence of `font-family`; zero occurrences of
    each banned construct (`display:flex`, `display:grid`, `float:`, `<img`, `class=`, `<style`,
    `xmlns`, `DOCTYPE html PUBLIC`); every `<table` occurrence accompanied by `role="presentation"`
    **except** the count contributed by `tableHtml`, which arrives pre-built from its producer — derive
    that expectation from the fixture rather than hard-coding a number, so the assertion stays true when
    the digest's table changes shape.

    Then the **first-URL block**, which is the security-relevant one. With the CTA fixture: find the
    index of the first `https?://` match in the HTML and assert it equals the index of the CTA href's
    own occurrence. With the no-CTA fixture: assert zero `https?://` matches in the HTML. State in the
    failure message that `tests/helpers/mocks.ts`'s `extractLink` takes the first match and that three
    shipped auth tests feed it to `new URL(...)` — so a regression here surfaces as a bogus "invalid
    token" three layers away.

    Then the **parity block**: for each paragraph in the fixture, assert the raw string appears in
    `text` and `escapeHtml(paragraph)` appears in `html`; assert the same for the heading; assert the
    text part contains the exact line composed from the CTA label and the **raw** href.

    Then the **escaping block**: render a content whose heading, first paragraph and CTA label all carry
    a quote-and-markup payload, and assert the raw payload appears nowhere in the whole HTML document —
    explicitly including the leading preheader region. Assert the escaped forms are present. Assert the
    payload DOES appear raw in `text`, because escaping `text/plain` would be a defect and an assertion
    that forbade it would be wrong.

    Then the **typography block**: collect every `font-size:` value in the rendered HTML and assert the
    set is exactly the five declared sizes — the wordmark size, the heading size, the body size, the
    footer/label size, and the 1px the preheader suppression uses. No send may introduce a sixth.

    Then the **footer-guard block**: with the shipped `SUPPORT_EMAIL` value, assert the rendered HTML
    contains zero `mailto:`. Add a source scan of `src/lib/email-shell.ts` asserting the guard exists
    exactly once and carries no `else` — a rendered absence alone cannot distinguish "guarded and
    currently null" from "never implemented".

    Finish with a **positive-control fixture**: a hand-written violating HTML string (containing a flex
    declaration, an `<img`, a `class=` and a second preheader) fed to the same scanning helpers the real
    assertions use, proving each scanner catches the class of defect it claims to. Follow
    `cancel-page-shell.test.tsx`'s rule and never write the fixture to disk.
