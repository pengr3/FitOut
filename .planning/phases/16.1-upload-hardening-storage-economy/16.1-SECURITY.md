## Trust Boundaries

Union of the seven plans' boundary tables, deduplicated.

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| host's local file → `api.cloudinary.com` | bytes go browser→vendor direct; our server never sees them (D-04, D-181). The client is **not** a boundary, and the module says so | untrusted image bytes, possibly EXIF/GPS-bearing |
| host's file picker → the widget's cross-origin iframe | our `options` are a *hint* to vendor code we do not control | file selection, client-side format/size hints |
| any signed-in host → `POST /api/cloudinary/sign` | untrusted `paramsToSign` crosses here; the response is a **credential-derived capability** | upload params in, HMAC signature out |
| our signature → Cloudinary's upload API | Cloudinary validates the signature against EXACTLY the params it receives, in both directions | signed param set (incl. `upload_preset`) |
| client-supplied `{ publicId, url }` → `persistPhoto` | untrusted; `isOwnCloudinaryAsset` is the ONLY thing that turns it into "an asset of ours" | asset identifiers written to a PUBLIC `<img src>` |
| our server → Cloudinary's destroy endpoint | a credentialed, **irreversible** delete against our own account | public ids (ours to delete only after provenance) |
| `softDeleteListing` → the listing's photo rows | ownership proven by `assertOwnership` before both the write and the destroy | listing/photo ownership scope |
| uploaded avatar bytes → our server | D-191's argument is that this boundary has **no decoder behind it** | `Buffer` handed straight to `upload_stream` |
| repo constant → live vendor configuration | the preset **NAME** is repo state; its **CONTENTS** are dashboard state | preset identity vs. preset settings |
| repo declaration → Cloudinary account configuration | `scripts/cloudinary-preset.ts` is the only committed writer of that configuration | transformation, `allowed_formats`, `unsigned:false` |
| `.env.local` → `scripts/cloudinary-preset.ts` | a server credential is loaded into a developer-run process; the allow-list is what bounds it | `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` |
| Cloudinary Admin API response → our drift verdict | an unrecognised vendor key must NOT be read as agreement | remote preset settings |
| e2e test process → Cloudinary | the test process holds **no** credential and must keep holding none | session-scoped product actions only |
| vendor English → our error copy | a third party's prose is the only discriminator available (I-2) | refusal strings |
| host's real phone photo → a public listing page | the GPS check is the only place the actual **delivered** bytes are inspected | EXIF/GPS in delivered image |
| a research measurement → a shipped claim | where measured-in-a-probe becomes proven-through-the-product | assumption A1 |
| source comments → the next reader | a comment promising declined work misdirects a reviewer as effectively as a wrong assertion | decision rationale, reversal conditions |
