# Phase 16.1 Plan 03: The Preset Reconciler Summary

**One committed command now creates the Cloudinary upload preset from the declaration and re-proves it still matches — parsing the declared transformation through a single table used for both sides of the diff so it re-spells not one number, format or component; failing closed on any vendor key it does not recognise; distinguishing "this drifted" from "I could not look"; and printing, beside its own green, the one thing it cannot see.**

## Accomplishments

- **RESEARCH § R-1.6 layer 4 exists, and it is a check of the declaration rather than of itself.** `DECLARED_PRESET` has three fields and all three are imports. The declared transformation string is **parsed** through `canonicalizeTransformation` into the long-key shape probe E12 measured, and the same table converts nothing on the remote side that it did not convert on ours — so there is no private spelling for the two to agree about. The rule-F2 source assertion proves it and has been **observed RED** (transcript below).
- **The preset can now be brought into existence.** `npm run cloudinary:preset -- --apply` GETs first, POSTs on 404 and PUTs otherwise, always sending `unsigned: false` explicitly, then **re-runs the verify path and exits on ITS result**. The phase's load-bearing security control stops being a thing somebody has to remember to configure by hand. (Not run here — see *User Setup Required*.)
- **"Drifted" and "could not run" are different answers, and the second one says so in a banner.** Exit 3 fires for an absent credential, a rejected credential, an unanswered API and an unexpected status, each printing `THIS IS *NOT* A DRIFT FINDING` and `Nothing about the preset has been checked, in either direction.` CI structurally holds no Cloudinary credential (`T-11-CISECRET`), so this is the code CI would see, and it must never be read as drift.
- **It fails closed on the one thing the research could not measure.** Probe E12's preset predates the format-conversion component, so the long key the vendor returns for `f_` was never observed. The script does not guess-and-pass: an unknown short prefix throws, and a returned long key the table does not know is a difference line with the raw payload already printed. `--verify` cannot report agreement about a component it does not understand.
- **The account-wide upload hole is re-proved, not inherited.** Every `--verify` lists the account's presets and FAILS on any `unsigned: true`. `ml_default` was measured `unsigned: false` on 2026-08-26 in RESEARCH § I-4; this turns that note into a check that runs (T-16.1-08).
- **The residual is printed beside the verdict, not filed in a planning document.** Every run ends with the sentence that a dashboard edit between two runs is undetectable, and that failing CLOSED is a different guarantee from still being correct. Whoever reads the green is the person who needs it.
- **The whole arithmetic half is pinned in CI with no network and no credential.** 19 tests in `tests/design/`, inside `npm run build`, on a machine that needs neither Docker nor a Cloudinary key.

## Decisions Made

- **`.ts` + tsx over `.mjs` + node.** Taken as the plan argues it, and the cost recorded rather than absorbed: `tsx` resolves at 4.22.4 via `drizzle-kit@0.31.10` and `vite@8.0.16` and is not a declared devDependency. Four shipped scripts already rest on that transitive, so this inherits an existing fragility rather than creating a class of one — and the header carries the `verify-workflows.mjs:116-121` rule verbatim: the fix is a dependency decision to raise, never the deletion of the reconciler.
- **`fetch_format` is pinned in the test, not read from the table.** Asserting `canonical[TRANSFORMATION_KEYS.f]` would have been asserting the table against itself. Spelling `fetch_format` in describe 1 means the row cannot change silently, which is exactly what makes 16.1-07's correction a deliberate one-line edit with the measurement in hand.
- **The matching-remote fixture is built from literals for the non-numeric keys, and from `LISTING_MAX_EDGE_PX` for the dimensions.** Building it by calling `canonicalizeTransformation` would have made describe 2's "no drift" case pass by construction whatever the parser did. Describe 1 pins the parser against explicit expectations; describe 2 then diffs against an independently-built fixture.
- **`presetDrift` is the authority, computed independently of the printed per-property checks.** The echoes exist for the human reading the output; the drift list is what decides the exit code, because only it can see a key on the remote object that the declaration never mentioned.
- **A 404 on `--verify` is a FAILURE, never "nothing to compare".** The message states the preset does not exist and that `--apply` creates it — and, because the mechanism fails closed, a 404 also means every upload through the widget is failing right now.

- **Found during:** Task 1 (pre-checking the rule-F2 property before committing, so Task 2 would not be written against a broken subject)
- **Issue:** The script's header explained the tsx choice by quoting the tsconfig path mapping with its glob. `tests/helpers/source-text.ts` strips block comments **first**, with `/\/\*[\s\S]*?\*\//g` — a regex, not a parser, exactly as its own header warns. The glob's slash-star opened a "block comment" at character 3659 that ran until the next close far below the imports, so `stripComments(SOURCE)` did not contain `@/lib/listing/upload-policy` at all. Measured: `contains @/lib/listing/upload-policy: false` against a file whose import statement was plainly present. This is the falsely-RED half of the `verify-workflows.mjs:24-32` finding, produced here by the *stripper* rather than by the naive substring — a third failure mode of the same family.
- **Fix:** Rephrased the header sentence to name the alias without the glob, and added a ⚠ paragraph recording the measurement and the rule it implies for any future file asserted over this way. The helper was **not** changed — its header explicitly says a caller who cannot narrow should replace it with a real tokeniser rather than grow special cases here, and this caller can simply not write the sequence.
- **Files modified:** `scripts/cloudinary-preset.ts`

**2. [Rule 2 - Missing critical correctness] The exit-code contract enumerated only "no credential" for exit 3, which would have made a REJECTED credential report as drift**

- **Found during:** Task 1 (writing the Admin API call path)
- **Issue:** The plan's contract reads `3 THE TOOL COULD NOT RUN — no credential. NOT a drift finding, and reporting it as one would train people to ignore the check.` The *reason* is stated in general terms but the *trigger* was enumerated narrowly. A `401`, a network failure, or a `500` from the Admin API each mean the tool did not look — and under the narrow reading each would have fallen through to a failure line and exit 1, which is the precise outcome the sentence forbids. - **Files modified:** `scripts/cloudinary-preset.ts`
