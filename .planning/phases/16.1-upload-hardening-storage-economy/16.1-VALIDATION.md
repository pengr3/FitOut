## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 4.1.8 (unit + integration) · Playwright (e2e) |
| **Config file** | `vitest.config.ts`, `vitest.design.config.ts`, `playwright.config.ts` |
| **Quick run command** | `npx vitest run tests/listing` |
| **Full suite command** | `npm test` (`vitest run`) |
| **Estimated runtime** | ~15s quick · ~3min full |

**CI reality — this constrains every row below.** The Vitest job runs with a Postgres service and
**no Cloudinary credential** (`cloudinary` is mocked in `tests/setup.ts`); the invariant is deliberate
and recorded as `T-11-CISECRET` at `.github/workflows/ci.yml:151`/`:875`. The e2e job runs
`price-parity.spec.ts` plus the visual job; `avatar-crop.spec.ts` is excluded by decision.

> **The honest limit, stated once so no plan has to re-argue it:** CI can prove *every decision our
> code makes* — the equality gate, the destroy ordering, the shared arrays, the refusal matcher. CI can
> prove **nothing** about what Cloudinary actually stores. The credential-bearing checks in
> § Manual-Only Verifications are not a gap to be closed; they are the phase's real gate.

## Sampling Rate

- **After every task commit:** Run `npx vitest run tests/listing`
- **After every plan wave:** Run `npm test` + `npm run lint` + `npx tsc --noEmit`
- **Before `/gsd:verify-work`:** Full suite green **plus** the six credential-bearing checks below
- **Max feedback latency:** ~15 seconds

## Manual-Only Verifications

**These are not a shortfall — they are the phase's real gate.** CI structurally cannot run them
(`T-11-CISECRET`: the test jobs hold no Cloudinary credential, deliberately). Each needs a local run
with a real credential, or a human.

| Behavior | Criterion / Decision | Why Manual | Test Instructions |
|----------|----------------------|------------|-------------------|
| The account really refuses >10 MiB | 1 / D-180 | Vendor-side; no CI credential | Upload a 10.1 MiB JPEG through the widget. Expect refusal + the too-big sentence. The ceiling is **exactly** `10485760` bytes with zero headroom — `10_000_000` is wrong. |
| SVG refused at the boundary | 2 / D-184, F-3 | Vendor-side | Signed upload of an `.svg` → `400 Raw file format svg not allowed`. Then pick an `.svg` in the widget → the wrong-format sentence. |
| HEIC uploads **and renders** | 2 / D-184, F-2 | Vendor-side + browser-side | Upload a real HEIC. Confirm the stored asset is **not** delivered as `image/heic` (Chrome/Firefox cannot render it) and that it displays at a render site. |
| Stored asset ≤2048px on the long edge | 3 / D-182 | Requires reading back what Cloudinary stored | Upload a 4000px photo through the widget. Read `width`/`height` back. Confirm ≤2048. |
| **GPS is gone, orientation is right** | 5 / D-189 | Needs real delivered bytes from a real phone photo | Take a photo on a phone with location on. Upload through the widget. Download the delivered file. Confirm no GPS IFD **and** correct rotation. **No new fixture** — a real phone photo is more honest than a synthetic one. |
| The preset matches its committed declaration | 3 / D-194 | Dashboard state; the residual risk layer 5 cannot close | `npm run cloudinary:preset -- --verify` → exit 0. Re-run at the phase gate, not only at apply time. |
| The avatar e2e leaves nothing behind | 6 / D-192 | Local-only e2e (excluded from CI) | Note the `fitout/avatars` count, run `npx playwright test e2e/avatar-crop.spec.ts`, confirm the count is unchanged. |
