<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form → signup server action | Untrusted email/password/firstName/intent; re-validated server-side with Zod |
| Browser → intent field | intent maps to a capability flag — must be set server-side, never trusted as a direct canHost value |
| Browser → /login, /reset-password | Credential + token input crosses here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | User maps intent to a host capability they shouldn't have, or tampers the request to set canHost directly | mitigate | Signup action sets canBook/canHost server-side from a validated `intent` enum; the flags are input:false so a direct canHost in the body is rejected (Plan-02 guard). intent only ever grants the chosen single capability. |
| T-03-02 | Information Disclosure | Account enumeration via forgot-password (different response if email exists) | mitigate | forgot-password shows a uniform "if an account exists…" message; Better Auth's requestPasswordReset returns uniform responses + fire-and-forget email (Plan 02). |
| T-03-03 | Spoofing | Reset-token replay / reuse after password change | mitigate | Better Auth tokens are single-use with TTL (resetPasswordTokenExpiresIn=3600, Plan 02); reset revokes other sessions (D-13). |
| T-03-04 | Tampering | CSRF on signup/login/reset POSTs | mitigate | Server actions (encrypted closures, Next 16) + Better Auth origin checks + sameSite cookies (Plan-02 defaults). |
| T-03-05 | Spoofing | OAuth state/CSRF on the Google flow | mitigate | Better Auth handles PKCE/state for socialProviders (do not hand-roll the OAuth dance — RESEARCH "Don't Hand-Roll"). |
| T-03-06 | Information Disclosure | Validation error messages leak which field/account exists | mitigate | Generic credential errors on login; uniform reset message; Zod errors are field-format only, not existence. |
</threat_model>
