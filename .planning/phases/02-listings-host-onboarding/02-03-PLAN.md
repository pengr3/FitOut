<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client wizard → server actions | Every field (price, capacity, status, address) crosses here untrusted; re-validated server-side |
| one host → another host's listing | Edit/publish/unlist/delete must be scoped to the owner (IDOR) |
| draft status → published status | The publish transition is the money-adjacent gate (D-02); only the server may flip it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-IDOR | Elevation of Privilege | saveListingStep/publish/unlist/softDelete | mitigate | assertOwnership (`hostId === session.user.id`) in every action before any write. |
| T-03-STATUS | Elevation of Privilege | listing.status | mitigate | status never accepted from a client body; publish/unlist are gated server actions asserting publishSchema + photo-count + emailVerified. |
| T-03-PRICE | Tampering | hourlyRateCents/dayRateCents/maxOccupancy | mitigate | publishSchema re-validates `.int().positive()` server-side; never trust the client price (UI-SPEC line 199). |
| T-03-PII | Information Disclosure | exact street address | mitigate | showExactAddress defaults off (D-09); exact street is withheld on the public page (Plan 05). Wizard stores the toggle only. |
| T-03-INPUT | Tampering | autocomplete lat/lng | mitigate | publish rejects absent coordinates; lat→y, lng→x axis order enforced (Pitfall 1). |
</threat_model>
