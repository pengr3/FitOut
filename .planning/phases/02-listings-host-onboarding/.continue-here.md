## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Selling a slot to an unpayable host | Treating `published` as `bookable`, or doing a one-time payout check | advisory | Bookability MUST be derived live as `published ∧ email_verified ∧ payouts_enabled`, driven by the `account.updated` webhook (D-14/D-15). Build the gate this phase so later phases can't bypass it. |
| Client-trusting price/capacity/status | Accepting price, capacity, status, or `payouts_enabled` from the client | advisory | Re-validate every field server-side (mirror Phase-1 `input:false`); `payouts_enabled` is webhook/server-set only, never client-settable. |
| Routing gallery uploads through the server | Reusing the Phase-1 avatar `upload_stream` for multi-photo galleries | advisory | Use Cloudinary **signed direct-to-client uploads** (`api_sign_request`) per the note in `src/lib/cloudinary.ts` (D-04). |
