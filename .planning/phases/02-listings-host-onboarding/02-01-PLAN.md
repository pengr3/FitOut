## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| schema/migration → test harness | Migration SQL is replayed verbatim into isolated schemas; a non-idempotent or mis-ordered extension statement breaks every integration test |
| money/status columns → future client writes | hourlyRateCents/dayRateCents/maxOccupancy/status/payoutsEnabled are money-adjacent; columns exist here but writes are gated in later plans |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-PRIV | Elevation of Privilege | `host_payout.payoutsEnabled` / `listing.status` columns | mitigate | Columns default false/draft; NO client-write path defined in this plan. payoutsEnabled is set only by the Plan-06 webhook; status only by the Plan-03 gated publish action. deriveBookable in this plan is pure (no setter). |
| T-02-PII | Information Disclosure | exact street address columns | mitigate | `showExactAddress` defaults false (D-09); the public projection (Plan 05) is the consumer. This plan only stores the toggle + structured fields. |
| T-02-FLOAT | Tampering (data integrity) | money columns | mitigate | Integer cents only (`integer`), never float/numeric (Pitfall 5); publishSchema validates `.int().positive()`. |
| T-02-GEO | Tampering (data integrity) | PostGIS location | accept→mitigate | Axis-swap risk (Pitfall 1) mitigated by mode:"xy" {x:lng,y:lat} convention + the geo-roundtrip test anchor. |
