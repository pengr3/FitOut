# Phase 2 — UI Design Contract

> Visual and interaction contract for the Listings & Host Onboarding phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase surface (from 02-CONTEXT.md):** the Airbnb-style multi-step listing creation/edit wizard, the listing photo gallery (Cloudinary signed direct upload + drag-reorder), space-type/amenity/activity pickers, structured address + map capture, pricing + booking-mode + status controls, the **public listing detail page**, the **Stripe Connect Express onboarding nudge + bookability status**, and the host's "my listings" management surface. Availability calendar, real search, and the live booking CTA are explicitly **out of scope** (placeholders only — Phase 3/4).

## Spacing Scale

Declared values (8-point scale, all multiples of 4). Maps to Tailwind v4 default spacing (`p-1=4px … p-16=64px`) — no custom spacing tokens needed.

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `1` | Icon-to-label gaps, chip inner padding, dense form-hint spacing |
| sm | 8px | `2` | Compact stacks (amenity checklist rows), button icon gap, photo-grid gutter |
| md | 16px | `4` | Default element spacing, form-field vertical rhythm, card inner padding (mobile) |
| lg | 24px | `6` | Card inner padding (desktop), wizard step section padding, gap between form groups |
| xl | 32px | `8` | Wizard content-column vs. summary gap, detail-page section gaps |
| 2xl | 48px | `12` | Major detail-page section breaks (gallery → header → amenities → map) |
| 3xl | 64px | `16` | Page top/bottom padding on the public detail page (desktop) |

**Exceptions:**
- **Touch targets:** all interactive controls (wizard nav buttons, photo reorder handles, amenity toggles, map controls) MUST be ≥44×44px hit area even when the visual is smaller — pad to reach it. This is a hit-area floor, not a new spacing step.
- **Photo gallery cells** use a fixed gutter of 8px (`gap-2`); the cover-photo cell on desktop spans 2×2 grid cells (CSS grid spans, not a custom spacing value).

## Typography

Single family (Geist). Exactly **4 sizes**, exactly **2 weights** (400 regular, 600 semibold). No italic, no third weight.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 28px (`text-3xl`≈30 → use `text-[28px]` or `text-2xl`=24; **declared 28px**) | 600 | 1.2 | Listing title on detail page; wizard top-level step heading ("Add photos") |
| Heading | 20px (`text-xl`) | 600 | 1.25 | Card titles, section headings (Amenities, Location, Pricing), "Your listings" page title |
| Body | 16px (`text-base`) | 400 | 1.5 | Listing description, field labels' help text, paragraph copy, input text |
| Label | 14px (`text-sm`) | 600 (form labels) / 400 (meta) | 1.4 | Form field labels (600), price/capacity meta, chip text, status badge text, helper/error microcopy (400) |

Rules:
- Body copy is always 16px / 1.5 / weight 400 — never smaller for primary reading content (listing descriptions).
- Headings use weight 600; never bold (700) — the 2-weight contract is regular(400) + semibold(600).
- Numbers in prices use the same sans family (Geist), tabular feel acceptable via `tabular-nums` but not required; do NOT switch prices to mono.
- `--font-heading` already aliases `--font-sans`; do not introduce a second display face.

## Color

The existing palette is **monochrome neutral** (shadcn `neutral` oklch) with **no brand accent claimed**. This phase introduces ONE brand accent — **FitOut Coral** — into the unclaimed 10% slot, consistent with the locked "mimic Airbnb" direction (Airbnb's signature is its rausch/coral). Everything else stays neutral.

### 60 / 30 / 10 split

| Role | Token | Light value | Dark value | Usage |
|------|-------|-------------|------------|-------|
| Dominant (60%) | `--background` / `--foreground` | `oklch(1 0 0)` (#FFFFFF) / `oklch(0.145 0 0)` (#0A0A0A) | `oklch(0.145 0 0)` / `oklch(0.985 0 0)` | Page background, body text. Unchanged. |
| Secondary (30%) | `--card` / `--secondary` / `--muted` / `--sidebar` | card `oklch(1 0 0)`, secondary/muted `oklch(0.97 0 0)`, border `oklch(0.922 0 0)` | card `oklch(0.205 0 0)`, secondary/muted `oklch(0.269 0 0)` | Listing cards, wizard side panel, summary rail, amenity chips, host dashboard surfaces, dividers. Unchanged. |
| Accent (10%) — **NEW** | `--brand` / `--brand-foreground` | **`--brand: oklch(0.637 0.208 25)`** ≈ **#E8484E** (FitOut Coral); **`--brand-foreground: oklch(0.985 0 0)`** (near-white) | **`--brand: oklch(0.645 0.205 25)`** ≈ **#F25C61**; **`--brand-foreground: oklch(0.145 0 0)`** | See reserved-for list. |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` ≈ #DC2626 | `oklch(0.704 0.191 22.216)` | Destructive actions only (see below). Unchanged. |
| Success (semantic, NEW) | `--success` / `--success-foreground` | `--success: oklch(0.62 0.17 150)` ≈ #16A34A; fg `oklch(0.985 0 0)` | `--success: oklch(0.7 0.16 150)`; fg `oklch(0.145 0 0)` | **Status only**, never a CTA. The "Payouts enabled / Bookable" state badge and "Published" confirmation. |

**Accent (FitOut Coral) reserved for — EXPLICIT, exhaustive list:**
1. The **single primary CTA per screen**: `Publish listing` (wizard review), `Create your first listing` (empty state), `Save and continue` (wizard primary advance button is neutral/`primary`; only the terminal `Publish` is coral — see rationale).
2. The **public detail-page book button** when bookable (it is a Phase-4 placeholder, but its *bookable* visual state is coral; its disabled/"not bookable yet" state is neutral-muted).
3. **Active wizard step indicator** (current step dot/bar in the stepper) and the completed-step check.
4. **Selected state of the primary space-type picker** (the one canonical category selection ring/fill).
5. Brand wordmark / logo lockup only.

Accent is NOT used for: secondary buttons, all links, amenity multi-select toggles (those use neutral `primary`/`secondary` selected states), form focus rings (those use `--ring`), the wizard "Save and continue" intermediate buttons, status badges (those are neutral/success/destructive), or generic hover states.

> Destructive vs. brand separation is deliberate: coral (warm red-orange, hue ~25) and destructive (true red, hue ~27 but higher chroma) are visually adjacent. To avoid confusion, **destructive actions always pair the color with a destructive icon + verb** ("Delete", trash icon) and live in confirmation dialogs — never as a bare colored button in normal flow. The brand coral never appears on a delete/remove control.

### Destructive / dangerous surfaces this phase
- **Remove a photo** from the gallery (hover-reveal X on each tile) — uses `--destructive` on the icon, inline, no dialog (low-stakes, reversible by re-upload, draft state).
- **Delete / archive a listing** (soft-delete per Claude's Discretion) — `--destructive` button, gated behind a confirmation dialog.
- **Unlist a listing** (published → unlisted) — NOT destructive-colored; it is reversible and data-preserving. Use neutral `secondary` with a confirming dialog explaining "hidden from the public, re-publishable anytime."

Voice: clear, warm, host-empowering, demand-aware. Plain verbs, no jargon ("Stripe", "KYC", "webhook" never appear in host-facing copy — say "payouts" / "get paid"). Sentence case for everything except the wordmark.

| Host dashboard, has listings | `Create listing` | Top-right, coral |

### Error / blocked states

| Condition | Copy (problem + solution path) |
|-----------|--------------------------------|
| Publish blocked — missing required fields | `Almost there — finish these to publish:` + a live checklist (title, description, space type, address, capacity, hourly rate, day rate, 3+ photos, verified email), each row links to its step |
| Publish blocked — email not verified (D-02) | `Verify your email to publish. We sent a link to {email}.` → `Resend verification email` |
| Photo upload failed | `That photo didn't upload. Check the file is an image under {N}MB and try again.` |
| Too few photos to publish | `Add {n} more photo{s} to publish (minimum 3).` |
| Address not resolvable / no coordinates | `We couldn't find that address. Pick a suggestion from the list so guests can find you.` |

## Screen / State Contract

Every interactive surface must define these states (loading / empty / error / success). Summary of the load-bearing ones:

| Screen | Key states the executor must implement |
|--------|----------------------------------------|
| Host "Your listings" | loading (skeleton grid) · empty (`No listings yet`) · populated (cards + status badges) · per-card actions (edit / unlist / delete) |
| Listing wizard | per-step valid/invalid · autosaving / saved (toast) · save-failed · publish-eligible vs blocked (live checklist) · email-unverified block |
| Photo step | empty (dropzone) · uploading (per-tile progress) · uploaded · upload-failed (per tile) · reordering · cover-designated · below-minimum (`Add n more`) |
| Address step | typing · suggestions · selected (coordinates captured) · unresolvable (error copy) · exact-toggle on/off (map updates) |
| Stripe onboarding | not-started (nudge banner) · in-progress / returned-incomplete (`Finish payout setup`) · enabled (success badge) · paused/disabled (destructive, auto-revert messaging) |
| Public detail page | loading (skeleton) · published+bookable (coral CTA) · published+not-payable (disabled neutral CTA + host prompt) · unlisted/draft (404 or owner-only preview) · availability placeholder |

Accessibility (non-negotiable):
- All form controls have associated `<label>` (reuse `form`/`label` pattern). Errors announced via `aria-live`.
- Stepper exposes current step to assistive tech (`aria-current="step"`).
- Photo reorder is keyboard-operable (not drag-only) — provide move-up/move-down controls or keyboard DnD.
- Coral CTA contrast: `oklch(0.637 0.208 25)` on white ≈ ≥4.5:1 with white foreground text — verify with the declared `--brand-foreground`. Status colors never the SOLE signal (always paired with icon + text).
- Map has a text address fallback for screen readers (respecting the approximate/exact toggle).
