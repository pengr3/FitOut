### PayMongo integration contract (authoritative — from CLAUDE.md § Marketplace Payments + D-20; embedded for self-containment)

**Client (`src/lib/paymongo.ts`)** — a thin `fetch` REST wrapper, NO official SDK:
- Base URL `https://api.paymongo.com/v1`.
- Auth: **HTTP Basic**, secret key as the username → header `Authorization: Basic ${base64(PAYMONGO_SECRET_KEY + ':')}`.
- Send an `Idempotency-Key` header on POSTs (PayMongo requirement for safe retries).
- **Fail-closed at module load in production** if `PAYMONGO_SECRET_KEY` is missing (copy the auth.ts boot guard).

**Onboarding (PayMongo Platforms / Linked Accounts)** — hosted-redirect KYC; we build NO KYC UI:
- Create a **Linked Account** (child/merchant) ONCE per host; reuse the stored id on later calls.
- Generate a **hosted onboarding link** (Linked-Accounts invite/redirect) with return/refresh URLs under
  `(host)/host/payouts/*`. This is the Stripe-Account-Links equivalent — treat links as **single-use / expiring**;
  **re-mint on every click** (never cache the URL).

**Webhook (`src/app/api/paymongo/webhook/route.ts`)**:
- `export const runtime = "nodejs"` (needs node crypto + raw body — NOT edge).
- Read the **RAW** body via `await req.text()` (do NOT `req.json()` first — parsing changes the bytes the HMAC covers).
- Header `Paymongo-Signature`, format `t=<ts>,te=<testSig>,li=<liveSig>`. Compute
  `HMAC-SHA256(key = PAYMONGO_WEBHOOK_SECRET, msg = ` `${t}.${rawBody}` `)`, hex digest, **constant-time**
  compare to `te` (test mode) / `li` (live mode). Mismatch → **400**.
- Idempotent by event id via a new `paymongo_event` table (duplicate → 200 skip).
- On `merchant.activated` → set host_payout `activationStatus:'activated'`, `payoutsEnabled:true`,
  `onboardingComplete:true` for the matching `paymongoAccountId` (the SINGLE writer of payoutsEnabled).
- On `merchant.declined` (or a deactivation event) → `activationStatus:'declined'`, `payoutsEnabled:false`
  (auto-revert, D-14 — deriveBookable reads payoutsEnabled, so every listing flips not-bookable with zero writes).
- Always `200` on handled events.

**Beta note:** PayMongo Platforms / Linked Accounts is beta / sales-gated. Real onboarding requires PayMongo
to enable the platform on the account; the code is built to the documented contract regardless.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PayMongo → webhook handler | The webhook is the trust boundary for payout state; only Paymongo-Signature-verified events may write payoutsEnabled |
| client → payout state | payoutsEnabled / paymongoAccountId must never be settable from a client body |
| one host → another host's PayMongo Linked Account | Onboarding must operate only on the caller's own host_payout row |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-SPOOF | Spoofing / Tampering | /api/paymongo/webhook | mitigate | Verify the Paymongo-Signature: HMAC-SHA256(PAYMONGO_WEBHOOK_SECRET, `${t}.${rawBody}`) constant-time compared to te/li; a bad/forged/missing sig → 400 (never trust an unverified body). |
| T-06-REPLAY | Tampering | webhook double-delivery | mitigate | Idempotency via the paymongo_event table keyed by event id; a duplicate is skipped and 200'd. |
| T-06-PRIV | Elevation of Privilege | payoutsEnabled / paymongoAccountId | mitigate | Webhook/server-set ONLY (single writer = the webhook); onboarding persists the account id server-side; mirrors Phase-1 input:false discipline; bookability is purely derived. |
| T-06-IDOR | Elevation of Privilege | startPayoutOnboarding | mitigate | Operates on the session user's own host_payout row only; rate-limited + audited (WR-06). |
| T-06-SECRET | Information Disclosure | PAYMONGO_SECRET_KEY / PAYMONGO_WEBHOOK_SECRET | mitigate | Server-only env; paymongo.ts fails closed in production if missing; webhook runtime=nodejs; the secret is used only as the HTTP-Basic username server-side; no secret in the client bundle (only PAYMONGO_PUBLIC_KEY is client-safe). |
