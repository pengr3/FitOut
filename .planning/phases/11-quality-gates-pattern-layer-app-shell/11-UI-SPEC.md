# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## What this document is, and what it deliberately does not touch

**Phase 10 shipped a complete, gated design system one commit ago.** Colour, type, focus, status tones,
elevation, z-index, motion and the 40-row contrast inventory are LOCKED, enforced by 22 gate files, and
`npm run build` = `lint && test:design && next build`, so a raw hex fails the build. **This document
re-decides none of it.** Everything below either *consumes* an existing token/recipe, or names precisely
where the existing inventories must be EXTENDED — and an extension is always "add a measured row to the
declared inventory", never "invent a value at the call site".

Read `10-UI-SPEC.md` for the foundation. This file adds four things on top of it:

| # | Adds | Requirements |
|---|------|--------------|
| 1 | **An app shell** — one chrome geometry, three compositions, a footer, two new legal routes, share/meta | SHELL-01, SHELL-02, SHELL-04 |
| 2 | **Four state families** — loading, error, not-found, empty — with geometry that does not shift | STATE-01, STATE-02, STATE-04 |
| 3 | **A pattern layer** — three named card patterns, one mobile-overlay primitive, and the shared state components | DS-11, RESP-01 |
| 4 | **The visual half of three gates** — what gets a baseline, what gets a stable hook, what a money figure must look like | GATE-01, GATE-04, GATE-05 |

**The standard this phase's own roadmap sets, restated because it shaped every acceptance criterion below:**
*"a gate that has silently never failed is worse than no gate — it trains reviewers to trust a rubber stamp."*
So every visual claim here is written to be **observable and falsifiable** — a measured dimension, a named
token, a required attribute, a byte comparison — never something that can only be eyeballed.

**The colour authority remains `tests/design/contrast.test.ts` (D-12).** Ratios computed in this session are
stated with their method; if the gate disagrees, the gate wins and this file is corrected.

## Design System

Inherited wholesale from Phase 10. Restated only so a reader of this file alone is not misled.

| Property | Value | Change in Phase 11 |
|----------|-------|--------------------|
| Tool | shadcn — `components.json` present, `style: "radix-nova"`, `baseColor: "neutral"`, `cssVariables: true`, no JS config | none |
| Registries | `"registries": {}` — **zero third-party** (verified 2026-08-13) | none |
| Component library | Radix (`radix-ui@1.4.3`) via **30 vendored primitives** in `src/components/ui/**` | **no new block is fetched** — see § Registry Safety |
| Icon library | `lucide-react@1.17.0` | none |
| Font | Geist Sans / Geist Mono via `next/font/google` | **one addition:** a committed Geist binary for the share image only — see § Share & Meta |
| Styling engine | Tailwind CSS 4.3.0, `@theme inline`, content root narrowed to `src/` | none |
| Theme runtime | `next-themes@0.4.6`, `attribute="data-theme"`, `["court","grove"]`, default `court` | none |
| Token module | `src/lib/design/tokens.generated.ts` → `THEME_TOKENS` (oklch + 8-bit hex), drift-gated | **two new consumers:** `global-error.tsx`, the OG image routes |

**New layer this phase creates:** `src/components/patterns/**` — domain-ignorant compositions. Its
membership rule is not aesthetic; it is the rule that stops it becoming a junk drawer:

1. Does it import a server action, a domain type, product copy, or anything under
   `@/lib/{booking,payments,listing,group,search,availability}`? → `src/components/{domain}/`.
2. Would `npx shadcn add <name>` create or overwrite it? → `src/components/ui/`.
3. Otherwise → `src/components/patterns/`.

Operative test for (3): *could this component be dropped into a different product by changing only its
props?* `EmptyState` yes. `PriceBreakdown` no.

**Two hard rules for `patterns/`:**

- **No `"use client"` unless the pattern's own behaviour requires it.** A client pattern drags every surface
  that composes it toward the client boundary — the exact D-130 hazard. Only `responsive-dialog.tsx` and
  `site-chrome`'s interactive slots qualify. `EmptyState`, `ErrorState` (which is `"use client"` only because
  `error.tsx` must be), `PageHeader`, `Section` and **every skeleton** are Server Components.
- **No product copy.** `EmptyState` takes `title`/`body`/`icon`/`actions`. It never contains the string
  "No spaces match those filters" — that sentence is owned by the surface and by the UI-SPEC that approved it.

## Spacing Scale

**Inherited unchanged from Phase 10 (D-05, global — identical in both themes).** Tailwind's
`--spacing: 0.25rem` ladder. The declared legal set:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`*-1`) | Icon-to-label gaps inside a chip |
| sm | 8px (`*-2`) | Compact element spacing |
| — | 12px (`*-3`) | Dense row padding, table cells |
| md | 16px (`*-4`) | Default element spacing; card padding |
| lg | 24px (`*-6`) | Section padding |
| xl | 32px (`*-8`) | Layout gaps; **empty/error panel padding** |
| 2xl | 48px (`*-12`) | Major section breaks |
| 3xl | 64px (`*-16`) | Page-level spacing; **desktop header height** |

### Exceptions — Phase 11 declares four, each on the 4px grid but off the ladder

Phase 10 declared "Exceptions: none". Phase 11 adds exactly four, each with the reason it exists. All four
are multiples of 4; none is an arbitrary value in the DS-13 sense.

| Value | Class | Where | Why it is not a ladder step |
|-------|-------|-------|------------------------------|
| **56px** | `h-14` | Site header height below `sm:` | The shipped headers measure ~57px (`py-3` + a 32px control). 56 is the nearest 4-multiple, so the app's chrome does not visibly jump when this phase lands. Choosing 48 or 64 would move every page's first paint for no reason. |
| **176px** | `w-44` | The reserved auth-slot width in the header | 4 × 44. Derived from the widest resolved actions cluster (booker: mode switch 96 + bell 32 + profile 48 = 176 before gaps). It is a *reservation*, not a design value — see § The auth slot. |
| **80px** | `lg:top-20` | Sticky-rail offset on listing detail | 64 (desktop header) + 16 (gap). **Load-bearing:** the shipped rail is `lg:top-8` (32px) and would tuck *under* the new sticky header. |
| **85dvh** | `max-h-[85dvh]` | Mobile sheet maximum height | Not a spacing value; a viewport bound. **`dvh`, never `vh`** — on iOS Safari `vh` includes the retracted URL bar and clips the sheet's footer, which is where its confirm button lives. |

### One off-ladder value this phase REMOVES

`p-10` (40px) — the padding on **five** shipped empty-state blocks (`bookings/page.tsx` ×2,
`host/requests/page.tsx`, `host/listings/page.tsx`, `host/bookings/page.tsx`). Off-ladder, and it is one of
the two drifted shells the `EmptyState` pattern exists to collapse. All five land on `p-8`.

## Typography

**Inherited unchanged.** Four named roles (`text-display` / `text-heading` / `text-body` / `text-label`),
per-theme, pinned by `tests/design/type-scale.test.ts`. Tailwind's re-declared `text-xs…2xl` ladder is legal
and is not a fifth role. Arbitrary `text-[NNpx]` is banned by ESLint **and** a Vitest gate.

| Role | court | grove | Phase 11 uses it for |
|------|-------|-------|----------------------|
| Display | 28px / 1.15 / 600 / -0.02em | 34px / 1.20 / 700 / -0.005em | `/terms` + `/privacy` `<h1>`; the not-found and error-page headline |
| Heading | 20px / 1.30 / 600 / -0.01em | 24px / 1.30 / 700 / 0 | `/terms` + `/privacy` `<h2>`; `PanelCard` title |
| Body | 16px / 1.50 / 400 / 0 | 17px / 1.60 / 400 / 0 | **Long-form legal prose** — the app's first prose surface |
| Label | 14px / 1.43 / 400 / 0 | 15px / 1.50 / 400 / 0 | Header/footer links, meta lines, the `digest` reference |

### Two type rules this phase adds

1. **The site header's height is fixed by a spacing token, never by type.** `h-14 sm:h-16`, not padding
   around a `text-lg` wordmark. Grove's type is one step larger throughout; a type-driven header measures
   differently in each theme, which makes every VR baseline theme-dependent in its *geometry* rather than
   only in its colour. **Falsifiable:** `header.boundingBox().height` is `56` at 375px and `64` at ≥640px,
   **identical in court and grove.**

2. **Long-form prose gets a measure, and it is not the `prose` plugin.** `@tailwindcss/typography` is not
   installed and must not be. It ships its own type scale, which is a second, un-gated type system living
   beside the four named roles — precisely what DS-02 exists to prevent. The legal pages instead compose
   the named roles by hand inside a `max-w-prose` (65ch) container. **Falsifiable:** the prose container's
   computed `max-width` resolves to `65ch`, and `tests/design/type-scale.test.ts` sees zero new arbitrary
   sizes under `src/app/(legal)/**`.

### The accent reserved-for list — Phase 11 adds exactly ONE entry

Phase 10 declared its list "the complete list, nothing else" with 7 entries. Phase 11 appends **item 8** and
nothing else:

> **8.** An 8px `--brand` rule at the foot of the generated share image (`opengraph-image.tsx`). Measured as
> `brand on background` — non-text bar 3.0, **4.77 court / 4.60 grove** — already a declared pair, so this

**Explicitly NOT accent, and each of these was considered:**

- Header links, footer links, focus rings, the legal-placeholder notice, skeletons.

### Pairings Phase 11 requires that the inventory does NOT yet declare

**These must be ADDED to `src/lib/design/contrast-pairs.ts` and measured by the culori gate. None may be
invented at a call site.** Ratios below were computed in this session with gamma-space alpha compositing —
the same method the inventory's own header describes — and the gate is the authority if it disagrees.

**Three new `EXCLUDED_PAIRS` rows** (each is a real, shipping, sub-bar pairing that the inventory currently
cannot see — an inventory that silently omits a failing pair is the exact defect DS-06 exists to remove):

| fg | bg | Measured | Reason it is legal |
|----|----|----------|--------------------|
| `muted` | `background` | **1.09 / 1.09** | **Skeleton fill.** A skeleton is a non-informational placeholder; the loading state's *meaning* is carried by a `role="status"` + `aria-busy="true"` region with an `sr-only` label, never by the fill. Compensating requirement is mandatory — see § Loading. |
| `muted` | `card` | **1.09 / 1.13** | Same, for skeletons inside a card or panel. |
| `foreground-10` | `card` | **1.24 / 1.24** | **`ui/card.tsx:15`'s `ring-1 ring-foreground/10` — the hairline on EVERY card in the app, shipped since v1.0 and measured by nothing.** Identical class to the `--border` / `--input` exclusions already in the file: a decorative container edge, never a control's sole visible boundary and never a focus indicator. `fg` names the composite rather than a raw token because the exclusion is about the 10% form specifically. |

**Two new `CONTRAST_PAIRS` rows** — the `ResultCard` hover, which the pattern layer is about to formalise
across every card surface in the app. The drift check cannot see them (a background on the card and an ink
on its descendants is a cross-element pairing, which that check's own NOT COVERED note excludes), so they
must be declared by hand:

| fg | bg | alpha | Bar | court | grove |
|----|----|-------|-----|-------|-------|
| `foreground` | `muted` | `{ value: 0.4, over: "background" }` | 4.5 | **19.42** | **17.80** |
| `muted-foreground` | `muted` | `{ value: 0.4, over: "background" }` | 4.5 | **5.08** | **5.56** |

> **`over: "background"`, not `over: "card"` — and the distinction is the whole point.**
> `group-hover:bg-muted/40` *replaces* the Card's `bg-card`; it does not layer over it. So the rendered
> surface is the tint composited over whatever is behind the card, which is the page. Writing `over: card`
> would measure a pairing that never renders — the same class of error that let the focus ring ship at 2.58
> as a token pair and 1.54 as rendered.

**Pairings Phase 11 needs that are ALREADY declared** — recorded so the planner does not add duplicates:
`foreground on background` (header, prose) · `muted-foreground on background` (header/footer links, meta) ·
`foreground on muted` and `muted-foreground on muted` (footer, empty-state panel, legal notice) ·
`destructive on background` and `destructive on card` (error-state icon and body) ·
`success on background` (the positive empty-state icon) · `brand on background` (the share-image rule) ·
`ring on background / card / muted` (every new focusable control).

**Result: the share image, the header, the footer, both legal pages, all four state families and all three
card patterns need exactly 2 new pairs and 3 new exclusions between them.** That is what building on a
finished token layer is supposed to look like.

## The App Shell (SHELL-01, SHELL-02)

### Decision: one shell, three compositions — and why D-04 survives it

`(app)/layout.tsx:38-45` and `(host)/host/layout.tsx:56-63` each carry an explicit written instruction:
*"There IS no shared header component… D-04 deliberately made the host shell distinct… Do NOT refactor the
two headers into one here."*

**That instruction is honoured.** What is shared is the **box**, not the content:
`src/components/patterns/site-chrome.tsx` is presentational, domain-ignorant, and owns *geometry only* —
height, padding, container width, border, stickiness, and three named slots (`brand`, `nav`, `actions`).
The host header keeps its own wordmark (`FitOut · Hosting`), its own neutral-tint surface, and its own link
set; the booker header keeps its own. Nothing merges. What ends is three independently-drifting boxes.

**Falsifiable form of "D-04 survives":** a test asserts the host composition renders `bg-muted` and a
wordmark whose text differs from the booker composition's, while all three compositions produce an identical
`boundingBox().height`.

### The geometry contract

| Property | Value | Note |
|----------|-------|------|
| Element | `<header data-testid="site-header">` | One `<header>` landmark per document |
| Height | `h-14` (56px) below `sm:`, `sm:h-16` (64px) at ≥640px | **Fixed by token, not by type.** Identical in both themes. |
| Inner container | `mx-auto flex h-full w-full max-w-6xl items-center gap-3 px-4 sm:px-6` | 1152px max — wider than every page container, so the chrome frames the content |
| Surface | `bg-background` (public, booker) · `bg-muted` (host, shipped, preserved) | Opaque is mandatory: content scrolls beneath it |
| Bottom boundary | `border-b` | `--border` is a declared decorative divider ✓. **No shadow.** |
| Stickiness | `sticky top-0 z-(--z-sticky)` | `--z-sticky` = 10, the layer this scale exists for |
| Brand | `text-lg font-semibold tracking-tight` — text wordmark, `--foreground` | Byte-identical to the three shipped wordmarks. **No logo asset (D-127).** |
| Nav links | `text-sm font-medium underline-offset-4 hover:underline` | Byte-identical to shipped |

> **Do not put `shadow-sticky` on this header.** `--elevation-sticky` is `0 -1px 12px -2px …` — a
> **negative** y-offset, i.e. an *upward* cast, authored in Phase 10 explicitly "for bottom-anchored bars".
> On a top header it renders a shadow above the viewport edge, which is nothing at all. The header's
> boundary is `border-b`. `shadow-sticky` keeps its zero call-site inventory until Phase 12's mobile CTA bar.

**Consequence the planner must carry: the sticky header breaks one shipped offset.**
`src/app/listings/[id]/page.tsx:346` renders `<Card className="lg:sticky lg:top-8">`. 32px < 64px, so the
booking rail would tuck under the header on every scroll. It moves to `lg:top-20`. **Rule, stated once:**
*every `lg:sticky` offset in the app is ≥ header height + 16px.* Falsifiable as a source scan — there is
exactly one such site today.

| | Brand | Nav | Actions |
|---|---|---|---|
| **public** (`/`, `/listings/[id]`, `/invite/[token]`, `(auth)`, `(legal)`) | `FitOut` → `/` | — | **anonymous:** `Log in` (ghost) + `Sign up` (default) · **signed in:** identical to booker |

**Passing neither `nav` nor `actions` yields the minimal presentation** — wordmark only. This is not a

- **`/listings/[id]/book` (checkout).** SHELL-03 (Phase 12) requires *"no navigation that can silently lose
  an active hold"*, so on this route the brand renders as a **`<span>`, not a `<Link>`**, via

  countdown rather than replacing a header this phase just built.
  **Falsifiable:** `/listings/[id]/book` renders zero `<a href>` inside `[data-testid="site-header"]` and
  renders no `[data-testid="site-footer"]` at all.
- **`(auth)`.** The layout's own centred wordmark (`(auth)/layout.tsx:24-31`) is **removed** — the shell
  supplies it, and two wordmarks on one screen is the duplication this phase exists to end. Phase 15 owns
  everything else about those screens.

### The auth slot — the no-layout-shift contract, stated as a measurement

`/listings/[id]` reads **no session today** (it is fully public). A session-aware header opts it into dynamic
rendering, so the auth-dependent cluster renders inside `<Suspense>`. That boundary is where a shift would
come from, so it is pinned:

```
<div data-testid="site-auth-slot"
     class="ml-auto flex h-8 min-w-44 items-center justify-end gap-3">
  <Suspense fallback={<AuthSlotSkeleton />}>  {/* also h-8 min-w-44 */}
```

| Pinned property | Value | Why this one |
|---|---|---|
| **Height** | `h-8` (32px), fallback and resolved | Height is the only axis that reflows the page. It is pinned to the tallest control (`Button size="default"` = h-8, `NotificationBell` = `size-8`). |
| **Anchor** | `ml-auto … justify-end` | Right-anchored, so resolution moves only the cluster's own left edge. The brand, the header box and every page element are outside it. |
| **Reserved width** | `min-w-44` (176px), fallback and resolved | 4 × 44. Bounds the horizontal delta and prevents the fallback collapsing to zero. |
| **Fallback shape** | `AuthSlotSkeleton` — one `Skeleton h-8 w-24` + one `Skeleton size-8`, `aria-hidden` | Reads as "two controls are coming", not as a blank |

**Acceptance criterion (Playwright, deterministic — not CLS, which is flaky):**
capture `[data-testid="site-header"]` and `[data-testid="site-brand"]` bounding boxes with the auth slot
still pending (route the session request through a delay) and again after it resolves. **Both boxes must be
byte-identical**, at 375 / 768 / 1280, in **court and grove**, in all three compositions. Twelve assertions
that a reviewer cannot rubber-stamp.

**The `(app)`/`(host)` restructure this obliges.** Both group layouts today `await` three DB reads
(`countUnread`, `listRecent`, `readDbNow`) — plus a `count()` on the host side — *before* rendering. Next's
documented behaviour is that a layout awaiting runtime data blocks navigation, so **`loading.tsx` under
either group buys nothing until this moves.** The session check stays blocking (it is the T-04-06 / T-04-02
security gate that `redirect()`s); the *ambient* notification read moves into an async child inside the
`actions` slot's `<Suspense>`. Owner-scoped-in-the-query (T-07-82) and the try/catch degradation both
survive unchanged. Without this, STATE-01 is unverifiable on 15 of ~27 routes.

### Responsive behaviour — measured, not assumed

At 320px with `px-4`, **288px** is available. Wordmark ≈ 62px leaves **226px**. Measured in **grove** (the
larger type — the worst case):

| Composition | Inline cluster | Fits 226px? | Behaviour |
|---|---|---|---|
| public / anonymous | `Log in` 52 + `Sign up` 74 + gap 12 = **138px** | yes | **Never collapses.** Hiding the acquisition CTA behind a hamburger is not a responsive strategy. |
| public / signed-in, booker | mode switch 96 + bell 32 + `Profile` 48 + 2 gaps 24 = **200px** | yes, barely | **Never collapses.** `Profile` renders as an icon button below `sm:` and gains its text label at `sm:` — **one instance, CSS-revealed label**, never a conditional render. Drops the cluster to ~176px. **The wrapper MUST carry `aria-label="Profile"` and the icon `aria-hidden="true"`:** `<Link aria-label="Profile"><UserIcon aria-hidden="true"/><span className="hidden sm:inline">Profile</span></Link>`. *(Corrected after UI-check.* `hidden` *removes content from the accessibility tree — which is the right mechanism for the nav-duplication case elsewhere in this doc, but applied here it would leave the control with NO accessible name below 640px, failing WCAG 4.1.2. `NotificationBell` in the same cluster already carries an* `aria-label`*; this one did not. Two mechanisms for two different reasons:* `hidden` *to avoid duplicating nav text,* `aria-label` *for an icon-only control.)* |
| host | booker's 200 + `Earnings` 62 + `Requests` 66 + 2 gaps 24 = **352px** | **no** | **Collapses below `md:`.** `Earnings` and `Requests` move into a drawer behind a `size-8` `aria-label="Menu"` trigger. `ModeSwitch`, `NotificationBell` and `Profile` **stay inline** — a status indicator and a context switch are not destinations. |

**The drawer is one source of truth for the links, two placements for the DOM.** Link data is authored once
(`src/lib/nav.ts`) and rendered by one presentational `<NavLinks>` in a `hidden md:flex` bar and inside the
`md:hidden` drawer. Use **`hidden`** — not `sr-only`, not `opacity-0` — so the inactive copy leaves the
accessibility tree and there is exactly **one navigation landmark at any viewport**.
**Falsifiable:** `getByRole("navigation")` resolves to exactly 1 at 320px and at 1280px.

The drawer is a `ResponsiveDialog` (§ The mobile-overlay primitive) — not a second overlay mechanism.

### The unfilled slot — and the gate that keeps it unfilled-visible

**No support address exists anywhere in `src/` and none may be invented.** A fabricated contact address is a
real-world claim shipped to users, and "support@fitout.ph" being wrong is worse than absent.

The contract:

1. `src/lib/site.ts` exports `export const SUPPORT_EMAIL: string | null = null;`
2. **The footer renders the support entry only when `SUPPORT_EMAIL` is non-null.** While it is null, nothing
   about support appears — no greyed link, no "coming soon", no `mailto:` to a placeholder. Nothing false
   ships.
3. `tests/design/site-contacts.test.ts` **fails while `SUPPORT_EMAIL` is null**, with a message naming what
   is needed and who supplies it. Because `npm run build` = `lint && test:design && next build`, **the phase
   cannot go green with the placeholder in place.**

> **This gate is expected to be RED from the moment it lands until the developer supplies the address. That
> is the mechanism, not a bug.** So it must land in the **same plan as the footer**, and that plan's
> checkpoint asks the developer for the address directly. It must not land early, or every subsequent plan
> in the phase runs against a red design suite for a reason unrelated to its own work.

**Acceptance criterion:** `SUPPORT_EMAIL` is a non-null string containing `@`, the footer renders exactly one
`mailto:` link, and `site-contacts.test.ts` passes. A phase-completion check that accepts a null here has
accepted a rubber stamp.

### The placeholder notice — visible, unmissable, and part of acceptance

**Copy — `/terms`:**

**Copy — `/privacy`:**

> **Placeholder — this is not FitOut's privacy policy.**
> FitOut has not published its privacy policy yet. This page exists so the site's links resolve. Nothing on

   A source scan — crude, but it fails loudly the moment someone "helpfully" drafts real-looking terms.
4. The notice is removed **only** in the same commit that supplies real copy, and that commit deletes

## The Four State Families

### 1. Loading (STATE-01) — the geometry is the requirement

**The rule for whether a route gets `loading.tsx`, stated so a planner does not re-derive it 27 times:**

> A route needs a `loading.tsx` if its `page.tsx` `await`s anything. A component needs its own states if it
> owns a `useTransition`, a `useState` fetch, or a server-action call. **A route can need both — and when it
> does, the two skeletons must be the same component, not two lookalikes.**

`/` is exactly that case and is counter-intuitive: `SearchResults` wraps `router.push` in `startTransition`,
so React keeps the current UI and flags `isPending` rather than falling back to `loading.tsx`. That
in-component skeleton is correct and **must not be deleted**; `loading.tsx` covers first load and hard
navigation. Both must render the *same* `CardGridSkeleton`, or the same page shimmers two different ways
depending on how you arrived.

**Measurement constants — the mechanism that makes "does not shift" true rather than intended.**

`src/lib/design/measurements.ts` (deliberately under `src/lib/design/**`, beside `contrast-pairs.ts` and
`status-tones.ts` — outside the leak-gate's scanned tree, consistent with how this repo already stores
design data):

```ts
export const RESULT_CARD_MEDIA  = "aspect-[4/3]";   // matches AspectRatio ratio={4/3}
export const ROW_CARD_HEIGHT    = "h-20";           // 80px: Card p-4 around a 48px thumb
export const ROW_CARD_THUMB     = "size-12";        // 48px
export const HEADER_HEIGHT      = "h-14 sm:h-16";
export const AUTH_SLOT_BOX      = "h-8 min-w-44";
export const PANEL_MIN_HEIGHT   = "min-h-40";
```

**Falsifiable, two layers, because one alone is a rubber stamp:**

1. **Source gate (Vitest, DB-free, cheap).** Every file matching `src/components/patterns/*skeleton*.tsx`
   imports its box classes from `measurements.ts` and contains **zero** literal `h-` / `w-` / `aspect-`
   utilities of its own. A skeleton that hardcodes `h-20` passes review and drifts the first time the real
   row changes; this catches it. Watch it go red by inlining one constant.
2. **Rendering gate (Playwright — jsdom cannot see this class of bug at all, per D-131).** For the three
   canonical shapes (card grid, row list, panel), capture the skeleton container's `boundingBox()` with the
   data request stalled, and the real container's after it resolves. **Assert equality within ±2px.**
   Run in both themes: grove's larger type is exactly where a skeleton sized against court silently drifts.

**Skeleton accessibility — mandatory, and it is what makes the 1.09:1 exclusion legal.**

Every skeleton region is wrapped in `<div role="status" aria-busy="true">` carrying an `sr-only` label
naming what is loading (*"Loading your bookings"*), and the decorative bars themselves are `aria-hidden`.
Without this the fill *is* the only carrier of "loading", and a 1.09:1 fill carrying meaning would be a real
WCAG 1.4.11 failure rather than a declared exclusion.
**Falsifiable:** every `patterns/*skeleton*.tsx` renders exactly one `role="status"` with a non-empty
accessible name; the pulse bars expose none.

**Motion:** skeletons use `animate-pulse`, which is a **continuous loading indicator and is exempt by design
from the 320ms cap** (Phase 10 wrote that exemption into the cap's own wording so the budget test is
writable). It is covered by the global `prefers-reduced-motion` reset instead. Do not "fix" this by giving
the pulse a duration token.

**Skeletons NOT to build.** Nothing under ~1s, and nothing whose box metrics are unpredictable — a skeleton
that does not match its content causes the layout shift it was built to prevent. Where metrics are
unpredictable, use an in-place spinner. The legal pages, being static, get no `loading.tsx` at all.

### 2. Error (STATE-02)

**Five boundaries:** `app/error.tsx` (root — covers `/`, `/listings/**`, `/invite/**`), `(app)/error.tsx`,
`(host)/host/error.tsx`, `(auth)/error.tsx`, `(legal)/error.tsx`.

`error.tsx` must be `"use client"`. **`next@16.2.7` is installed; the `retry` prop is stable only from
16.3.0** (`unstable_retry` in 16.2.0). Write against **`reset`** and leave a `// TODO(next@16.3): retry()`
marker — otherwise the first boundary written picks an API that does not exist.

**The `ErrorState` pattern — two actions, always:**

| Slot | Treatment |
|---|---|
| Icon | `AlertTriangleIcon size-6 text-destructive` — 5.76 / 5.56 on background, well past the 3.0 non-text bar ✓ declared |
| Heading | `text-heading text-foreground` |
| Body | `text-sm text-muted-foreground max-w-prose` — one sentence, names what failed in ordinary words |
| Action 1 | `Try again` — `Button variant="secondary"`, calls `reset()` |
| Action 2 | **A route out** — `Button variant="outline" asChild`, group-specific |
| Reference | `digest`, when present: `text-label text-muted-foreground tabular-nums`, prefixed `Reference` |
| Hook | `data-testid="error-state"` |

**A bare "Something went wrong" with one button is a failure of this contract.** Both actions are required:
retry covers a transient fault; the route out covers a persistent one, and without it the user's only
recourse is the browser's back button into the same error.

| Group | Route out |
|---|---|
| root | `Back to search` → `/` |
| `(app)` | `Your bookings` → `/bookings` |
| `(host)` | `Host dashboard` → `/host` |
| `(auth)` | `Back to log in` → `/login` |
| `(legal)` | `Back to FitOut` → `/` |

**Security property, and it is falsifiable:** the error surface renders **neither `error.message` nor
`error.stack`**. Server error text routinely carries table names, file paths and connection strings. Only
`digest` — an opaque hash Next generates for exactly this purpose — reaches the DOM.
**Assert:** a boundary rendered with `new Error("SENTINEL_LEAK_PROBE")` produces a DOM containing
`SENTINEL_LEAK_PROBE` **zero** times.

### 3. `global-error.tsx` — the one surface a theme cannot reach

**Next 16 documents this outright: `global-error` renders its own document and does not receive your global
styles, so an app-level `data-theme` attribute never reaches it.** Everything follows from that:

| Constraint | Requirement |
|---|---|
| No Tailwind | Classes do not exist here. **Inline `style` objects only.** |
| Colours | Read from **`THEME_TOKENS.court`** hex — the sanctioned duplicate (DS-12 / D-18). This is *why* that module exists. |
| Theme | **court, unconditionally.** Not an omission — a documented impossibility. Record it as data, not as silence. |
| Font | A system stack literal; Geist's CSS variable is not defined here. Not a DS-13 pattern (the gate bans hex / `rgb(` / `oklch(` / `text-[NNpx]`, and a font stack is none of those). |
| Links | A plain `<a href="/">`, not `next/link`. |
| Footer / header | None. |
| Copy | Names the failure, blames nobody, offers one action: **"FitOut hit an unexpected error"** / *"The page couldn't load. Reloading usually fixes it — if it doesn't, come back in a few minutes."* / `Reload` + `Back to FitOut`. |

**Falsifiable, and the first assertion is already enforced for free:** `global-error.tsx` sits under
`src/app/**`, which the DS-13 leak gate scans — so **a raw hex in this file already fails the build today.**
The only remaining assertion is that it *imports* `THEME_TOKENS`, which is the sole legal way for it to have
a colour at all. Two lines of test, one of them already paid for.

**Consequence for the VR gate:** `global-error` is the single baselined surface **excluded from the
theme-swap smoke** (identical court/grove screenshots normally mean a surface ignored the tokens; here
identical is correct). That exclusion is carried **as data with its reason**, in the `EXCLUDED_PAIRS` idiom —
never as a silently absent baseline.

## Responsive Baseline (RESP-01)

**Breakpoints — Tailwind v4 defaults, declared as the app's set so no surface invents one:**

| Name | min-width | What changes |
|---|---|---|
| — | **320px floor** | Single column everywhere. The hard floor (D-131). |
| `sm` | 640px | Sheet → centred dialog · header 56 → 64px · result grid 1 → 2 col · `Profile` gains its text label |
| `md` | 768px | Host nav: drawer → inline |
| `lg` | 1024px | Listing detail `1fr 360px` + sticky rail · result grid 2 → 3 col |
| `xl` | 1280px | **Declared, unused.** No surface needs it; a `xl:` in a plan is a question, not a bug. |

**One tree, never mobile/desktop forks.** Four techniques, in order of preference:

1. **Reorder with CSS, never with conditional rendering.** `{isMobile ? <A/> : <B/>}` needs JS to know the
   viewport, breaks SSR, doubles the VR surface, and duplicates content for screen readers.
2. **Move one instance; do not render two.** Two instances of a client island double-mount, double-submit,
   and produce two focus targets.
3. **One dialog, two presentations** (§ the mobile-overlay primitive).
4. **One source of truth for links, two placements for the DOM** (§ the host drawer).

**320px acceptance criterion:** `document.documentElement.scrollWidth <= clientWidth` at a 320px viewport,
in **both themes**, on `/`, `/listings/[id]`, `/listings/[id]/book`, `/invite/[token]`, `/terms`,
`/privacy`, the root not-found, and each of the five error boundaries. This is the same check 10-16 already
ran for `/dev/theme`, so the harness exists.

**320px pressure points to plan for explicitly:** the host header's inline cluster (measured above — the one
that genuinely does not fit), the availability month grid (7 × 44px = 308px before padding — it fits, but
only just), and `ui/table.tsx` on the host side. **Tables become definition lists below `@md`**, never
horizontally scrolling tables — a scrolling table at 320px fails both the responsive and the keyboard gate.

## Share & Meta (SHELL-04)

Today a pasted FitOut link renders as **"FitOut"** with the app's one-line description and **no image** —
better than the "Create Next App" the requirement describes (DS-14 fixed that), but there is still no share
card, and `metadataBase` is in place and unused (`layout.tsx:92` records it as "latent today").

### The generated card — and the gate that already enforces it for free

| Property | Value |
|---|---|
| Mechanism | `opengraph-image.tsx` → `ImageResponse` (`next/og`), **1200 × 630**, `image/png` |
| Colours | **`THEME_TOKENS.court` hex only.** Satori resolves no CSS custom properties and parses no `oklch()`. |
| Theme | **court, unconditionally** — there is no user and no `data-theme` on a server-rendered image. Like `global-error`, this is a documented impossibility, and it is excluded from the theme-swap smoke with that reason recorded. |
| Photography | **None.** Host photos are unvetted, listings can have zero, and a 1200×630 crop of an arbitrary portrait photo is unpredictable. "Token-driven share image" is also what the requirement literally asks for. |
| Brand asset | None (D-127). The card is a text wordmark, the type, and one accent rule. |

**The DS-13 leak gate already makes this correct-by-construction.** `src/app/**` is scanned for raw hex —
so **a hex literal in an OG route fails the build today**. The only way to paint the card is
`THEME_TOKENS.court["--brand"].hex`. The one assertion still worth writing is that the file *imports*
`THEME_TOKENS`; the rest is already paid for.

> **One clarification so a reviewer does not read a violation where there is none:** satori sizes type with
> inline `style={{ fontSize: 64 }}`. DS-13's arbitrary-size ban is `text-\[[0-9.]+px\]` — a *Tailwind class*
> pattern. An inline numeric font size in an image renderer is outside it, and it must be, because satori
> has no access to the type tokens at all.

**Listing card layout** (`src/app/listings/[id]/opengraph-image.tsx`):

| Element | Treatment |
|---|---|
| Canvas | `--background`, 64px padding, flex column |
| Wordmark | `FitOut`, 40px / 600, `--foreground`, top-left |
| Title | up to 2 lines, 64px / 600, `--foreground`, line-height 1.15, letter-spacing -0.02em (court's display role, as literals — satori has no tokens) |
| Sub-line | `{Space type} · {City}`, 32px, `--muted-foreground` |
| Price | the **first** part of `allInRateParts` (e.g. `₱450/hr`), 32px, `--foreground` |
| Accent rule | 8px × 240px `--brand` bar, bottom-left — **accent list item 8**, the only accent on the card |
| `alt` export | `FitOut — {title}, {city}` |

**Fonts.** Satori requires at least one font buffer and `next/font/google` exposes none. Two Geist binaries
(`Regular`, `SemiBold`) are committed beside the route and loaded via `fetch(new URL("./…", import.meta.url))`.
**This is not a D-127 violation:** Geist is already the app's typeface, shipped by `next/font`; committing
the same family's binary for a renderer that cannot read CSS is not a new brand asset. Record the byte cost
in the plan.

**Robustness requirement:** the OG route must never return non-2xx. A failed font read makes satori throw,
and a 500 on an unfurl produces *no card at all* — silently, and only ever discovered by someone pasting a
link. Wrap it: on failure, serve the root card.

**Price rule that binds here too (D-75):** the card shows a **rate**, never a computed total. `₱450/hr` is a
rate; "from ₱1,350" is a promise checkout could break by a centavo.

### The invite card — a security property, not a copy choice

`/invite/[token]`'s URL **contains a credential**. The shipped route already carries
`robots: { index: false, follow: false }` and `referrer: "no-referrer"` for exactly that reason, and
**both stay, non-negotiably.** Converting the static `metadata` export to `generateMetadata` must preserve
them; a test asserts both survive.

Three consequences follow, and each is a requirement rather than a preference:

1. **The invite share card names the venue and nothing else.** No date, no address, no organizer name, no
   headcount, no booking reference. The recipient already holds the link — but a chat service, a link
   scanner, a corporate URL-preview proxy and a spam filter all fetch that URL too, and everything the
   unfurl states is stated *to them*.
2. **The invite image route must not accept the token as an input to its output.** It renders a constant
   card (wordmark + *"You're invited"*), never reads `params.token`, and **performs zero DB reads**. A
   per-token image would put an unauthenticated, credentialed, DB-backed endpoint on the internet whose
   response varies by token — which is a probe oracle wearing an image's clothing.
   **Falsifiable:** `invite/[token]/opengraph-image.tsx` contains no reference to `params` and imports
   nothing from `@/lib/db` or `@/lib/group/**`.
3. The venue name reaches the unfurl through `generateMetadata` only — the same token lookup the page itself
   already performs and already gates.

The AST boundary check is engineering. Its **visual** half, so the DB-vs-DOM price assertion is writable:

## Anti-Patterns — reject these in plan review

- **Merging the booker and host headers' content.** Sharing `site-chrome`'s *geometry* is the contract;
  merging their link sets violates D-04 and contradicts two written in-file instructions.
- **`shadow-sticky` on the site header.** Its y-offset is negative — an upward cast for bottom-anchored
  bars. On a top header it renders nothing.
- **Leaving `lg:top-8` on the listing rail.** It tucks under a 64px sticky header on every scroll.
- **Installing shadcn `sheet`.** Two focus traps, two escape behaviours, two baseline sets for one concept.
- **A grab handle on the sheet.** Drag-to-dismiss is out of scope; a handle implying it is an affordance
  that lies.
- **Adding `@tailwindcss/typography`.** A second, un-gated type system beside the four named roles.
- **A skeleton that hardcodes its own box.** It passes review and drifts the first time the real content
  changes. Constants come from `measurements.ts`.
- **A skeleton with no `role="status"`.** Without it the 1.09:1 fill is the sole carrier of meaning, and the
  exclusion this spec declares becomes a real WCAG failure.
- **Rendering `error.message` or `error.stack`.** Server error text carries table names and paths. `digest`
  only.
- **Tailwind classes in `global-error.tsx`.** It receives no stylesheet. Inline styles from `THEME_TOKENS`.
- **A per-token invite OG image.** An unauthenticated, credentialed, DB-backed endpoint whose response
  varies by token is a probe oracle.
- **Dropping `robots: noindex` or `referrer: no-referrer` from the invite route** while converting it to
  `generateMetadata`.
- **A distinguishable invite 404.** It reintroduces the oracle 08-06 closed.
- **Inventing a support address.** A fabricated contact is a real-world claim shipped to users.
- **Drafting real-sounding legal copy.** A placeholder that reads as binding terms is worse than no page.
- **A fourth card pattern.** DS-11 says three.
- **`{isMobile ? <A/> : <B/>}`.** Breaks SSR, doubles the VR surface, duplicates content for screen readers.
- **A new accent use beyond item 8.** Phase 10's list is closed; this phase appends exactly one entry.
- **Inventing a colour pairing at a call site.** New pairings are measured rows in `contrast-pairs.ts`.
- **Capturing a baseline that needs seeded DB data.** Flaky, so retried until green — a rubber stamp.
- **Proposing a schema migration.** GATE-06 binds; `drizzle/` stays at `0025`.
