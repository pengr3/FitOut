<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → GitHub-hosted runner | Workflow YAML is executed with repository credentials |
| CI job → secrets | Anything a job can read, a compromised or flaky job can exfiltrate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-CISECRET | Information Disclosure | CI job environment | mitigate | Jobs 1 and 2 need **only** `DATABASE_URL`; the 12 e2e specs stay out of CI (D-24), so no PayMongo/Resend/Cloudinary/auth secret is referenced. Asserted by an acceptance criterion. |
| T-11-CIWRITE | Elevation of Privilege | `GITHUB_TOKEN` scope | mitigate | Top-level `permissions: contents: read`; write is granted per-job only in plan `11-22`'s dispatch job |
| T-11-CANCEL | Denial of Service | `concurrency` group | mitigate | `github.event_name` in the group so a push cannot cancel a running baseline dispatch and leave a partial commit |
| T-11-DBFREE | Tampering | job 1's DB-free property | mitigate | `DATABASE_URL` set to an unreachable host, converting RESEARCH Assumption A5 into a per-run measurement |
| T-11-WRONGDB | Tampering | job 2's target database | mitigate | `tests/helpers/test-db-url.ts` throws on any database name not ending in `_test`; `db:test:setup` provisions `fitout_test` |
| T-11-SC | Tampering | third-party Actions | mitigate | Only `actions/checkout` and `actions/setup-node` (first-party). Any third-party action proposed here is a supply-chain decision to raise, not absorb. |
</threat_model>
