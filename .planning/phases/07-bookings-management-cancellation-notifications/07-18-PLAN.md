<interfaces>
The cancel-side discriminant is already written and verified:
- `cancelUnpaidHold` (src/app/actions/cancel-booking.ts): a booker cancelling a `requested` hold flips it
  `requested → declined` with `cancelled_by = 'booker'`. An `approved` hold flips to `cancelled` with
  `cancelled_by = 'booker'` (this case ALREADY lands correctly on the generic "This booking was cancelled"
  branch — do NOT touch it).
- `declineRequest` (src/app/actions/host-requests.ts): a genuine host decline sets `status='declined'` and
  does NOT set `cancelled_by` (stays NULL). The SLA auto-decline cron (request-expiry.ts) likewise leaves
  `cancelled_by` NULL. So: `declined` + `cancelled_by='booker'` ⇒ the booker cancelled; `declined` +
  `cancelled_by IS NULL` ⇒ a real host decline OR an SLA lapse (KEEP the current copy).

Existing shared derivation (src/components/booking/booking-status.ts):
```typescript
export function deriveDisplayStatus(status: BookingDbStatus, endsAt: Date, now: Date): BookingDisplayStatus
export function deriveBookingStatusView(status, endsAt, now, side): BookingStatusView  // { label, tone, icon }
```
`BookingStatusBadge` (booking-status-badge.tsx) calls BOTH, keyed on the DISPLAY status. `cancelled` → "Cancelled"/Ban/muted; `declined` → "Declined"/XCircle/muted.

The booker row already links via an overlay anchor (booking-row.tsx): the title `<Link>` uses
`after:absolute after:inset-0` to make the whole card clickable, and its inline "Pay now" button sits
above it with `relative z-10`. MIRROR this on the host row (T6) — the host row's inline `RequestActions`
must get `relative z-10` so Approve/Decline stay clickable above the overlay.
