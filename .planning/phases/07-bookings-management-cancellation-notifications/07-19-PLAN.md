<interfaces>
LADDER + rung math (src/lib/payments/cancellation.ts):
```typescript
export const LADDER: Record<CancellationTier, Rung[]>   // rungs DESCENDING by minHours (most generous first)
export function rungBoundaries(tier, startsAt): { refundBps: number; boundary: Date }[]  // index-aligned with LADDER[tier]
```
Because rungs are descending by minHours, their boundaries (`startsAt − minHours`) are ASCENDING in time:
LADDER[tier][0] is the most generous rung AND the earliest boundary. So "the best rung still open at `now`"
is the FIRST index whose `boundary > now`.

Disclosure (src/components/booking/cancellation-policy-disclosure.tsx):
```typescript
export function policySummaryLine(tier, boundaryLabels?): string   // concrete mode = boundaryLabels present
export function policyDisclosureLines(tier, boundaryLabels?): PolicyDisclosureLine[]   // the expanded list — CORRECT, do not touch
export function CancellationPolicyDisclosure({ tier, boundaryLabels }): JSX
```
The component performs NO date math (its header rule). Compute the "best future rung" index SERVER-SIDE in
the RSC (book/page.tsx already has `now = new Date()` at line 58 and `rungBoundaries` at ~199) and pass it in.
Generic mode (the listing page, no boundaryLabels) is unaffected and stays relative-to-session-start.

placeHold replay (src/app/actions/booking.ts, request branch ~159-253):
`createPendingHold` returns `{ ok:true, id, spacePriceCents, quotedTotalCents, expiresAt, replayed }`. The
re-request.ts precedent guards its emissions with `if (asRequest && !res.replayed) { … emitNotify … }`.
