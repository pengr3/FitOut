## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → re-request action | Untrusted booking id; the window is derived server-side from the stored row, never from the request |
| render-time availability read → submit | The slot can be taken in between; the UI must not be the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-69 | Elevation of privilege | Re-requesting another user's booking | mitigate | Owner-gate `booking.bookerId === userId` before any write; the identical `DENIED` string for cross-user and missing (test 4). |
| T-07-70 | Tampering | Re-request used to bypass the lead-time guard | mitigate | The action calls `createPendingHold`, which re-validates the mode-scoped lead time in-transaction against `now()` unconditionally (test 3). The action supplies no override. |
| T-07-71 | Tampering | Double-booking via re-request | mitigate | A NEW row is inserted so the GiST EXCLUDE adjudicates; no status flip resurrects a terminal booking into the occupancy set through an unmodelled path. `tests/availability` remains the gate. |
| T-07-72 | Tampering | Resurrecting a terminal booking to evade a cancellation fee or refund | mitigate | `grep -c "UPDATE booking" src/app/actions/re-request.ts` returns 0 — the action can only insert. The original row, its refund columns and any debit are untouched (test 1). |
| T-07-73 | Denial of Service | Re-request spam against a host | mitigate | `rateLimit("re-request:{userId}", { window: 60, max: 5 })` with an audited denial (test 6). |
| T-07-74 | Information disclosure | Availability probing via the render-time check | accept | The check reveals only whether a specific window on a PUBLIC listing is free — information the listing's own availability calendar already publishes. |
| T-07-75 | Information disclosure | Refund amount shown before settlement | mitigate | The `cancelled` branch renders `refund on its way` until the webhook writes terminal state; "Refunded" is never claimed off the POST (D-57). |
</threat_model>
