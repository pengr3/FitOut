<objective>
Put **Didit** behind the port — as a registration, not a re-architecture.

The adapter does two things and nothing else. `beginDiditVerification(userId)` calls
`POST https://verification.didit.me/v3/session/` and returns the four-field `VerificationResult` with
`result: null`, `checkedAt: null` and `vendorRef` set to the session id — the shape `port.ts:76-98`
already permits, and the shape that makes an unfinished check correctly **not verified**.
`verify(decision)` shapes a verdict that has already arrived, for the webhook and the sweep to write.

**Zero new npm dependencies.** `didit-sdk` on npm is a **different product** — a Web3 login protocol
from Gamium, ~8 downloads/week, real repo, completely wrong. Didit's own docs recommend no SDK and
show a native `fetch` example. This is CLAUDE.md's PayMongo rule applied verbatim.

⚠ **The port is the ONLY branch point.** Never write `provider === "didit"` at a call site, never
construct a `VerificationResult` literal outside a provider, never add a permissive default.

Purpose: the vendor becomes reachable through one contract, and the manual override survives beside
it.
Output: one adapter module, one registry row, one unit test file with a captured response fixture.
</objective>

    write must never overwrite `vendor_ref`. That property is asserted by plan 18.1-08.
    `checkedAt` uses the JS clock for the same reason `manual.ts` argues: it is PROVENANCE, never a
    comparand, and no predicate or money is derived from it. ⚠ It must NOT be read from the webhook
    body — state is derived from the VERIFIED event, never from a client-supplied field.

    Also export a `fetchDiditDecision(sessionId)` **stub declaration is NOT wanted here** — plan
    18.1-09 adds the decision-endpoint reader. Do not pre-build it.

    ⚠ Do not add a fifth field to `VerificationResult`. Do not add a document url, an ID number, a
