## Decisions Made

### 1. FINDING F-6 — the projections do not widen, and the argument is the RSC payload

`18.1-CONTEXT` § Integration Points says D-271 *"adds `email` and `phone` to both branches"* of `review-queue.ts`. D-271's own ⚠ says the values must **not** be in the initial RSC payload. Both cannot hold.

Resolved **against the CONTEXT wording**, and the reason is a count rather than a preference: shipping the two columns on the queue item would put **every queued host's** email and phone into the initial payload of a page **every operator loads**, for **every row**, whether or not anybody had a question — many disclosures to buy one reach, none of them audited. The reveal is one host, one press, one row in the trail.

The mechanism that makes it stick is `review-queue.ts`'s own: *"because the row TYPE has no field for a column, re-exporting it is a TYPE ERROR at every consumer."* With the projections byte-unchanged there is no consumer that **can** read an email off a queue item.

### 2. `ID_MAX` is exported rather than re-typed

The action parses a host id across the same boundary as the five decision actions, for the same two reasons (`src/lib/rate-limit.ts:36-40`'s memory-exhaustion path, and the durable `meta` value). `ID_MAX` was a private const. Re-typing `128` in a second file is the drift this repository spends whole headers preventing, so it is exported — the shape `REJECT_NOTE_MAX` above it already uses. The schema itself stays **local and un-exported** in the `"use server"` module, which is `host-verification.ts:257`'s shipped precedent and what keeps `tests/use-server-exports.test.ts` green.

### 3. The rate-limit shape is re-stated locally, and the reason is 18.1-08's measurement

`OPS_ACTION_RATE_LIMIT` could not be imported: `ops-review.ts` is a `"use server"` module, **every export of one is a network-reachable POST endpoint**, and Next permits only async functions to be exported from one at all. A shared constant would need a third module holding one object literal. So the shape is re-stated with the reason at the site, and the number is **not lowered for being a PII read** — an operator clearing a backlog legitimately opens several rows a minute, and `ops-review.ts:121`'s rule is that a limit which fires on correct use is one an operator learns to work around. What actually rations this surface is the trail: all 30 are attributable.

### 4. `Fact` moved to a third module rather than being exported back into a cycle

D-271 makes the reveal a state machine — one fact before, **two** after — and a component cannot replace the `<dt>`/`<dd>` pair it is rendered inside. So the island must author pairs, and the class constants then need an owner that is neither file. Exporting `Fact` from `ops-queue-row.tsx` (which imports the island) would be an **import cycle between two client modules**, whose only symptom would be a temporal-dead-zone error the day somebody moved a `const` read from a render body to a module body. The three constants and `Fact` moved verbatim, docblocks included; `ROW_LEAD_CLASS` deliberately did not, because the wait figure is `RowCard`'s `status` slot and not a fact in the `<dl>`.

### 5. The row-height pin rounds DOWN, against the file's own convention

Every sibling constant in `measurements.ts` over-claims. The new observations are 576.13 and 892.09; the steps above are 580 and 896, which over-claim by **3.87px and 3.91px** — inside the 4px tolerance by 0.13px and 0.09px. A pin that sits 0.13px from the bound it is checked against reddens on the next sub-pixel change to any font, gap or border on the row, and a gate that fails for reasons unrelated to what it measures is a gate somebody eventually widens. `h-144 lg:h-223` under-claims by 0.13px and 0.09px and buys back ~3.9px of real headroom. **The departure from the convention is argued at the constant, not just applied.**

### 6. OPS-06 stays open, deliberately

Its traceability row names two contributors: `18.1-13 (the reveal + its audit row)` and `18.1-14 (the proof)`. The code half is done and is now written up in that row in HVER-06's established style; the checkbox and the `Planned` status cell were **not** touched, because the revealed row hand-measured at 320 and 1280 in both themes — overflow, focus order, and that focus visibly lands on the email anchor — is not something jsdom or CI can see.
