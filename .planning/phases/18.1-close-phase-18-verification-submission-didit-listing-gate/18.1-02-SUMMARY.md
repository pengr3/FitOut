## What Shipped

### 1. `src/lib/host/frozen-payouts.ts` — the inverted freeze query (new, 218 lines)

`loadFrozenPayoutSummary(dbConn, hostId)` returns `{ count, earliestSpaceTitle, earliestSessionEnd }`
or `null`. It selects exactly the rows `queryDuePayouts` drops: delivered, paid, unclaimed sessions
belonging to a host whose `host_verification.status` is `suspended`.

Line 1 is the bare `import "server-only"` guard (`payment-reconcile.ts:1`'s shape). The module is
READ-ONLY — no INSERT, no UPDATE, no side effect — and adds no way to unfreeze anything.

**The header states three refusals**, because each is a thing a later reader would otherwise
"helpfully" add:

- it does **not** decide suspension — `loadHostVerification` owns that and the page still branches on
  it; the `suspended` clause exists only so this module cannot report a frozen session for a host who
  is not frozen;
- it does **not** offer a route out (D-263);
- it does **not** move the freeze — `payout-sweep.ts` is byte-unchanged, and `git diff --stat` on it
  is empty.

**The divergence rule is the module's design.** The predicate is written out a second time rather
than extracted and negated, because the freeze invariant belongs to the sweep and a shared helper
would make this module a second author of it. The cost — two predicates that can drift — is stated at
the top and each deliberate difference is argued at its own clause:

| # | This module | `queryDuePayouts` | Why |
|---|---|---|---|
| 1 | `JOIN host_verification` + `hv.status = 'suspended'` | `LEFT JOIN` + `COALESCE(hv.status::text,'unverified') <> 'suspended'` | Opposite questions, both failing closed in their own safe direction. A missing row means NOT suspended: the sweep must still PAY them, this module must say NOTHING about them. Copying the sweep's shape here would name frozen sessions for every unverified host in the catalogue. |
| 2 | `p.id IS NULL` alone | also re-selects a `failed` row inside the WR-04 retry backoff | The sentence is about sessions with **no line at all**. A `failed` ledger row is ON the page with its own state badge; calling it missing would contradict the table directly above the notice. |
| 3 | no batch cap | `LIMIT ${SWEEP_BATCH_SIZE}` | The sweep pages through work; this counts a fact. `count(*) OVER ()` counts the whole frozen set before `LIMIT 1` takes the earliest row for the sentence. |

Two clauses were kept from the sweep **because** dropping them would have made the sentence lie: the
`JOIN host_payout` (a host with no payout account is not swept at all, so their missing line is not
the suspension's doing — and the payout banner one block below would contradict us), and the
`ends_at + PAYOUT_DELAY_HOURS <= now()` due window (a session that ended an hour ago has no payout
line for reasons unrelated to any suspension).

`formatFrozenSessionDate` is `formatSubmitted`'s idiom (`ops/page.tsx:58`) with the launch region's
clock and locale named rather than inherited: a host is not a place, so there is no venue zone to
render in, and letting the server's zone decide would make one session read differently on two
machines.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Backticks inside a `sql` template literal terminated the string**

- **Found during:** Task 1
- **Issue:** The SQL comments were first written quoting identifiers in backticks (this repo's prose
  convention), which closed the `sql\`…\`` tagged template and produced 12 `TS1005` parse errors.
- **Fix:** Every backtick inside the template replaced with a double quote — which is also what
  `payout-sweep.ts`'s own SQL comments do, so the two predicates now read in the same voice.
- **Files modified:** `src/lib/host/frozen-payouts.ts`
- **Commit:** 0012a9a

### Deliberate choices the plan left open

**`frozenSessionSentence(summary)` was added as a second export.** The plan's action text says the
page "formats the date server-side … composes the sentence through the copy module", and then — one
paragraph later — that the page may gain "an IMPORT SPECIFIER and a JSX ATTRIBUTE NAME only — ZERO
new string literals", with the explicit instruction that formatting and composition move into
`frozen-payouts.ts` if keeping them in the page would introduce a literal. It would have: the
`Intl.DateTimeFormat` options are three string literals. So both moved, behind one exported call the
page can pass through as a single expression. The `FROZEN` map did not move, which is the property
the instruction exists to protect.

**The predicate is narrower than "session end in the past".** The plan describes the target rows as
"delivered sessions (session end in the past, booking in a paid/confirmed state)". The shipped
predicate uses the sweep's own due window instead — a strict subset — because the wider reading would
have named sessions inside the ordinary T+24h hold as things the suspension is withholding. Argued at
the clause; this is the T-18.1-0204 repudiation mitigation doing its job.
