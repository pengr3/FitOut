## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 4.1.8 (two configs) + Playwright 1.60 |
| **Config file** | `vitest.config.ts` (env `node`, `globalSetup: tests/global-setup.ts`, `setupFiles: tests/setup.ts`, requires Postgres/Docker, per-file isolated schema) · `vitest.design.config.ts` (owns **only** `tests/design/**`, **no `globalSetup`, no `setupFiles`, DB-free by construction** — adding either key silently reintroduces the Docker dependency) |
| **Quick run command** | `npx vitest run <path>` (unit/integration) · `npx vitest run --config vitest.design.config.ts <path>` (design) |
| **Full suite command** | `npx tsc --noEmit` · `npm test` · `npm run test:design` · `npm run build` — **four separate invocations** |
| **Estimated runtime** | ~90–240s for the full four-gate sweep (DB-backed suite dominates) |
| **E2E** | `npm run test:e2e` — ⚠ **D-24: not in CI.** Sampled only when a human runs it; a supplement, never the proof. |

⚠ **STANDING RULE — GATES RUN ALONE.** `tsc`, `npm test`, `npm run test:design`, `npm run build`
are four separate invocations, never chained into one command. Every plan's verification block
must reflect this.

---

## Sampling Rate

- **After every task commit:** `npx vitest run <the one file the task touched>` (or the design
  config equivalent for `tests/design/**`)
- **After every plan wave:** `npx tsc --noEmit` → `npm test` → `npm run test:design` →
  `npm run build`, each alone
- **Before `/gsd-verify-work`:** all four green, **plus** `npm run test:e2e` run once by a human,
  **plus** the Didit sandbox transcript recorded in `18.1-EVIDENCE.md`
- **Max feedback latency:** ~30s per-task (single file), ~240s per-wave

## Success Criterion 1 — "proven by driving it"

R1 settled that **Didit answers asynchronously**, so the `pending` window is real and SC1 is
drivable as written. Three layers, strongest first:

1. **Integration (primary — runs in `npm test`, in CI, every time).** Drive
   `requestHostVerification()` against the isolated schema with the Didit adapter's `fetch` mocked
   to a real captured create-session response, then assert `loadReviewQueue()` returns a
   `kind:"host"` item for that user in `created_at ASC` position, interleaved with a listing item.
   ⚠ **Mutation-score it:** comment out the INSERT and watch the queue assertion go red. If it does
   not, the test measures the seed, not the path.
2. **Sandbox end-to-end (one-time, human-run, recorded).** Real Didit sandbox, `sandbox_scenario:
   "approve"` then `decline_document_expired`; record the actual webhook delivery, headers, verified
   signature and row transition in `18.1-EVIDENCE.md` with retrieval dates — the `18-EVIDENCE.md § P1`
   pattern (a ONE-TIME AUDIT paired with a named structural test as the ongoing pin). This is the
   only thing that proves the signature scheme is right; a self-signed mock proves only that the
   code agrees with itself.
3. **Playwright** (`e2e/host-verification.spec.ts`) — the host-facing half. ⚠ D-24 keeps it out of
   CI; supplement only.
