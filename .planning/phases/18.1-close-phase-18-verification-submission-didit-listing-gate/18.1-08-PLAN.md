<objective>
Let the verdict in — through **one** authenticated door.

Didit answers asynchronously, always. `POST /v3/session/` returns `status: "Not Started"` and a
hosted URL; the decision arrives later as a `status.updated` webhook. **B3 — this endpoint — is the
highest-severity trust boundary in the phase**: a forged verdict is a fabricated identity check that
makes an unverified host sellable. It is unauthenticated at the network layer, and **the signature is
the only authentication it has.**

The repo already contains a complete, argued, tested webhook 226 lines long at
`src/app/api/paymongo/webhook/route.ts`. **Follow it property for property**, and make exactly two
divergences deliberately, both documented at the site:

1. **Add the `X-Timestamp` ±300s replay window.** PayMongo has no equivalent. This is a
   strengthening, not a copy — and there is no in-repo precedent, so the reason goes at the site.
2. **Skip the event-ledger table.** The verdict write is a guarded `UPDATE … WHERE status='pending'`,
   so a re-delivery flips 0 rows and is a calm no-op by construction — the same shape `approveHost`
   already uses to return `STALE`. Zero new schema. ⚠ **Return 200 on the 0-row path**: a non-2xx
   would burn one of Didit's only two retries on an already-handled event.

Purpose: a real identity verdict reaches FitOut, and nothing else can.
Output: one shared write module, one route handler, one signing helper pair, one integration file.
</objective>
