## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous visitor → public calendar | Anyone (no session) can view availability; the read model returns only free/blocked state, no PII. |
| client selection → book action | The booker selects slots client-side; the real booking (Phase 4) re-derives and re-validates server-side. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-TAMPER-SELECT | Tampering | slot selection on non-bookable listing | mitigate | Selection is enabled only when `deriveBookable()` is true; a published-but-not-payable listing renders read-only with the existing "Not bookable yet" rail — no dead-end selection (UI-SPEC Interaction rules). |
| T-03-STALE | Tampering | advisory calendar state | mitigate | The calendar is advisory (Pitfall 6); the DB constraint (Plan 01) is authoritative; the real insert re-checks in Phase 4. Phase-3 selection never asserts a booking guarantee. |
| T-03-ENUM | Information Disclosure | public availability read (getDayAvailability) | accept | The read model returns only published/free/blocked state — no PII, no booker identity. Low risk; single-city public catalog. |
| T-03-TZBROWSER | Tampering | slot time display | mitigate | Times always render in the venue tz via `{ in: tz(listing.timezone) }` + react-day-picker `timeZone` — the browser tz is never used (SC#2); E2E asserts this. |
</threat_model>
