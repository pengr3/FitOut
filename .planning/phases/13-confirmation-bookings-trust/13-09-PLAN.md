<objective>
Build the trust block over the four real columns, and open the one address boundary TRUST-01 needs
without expanding the promise FitOut made to hosts.

Purpose: TRUST-04 exists to prevent invented trust chrome, and 13-CONTEXT D-68 closes the signal set at
four — each mapped to a verified column, with the explicit finding that **there is no response-rate or
response-time column in `src/lib/db/schema.ts`**. D-65 reframes the fourth signal so it is about where
the booker's money is (*"FitOut holds your payment until after your session"*) rather than a credential
no program stands behind. D-91 then resolves the one genuine tension: TRUST-01 wants the full address,
`listing.showExactAddress` defaults to false — but the host-facing control already reads *"Off by
default — guests see an approximate area until they book."* Revealing the street to a booker who has
paid is exactly what the host was promised, so it needs a named boundary, not a new promise.

Output: one component with two variants, one address projection beside the existing one, the page's
select widened to feed both, and the forbidden-string scan that keeps a fifth signal out.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host privacy toggle → booker's screen | `showExactAddress = false` is a promise to the host; revealing the street is an exception that must be auditable |
| booker's own email → their own page | D-63 renders it unmasked on an owner-gated page |
| trust copy → a program that does not exist | An invented badge is a worse lie on a money path than showing nothing |

No call site reads a raw address column (asserted by grep) |
