## Accomplishments

- **The four were measured into two classes, and RESEARCH.md groups them as one.** A six-run matrix (this box as it stands / CI's shape / CI's shape plus the public cloud name) settles it: the avatar three fail in all three environments that lack a SECRET, and `:974` fails with CI's message word for word; the photos step passes the moment a *made-up* public name exists. The instrument is deliberately not plan 09's container — the hypothesis was an absent environment variable, and absenting it is sharper than reproducing a whole image that also varies the rasteriser.
- **The plan's prescribed route for the photos step was falsified before it was executed.** Task 3 was written to seed a listing photo. `overflow-320.spec.ts:2731-2755` already seeds exactly one, at `/vrt/photo-0.svg`, under a comment headed "EXACTLY ONE PHOTO, AND THE COUNT IS LOAD-BEARING IN BOTH DIRECTIONS". A second would have changed nothing. What the run actually printed was `A Cloudinary Cloud name is required` on the dev server's stderr: `<CldUploadWidget>` throws at render without it and the error boundary takes the whole step down. **The spec's own failure message and the cause share no term** — the fifth message this phase to name the wrong thing, and the most complete miss of the five.
- **That row is repaired rather than allowlisted, and the distinction is the plan's central refusal working in reverse.** A cloud NAME is a `NEXT_PUBLIC_` value served to every browser; it is not a credential, so the zero-`secrets.` invariant does not forbid it and 19.1-08's rule applies — a repaired defect is not an annotation candidate. Writing "requires a live Cloudinary credential" on that row would have been a false reason, which is precisely what plan 02 caught one paragraph before it shipped.
- **Two avatar cases were seeded, and the route was proved before it was recorded.** A throwaway probe under `e2e/`, run with every Cloudinary variable empty and deleted in the same task, established all three unknowns at once: a directly-written row renders the circle from a committed local asset, the removal affordance appears, and the removal still LANDS with a `public_id` naming no asset and no credential to destroy with. The collected count returned to `460 tests in 39 files`.
- **`test.fail()` does not cover a TIMEOUT, and nothing in this phase knew that.** The first CI-shape run after annotating `:974` reported a plain `1 failed` and burnt all three attempts, because the case's final `toBeVisible` is given the same 30 s the test itself has, so the TEST expires before the ASSERTION does. Raising the case's own budget alongside the annotation makes the failure an assertion, `test.fail` covers it, and the case runs once — 34.2 s instead of 3 × 30 s. **`e2e/hold-countdown.spec.ts:443`, the entry plans 11 and 13 attribute a ~6-minute saving to, is exactly this shape.**

## Decisions Made

- **The repair lives in `playwright.config.ts`, not `.github/workflows/ci.yml`.** `gate-e2e` boots its server through that config, so one line fixes the gate and every local run at once; `ci.yml` is plans 06 and 12's file; and the config's own doctrine is that the booted environment must be "a STATIC PROPERTY OF THIS FILE" rather than a runtime condition, which is an argument *for* an unconditional literal and against a CI-only one.
- **The placeholder is unconditional, shadowing an operator's real cloud name.** No spec drives a real listing-photo upload (grepped), so the cost is currently zero, and the benefit is that local and CI boot the same server — which is this phase's whole subject. Recorded at the site with the condition that reverses it.
- **The seed writes BOTH columns.** Seeding only `avatar_url` would be a state no upload produces and would silently skip `removeAvatarAction`'s destroy branch — the branch `:2747` has to survive.
- **The annotation's condition is `CI`, not "the credential is missing".** The test process does not load `.env.local`, so a capability-derived condition would be true on a developer machine whose server has the credential, and the resulting unexpected pass burns three attempts.
- **`verify-workflows.mjs:538` is cited AND corrected rather than repeated.** The invariant moved to `:813` when plans 01, 05 and 06 added invariants above it; the evidence file records what lives at `:538` today so nobody re-derives the stale citation.
