## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest ^4.1.8 (design + unit) · @playwright/test 1.60.0 (pinned exact, e2e) |
| **Config file** | `vitest.design.config.ts` (design, DB-free, no globalSetup/setupFiles) · `playwright.config.ts` (`chromium` + `visual` projects) |
| **Quick run command** | `node scripts/verify-workflows.mjs` (~1s) — the checker |
| **Design suite command** | `npm run test:design` → `vitest run --config vitest.design.config.ts` |
| **Full suite command** | `npm run build` (lint + test:design + next build) then `npx playwright test --project=chromium` |
| **Estimated runtime** | checker ~1s · design suite ~seconds · e2e ~44m in CI (1 worker) |

**DB-backed vitest** (`npm test`) needs `npm run db:test:setup` once. The e2e suite needs Docker Postgres
plus `npm run db:migrate` and `npm run db:seed` — five specs fail against an empty catalogue by design.

---

## Sampling Rate

- **After every task commit:** `node scripts/verify-workflows.mjs` for checker work (SC1–SC3); the single
  repaired spec (`npx playwright test <spec> --project=chromium`) for suite work (SC4).
- **After every plan wave:** `npm run build` — lint, the full design suite, and the Next build.
- **Before `/gsd-verify-work`:** a full `ci` run on `dev` green in **all five jobs**.
- **Max feedback latency:** ~1s for the checker, seconds for the design suite; the 44-minute e2e suite is
  a wave-level gate, never a per-task one.
