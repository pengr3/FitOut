DIAGNOSIS
================================================================================

1. THE PAYMENTS CALL RAISED BECAUSE NO CREDENTIAL IS PRESENT. `PAYMONGO_SECRET_KEY` was shadowed to a
   defined empty string for this run, matching the state every CI run is in — `.github/workflows/ci.yml`
   is invariant-forbidden from carrying any `secrets.` reference, so `gate-e2e` structurally CANNOT have
   a payments credential. (On this box the dev-only origin-wide interceptor in `instrumentation.ts`
   independently guarantees the same raise; see the bring-up note above.)

2. THE PAGE THEREFORE RENDERED THE MANUAL-RETURN NOTICE RATHER THAN THE IN-TRANSIT SENTENCE.
   `src/app/(app)/bookings/[id]/page.tsx:1121-1122` computes
   `manualReturn = refundCents !== null && refundCents > 0 ? await refundNeedsManualReturn(bk.id) : false`
   and the fork at `:1168-1176` states in its own comment: *"THE FORK. `manualReturn` wins, and it must:
   the two sentences are mutually exclusive money claims about the same figure, and the in-transit one
   is the false half whenever the dispatch did not happen."* `ManualReturnNotice` renders INSTEAD of the
   `MoneyStatement` carrying `refundLine`. The in-transit sentence is not merely absent — it is
   WITHHELD, deliberately, because telling the booker a refund is on its way would be false on this path
   (`src/lib/booking/refund-dispatch.ts:14-18`).

3. AN AUDIT ROW WAS WRITTEN, WITH A NAMED ACTION: `refund_dispatch_failed` / `needs_attention`, quoted
   above. That row is not incidental to the render — it IS what the render is derived from. D-80 forbade
   a `refund_dispatched_at` column, so the operator queue is the single source of truth for the booker's
   sentence: *"One row, two audiences, no way for them to disagree"* (`refund-dispatch.ts:31-33`).

4. THE SPEC ASSERTS ONLY ONE OF THE TWO LEGITIMATE OUTCOMES. `:249` demands the in-transit sentence
   unconditionally. Both sentences are correct renders of a cancelled booking with a positive refund —
   which one appears is decided by whether the dispatch succeeded, a fact the spec never establishes and
   never branches on. THE PRODUCT IS RIGHT AND THE SPEC IS INCOMPLETE.

VERDICT — `e2e/cancel.spec.ts:232` is REPAIRED, NEVER ALLOWLISTED. D-01 names this test explicitly as
the reason blanket quarantine was rejected: a green badge sitting on top of an unverified refund
behaviour is the exact failure mode this phase exists to prevent. It sits on the money path. The repair
is the named disjunction — identify which branch rendered, then assert what that branch owes — which is
a STRONGER assertion than the one it replaces, because in the manual-return branch it additionally
requires the audit row that branch is derived from. The database assertion beneath it
(`row.refund_cents === EXPECTED_REFUND_CENTS`) already passes in both environments and stays byte-
unchanged; this repair adds a second truth beside it rather than trading one for another.
