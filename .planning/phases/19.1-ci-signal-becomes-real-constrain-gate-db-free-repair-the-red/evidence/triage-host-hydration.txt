WHAT THE BROWSER NAMED, IN ITS OWN WORDS AND NOT IN PLAN 13's.

  THE NODE:      `<button data-slot="button" data-variant="ghost" data-size="icon"
                 aria-label="Menu" type="button">` — the nav drawer's trigger.
  THE ATTRIBUTE: `aria-controls="radix-_R_ad5ritulb_"`, a Radix identifier generated per render from
                 React's own id hook.
  THE POSITION:  under `<nav data-testid="site-nav">` → `<Suspense fallback={[...]}>` →
                 `<div className="md:hidden">` → `NavDrawer` → `ResponsiveDialog` → `Dialog` →
                 `DialogProvider` → `DialogTrigger` → `Primitive.button.Slot`.
  THE SIGN:      every line of the node is prefixed `+`. In React's diff `+` is CLIENT-ONLY — the
                 client rendered this button at a position the server's HTML did not put it at.

MATCHED OR REFUTED? MATCHED. 19.1-13 recorded the chain
`host layout → SiteNav → NavDrawer → ResponsiveDialog → Radix DialogTrigger` and the attribute
`aria-controls` as the LEADING CANDIDATE, and said in writing that it had not been read as this
plan's own measurement. It is now read: the element and the attribute the browser names are the
element and the attribute 13 named. Nothing in the reading was inherited — the block above is this
run's output, and the id value (`radix-_R_ad5ritulb_`) is this run's own.

streams too — `src/app/(app)/layout.tsx` wraps its bell in a boundary — but its fallback is

MOUNTS. That single in-repo contrast is what selects the repair shape in STEP 2.
