# Phase 19.1 Plan 16: the `(host)` hydration failure — Summary

**Radix's `asChild` clones rather than renders, so a trigger element created in a Server Component was absent from the served HTML and appeared only on the client — every `(host)` route regenerated its tree, 110 times per CI run, and now zero. The two failures this plan owned are unmoved by that, which is the plan's second and more expensive finding.**

## Accomplishments

- **The defect is repaired and proven where SC4 lives.** `gate-e2e`'s own job log carried **110** `Hydration failed … this tree will be regenerated on the client` messages on the previous run and **0** on this one. ## What React's error detail actually named, and whether it matched plan 13

**It matched as a DESCRIPTION and it is REFUTED as a MECHANISM, and the difference is the whole plan.**

React named exactly what 19.1-13 said it would: the node is
`<button data-slot="button" … aria-label="Menu" …>`, the drawer trigger; the attribute is
`aria-controls="radix-_R_ad5ritulb_"`, generated per render; the position is
`<nav data-testid="site-nav">` → `<Suspense>` → `NavDrawer` → `ResponsiveDialog` → `DialogTrigger`.
Every line of the node is prefixed `+` — React's notation for CLIENT-ONLY.

Plan 13 read that as *two renders disagreeing about an id*. Applying the repair that shape implies —
a fallback that mounts no overlay — left the count at 1 **with the same id**. Two renders that
disagree about a generated id do not produce the same id after one of them stops existing.

The served document said what `+` had meant all along:

```
S:0 → <div class="hidden md:flex">…links…</div><div class="md:hidden"></div>
      aria-label="Menu" count in the whole document: 0
```

The drawer placement is served **empty**. `ResponsiveDialog` forwards `trigger` into
`DialogTrigger asChild`, and `asChild` is Radix's `Slot` — which **clones** an element rather than
rendering one. `patterns/site-chrome.tsx` is a Server Component, so the trigger element crossed the
RSC boundary and could not be cloned during the SSR pass. It was not two ids; it was **one render
missing**. Every other adopter of the pattern was already a client module — one exception in the
tree, one route reporting the mismatch.

The repair is `src/components/patterns/nav-drawer-shell.tsx`: a `"use client"` module that owns the
trigger. `NavDrawer` stays a Server Component and passes `NavLinks` down as ordinary children, which
cross the boundary unchanged because children are never cloned.
