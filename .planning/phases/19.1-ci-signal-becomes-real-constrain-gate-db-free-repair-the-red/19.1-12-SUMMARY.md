- **`gate-visual`'s standing failures went 12 → 4**, and the reduction is attributable per row rather than to a threshold moving.
- **The diffs became reviewable at all.** Until Task 1 the visual job produced its diff images and destroyed them on the same runner in the same second, because nothing uploaded them. ## Decisions Made

**1. Rows 9–12 were not regenerated — stability, not correctness.** The PM classified all twelve as drift and found no regressions. Rows 9–12 are nonetheless blocked on a different property: their references encode a particular calendar day. Two causes, both measured and then confirmed in the source:

- `react-day-picker@10.0.1` `DayPicker.js:131` does `if (!props.today) props = {...props, today: dateLib.today()}`, and neither `availability-calendar.tsx` nor `ui/calendar.tsx` passes the prop — so the today ring follows the wall clock.
- `scripts/seed-baseline-fixtures.ts:193` inserts the host with `created_at = now()`, so `Host since <month>` is the month the seed ran.

Confirmed **observationally** rather than by inference: the images the dispatch actually minted read `Host since September 2026` and carry the today ring on day 5 — the day the dispatch ran. Both crops are committed.

**2. The fixture fix is NOT small and localised (D-02).** Three changes in three layers plus a test, and the third is production source: fixing the ring means changing it from the rendering host's day to venue-local today, which is a **product** question. Compounding it, the visual project is not constructed off Linux (D-29), so the fix's effect on the rendered calendar cannot be observed before minting — doing it here would have committed four references whose stability was an assumption. The phase grows by a plan.

**3. Mint twelve, then un-mint four.** `baselines.yml` has no filter and stages `*-visual-linux.png` by glob. Teaching it one means editing the single job holding `contents: write` and carrying eleven invariants — not worth it for one plan. Both halves are separate commits, each constrained to the baseline-image glob.

## Deviations from Plan

### Auto-fixed / scope adjustments

**1. [Rule 3 — Blocking] The dispatch workflow cannot regenerate a subset**
- **Found during:** Task 3, before dispatching
- **Issue:** The PM authorised eight images. `baselines.yml` runs `--update-snapshots` over the whole project and has no filter input, so a dispatch necessarily mints all twelve.
- **Fix:** Dispatch, then revert rows 9–12 to the restore point in a separate commit, with per-file byte-identity verification. Rejected the alternative (adding a filter input to the one job with `contents: write`) as disproportionate.
- **Verification:** Restored files byte-identical to `fe99817` (4/4 md5 match); the restore commit's changed-file list is 0 non-baseline files.
- **Committed in:** `5d9e90f`

**2. [Rule 2 — Missing critical] The restore command was unverified, and one form of it looked broken**
- **Found during:** Task 3, writing the restore point
- **Issue:** The plan requires a restore command but not that it works. A command that silently matches nothing reads as a reversal and is a no-op — the exact false-assurance shape this phase exists to remove. Separately, `git ls-tree -r` reports **0** for the same glob `git ls-files` reports **36** for, which invites someone to "fix" a working command.
- **Fix:** Proved it — corrupted a real baseline and restored it byte-identically, with a non-matching-pathspec negative control to show a silent success means something matched. Recorded the `ls-tree` trap in the file.
- **Committed in:** `9dd4bcf`

**3. [Scope] Task 3's literal `HEAD~1 HEAD` verify is only meaningful when HEAD is the regeneration commit**
- **Issue:** `git diff --name-only HEAD~1 HEAD | grep -cv -- '-visual-linux\.png$'` was written assuming the regeneration commit is HEAD. Evidence commits necessarily follow it.
- **Fix:** Evaluated against the commits it is actually about — `7d225a7` (regeneration, 12 files, 0 non-baseline) and `5d9e90f` (restore, 4 files, 0 non-baseline) — rather than against whatever happened to be HEAD at the end. Stated rather than silently satisfied by commit ordering.

The plan's own `<success_criteria>` asks for a green gate; that is not met, and the PM's decision explicitly made this the acceptable outcome — *"leaving four baselines red with a stated reason is an acceptable outcome of this plan; minting an unstable reference is not."*

It moves `startMonth`, `endMonth`, `disabled` and the `initialDate` fallback, and it does not reach react-day-picker's `today` modifier — the one element that still expires. Its docblock reads as though the case is closed. Logged as part of `D-19.1-D`.

**Carried, not closed (from Task 1):** the hydration mismatch on the two `checkout` surfaces. Both pass and neither is in the failing twelve, so no image regenerated here is downstream of it — but it is a live instability on two currently-green baselines.
