# Phase 19.1 Plan 01: Constrain gate-db-free Summary

**The job that runs the workflow checker is now itself checked: deleting its checker step, renaming its display name, or appending an argument to its invocation each turn `node scripts/verify-workflows.mjs` red with a named FAIL line — while a decoy step impersonating the checker in a `run:` body deliberately stays green.**

## Accomplishments

- **CR-03 closed.** Before this plan, `gate-db-free` — the job that executes `scripts/verify-workflows.mjs`, `lint`, `test:design` and `next build` — was read by NOTHING in the checker. Deleting the two-line step that runs the checker left `All 50 invariants hold` and exit 0. That is now a named FAIL, and the transcript of the green it used to print is on disk beside the transcript of the red it prints now.
- **The display name is pinned.** `gate-db-free (lint + design + build + workflow parse)` is declared exactly once in the checker and asserted against the workflow. This is the string plan 15 registers as a required status check on `main`; renaming it would have left every invariant here green over a job branch protection no longer recognises.
- **The anchor rule was applied on arrival, not retrofitted.** The step is selected by its exact `name:`. Case 16 — the only GREEN-asserting case this plan adds — proves a decoy step whose `run:` merely mentions the checker's path cannot capture that anchor. `gate-db-free`'s own step 1 already carries multi-line free text, so the decoy was never hypothetical in this job.
- **The invariant total moved in all three spellings, twice.** 50 → 51 (Task 1) → 52 (Task 2), taken from the checker's printed output each time and never computed, in the checker's summary line, `ci.yml`'s verbatim quote and `EXPECTED_GREEN`.
- **The standing suite grew from twelve cases to sixteen**, and every predicate this plan added is proved twice — once by a hand mutation on the tracked file with md5 and `git status --porcelain` revert proof, once by a standing case that spawns the shipped checker against a mutated copy.

## Decisions Made

- **The invariant total is 52 (`baselines=11, ci=33, cross=8`).** RESEARCH.md A10 estimated 52 and the run agrees, but by the route the plan specified: the number was read from the checker at each step (50 → 51 → 52), never computed. No delta to report.
- **The decoy control needed no adjustment to stay green.** It was written once, against the exact-`name:` anchor Task 1 shipped, and passed on its first run. That is the intended outcome — the anchor rule was applied on arrival, so there was no substring anchor for the decoy to defeat.
- **The predicate region is literally containment-free.** The diagnostic `checkerSteps.indexOf(checkerStep)` was hoisted to a `const` above the `check()` so a grep over the region counts zero containment- or search-shaped calls. An array `indexOf` reporting a position is not a containment test, but a reader who has to make that distinction has already lost the glance.
- **`withJobKey`'s silent fallback (IN-02) was left alone.** Plan 06 owns it. `MAIL_STEP_NAME` was re-expressed through `constFromChecker` because that is a behaviour-identical de-duplication (it already threw), and PATTERNS.md names the generalised helper as this phase's shape.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Evidence capture reverted the plan's own ci.yml edits**

- **Found during:** Task 1 (STEP 5, the post-fix capture)
- **Issue:** The capture script reverts each hand mutation with `git checkout -- .github/workflows/ci.yml`, which restores from HEAD — not from the working tree. Task 1's `ci.yml` comment edits were still uncommitted at that moment, so the revert discarded them along with the mutation. Detected immediately (`grep -c "All 51 invariants" .github/workflows/ci.yml` → 0).
- **Fix:** Re-applied the comment edits, then **reordered the capture**: code changes are committed FIRST, and the mutation transcript is taken against the clean committed tree, with the evidence file folded into the same task commit via `git commit --amend`. This also makes the plan's own acceptance criterion — "`git status --porcelain` producing no line for `.github/workflows/ci.yml` after the revert" — literally true instead of approximately true. The reordering is recorded in the evidence file's own header so the next round does not rediscover it.
- **Files modified:** `.github/workflows/ci.yml` (restored), evidence capture procedure
- **Verification:** `node scripts/verify-workflows.mjs` back to 51/exit 0; `git diff -U0` comment-only re-confirmed; final `git status --porcelain -- .github/workflows/ci.yml` empty.
- **Committed in:** `d6d420d` (Task 1 commit, amended)

**2. [Rule 1 - Bug] Task 1's acceptance criterion "zero containment calls in the predicate region" was failing**

- **Found during:** Task 1 (acceptance-criteria gate, first pass)
- **Issue:** The evidence string carried `checkerSteps.indexOf(checkerStep)` inline. Semantically an array position lookup, not a containment test — but the criterion counts containment-method occurrences in the region between the `check(` opening and its closing `);`, and it counted 1.
- **Fix:** Hoisted the index to `const checkerStepIndex` above the `check()`, with a comment stating why the hoist exists (the property most needing a reader's confirmation is that the invocation conjunct is an equality, and that must survive a glance).
- **Files modified:** `scripts/verify-workflows.mjs`
- **Verification:** region scan for `.includes|indexOf|lastIndexOf|startsWith|endsWith|match|search|test` → 0; checker still exit 0; suite still 13/13 at that point.
- **Committed in:** `d6d420d` (Task 1 commit, amended)
