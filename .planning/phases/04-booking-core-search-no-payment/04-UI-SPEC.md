# Phase 4 — UI Design Contract

> Visual and interaction contract for the Booking Core & Search (no payment) phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase surfaces (from 04-CONTEXT.md + ROADMAP UI hint = yes):**
> 1. **Search home at `/`** (D-29) — replaces the Next.js scaffold (`src/app/page.tsx`). Airbnb-style search bar (location autocomplete + activity/type + date + optional time + price + radius) → results as a **list of cards** (photo, name, price, distance). Default no-query view = all bookable listings in the launch city (D-30); zero-result state with escape hatches (D-31); **"Load more"** pagination (D-32); **nearest-first / price** sort (D-37).
> 2. **Reserve / checkout page** at `/listings/[id]/book` (D-39) — listing summary + selected window + **price breakdown** (rate × qty = subtotal = total; NO fee line yet, room reserved — D-46); a visible **hold countdown** ("Held for 14:59") + **graceful expiry** (D-44); **sign-in gate** at Book (D-41); **Confirm** disables on click + idempotency (D-42). The pending hold is placed on **entering** checkout (D-39 / SC#3), not on final confirm.
> 3. **Confirmation page** at `/bookings/[id]` (D-43) — durable, owner-gated booking reference + details that survives refresh. **No "My Bookings" list** (Phase 7).
> 4. **The listing "Book this space" CTA seam** (`src/app/listings/[id]/page.tsx` ~298–305) — wired from a state-reflecting placeholder to the reserve page.
>
> **Out of scope for this contract (later phases):** payment fields / fee / commission lines (Phase 5 — layout only leaves room), instant-book vs request-to-book fork (Phase 6), My Bookings list + cancel/manage (Phase 7), map view of results (v2 / DISC-01), group RSVP (Phase 8), amenities filter (deferred, D-36).

## Spacing Scale

Reuses the locked 8-point scale (Tailwind v4 defaults; all multiples of 4). No custom spacing tokens.

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `1` | Icon-to-label gaps, distance/meta chip spacing, countdown clock-to-digit gap |
| sm | 8px | `2` | Search-field inner element gaps, card intra-content spacing, breakdown line-item vertical gap |
| md | 16px | `4` | Default control spacing, card inner padding (mobile), results grid gutter (mobile), search-bar field gap |
| lg | 24px | `6` | Card inner padding (desktop), results grid gutter (desktop), reserve-summary card padding, section padding |
| xl | 32px | `8` | Reserve two-column gap (summary ↔ breakdown/CTA), search-home content gutters |

| 3xl | 64px | `16` | Page top/bottom padding (desktop) on search home, reserve, and confirmation |

**Exceptions:**
- **Touch targets ≥44×44px** for every interactive control: search fields, activity/location comboboxes, date cell, time selects, price inputs, radius select, sort select, the whole result-card tap area, "Load more", "Book this space", "Confirm booking", and all escape-hatch buttons. On dense desktop layouts the *visual* may be smaller, but the **hit area is padded to ≥44px**. Hit-area floor, not a new spacing step.
- **Results grid gutter** = 16px mobile (`gap-4`), 24px desktop (`gap-6`).

## Typography

Reuses the locked contract: single family (Geist), exactly **4 sizes**, exactly **2 weights** (400 regular, 600 semibold). No third weight, no italic.

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Display | 28px | 600 | 1.2 | Search-home hero line (e.g. "Find a space to play"); reserve page title ("Review and book"); confirmation "Booking confirmed" + the booking **reference** |
| Heading | 20px | 600 | 1.25 | Results header ("N spaces near {area}"); reserve "Your booking" / listing name in the summary; breakdown **Total** value; confirmation section headings |
| Body | 16px | 400 | 1.5 | Descriptions, empty-state body, reserve summary prose, confirmation detail values |
| Label | 14px | 600 (control labels, card title, breakdown labels) / 400 (meta, distance, tz note, helper, countdown) | 1.4 | Search-field labels (600), **result-card title** (600), price-per-unit, distance ("2.3 km away", 400 muted), sort/radius labels, breakdown line labels (600) + values, the **hold-countdown** label + digits (400 + `tabular-nums`), error microcopy (400) |

Rules:
- **All prices, the price breakdown, the hold-countdown timer, and the booking reference use `tabular-nums`** so digits align and the countdown doesn't jitter (Geist sans — never switch to mono).
- **Result-card title = Label 14px / weight 600** (semibold). The existing `listing-card.tsx` uses `font-medium` (500) — normalize it to **600** so search cards obey the strict 2-weight contract (400 + 600); 500 is not a declared weight.
- Body reading copy stays 16px / 1.5 / 400 — never smaller for primary reading content.
- Headings stay weight 600 — never 700.

## Price breakdown contract (BOOK-01 · D-45 · D-46)

Formalizes the existing `RailSelectionSummary` estimate (`fullDay ? dayRateCents : hourlyRateCents × hours`) into a committed, server-quoted breakdown on the reserve page.

**Layout (a line-item list; a fee row can be appended before the Total divider with zero layout shift):**

```
{₱rate}/hr  ×  {N} hours                 {₱ subtotal}      ← hourly run (D-45)
        — or —
{₱rate}/day ×  1 day                      {₱ subtotal}      ← "Book full day" (D-45)

[ reserved slot for Phase-5 fee/commission rows — renders nothing in Phase 4 ]

──────────────────────────────────────────
Total                                     {₱ total}          ← == subtotal in Phase 4
```

Rules:
- **PHP** via `formatMoney(cents, "php")`; all figures `tabular-nums`; `Total` value is Heading-weight (600).
- Phase 4 has **NO fee/commission line** (D-46) — but the component MUST render line-items in a list whose structure lets Phase 5 insert `Service fee` / `FitOut commission` rows above the Total divider without moving anything. Document the seam in the component.
- The displayed subtotal/total is the **server-quoted, frozen** amount (D-49 `quotedTotalCents` + `currency`), **never** a client recompute. Re-derive `hours`/`fullDay` and price server-side from the read model before quoting (CLAUDE.md "never trust the client for price/time").
- Sub-line under Total: `Final price. No booking or service fees in this step.` (sets the Phase-5 expectation honestly).

## Screen / State Contract

Every interactive surface defines loading / empty / error / active states.

| Screen | Key states the executor must implement |
|--------|----------------------------------------|
| **Search home (`/`)** | initial default city view (D-30, all bookable, curated sort) · typing in location (autocomplete suggestions) · filters applied (URL-synced) · **loading** (skeleton card grid) · **populated** (cards + distance + sort + Load more) · **loading more** (append + spinner, button `Loading…`) · **exhausted** (Load more hidden) · **zero results** (escape-hatch empty state, D-31) · **cold-start empty** (no bookable listings at all) · sort disabled when no origin · search fetch error (retry) |
| **Reserve page (`/listings/[id]/book`)** | **entering** (placing hold — brief loading) · **hold active** (countdown + breakdown + Confirm enabled) · **confirming** (Confirm disabled → `Confirming…`, idempotent) · **confirmed** (redirect → `/bookings/[id]`) · **hold expired** (graceful expiry state) · **just taken** (race — calm, path back) · **not signed in** (redirect to login, return-to checkout, D-41) · **signed in but `!canBook`** (activate-booking prompt) · **listing not bookable** (guard → back to listing; should not normally reach) |
| **Confirmation page (`/bookings/[id]`)** | **loading** (skeleton) · **confirmed** (reference + details, the success state — survives refresh) · **not owner / not found** (owner-gated message or 404, D-43) · (no cancel/manage — Phase 7) |
| **Listing detail seam** | unchanged states from Phase 2/3 (bookable coral CTA / not-bookable disabled) — the only change is the bookable CTA now navigates to the reserve page and triggers the hold on entry |

**Visual hierarchy / focal point (locked, per surface):**
- **Search home:** the **search bar is the entry focal point** (top, roomy), and the single coral **Search** button is its terminal action; the eye then travels to the **results grid** (the working area). Result cards are uniform and neutral — no per-card coral — so no single card competes; the cover photos carry the visual weight. Coral appears exactly once (Search), which enforces "search first, then browse."
- **Reserve page:** the **selected window + price breakdown is the anchor** (what am I booking, for how much), the **hold countdown sits adjacent as a quiet urgency cue** (neutral), and the coral **`Confirm booking`** is the terminal focal point. Coral appears once (Confirm), so the eye travels summary → breakdown → Confirm.
- **Confirmation page:** the **`Booking confirmed` heading + reference is the focal point** (reassurance first), the `--success` badge reinforces it, details sit below. Any forward action is secondary and at most one coral.

**Interaction rules (locked):**
- **The pending hold is placed on ENTERING checkout** (D-39 / SC#3), not on final confirm — the slot is protected during review and immediately reflects in the calendar + search. Entering a checkout that races a conflict shows the calm "just taken" state.
- **Confirm is idempotent** (D-42): a per-checkout idempotency key makes a double-click a no-op that returns the **same** booking; the button also disables on click. A booker double-clicking **their own** slot always sees success — never a false "just got taken."
- **Occupancy / "just taken" / "hold expired" are never red errors** (occupancy is a normal state) — they are neutral, calm, and always offer a path back to availability.
- **Every displayed time names the venue timezone** (SC#2), on search results (searched-window line), the reserve window, and the confirmation.
- **Prices are server-quoted and frozen** at hold time (D-49) — the reserve breakdown and confirmation display that quote, never a client recompute.

**Accessibility (non-negotiable):**
- The whole result card is a single focusable link (not nested competing tab stops); the cover `img` has a meaningful `alt` (listing title).
- Search fields have associated `<label>`s (reuse the `form` pattern); the sort/radius `Select`s are keyboard-operable; the disabled "Nearest" option exposes its hint via `aria`.
- The **HoldCountdown** is `role="timer"`; do **not** announce every second (`aria-live="off"`) — announce only the final-minute threshold and the expired state (`aria-live="assertive"` on the expiry interstitial).
- The expiry and "just taken" states move focus to the recovery CTA so keyboard users aren't stranded.
- Coral CTA contrast (`--brand` + `--brand-foreground`) meets ≥4.5:1 (verified Phase 2); `--success` badge is paired with the check-circle icon + "Confirmed" text (never color-only).
- Confirm button: `aria-disabled` while submitting; the idempotent no-op must not produce a confusing double toast.

## New Tokens to Add

**None.** This phase introduces no new color tokens, type sizes, or spacing steps. Search, reserve, countdown, expiry, and confirmation states are expressed entirely through the existing `--brand` / `--muted` / `--muted-foreground` / `--border` / `--success` / `--ring` tokens plus non-color signals (disabled state, icon + text labels, `tabular-nums`). Do **NOT** introduce a bespoke "taken/expired red" or "available green" — occupancy and holds are neutral states, not semantic error/success (the only success surface is the terminal **Confirmed** badge; `--destructive` has no required use). Promote the existing `DISPLAY_CURRENCY = "php"` constant to a shared module so all price surfaces share one source (a code-org note, not a token).
