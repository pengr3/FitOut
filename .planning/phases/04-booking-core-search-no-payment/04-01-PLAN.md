<objective>
Extend the `booking` occupancy table with the pending-hold lifecycle columns (D-49) and teach the single availability read model to treat a stale pending hold as free (D-48a lazy reads). This is the shared data-layer substrate the whole phase sits on: search Stage-2 and the booking transaction both consume the modified `read-model.ts`; the new columns back the frozen price snapshot (Phase-5 charge integrity) and double-click idempotency.

Purpose: The hold + expiry mechanism has NO background worker (D-48) — correctness rests on the DB EXCLUDE constraint plus lazy reads + sweep-on-write. This plan lands the columns and the lazy-read half; Plan 04 lands the sweep + the WR-03 transaction.
Output: 4 new `booking` columns + a partial-unique idempotency index, applied to the live DB; a one-line occupancy-predicate change reused everywhere; a regression test proving a past-expiry pending is free.
</objective>
