<objective>
Build the correctness spine of search: a two-stage candidate-then-filter query. Stage-1 SQL narrows to a bounded candidate set with the cheap/indexable predicates (bookable-gate + `::geography` radius + category (type-or-tag) + price + "open this weekday" + sort + Load-more probe); Stage-2 reuses the SAME `getAvailability` read model the listing page uses to enforce the true free-window filter (D-34), so search results and the listing calendar structurally cannot diverge.

Purpose: SEARCH-01..05. A search result must be a GENUINE offer. The single highest-risk trap is `ST_DWithin` on a `geometry(Point,4326)` measuring in DEGREES — the radius must cast both operands `::geography` for meters, or the filter silently matches everything.
Output: `src/lib/search/query.ts` exporting `searchListings`, proven by four integration tests against the seeded data.
</objective>
