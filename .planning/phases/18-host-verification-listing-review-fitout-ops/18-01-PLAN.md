<objective>
Give FitOut an authenticated staff identity, and one expression that answers "is this caller staff?".

Purpose: The ROADMAP is explicit — *"an ops console over live bookings and money, built before staff
auth, is a bigger hole than the one being closed."* Everything else in Phase 18 is a consumer of this
plan. `audit.resolved_by` has been *"asserted, not authenticated"* since Phase 8; this is the plan that
finally makes an authenticated ops actor possible.

grant policy), `scripts/ops-grant.ts` (the CLI), and three tests.

`tests/design/loading-coverage.test.ts` pins page counts and is build-blocking, so a route and its
`loading.tsx` and the three pinned constants move in ONE commit (plan 18-12).

`readStaff()`; on null it calls `notFound()` from `next/navigation`. Never `forbidden()`, never
`redirect("/login")` — D-219 forbids confirming the route exists to a prober. Returns the staff id so
every caller has the authenticated `actorId` OPS-03 needs.

it exists only to win the 404 STATUS LINE, because every `(ops)` page carries a build-mandated
`loading.tsx` whose Suspense boundary commits a 200 before a page-level `notFound()` can run. Quote
the Next 16 rule that a layout *"does not control whether the rest of the route renders"*.

only while `session.cookieCache` stays unconfigured in `src/lib/auth.ts` (a repo-wide grep for

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Better Auth `[...all]` catch-all | Untrusted JSON reaches `/api/auth/update-user`; `role` must be unwritable across it |
| browser → RSC / server action | Every ops caller crosses here; `requireStaff()` is the only thing standing on the other side |
| operator shell → database | `scripts/ops-grant.ts` writes a privileged field with an ASSERTED, not authenticated, actor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-0101 | Elevation | `user.role` via `/api/auth/update-user` | mitigate | `input: false` stays on the `role` additionalField; `tests/auth/ops-role.test.ts` measures that a crafted body does not write it |
| T-18-0102 | Elevation | Better Auth admin plugin | mitigate | Plugin NOT added. Its 15 mounted routes (incl. `set-role`, `impersonate-user`, `set-user-password`) would be published instantly by the existing catch-all; asserted by a grep in this plan's acceptance criteria |
| T-18-0103 | Information disclosure | ops route-existence oracle | mitigate | `requireStaff()`/`assertStaff()` call `notFound()`, never `forbidden()` and never a redirect — a prober cannot tell an ops route from a bad URL |
| T-18-0104 | Spoofing / Elevation | NULL `role` fail-open | mitigate | Positive string equality `role === "staff"`; `!== "user"` is grep-forbidden in the acceptance criteria because the column is nullable |
| T-18-0105 | Elevation | stale session role after revocation | mitigate | `session.cookieCache` stays unconfigured; the dependency is written into `src/lib/ops/staff.ts`'s header so a later performance change cannot silently break revocation |
| T-18-0106 | Repudiation | a staff grant with no record | mitigate | `grantStaff`/`revokeStaff` insert an `audit` row through the injected connection; the test READS IT BACK rather than trusting a return value |
| T-18-0107 | Elevation | self-serve staff grant | mitigate | Grant exists only as a CLI subcommand with a required `--by`; no server action, no HTTP route, no env allow-list |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs NOTHING (18-RESEARCH § Package Legitimacy Audit is vacuous). Any `npm install` proposed here is a divergence from research and must stop the plan |
</threat_model>
