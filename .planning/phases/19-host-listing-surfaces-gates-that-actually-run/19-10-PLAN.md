Close GAP 2: the D-03 failure signal is unreachable for the one case it exists to catch.

`createDraftListing` has no `try`/`catch` anywhere. Its only two `{ ok: false }` paths are the
no-session check and the verification refusal — and `new/page.tsx` redirects away from both BEFORE
calling the action. The reuse read and the insert both throw uncaught on any infrastructure failure,
so Next's error boundary renders a generic error page and the D-03 sentence never fires. The copy
module, the query token and the grid notice are all real, all wired, and orphaned for their stated
purpose.

failure that was supposed to reach them able to reach them — and, because the two windows where the
branch IS live today would render copy `create-signal.ts` bans by name, it routes those two windows
to their true destinations instead of dressing them as infrastructure failure. No third message is
invented; the exported copy is byte-unchanged.

branch impossible rather than merely deleted, a three-way router at the page, and three tests — one
that stubs the DB to fail, one that drives the router, and one build-blocking census that keeps the
refusal set and the router in agreement.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/host/listings/new` (a GET that writes) | The session cookie alone authorises the write; no form post, no CSRF token. Pre-existing (WR-07), unchanged by this plan and recorded rather than absorbed. |
| `createDraftListing` → the caught error → the host | The catch is where infrastructure detail could cross into host-facing output. |
| `?create=failed` query value → `HostListingsPage` | An untrusted URL value reaching a render, already mitigated by 19-07's single equality check. |
| ops suspension / session expiry → the window between the page's read and the action's | Two authorities read at two times; the gap is the race this plan routes. |
