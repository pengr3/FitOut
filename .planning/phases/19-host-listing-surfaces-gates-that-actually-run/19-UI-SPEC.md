# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## ⚠ What this contract is — read before using it

**This is a NARROW phase and every visual decision in it is ALREADY MADE AND MEASURED.** This document
writes them down as an enforceable contract. It is **not** a redesign, and it proposes **no** restyle,
**no** new component, **no** token change and **no** layout rethink — each of those would breach the
v1.2 invariants (zero new runtime dependencies, zero schema migrations) and the phase's locked
decisions D-01…D-15.

**Everything in `## Copywriting Contract` and `## Surface Contract` marked SHIPPED is byte-unchanged
by this phase.** Only three things change on this surface, and all three are named below:

1. `CardFooter`'s call-site class string gains **two appended tokens** (`mt-auto flex-wrap`).
2. The Delete control becomes **icon-only** at `size="icon-sm"`, keeping its accessible name.
3. `/host/listings` gains **one new failure sentence**, rendered inline above the grid.

**Out of scope for this contract:** anything under `(ops)`, the host verification surfaces, the
review/resubmit loop. Those are phases 20–22.

**Scope alarms.** If a plan or an executor proposes any of the following, stop and re-read this file:
a new npm package; a schema migration; an edit to `src/components/ui/card.tsx` or
`src/components/ui/button.tsx`; `h-full` on `Card`; a 44px hit-area requirement on the footer cluster;
a support / "get in touch" clause in any copy.

## Surface Contract A — the `/host/listings` card, at three bands

### The three bands, and why they are these numbers

The grid is `cn(RESULT_GRID_GAP, "grid sm:grid-cols-2 lg:grid-cols-3")`
(`src/app/(host)/host/listings/page.tsx:180`), i.e. Tailwind v4 defaults `sm = 640px`, `lg = 1024px`.

⚠ **The measurement widths are deliberately OFF the breakpoints.** `640` and `1024` are the exact
edges; a 1px rounding difference at an edge changes the column count and makes a failure unreadable.

| Band | Viewport | Columns | Card bottoms flush (Guard A cl.1) | Footer flush to card bottom (Guard A cl.2) | Footer no self-overflow (Guard B) |
|------|----------|---------|---|---|---|
| Floor | **320 × 800** | 1 | skip (one card per row) or assert `row.length === 1` deliberately | **required** | **required** — tightest width, most likely clip |
| `sm` | **700 × 900** | 2 | **required** (needs ≥2 listings) | **required** | **required** |
| `lg` | **1280 × 900** | 3 | **required** (≥2 in a row suffices) | **required** | **required** — the second-tightest, per the arithmetic below |

`1280` also matches the wide band `host-headings.spec.ts` already uses.

**Resize, do not re-navigate.** The grid is server-rendered and its content does not depend on the
viewport — one navigation and three `setViewportSize` reads is correct and ~3× cheaper (the shape
`host-headings.spec.ts` documents in its own header). ⚠ After each resize,
`await page.evaluate(() => document.fonts.ready)` before measuring: a font swap reflows
`CardContent` and changes the numbers.

### The state contract, per band

| # | Claim | Status today |
|---|-------|--------------|
| A1 | Every card in a visual row ends at the **same bottom edge** (`cardBottom` equal within 1px, grouped by `cardTop` within 1px) | **already true** — the grid stretches them; kept as a vacuity check and as a regression guard against anyone adding `items-start` |
| A2 | **The footer band is flush with the card's bottom edge**: `cardBottom − footerBottom ≤ 1px` | ⚠ **RED TODAY. This is the defect.** |
| A3 | `[data-slot="card-footer"]`'s `scrollWidth ≤ clientWidth` | ⚠ **RED TODAY at the tight bands. This is the second, independent defect.** |
| A4 | ≥2 cards rendered before A1–A3 are believed | vacuity gate — an empty grid satisfies every assertion above |

⚠ **A2's tolerance is not a taste call.** `Card`'s base carries `has-data-[slot=card-footer]:pb-0`
(`ui/card.tsx:15`) — **zero is the designed gap.** The ≤1px absorbs sub-pixel layout only. Do not
widen it.

### The measured geometry, so nobody re-derives it

Container `max-w-5xl px-4` → 1024 − 32 = **992px**. Three columns with two `sm:gap-6` (24px) gutters
→ (992 − 48)/3 ≈ **314.7px** per card. Minus `CardFooter`'s `p-4` (32px) → ≈ **282.7px**. Minus three
`gap-2` (8px) gaps → ≈ **258.7px** for four `size="sm"` buttons, two of them carrying a `size-3.5`
icon plus `gap-1`. DERIVED — tight to impossible. The guards settle it by measuring.

### ⚠ Why three obvious assertions are ALREADY GREEN on the broken tree

This is the whole reason D-08 says *two* guards, and why each assertion must name the element it
measures.

- `Card` carries **`overflow-hidden`** (`ui/card.tsx:15`) → nothing paints outside the card, so
  document-level overflow scans pass.
- `document.scrollWidth === document.clientWidth` holds at every width → **`e2e/overflow-320.spec.ts`
  passes today**, with a `/host/listings` row in its table.
- The *card boxes* are all equal height (the grid stretches them) → a naive "all cards equal
  `offsetHeight`" assertion **also passes** against the defect.

**The controls are CLIPPED, not spilled.** `Button` carries `shrink-0` **and** `whitespace-nowrap`
(`ui/button.tsx:74`) and `CardFooter` has no `flex-wrap` on either base or call site, so the row
exceeds its content box and is cut at the card's rounded edge.

⚠ **`getBoundingClientRect`, not `offsetHeight`, for A2.** `offsetTop` is relative to the offset
parent, which for a `position: static` card in a grid is **not the card**.

⚠ **Prove the guards are not vacuous.** The project's standing rule
(`selector-contract.test.ts`, `axe.ts`'s `MIN_SCANNED_NODES`, `overflow.ts`'s
`MIN_EXAMINED_ELEMENTS`) is that an absence assertion must be driven red once. **Watch A2 and A3 fail
against the tree BEFORE the fix lands**, and record both failure messages verbatim in the plan
summary. If A2 is green before the fix, the fixture is producing no height variation and the guard is
measuring nothing.

### The fixture the state contract depends on

A2's misalignment is proportional to how much the cards' `CardContent` heights differ. **Three cards
with identical content produce identical heights and the guard is green on the broken tree.**

Height variation, cheapest first: (1) a **draft with no title** → "Untitled listing" and no
`primarySpaceType` line; (2) a **published listing with no weekly hours** → the two-line hours notice
(`loadPublishedListingsMissingHours`, `page.tsx:118-121`); (3) a **long title** wrapping to two lines
at 320px. Any two in one row is enough.

⚠ **After D-02 lands, repeating `mintDraftListing(page)` returns the SAME id** — that is D-02's whole
point, and it is a real trap for this fixture. Touch each draft (via `saveListingStep` or the wizard)
before minting the next, or seed directly.

### The exact edit, element by element

| Element | Line | Change | Rationale |

### Wrap behaviour, stated as the contract

`CardFooter`'s flex children are exactly three: `Edit`, `Availability`, and `div.ml-auto` (holding
Unlist + Delete). With `flex-wrap`:

- **When the row fits** (`lg`, `sm` with short labels): one line, Edit and Availability left,
  destructive pair pushed right by `ml-auto`. **Visually identical to today.**
- **When it does not fit** (320px, and `lg` per the arithmetic): the cluster wraps to a second line
  with `gap-2` (8px) between lines, and `ml-auto` right-aligns the destructive pair on its own line.
- **Never**: a clipped control. A3 is the assertion that says so.

### ⚠ The hit-area bar for this cluster is 24px, NOT 44px

`e2e/overflow-320.spec.ts:3144-3150` declares `touch: []` for this row with the argument written out
in full. Verbatim:

> "NONE DECLARED, and it is `/host`'s argument verbatim: `Create listing` is this page's one
> accent-filled control and it renders at the Button's DEFAULT height. The card's own
> `Edit`/`Availability`/`Unlist`/`Delete` cluster is `size="sm"`, i.e. SMALLER than the default by
> design. **Asserting 44 on any of them would be red against reviewed code**; all of them are inside
> `expectTargets`'s 24px scan."

`size="icon-sm"` is `size-7` = **28px ≥ 24px**, so the bar is cleared with room. **Importing a 44px
requirement here would contradict reviewed code.** Do not.

The spec row's `tell` is `a[href^="/host/listings/"][href$="/availability"]` — the Availability
*anchor*, which D-07 does not touch. That row keeps working unchanged.

### ⚠ Append, never prepend (D-06 / WR-04)

Phase 17's **WR-04** measured a case where hoisting a named constant to the front of `cn()` **deleted
`pb-20` outright**, leaving a state worse than the defect being fixed. tailwind-merge resolves a
conflict by deleting the **earlier** class.

Why the hazard is structurally absent from these three edits — and why the check is still cheap:

1. `Card`, `CardContent` and `CardFooter` all call `cn(<base>, className)` with the call-site string
   **last** (`ui/card.tsx:14-18`, `:76`, `:86-91`), so it is in the winning position by construction.
2. Within the call-site string, appending is what happens: `"gap-2"` → `"gap-2 mt-auto flex-wrap"`.
3. **No group conflicts exist.** `CardFooter`'s base has no `m*`/`mt-*` and no `flex-wrap`/`flex-nowrap`;
   `Card`'s base has `flex` (display group) and `flex-col` (flex-direction group), neither of which is
   tailwind-merge's `flex-wrap` group. `src/lib/utils.ts` extends **only** `theme.text`.

**Standing check the plan should carry, no new dependency:**
`cn("flex items-center rounded-b-xl border-t bg-muted/50 p-4", "gap-2 mt-auto flex-wrap")` must
contain **all of** `p-4`, `gap-2`, `mt-auto`, `flex-wrap`. If any is missing, stop.
