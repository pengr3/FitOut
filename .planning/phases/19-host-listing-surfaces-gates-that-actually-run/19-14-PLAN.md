<objective>
Stop patching the deny-list. Give the checker an instrument, and give the refusal step a permitted
shape.

Phase 19 has now run three gap-closure rounds against the same control, and each round found a NEW
single-token way to defeat it while `node scripts/verify-workflows.mjs` printed every invariant green:
`${{ env.… }}` (round 1), an appended `argv[2]` plus a step-level `continue-on-error: true` (round 2),
and a custom-shell override plus `continue-on-error: ${{ true }}` (round 3, reproduced independently by
both 19-REVIEW.md and 19-VERIFICATION.md this session).

The converged root cause is not that any one fix was wrong. It is that **every fix reacted to the one
mutation that happened to be measured, rather than stating positively what the step is permitted to look
like.** The attack surface is every YAML key GitHub Actions accepts times every value form each key
permits — an open set. Enumerating against an open set loses by construction.

The compounding cause is that **none of the tightenings left an instrument behind.** Each was proven by a
hand-applied mutation that was then reverted, so the tree holds zero standing tests for the checker half
— the half that caught nothing for a full round, three times. The script half, by contrast, has eight
build-blocking cases and has not regressed once.

Purpose: change the shape so unknown-unknowns are red by default, and leave behind a test that remembers.

Output: a new build-blocking `tests/design/workflow-invariants.test.ts` that mutates a copy of the
workflow tree and spawns the real checker against it; an allow-list on the refusal step's attribute
surface, proven against a key the checker's source never names; presence tests replacing both
value comparisons for `continue-on-error`; Invariant C's permitted-predecessor claim made true over the
full step list; and a `ci.yml` header that claims only what a conjunct beside it enforces. The invariant
total stays 48 throughout — every change here tightens a check that already exists.
</objective>
