## What plan 17.1-06 inherits — read this before writing the seam

1. **`disableNetConnect()` is REFUTED. Use an `enableNetConnect` predicate admitting every host EXCEPT
   `api.paymongo.com`.** Three measured reasons: `api.resend.com` is reached by **application** code
   (blanket-blocking it changes a shipped path inside the runs the audit uses to measure the product —
   the very thing `[17-D18]` argues against); two of the four hosts are **Next's own and intermittent**
   (a second boot produced neither `telemetry.nextjs.org` nor `registry.npmjs.org`), so **an allow-list
   built from one boot is incomplete by construction**; and a deny-of-one fails closed for PayMongo and
   open for everything else, where `disableNetConnect()` fails closed for a set nobody has enumerated.
2. **Scope the seam at the ORIGIN, never at a path.** A seam scoped to the two `linked_accounts*` paths
   would leave `[17-D27]`'s `GET /v1/checkout_sessions/{id}` live and `[17-D18]` would still be false.
   This is also why **seam C is now more expensive than when the seams were compared** — a page-level
   `?param` on `/host/payouts/refresh` cannot see an endpoint reached from a different route.
3. **⚠ Do NOT rest the inertness argument on "undici is not in the production tree."** It is —
   see `[17-D29]`. The protection is D-09's build-time `NODE_ENV` constant as `register()`'s **first**
   statement plus a **dynamic** `await import(...)` after it, pinned by an inertness test with a
   **positive control**. The guard is the protection; the dependency scope never was.
4. **⚠ Clearing an `instrumentation.ts` wedges the next dev boot.** After deleting
   `src/instrumentation.ts`, `next dev` failed with
   `Could not parse module '[project]/src/instrumentation.ts', file not found … code: 'MODULE_UNPARSABLE'`
   from a stale `.next/dev/server/instrumentation.js` chunk. **Playwright reported it only as
   *"Process from config.webServer was not able to start"*** — which reads like a port or timeout
   problem. `rm -rf .next` fixed it. 17.1-06 edits this exact file: clear `.next/` after any change to
   it before reading a red as a verdict on the seam.
5. **Placement is not the risk.** Both `src/instrumentation.ts` and root `instrumentation.ts` were
   **driven** and Next 16.2.7 loaded both (two `INSTALLED` lines, two working self-tests).

**Measured after the edit:** `npm ls undici --omit=dev` resolves it through
`better-auth@1.6.14 → vitest@4.1.8 → jsdom@29.1.1 → undici@7.27.0`, and `npm ci --omit=dev --dry-run`
removes **232** packages with `undici`, `jsdom` and `vitest` **not among them**. The cause is that
`better-auth` — a **production** dependency — declares `vitest` as an **optional peerDependency**, which
this repo satisfies from its own root copy; a peer edge from a production package is not a dev edge, so
all three carry no `dev` flag (against **264** entries of **1183** that do).

**This does not invalidate the approval, and the reason matters:** the property is **pre-existing** and
the declaration changed it in **neither** direction — `git show HEAD:package-lock.json` at `2822284`
shows `node_modules/undici` with no `dev` flag too, and the lockfile diff does not touch that entry.
`undici` was in the production tree before the pin and is in it after. The two facts the promotion
actually rests on — already on disk, artefact byte-identical — are untouched. What is retired is one
*reason* that was offered for it, and it is **appended** to the gate record rather than substituted, so
a reader meets the claim and its refutation together. Filed as `[17-D29]`; not repaired here because
re-scoping a production peer edge changes what every deploy installs and would have made the approved
one-line change unreviewable.

**2. RESP-03 is NOT marked complete.** Not in this plan's frontmatter and not touched.
`grep -c "\[ \] \*\*RESP-03" .planning/REQUIREMENTS.md` is **1**, and the file is byte-untouched.

**3. The un-instrumented verification drive sent real traffic, and the cost is named rather than
