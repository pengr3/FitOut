## The unplanned finding — a gate that was green for the wrong reason

RESEARCH *inferred*, from reading the `tell`, that the deleted `axe-sweep` row had been auditing the
wrong document. It was **driven** instead, in the intermediate state, and the result is stronger than
the inference:

```
$ npx playwright test e2e/axe-sweep.spec.ts --project=chromium --workers=1 -g "not found"

  ok 1 … › /listings/[id] · not found · court · 320px (3.1s)
  ok 2 … › /listings/[id] · not found · court · 1280px (1.7s)
  6 passed (30.5s)
```

**The row named a file that had already been deleted from disk, and passed in both viewports.** Its
`path` 404s to the ROOT boundary and its `tell` (`[data-testid="empty-state"]`) is rendered by the
root boundary too, so the row never once visited the file in its `file:` column. Only the
**disk-walked** AC#2 could see the problem, because AC#2 is the one clause that compares the table
against reality instead of against itself.

This is the phase's own key insight arriving as a measurement rather than a maxim — *the failure mode
in this codebase is never "no gate", it is "a gate that reads the wrong thing and is green"*. It is
also why deleting the row costs **zero** real coverage: the document it actually visited is still
audited, by the `root not-found` row that legitimately owns it. Both the commit message and the
`[17-D3]` block say so, so nobody later reads the row's absence as a gap.

## Decisions Made

- **Freezing beat the zero-count.** The plan required both `grep -rn "detail)/not-found" src tests e2e`
  → 0 **and** the `[17-11:` bracket byte-identical — and that bracket contains the path. Those cannot
  both hold. History won: a dated amendment that edits the sentence it amends is not an amendment.
  The count is **1**, it is the frozen bracket, and the `[17.1:` bracket appended beneath it says so.
- **Everywhere else, the path is deliberately not spelled as one string.** Applying
  `price-breakdown.tsx`'s GREP TRIPWIRE idiom to a deletion instead of an identifier keeps the count
  meaningful; the docblock carries a ⚠ note so a future reader does not "tidy" it back and silently
  break it.
- **Named the reding clauses by TITLE, not by line number,** in the docblock — writing that block
  moves every line under it, which is the pointer-invalidation hazard `mobile-booker-path.spec.ts`
  already avoids by omitting stack frames.
- **Re-pointed the `bookings/[id]` contrast to `src/app/not-found.tsx:96`, verified rather than
  assumed** — it opens its own `<main>` and the root layout supplies none, so the argument survives
  intact with a live example.
