## Sampling Rate

- **After every task commit:** `npm run build`, then `npx tsc --noEmit`, then the per-file e2e for
  whatever the task touched, `--project=chromium --workers=1`, **alone**.
- **After every plan wave:** `npm run build` → `npm test` **ALONE** → every e2e file the wave touched,
  per file, each failure compared against `e2e-baseline-reds.md`'s 10 declared rows.
- **Before `/gsd:verify-work`:** the full local set green, **plus** a green `ci` run whose
  `headSha == git rev-parse HEAD` with `gate-visual` included.
- **Max feedback latency:** ~120s (`npm run build`). See "Accepted latency exception" below.

### What CI actually samples, and the honest gap

| Instrument | What runs it | Rate | Consequence |
|---|---|---|---|
| `test:design` (~2169 vitest tests) | `npm run build` locally **and** CI `gate-db-free` on every push | **per commit** | An item-4 mistake is caught within one push. |
| `npm test` (full vitest) | CI `gate-db` on every push | **per commit** | Same. |
| `gate-visual` (`--project=visual`) | CI on every push | **per commit** | An item-1a/1b baseline mistake is caught within one push. |
| `e2e/price-parity.spec.ts` | CI `gate-price-parity` | **per commit** | The **only** e2e spec CI runs. |
| **Every other e2e spec** — `overflow-320`, `axe-sweep`, `mobile-booker-path`, `public-listing` | **nothing automatic** (D-24) | **only when a human runs the file** | ⚠ **This phase's sampling problem.** Items 1b, 2 (dev half), 3 and 4's e2e halves are sampled at "whenever somebody remembers". That is how `[17-D18]` shipped, how `[17-D3]` shipped, and how `axe-sweep` AC#2 went stale for four route files. |

**Nyquist note.** The four items' defect classes have very different natural frequencies. Item 4's
class (an inventory drifting from disk) is sampled **per commit** and is well-covered. Item 3's class
(an outbound call) is sampled at **zero** — nothing measures it today; this phase leaves behind a
standing net-connect policy in `instrumentation.ts` so the rate stops being zero (which policy —
`disableNetConnect()` or `enableNetConnect()` with a predicate — is decided by P3's census, not here). Item 1b's class (a class present but overridden)
was sampled at zero for the entire life of the constant; the band case raises it to "per manual e2e
run", and the computed-padding clause makes a future override fail on a pixel rather than survive on
luck.

## Accepted latency exception

Several tasks' automated verify commands chain `npm run build` (lint + `test:design` + `next build`,
~120s), which exceeds the 30s quick-feedback guideline. This is deliberate and matches the codebase's
established convention for route- and config-level work: `next build` is the only instrument that
catches the `.next/dev/types` staleness class that has previously presented as a false HTTP 500
(`[17-D24]`). Sampling continuity is unaffected — no three consecutive tasks lack an automated verify.
