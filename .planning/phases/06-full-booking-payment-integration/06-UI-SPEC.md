# Phase 6 — UI Design Contract

> Visual and interaction contract for the Full Booking + Payment Integration phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase adds NO new design system, component library, tokens, or fonts.** It REUSES the FitOut design system established across Phases 02–05 (shadcn `radix-nova` / neutral / lucide / Geist; the locked 8-point spacing, 4-size/2-weight typography, and the 60/30/10 coral-accent color contract). The job here is to lock the phase-specific **interaction + copy** contracts for the request-to-book fork and confirm consistency — NOT to invent a visual language.
>
> **Phase surfaces (from 06-CONTEXT.md D-61..D-66 + 06-RESEARCH.md; ROADMAP Phase-6 SC #2/#3 corrected authorize→capture ⇒ pay-on-approval):**
>
> Phase 6 forks booking into two modes and adds the host-side request-approval surface. The NET-NEW / changed UI surface is:
>
> 1. **`/host/requests` (NEW)** — an owner-scoped `(host)` RSC inbox listing **pending** booking requests (booker, space, requested window, quoted price, an **expiry countdown**) with **Approve / Decline** server actions. Clones the visual + interaction language of `/host/earnings` (05-UI-SPEC): calm, neutral, table-on-desktop / cards-on-mobile, **no coral**. (D-65.)
> 2. **Host pending-count nudge (MODIFIED)** — a count indicator in the `(host)` dashboard action row **and** a `(host)` header nav link ("Requests" + a count badge). Mirrors the existing neutral `Earnings` nav pattern. (D-65.)
> 3. **Listing-editor booking-mode toggle (CONFIRMED / MODIFIED)** — the instant-vs-request toggle already exists at Step 5 of the listing editor wizard (`.../[id]/edit/wizard.tsx:666`). Phase 6 makes it **editable while hosting** (it already is, via the editor) and clarifies its copy with the D-61 "new-bookings-only" rule. Default selection flips to **Instant book** (D-62). (D-61.)
> 4. **`/bookings/[id]` new states (MODIFIED)** — the confirmation page must render the new **`requested`** ("request sent — awaiting host") and **`approved`** ("approved — pay now", carrying the coral pay CTA + a payment-window countdown) states, alongside the existing `confirmed` / pending-interstitial / reversed states. (BOOK-06 / PAY-05.)
> 5. **Expiry countdown (NEW component)** — a host-inbox + booker-approved countdown at an **HOURS scale** (24h SLA / 24h payment window), mirroring the minutes-scale `hold-countdown.tsx` from Phase 4 exactly (timer discipline, a11y, DB-clock-is-authority).
> 6. **Five lifecycle emails (NEW)** — booking confirmed · request received · request approved→pay-now · request declined/expired · host new-request — thin plain-HTML sends over the existing `src/lib/email.ts`. Copywriting contract below (subject + key body line + CTA), consistent with the auth email tone (plain, warm, no jargon, thin HTML — NOT React Email).
>
> **Out of scope for this contract (later phases):** the PayMongo-hosted checkout page (external, unchanged from Phase 5 — pay-on-approval reuses it verbatim); booker-facing cancel/refund flow + refund-% matrix (Phase 7); My-Bookings management lists both sides (Phase 7); the hardened email layer — retry/observability/queue/reminders (Phase 7); card authorize/hold UX (not built, D-63); group RSVP (Phase 8). No new payment UI is designed — pay-on-approval is "the Phase-5 checkout gated behind host approval."

Reference the SLA / payment window by their config values (`APPROVAL_SLA_HOURS`, `APPROVAL_PAYMENT_WINDOW_HOURS` — default 24h) as **hours**, not internal names.

## Lifecycle email contract (D-66 · BOOK-06 · Pattern 5)

Five thin **plain-HTML** sends extending `src/lib/email.ts` (mirror `sendVerificationEmail`/`sendResetPassword`). **NOT React Email** (not installed; keep the send thin). `escapeHtml` on **every** interpolated field (space title, booker name, pay link — email.ts:25 pattern). **Fire-and-forget** (`void send…`) so a Resend failure can never reject a webhook 200 ACK or block a server action. Dev fallback logs the body; prod withholds the link if the key is missing (existing behavior — do not change). Tone = the auth emails: plain, warm, sentence case, no jargon; **always name the venue timezone** on times; amounts are the server-frozen `{₱total}`.

| # | Email | Recipient | Trigger | Subject | Key body line | CTA (link) |
|---|-------|-----------|---------|---------|---------------|------------|
| 1 | **Booking confirmed** | Booker | Webhook `payment.paid`, after a successful confirm (≥1 row) — covers **instant AND pay-on-approval** | `Your FitOut booking is confirmed — {space}` | `You're booked at {space} on {date}, {time} ({City} time). Booking reference {FIT-XXXXXXXX}.` | `View your booking` → `/bookings/{id}` |
| 2 | **Request received** | Booker | `placeHold` request branch, after minting `requested` | `We sent your request — {space}` | `Your request to book {space} on {date}, {time} ({City} time) is with the host. You'll hear back within {SLA_HOURS} hours. You haven't been charged — you'll only pay if the host approves.` | `View your request` → `/bookings/{id}` |
| 3 | **Request approved → pay now** | Booker | `approveRequest`, after the atomic approve | `Approved — pay to confirm {space}` | `Good news — the host approved your booking for {date}, {time} ({City} time). Pay {₱total} within {PAYMENT_WINDOW_HOURS} hours to lock it in.` | `Pay now` → `/listings/{listingId}/book?hold={id}` |
| 4 | **Request declined / expired** | Booker | `declineRequest` AND the SLA auto-decline sweep | `Your request for {space} wasn't available` | declined → `Unfortunately the host couldn't take your booking for {date}, {time} ({City} time). You haven't been charged.` · expired → `Your request for {date}, {time} ({City} time) expired before the host responded. You haven't been charged.` | `Find another space` → `/` |

- The `approved`→`cancelled` payment-window auto-release (booker didn't pay) is **not** one of the five required sends (D-66 enumerates exactly five). Fold it under #4 ("expired") copy or leave it silent — the booker chose not to pay. Planner's call; either is contract-compliant.
- Keep the HTML minimal (a heading line, the body line, one anchor CTA). No design-heavy templates — hardening/branding is Phase 7 (WR-04).

## Expiry countdown contract (NEW component — mirrors `hold-countdown.tsx` at HOURS scale)

A `RequestCountdown` client component (`src/components/booking/request-countdown.tsx` or `components/host/`), a **direct structural clone** of `hold-countdown.tsx` retuned from a 15-minute to a 24-hour horizon.

| Property | Contract |
|----------|----------|
| Props | `expiresAt: string | Date`, optional `onExpire?: () => void` (identical to `HoldCountdown`) |
| Display format | Hours scale: `Expires in {N}h {M}m` (host inbox) / `Pay within {N}h {M}m` (booker approved state). Under 1 hour: drop the hours → `{M}m` (or `Under 1h`). Muted `--muted-foreground` + `Clock` icon; digits `tabular-nums`. |
| Tick interval | **Per-minute** (`setInterval` 60s), NOT per-second — the horizon is 24h; per-second ticking is wasteful and jittery at this scale. |
| Final-window emphasis | Optional `--destructive` numerals in the **final hour** (analogous to `HoldCountdown`'s final-60s destructive numerals). Icon + label persist — never color-only. |
| Timer discipline | Copy `HoldCountdown` exactly: the `setInterval` callback is the ONLY setState site (dodges `react-hooks/set-state-in-effect`); `onExpire` read through a ref synced in its own effect; `suppressHydrationWarning` on the digits; `role="timer"`, `aria-live="off"` on the digits. |
| a11y announcements | Announce ONLY at a threshold (e.g. "One hour left") and on expiry (`aria-live="polite"` sr-only span) — never per-minute spam. |
| Authority | **Display cue only.** The DB `now()` vs `expires_at` is the sole authority (the atomic `AND expires_at > now()` guard in `approveRequest` / the webhook / the sweep). A host clicking `Approve` one second after the SLA is refused server-side regardless of what the countdown shows. On reaching 0, flip to an "Expired" label / fire `onExpire`; the row is removed on the next `revalidatePath` — it does NOT silently vanish. |

## Screen / State Contract

Every interactive surface defines loading / empty / error / active states.

| Screen | Key states the executor must implement |
|--------|----------------------------------------|
| **Host requests inbox (`/host/requests`)** | **loading** (skeleton rows) · **empty** (`No requests right now`) · **populated** (rows: space · when · booker · guest-pays · `Expires in {Nh Mm}` countdown · Approve/Decline) · **approving** (Approve disabled → `Approving…`) · **decline-confirm** (dialog open) · **declining** (dialog confirm disabled) · **already-actioned/lapsed race** (calm "no longer pending"; row refreshes away) · **load error** (retry) · owner-scoped (never another host's requests) |
| **Confirmation page (`/bookings/[id]`)** | **`requested`** (Request sent — awaiting host; no pay CTA) · **`approved`** (Your request was approved; `Approved` badge + payment-window countdown + coral `Pay now`) · **`confirmed`** (unchanged success UI) · **pending-payment interstitial** (`?paid=1` + `pending`; unchanged) · **reversed** (D-58 `PaymentReversedState`; unchanged) · **`declined`/`expired`** (optional calm landing) · **not owner / not found** (owner-gated 404, unchanged) |
| **Listing-editor Step 5 (mode toggle)** | instant selected (default) · request selected · both with the D-61 "new bookings only" description. Unchanged structure. |
| **`(host)` header + dashboard nudge** | count = 0 (link/button, no badge) · count > 0 (neutral count badge). Reflects `revalidatePath` freshness. |
| **Booker reserve / `Confirm & pay`** | Unchanged from Phase 5 — the pay-on-approval booker lands here from `Pay now`; the hold is `approved` (not `pending`) but the page/CTA behave identically. |

**Visual hierarchy / focal point (locked, per surface):**
- **Host requests inbox:** the **request rows are the working area**; each row's focal action is `Approve` (solid neutral). The `Expires in …` countdown is a quiet urgency cue (muted, per-minute). **No coral** — this is a calm host workflow surface, not a conversion funnel (mirrors `/host/earnings`).
- **Confirmation — `requested`:** the **`Request sent` reassurance is the whole focal point** — calm, single-purpose, no competing action ("you'll hear back / you haven't been charged").
- **Confirmation — `approved`:** the **coral `Pay now` CTA is the terminal focal point**, with the payment-window countdown as the adjacent urgency cue; the `Approved` badge reinforces the good news without stealing the green reserved for `confirmed`.

**Interaction rules (locked):**
- **The webhook is the sole confirm authority (D-57)** — request-to-book confirms through the SAME `payment.paid` handler after pay-on-approval; the browser never fabricates a confirmed state. `?paid=1` is never proof.
- **Approve/Decline are server-authoritative + SLA-guarded** — the atomic `AND expires_at > now()` (DB clock) guard is the authority; the client countdown is a display cue. A host acting one second past the SLA is refused → calm "no longer pending".
- **Owner-gate everything (Security V4)** — the `(host)` route group is NOT the gate; approve/decline and the inbox read re-verify `listing.hostId === session.userId`. Missing vs cross-host → the same calm denial.
- **Nothing is charged at request time (D-63)** — booker copy on the `requested` state says "you haven't been charged / you'll only pay if the host approves". No commission line ever leaks to the booker (D-50).
- **Holding/lifecycle states are calm, expected states** — `requested`/`approved`/`declined`/`expired` are never red, never `--success` (until `confirmed`). Only the inherited D-58 reversal edge uses the destructive `Alert`/`PaymentReversedState`.
- **Every displayed time names the venue timezone** (SC#2), on the inbox rows, the new confirmation states, and every lifecycle email.

**Accessibility (non-negotiable):**
- Status badges (`requested`/`approved`/`declined`) are **icon + text, never color-only** (they're neutral and hue-indistinguishable).
- The `RequestCountdown` is `role="timer"`, `aria-live="off"` on digits; announce only at the threshold + expiry (`aria-live="polite"`), never per-tick.
- The decline confirm dialog traps focus, is keyboard-dismissable, and returns focus to the trigger; `Approve`/`Decline` are keyboard-operable with ≥44px hit area.
- The inbox `table` uses real `<th scope="col">`; the mobile card fallback keeps label↔value pairs associated (mirror `PayoutRow`).
- The pending-count badge exposes its meaning to assistive tech (e.g. `aria-label="{n} requests to review"`), not the numeral alone.
- Coral `Pay now` contrast (`--brand` + `--brand-foreground`) ≥4.5:1 (verified Phase 2); `--success` (Confirmed) never the sole signal (icon + text).
