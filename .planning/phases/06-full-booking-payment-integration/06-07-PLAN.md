| host client → approve/decline action | The host may act on any request id; the action must re-verify ownership (IDOR). |
| host client countdown → approve | The DB clock is the SLA authority; a lapsed approve must be refused server-side. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-19 | Elevation | approve/decline IDOR | mitigate | Load the request joined to its listing and verify listing.hostId === session.user.id BEFORE any UPDATE; missing vs cross-host return the SAME calm denial (leak nothing). The (host) route group is NOT the gate (Security V4). |
| T-06-20 | Tampering | approve a lapsed request | mitigate | The atomic UPDATE carries `AND status='requested' AND expires_at > now()` (DB clock) — a host acting one second past the SLA claims 0 rows → calm "no longer pending", never a confirm. |
| T-06-21 | Tampering | double-action / replay | mitigate | Every UPDATE is status-scoped (`AND status='requested'`) so a second approve/decline is a 0-row no-op; the approve is rate-limited + audited (WR-06). |
| T-06-22 | Denial of Service | email send blocking the action | mitigate | sendRequestApproved/Declined are fire-and-forget (void); a Resend failure never blocks or fails the action. |
