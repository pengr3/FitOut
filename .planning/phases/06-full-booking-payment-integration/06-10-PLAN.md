<objective>
Close **G-06-01 (CRITICAL)** from `06-VERIFICATION.md`: the webhook signature parser rejects every real PayMongo signature, blocking the payment-confirm authority (D-57) shared by instant-book AND pay-on-approval.

`parseSignature` (route.ts:91) requires all three of `t`/`te`/`li` to be non-empty. Real PayMongo signs `te` in TEST mode (empty `li`) and `li` in LIVE mode (empty `te`) — never both. So every real signature → `parseSignature` returns `null` → the handler returns `400 Invalid signature` before confirming. Proven live in the 06-09 UAT: a real paid PayMongo test checkout never confirmed the booking; the recomputed HMAC matched the `te` digest exactly; manual replay to the correct endpoint returned 400 (parser, not network).

The fix is a **one-predicate widening** plus a **tolerant return**, and a **regression test with the real single-mode signature shape** — which is the fixture gap that let the bug through (existing fixtures populate BOTH `te` and `li`).

Purpose: Re-enable PAY-05 (payment confirm), BOOK-06 (confirmed email), and BOOK-04's confirm — the core-value "a real booking" path.
Output: A widened `parseSignature`, a single-mode test signer, and regression cases proving a real te-only / li-only signature confirms a booking.

**SURGICAL SCOPE:** This plan modifies ONLY the signature parser and its regression tests. It does NOT re-touch the request-lifecycle code (request/approve/decline/inbox/countdown/booker states) already VERIFIED live in 06-09. `verifySignature`, `handleGoneSlot` (D-58), `handleRefund`, the `paymongo_event` dedupe, and the confirm UPDATE WHERE stay exactly as Phase 5 / 06-05 built them.

```typescript
/** Parse `t=<ts>,te=<testSig>,li=<liveSig>` into its parts; a missing header or any missing part → null. */
function parseSignature(header: string | null): SigParts | null {
  if (!header) return null;
  const parts: Record<string, string> = {};
  for (const seg of header.split(",")) {
    const idx = seg.indexOf("=");
    if (idx === -1) return null;
    parts[seg.slice(0, idx).trim()] = seg.slice(idx + 1).trim();
  }
  if (!parts.t || !parts.te || !parts.li) return null;   // ← line 91: rejects real te-XOR-li signatures
  return { t: parts.t, te: parts.te, li: parts.li };
}
```

CURRENT verifySignature (line ~100-110 — MUST stay unchanged; it already skips empty candidates):
```typescript
function verifySignature(rawBody: string, sig: SigParts, secret: string): boolean {
  const expected = createHmac("sha256", secret).update(`${sig.t}.${rawBody}`).digest("hex");
  const expectedBuf = Buffer.from(expected, "utf8");           // length 64 (hex)
  for (const candidate of [sig.te, sig.li]) {
    const candBuf = Buffer.from(candidate, "utf8");            // "" → length 0 → never length-matches
    if (candBuf.length === expectedBuf.length && timingSafeEqual(candBuf, expectedBuf)) {
      return true;
    }
  }
  return false;
}
```
