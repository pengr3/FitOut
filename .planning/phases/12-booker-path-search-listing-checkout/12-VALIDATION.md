## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework (unit/integration)** | Vitest 4.1.8 — `vitest.config.ts` (env `node`, jsdom per-file via `// @vitest-environment jsdom`). `globalSetup: tests/global-setup.ts` + `setupFiles: tests/setup.ts` force `fitout_test`, per-file schema. **Requires Docker + Postgres.** |
| **Framework (design gate)** | Vitest 4.1.8 — `vitest.design.config.ts`, owns `tests/design/**` only. **No `globalSetup`, no `setupFiles` — deliberately DB-free** (runs inside `next build`). Never add either key. |
| **Framework (e2e/a11y/viewport/rendering)** | Playwright 1.60.0 — `playwright.config.ts`, project `chromium`, `testMatch: "e2e/*.spec.ts"`, `webServer: npm run dev` on :3000. |
| **Framework (visual regression)** | Playwright project `visual`, `testMatch: "e2e/visual/**/*.spec.ts"`. **Linux-only** (`RUN_VISUAL_PROJECT = process.platform === "linux"`), `updateSnapshots: "none"` unconditional. **Cannot be minted on this Windows box — CI dispatch only.** |
| **Quick run command** | `npm run test:design` (DB-free, seconds) — the per-commit sampler |
| **Targeted unit run** | `npx vitest run tests/<area>` (needs Docker; `npm run db:test:setup` once) |
| **Targeted e2e run** | `npx playwright test e2e/<spec>.spec.ts --project=chromium` |
| **Full suite command** | `npm test && npm run test:design && npx playwright test --project=chromium` |
| **Build gate** | `npm run build` = `lint && test:design && next build`. A raw hex, an arbitrary type size, an undeclared `data-testid`, a literal box class in a skeleton, or a `server-only` boundary violation fails the build today. |
| **Estimated runtime** | design gate ~seconds · full Vitest ~minutes (Docker) · Playwright chromium ~minutes (dev server + DB) |

---

## Sampling Rate

- **After every task commit:** `npm run test:design` (DB-free, seconds — catches undeclared testids, literal box classes, contrast, motion, error-leak, focus recipe) **plus** the one or two Vitest files the task touched.
- **After every plan wave:** `npm test` (full Vitest, needs Docker) + `npm run test:design` + `npx playwright test --project=chromium` (needs dev server + DB).
- **Before `/gsd:verify-work`:** `npm run build` green, full Vitest green, full Playwright `chromium` green, **and visual baselines regenerated by the Linux CI dispatch job** — never locally (`updateSnapshots: "none"` is unconditional; an illegal `*-win32.png` can never be committed).
- **Max feedback latency:** design gate < 30s per commit; wave gate bounded by the Playwright run.

## Manual-Only Verifications

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| The route "reads as one designed product" | Phase goal / D-59 | A judgement about a sequence of screens. Automation proves ordering, tokens, geometry — not effortlessness. | Walk search → listing → checkout on a phone and a desktop; note any seam that reads as a different product. |
| Reduced-motion actually silences a real Radix animation | BFLOW-05 | `tests/design/motion-budget.test.ts` header states it: only a real paint settles it. | Enable OS reduce-motion; change calendar month; confirm no perceptible transition. |
| A screen reader announces **once**, in the intended order | GATE-03 / STATE-07 | The automated proof is a text-change count on a DOM node, not what a reader utters. | NVDA/VoiceOver: trigger a collision; confirm the notice is read before the refreshed grid and the moved focus is not double-read. |
| Full-screen lightbox on a real touch device | BFLOW-03 | Swipe-absence-by-design vs. broken is indistinguishable to Playwright. | On a phone: open lightbox, confirm 44px chrome is reachable one-handed and paging works via controls. |
| The PayMongo redirect tail | BFLOW-07 | `e2e/search-and-book.spec.ts` records that `Confirm & pay` opens a hosted checkout — un-automatable. | Test-mode booking; confirm the at-rest line naming PayMongo matches where you land. |
| Visual baseline **judgement** | D-58 / GATE-01 | The gate proves pixels did not change; not that the new pixels are right. Theme smoke proves only that themes differ. | Review the CI-minted baselines by eye in both themes. |
