THE SHEET (D-48): `ResponsiveDialog`, `data-testid="responsive-dialog"`, already declared and already this
app's one overlay primitive. Below `sm:` it is the bottom sheet; at `sm:` and up it is the vendored centred
dialog, byte-unchanged. NO GRAB HANDLE — drag-to-dismiss is out of scope and a handle implying it is an
affordance that lies. Dismissal is the visible close button, the overlay click, and Escape. The close
button's accessible name is `Close booking`, NOT the vendored `Close` — the lightbox already took
`Close photos`, and two controls both named `Close` are indistinguishable in a screen reader's element list.

  contents, top to bottom: title · month nav · the calendar · the day's slot chips · the run/fee/Total
  breakdown · a PINNED action bar carrying `Book · {total}` and the hold promise.

  The pinned bar is `sticky bottom-0` INSIDE the scroll container, `bg-card`, `border-t`, so it is
  reachable no matter how far the booker has scrolled inside the sheet. That is the whole reason the sheet
  works at 320x568, where its content does not fit.

THE THREE HARD CONDITIONS, all falsifiable:
  1. `BookingPanel` owns ZERO state. Selection lives in `BookingSelectionProvider`; the day's availability
     read is the single hoisted hook from plan 12-02. Two views, one state, one fetch.
     ASSERT: selecting a day at 375px and at 1280px issues exactly ONE availability request each.
  2. Exactly one of anything a user can reach.
     ASSERT: `getByRole("button", { name: /^Book/ })` resolves to exactly 1 at 375px AND at 1280px;
     `getByRole("dialog")` resolves to 0 until the bar is tapped.
     ⚠ THIS MUST USE ROLE QUERIES, NEVER `getByTestId`. Playwright's role queries exclude elements hidden
     from the accessibility tree, so the `max-lg:hidden` copy will not satisfy `=== 1` by accident — a
     testid query WOULD find it, and the assertion would be measuring nothing.
  3. Exactly one hook per surface: `rail-price-total` from the rail placement, `sheet-price-total` from
     the sheet placement, never both from one.

REJECTED, recorded so nobody re-litigates: a `useMediaQuery` fork (breaks SSR, doubles the VR surface,
duplicates content for screen readers); a third `ResponsiveDialog` presentation rendering inline at `lg:`
(Radix `DialogContent` portals unconditionally, so this needs the same JS media query wearing a pattern's
name); and shipping the calendar only in the sheet at every width (it deletes the desktop layout BFLOW-02
requires).

`shadow-sticky` gets its FIRST call site here; the checkout bar is the second (plan 12-11), which is where
the "exactly 2 call sites, zero on any header" assertion lands. Its `-1px` y-offset is an UPWARD cast and
it must never go on a top header.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| duplicated DOM <-> assistive technology | Two mounted copies of one control is two things a screen-reader user can activate and one of them is a ghost |
| client bar <-> server price authority | A bar that computes its own amount is a second source of truth on the money path |
| sticky overlay <-> page content | A fixed bottom bar without page clearance makes the last row permanently unreachable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-10-DUPCONTROL | Denial of service (accessibility) | two placements | mitigate | `hidden` removes the inactive copy from the accessibility tree; asserted with ROLE queries (`Book` === 1 at 375 and 1280), which a testid query would silently satisfy |
| T-12-10-BARPRICE | Tampering | `booking-sticky-bar.tsx` | mitigate | The bar receives pre-formatted figures from the same `AllInTable` lookup; byte-equality with the sheet's `Total` is asserted, and a locally computed figure is watched failing at the rounding edge |
| T-12-10-DOUBLEHOLD | Tampering | the bar's selection action | mitigate | The bar submits through the SAME action `BookCta` uses; no second submission path, so the checkout lease and the GiST `EXCLUDE` remain the only authorities |
| T-12-10-DOUBLEFETCH | Denial of service | availability reads | mitigate | `BookingPanel` owns zero state and the day read is the single hoisted hook; a request counter asserts exactly one per day selection at both widths |
| T-12-10-CLOSEAMBIG | Denial of service (accessibility) | two close buttons | mitigate | `Close booking` here and `Close photos` on the lightbox; both accessible names asserted, so an element list distinguishes them |
| T-12-10-CLEARANCE | Denial of service | page bottom | mitigate | `STICKY_BAR_CLEARANCE` on the page container, and the sheet's pinned bar asserted reachable after scrolling to the bottom at 320x568 |
| T-12-10-SC | Tampering | npm/registry installs | mitigate | Zero packages; no `sheet` block, no gesture library, no `useMediaQuery`. `git diff --stat package.json` must be empty and `sheet-absent.test.ts` must pass |
