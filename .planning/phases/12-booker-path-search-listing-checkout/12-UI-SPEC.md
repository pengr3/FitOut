# Phase 12 — UI Design Contract

> Visual and interaction contract for the booker path. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## What this document is, and what it deliberately does not touch

**Phases 10 and 11 shipped a complete, gated design system and a pattern layer.** Colour, type, focus,
status tones, elevation, z-index, motion, the 40-row contrast inventory, the three card patterns, the four
state families, the app shell, the mobile-overlay primitive and the three typed inventories
(`contrast-pairs.ts`, `measurements.ts`, `selector-contract.ts`) are **LOCKED**. `npm run build` =
`lint && test:design && next build`, so a raw hex, an arbitrary type size, an undeclared `data-testid` or a
skeleton with a literal box class already fails the build today.

**This document re-decides none of that.** Everything below either *consumes* an existing token, pattern or
recipe, or names precisely where a declared inventory must be **EXTENDED** — and an extension is always
"add a measured row to the declared inventory", never "invent a value at the call site."

Read `10-UI-SPEC.md` for the foundation and `11-UI-SPEC.md` for the shell, states and patterns. This file
adds five things on top of them:

| # | Adds | Requirements |
|---|------|--------------|
| 1 | **The search surface** — the rate-only card on a fixed grid, and the named relaxation band | BFLOW-01, STATE-03 |
| 2 | **The listing surface** — the conventional order, the key-facts strip, the mosaic + lightbox, the 44px calendar | BFLOW-02, BFLOW-03, BFLOW-05 |
| 3 | **Price as one fact** — one `PriceBreakdown` on rail and checkout, and the fee's own explanation | BFLOW-04 |
| 4 | **The mobile path and the handoff** — sticky bar → sheet → single-column checkout → named redirect | RESP-02, BFLOW-06, BFLOW-07, SHELL-03 |
| 5 | **The two dead ends and the announcement rule** — zero results, the mid-selection collision, one live region per outcome | STATE-03, STATE-07, GATE-03 |

**The standard, restated because it shaped every criterion below.** Phase 11's roadmap entry says *"a gate
that has silently never failed is worse than no gate."* Phase 12 adds the one this phase's own CONTEXT
names: **D-59 — when two options both satisfy a requirement, choose the one that costs the booker less.**
Every claim here is written to be observable and falsifiable — a measured dimension, a named token, a
required attribute, a string equality, a count.

**The colour authority remains `tests/design/contrast.test.ts` (D-12).** Ratios computed in this session are
stated with their method; if the gate disagrees, the gate wins and this file is corrected.

**Sketch winners are LOCKED input, not proposals.** 002-A (banner + undo), 003-B (bordered strip), 004-A
(same component), 005-A (one sheet), 006-A (in-place notice). Their rejected alternatives are preserved in
each sketch's README and are not re-litigated here.

**GATE-06 binds.** Zero schema migrations. `drizzle/` stays at `0025`. A migration proposed in any plan
under this spec is a scope alarm to be raised explicitly, never absorbed.

## Spacing Scale

**Inherited unchanged from Phase 10 (D-05, global — identical in both themes).** The declared legal set:
4 (`*-1`) · 8 (`*-2`) · 12 (`*-3`) · 16 (`*-4`) · 24 (`*-6`) · 32 (`*-8`) · 48 (`*-12`) · 64 (`*-16`).

Phase 11's four declared exceptions (56px header, 176px auth slot, 80px sticky offset, 85dvh sheet bound)
carry forward unchanged.

### Phase 12 declares five exceptions, each on the 4px grid and each with the reason it exists

| Value | Class | Where | Why it is not a ladder step |
|-------|-------|-------|------------------------------|
| **44px** | `h-11` / `size-11` / `min-h-11` / `[--cell-size:--spacing(11)]` | Calendar day cells, slot chips, the two sticky bars' actions, the fee popover trigger, lightbox nav buttons, the `Show all N photos` button | 4 × 11. The WCAG 2.5.5 target-size figure, already on the grid, already the app's declared `size="touch"` (D-22) and already `NOTIFICATION_BELL_BOX`. This phase is where it stops being opt-in on the booker path. |
| **80px** | `pb-20` | Bottom padding on any page that renders a sticky bottom bar | 64 (bar) + 16 (gap) — the **same arithmetic as `lg:top-20`**, from the other end of the viewport. Without it the last row of content sits under the bar and the page has a permanently unreachable line. |
| **20px** | `gap-5` — **REMOVED** | `CardGridSkeleton` | See below: `gap-5` is retired, not declared. |
| **96px** | `min-w-24` | The checkout header's countdown box | Reuses `AUTH_SLOT_CONTROL`'s 96px rather than inventing a second reservation width. It is a *reservation*, not a design value: `14:52` and `0:09` are different character counts, and a right-anchored box with a floor is what stops the header reflowing once per session. |
| **~41px** | fluid | A calendar day cell's **width** below a 344px content box | **A measured consequence, declared rather than hidden.** Seven 44px cells is 308px; at the 320px floor with `px-4` the content box is 288px, so a fixed 44px grid overflows. The cell's **height stays 44px at every width**; its width is `1fr` and falls to ~41px between 320px and ~376px viewport. 41 > the WCAG 2.5.8 AA 24px bar with room to spare, and the alternative — a horizontally scrolling month grid — fails both the responsive and the keyboard gate. |

### The ±4px grid gutter (`[11-17]` / 12-CONTEXT D-57) is resolved here, mechanically

`ResultsGrid` ships `gap-4 lg:gap-6`; `CardGridSkeleton` ships `gap-5`. That is ±4px per gutter **in
opposite directions either side of `lg`**, and it is invisible to jsdom (D-131).

**Resolution: one constant, imported by both.** `RESULT_GRID_GAP = "gap-4 sm:gap-6"` in `measurements.ts`.

- Both values (16px, 24px) are declared ladder steps. `gap-5` (20px) is not, and it is retired.
- The `lg:` step disappears. A third gutter value at a third breakpoint is a number nobody can justify, and
  the grid already changes column count at `sm:` and `lg:`.
- The two sides **cannot** disagree any more, because there is only one string. That is the same argument
  `measurements.ts`'s own header makes for existing constants.
- `/host/listings` (Phase 14) adopts the constant when it adopts the skeleton. It does not get a second one.

### New measurement constants (all must live in `src/lib/design/measurements.ts`)

A skeleton that hardcodes its own box passes review and drifts the first time the real content changes;
`tests/design/skeleton-measurements.test.ts` already bans literals in `patterns/*skeleton*.tsx`.

| Constant | Value | Derivation |
|---|---|---|
| `RESULT_GRID_GAP` | `"gap-4 sm:gap-6"` | Above. The one gutter for the result grid and its skeleton. |
| `CALENDAR_CELL` | `"[--cell-size:--spacing(11)]"` | 44px. `ui/calendar.tsx:34` ships `--spacing(7)` = **28px** — the actual BFLOW-05 debt, measured. Overriding the variable at the call site re-sizes the day button, the nav buttons, the weekday row and the caption in one edit, because all four read it. |
| `SLOT_CHIP_BOX` | `"h-11 w-20"` | The shipped slot skeleton (`availability-calendar.tsx:265-268`) and the real chip's minimum (`slot-picker` chips are `min-h-11 min-w-20`). One source, so the shimmer and the chips are the same box. |
| `STICKY_BAR_HEIGHT` | `"h-16"` | 64px — a declared ladder step, and the same height as the desktop header, so the app's two fixed edges match. A 44px action centred inside it needs no declared vertical padding at all. |
| `STICKY_BAR_CLEARANCE` | `"pb-20"` | 80px = bar + 16px gap. |
| `HOLD_COUNTDOWN_BOX` | `"h-8 min-w-24"` | 32 × 96px. Height matches the header's control step; width reuses `AUTH_SLOT_CONTROL`. |
| `MOSAIC_ASPECT` | `"aspect-[16/9]"` | The gallery's outer box at every photo count, so the listing's `loading.tsx` skeleton and the real mosaic occupy the same height. |

## Typography

**Inherited unchanged.** Four named roles (`text-display` / `text-heading` / `text-body` / `text-label`),
per-theme, pinned by `tests/design/type-scale.test.ts`. Tailwind's re-declared `text-xs…2xl` ladder is legal
and is not a fifth role. Arbitrary `text-[NNpx]` is banned by ESLint **and** a Vitest gate.

| Role | court | grove | Phase 12 uses it for |
|------|-------|-------|----------------------|
| Display | 28 / 1.15 / 600 / -0.02em | 34 / 1.20 / 700 / -0.005em | `/` `<h1>` at `sm:` and up (shipped) |
| Heading | 20 / 1.30 / 600 / -0.01em | 24 / 1.30 / 700 / 0 | Every listing-page section `<h2>`; the checkout `<h1>`; `PanelCard` titles |
| Body | 16 / 1.50 / 400 / 0 | 17 / 1.60 / 400 / 0 | Listing description; key-fact **values**; the collision notice's first line; the relaxation band's first line |
| Label | 14 / 1.43 / 400 / 0 | 15 / 1.50 / 400 / 0 | Key-fact **labels**; every muted meta line; both notices' second lines; the tz note |

### Four type rules this phase adds

1. **Every money figure carries `tabular-nums`, and so does any label that embeds one.** Already the shipped
   convention and already GATE-05's visual half; restated because this phase renders money in eight new
   places (both sticky bars, the sheet's pinned action, the rail breakdown, the disclosure trigger, the
   popover row, the band, the card). `price-breakdown.tsx:140` is the model — the *label* carries it too,
   because `runLabel` embeds a formatted rate.

2. **The Total is `text-xl font-semibold tabular-nums` on both surfaces, byte-identical.** This is the shipped
   value at `price-breakdown.tsx:209` and it is the single most load-bearing typographic fact in the phase:
   BFLOW-04's recognisability claim is *visual*, so a weight or size that differs between rail and checkout
   is the requirement failing, not a nuance. **Falsifiable:** the rail's total element and the checkout's
   total element resolve to the same computed `font-size`, `font-weight` and `font-variant-numeric`, in both
   themes.

3. **The rail's rate headline disappears once a window is selected (D-41).** With the breakdown in the rail,
   `₱714/hr` (the **all-in** headline, D-75) and `₱680/hr × 2 hours` (the run line, built from the host's raw
   **space** rate) would sit ~60px apart wearing the same `/hr` suffix. Both are correct; they are not the
   same rate. The headline persists in the **no-selection** state — a deep-linked booker must still see a
   price — and is removed the moment a selection exists. *Rejected: labelling the run line "Space rate",
   which introduces a term the booker meets nowhere else, on the panel where money commits.*

4. **No `<p className="font-semibold">` standing in for a heading.** Phase 11 fixed this in the empty states;
   the key-facts strip, the host block and both notices are new surfaces where the same shortcut is available.
   The strip's cells are `<dt>`/`<dd>` inside a `<dl>` (they are literally a definition list); both notices'
   first lines are `<p>` inside a `role="status"` region and are **not** headings, because a live region that
   announces a sentence should not also inject a heading into the document outline mid-flow.

## The Search Surface (BFLOW-01, STATE-03)

### The card — what changes is nothing, and that is the finding

`search-result-card.tsx` + `patterns/result-card.tsx` **already satisfy BFLOW-01 in full**: photo first via
`AspectRatio ratio={4/3}`, title and price on one optical column (the pattern renders `price` last), the
price rendered as an **all-in rate** pre-formatted server-side, and `Service fee included` welded into the
same node so nothing can be inserted between them.

**D-37 stands unchanged: the card carries the rate and never a computed window total**, even when a date and
time were searched. SC#1's *"same unit checkout will charge"* is read as the **all-in unit**. The reason for
refusing a total is arithmetic, not taste: 5% of an hourly rate × N hours can differ by one centavo from 5%
of (rate × N hours), so a promised total is a promise D-75's "never goes up" cannot keep at the rounding
edge. The rule is already written into that file's header at `:141-144` and it stays.

**The one card-level change is the grid gutter** (`RESULT_GRID_GAP`, above). Everything else on the tile is
preserved byte-for-byte, including the meta order pinned by `tests/search/search-card-open.test.tsx` case (9).

### The relaxation band (STATE-03 · D-52, D-53 · sketch 002-A)

**What ships today and is replaced:** `(public)/page.tsx:82-98` drops radius, category, priceMax, date, start
**and** end in one broadened query and renders the result under an unlabelled *"You might also like"* divider.
That is precisely the gap STATE-03 names — six constraints vanish and the page says which one gave: none.

**The ladder decides WHAT is relaxed (D-52). The band decides HOW it is told (D-53).**

**The ladder — one constraint at a time, in a fixed order, stopping at the first rung that returns rows:**

| Rung | Relaxes | Band's phrasing for the changed constraint |
|---|---|---|
| 1 | radius → the next step up, to a declared max | `within {N} km` |
| 2 | price ceiling → removed | `at any price` |
| 3 | time-of-day → removed, date kept | `any time on {Fri, Aug 21}` |
| 4 | date → removed, time-of-day kept | `on other days` |

**The activity is NEVER relaxed.** Someone searching for a badminton court will not take a yoga studio, and a
page that swaps it has stopped answering the question that was asked.

**The ladder is capped at four rungs and runs sequentially, stopping at the first hit.** Four PostGIS
round-trips on an already-empty search is the worst case and it only occurs when the answer is genuinely
"nothing" — which is also the case where the booker is going to see the empty state anyway. Running all four
concurrently would pay for every rung on every zero-result search to buy bounded latency on the rarest path.
*(This is the open risk the CONTEXT flagged; it is answered here so a plan does not re-derive it. If a plan
measures the sequential worst case above a budget it declares, the fallback is to bound the ladder at two
rungs — radius and price — never to fan out.)*

**The band's geometry and behaviour:**

| Property | Value |
|---|---|
| Element | `<div role="status" data-testid="search-relax-band">` |
| Placement | Directly above the results grid, below the filter chips. Never inside the grid. |
| Surface | `bg-muted` + `border` + `rounded-lg` — the `neutral` tone at panel scale |
| Layout | `flex items-start justify-between gap-3 p-4`; the `Undo` control `shrink-0`. Below `sm:` it stacks and `Undo` becomes full-width. |
| Line 1 | `text-body font-semibold text-foreground` |
| Line 2 | `text-label text-muted-foreground mt-1` |
| Action | `Undo` — `Button variant="outline" size="touch"`. Restores the booker's original query exactly, including the filter chip. |
| Live region | `role="status"` (implicit polite). **One announcement, on arrival, naming the outcome — never a re-announce on scroll or on a `Load more`.** |

**The filter chip moves with the results, and that is half the requirement.** When rung 1 fires, the `where`
chip reads `Makati · 25 km` and carries the **soft-accent** tone (accent item 9) so it is visibly *the thing
the system changed*. **Falsifiable:** at zero-result-with-relaxation, the chip's rendered value string and the
band's changed-constraint substring are equal. A page whose control and whose results disagree is the failure
002-A's README names as the variant's cost, and the chip is what pays it.

**When every rung is exhausted** the band does not render and the shipped `EmptyState` does — see
§ Copywriting for the one body-copy change.

**Cold start is UNCHANGED (D-54).** No band, no ladder, no escape hatches. Every hatch is a filter control,
and offering "Broaden radius" to someone in a city with no supply is a button that cannot work.
`search-results.tsx:281-287` is shipped and correct.

**The inline fetch error is UNCHANGED.** `[11-18]` ruled it a permanent one-action block with the argument
recorded; do not convert it to `ErrorState` and do not add a second action.

## The Listing Surface (BFLOW-02, BFLOW-03, BFLOW-05)

### The order (BFLOW-02)

**Required:** gallery → title → key facts → description → availability → map → cancellation policy → host.

**What ships today:** gallery → title → About → Amenities → **Location (map)** → **Availability** → rail.
Two real moves: availability rises *above* the map, and cancellation gets its own section while **keeping**
its compact line in the rail.

**Resolution of the one ambiguity the requirement leaves.** Amenities is not named in the order. It is
descriptive content, so it renders **immediately after the description, inside the same "description" slot**
— `About this space` then `Amenities`, then a section break. It is not promoted to a key fact: activity and
amenity badges are a wrapping list of unbounded length and the strip is a fixed four cells.

**Sections are separated by `Separator` + the shipped 28-32px rhythm, not by cards.** The main column is page
ground (`--background`), not a stack of panels. Only the rail is a `PanelCard`.

### The key-facts strip (D-43 · sketch 003-B)

`<dl data-testid="listing-key-facts">` — a bordered strip, label above value, one border box, collapsing to
2×2 below 700px.

| Property | Value |
|---|---|
| Container | `grid rounded-lg border overflow-hidden`; `grid-cols-2` below 700px, `grid-cols-{n}` at ≥700px where n = the number of cells rendered (3 or 4) |
| Cell | `p-4 border-r last:border-r-0`; below 700px the right border drops on even cells and a bottom border appears on the first row |

### One instance, two placements — the declared exception, and why it is bounded

Phase 11's responsive rules are (1) reorder with CSS, never with conditional rendering, and (2) move one
instance, do not render two. D-48 puts the calendar, the slot picker, the breakdown and the CTA **inside the
sheet** on mobile, while BFLOW-02 puts the calendar **in the main column** in the desktop order. A React
portal is a runtime decision, so there is no CSS that relocates a mounted subtree across it.

**Resolution — and it is the precedent Phase 11 itself set for the host nav drawer:**

> **One source of truth, two placements for the DOM, `hidden` as the mechanism.** The interactive content is
> a single named component, `<BookingPanel>` (`data-testid="booking-panel"`), rendered twice: once in the
> listing's main column + rail inside a `max-lg:hidden` wrapper, once inside the sheet inside a `lg:hidden`
> wrapper. `hidden` — not `sr-only`, not `opacity-0` — so the inactive copy leaves the accessibility tree.

**Three hard conditions make the duplication safe rather than merely tolerated. All three are falsifiable:**

1. **`BookingPanel` owns zero state.** Selection lives in the existing `BookingSelectionProvider`; the day's
   availability read is **hoisted to a single hook mounted once above both placements**. Two views, one
   state, one fetch. **Assert:** selecting a day at 375px and at 1280px issues exactly **one** availability
   request each.
2. **Exactly one of anything a user can reach.** **Assert:** `getByRole("button", { name: /^Book/ })` resolves
   to exactly **1** at 375px and exactly **1** at 1280px; `getByRole("dialog")` resolves to 0 until the bar is
   tapped. This is the same criterion shape as Phase 11's `getByRole("navigation") === 1`.
3. **Exactly one hook per surface.** `rail-price-total` is emitted by the rail placement, `sheet-price-total`
   by the sheet placement, never both by one.

*Rejected, recorded so nobody re-litigates it:* a `useMediaQuery` fork (breaks SSR, doubles the VR surface,
duplicates content for screen readers — the exact rule 1 hazard); a third `ResponsiveDialog` presentation
that renders inline at `lg:` (Radix `DialogContent` portals unconditionally, so this needs the same JS media
query wearing a pattern's name); and shipping the calendar only in the sheet at every width (it deletes the
desktop layout BFLOW-02 requires).

## GATE-03 — The Live-Region Contract

**34 `aria-live` attributes across 18 files.** `hold-countdown.tsx` is already correct and is the model the
rest are measured against — not re-decided.

### The rule, stated once so a plan does not re-derive it per component

| # | Situation | Required markup |
|---|---|---|
| 1 | The **result** of something the user did (hold refused, slot taken, filters relaxed, lease busy) | `role="status"` — implicit polite. **Never `assertive`.** |
| 2 | A **genuine failure needing a human** | `role="alert"`. Reserved. Occupancy, expiry and sold-out are **not** failures. |
| 3 | A **ticking value** | `role="timer"` + `aria-live="off"` on the digits, and a **separate** `sr-only` polite region that changes only at declared thresholds |
| 4 | **Loading** | `role="status" aria-busy="true"` with a non-empty accessible name; every placeholder bar `aria-hidden="true"` |
| 5 | Any live region | Has an accessible name or is inside a region that does. A bare `aria-live` on an unnamed `<div>` announces to nobody. |
| 6 | Any outcome | **Exactly one** live region announces it. Two regions reporting the same event is the defect GATE-03 exists to catch. |
| 7 | The whole booker path | **`aria-live="assertive"` is banned.** It interrupts whatever the user is reading. Where an event genuinely must be noticed, the mechanism is *polite region + moved focus*, which is what the collision notice and `HoldExpiredState` both do. |

### The booker-path inventory, and the mechanism that makes it checkable

**Declare `LIVE_REGIONS` in `src/lib/design/live-regions.ts`** — a const tuple plus a total `Record` over the
union it derives, the shape this repo has converged on for `contrast-pairs.ts`, `status-tones.ts`,
`measurements.ts` and `selector-contract.ts`. Each row carries `{ file, kind, announces, why }`. Adding a
name without a row is a **compile** error, not a review comment. `src/lib/design/` sits outside the DS-13
leak gate's scanned tree, so the module can quote markup honestly.

| File | Today | Phase 12 |
|---|---|---|
| `hold-countdown.tsx` | `role="timer"` + `aria-live="off"` + one polite sr-only | **Model. Keeps the 60s announcement; loses the expiry announcement** (the page-level state owns it — rule 6) |

## Anti-Patterns — reject these in plan review

- **A computed window total on a search card.** D-37: a centavo of rounding breaks D-75's "never goes up".
- **`Est.` anywhere on the rail.** The figure is exact by construction.
- **A lookalike breakdown in the rail.** BFLOW-04's claim is that it is the *same component*, not a similar one.
- **Computing the fee, the total or the rate in a client component.** GATE-05 fails the build; a percentage
  literal in client copy is the same defect wearing prose.
- **A second `price-total` hook on one page.** The parity spec would parse whichever came first.
- **A tooltip anywhere on the booker path.** Half this traffic is touch. `search-result-card.tsx:214`,
  D-39 and D-ELM-01 all already refused it; D-56 deletes the last one.
- **Keeping the `TooltipProvider` + `tabIndex` wrapper around the disabled CTA.** That node is the `[11-13]`
  hydration site.
- **Red on a taken slot, a sold-out day, an expired hold or a full space.** Occupancy is the marketplace
  working. `--destructive` on this path is the countdown's final minute and nothing else.
- **A dialog for the collision.** It modals a normal outcome and, at 375px, hides the very grid that is the
  evidence.
- **Nearest-**day** alternatives on a collision.** D-55 offers same-day windows because the refreshed grid
  already contains them. A multi-day read is a capability addition with its own phase.
- **`aria-live="assertive"` anywhere.** Polite region + moved focus is the mechanism.
- **Two live regions for one outcome.** Digits in both the header and the rail; a countdown expiry
  announcement *and* a `HoldExpiredState` announcement; `book-cta`'s notice *and* the collision notice.
- **A bare `aria-live` on an unnamed `<div>`.** It announces to nobody — measured, not theorised.
- **A skeleton without `role="status"` and a name.** The 1.09:1 fill exclusion is conditional on that wrapper;
  without it, it is a real WCAG 1.4.11 failure.
- **`{isMobile ? <A/> : <B/>}` or `useMediaQuery` to choose the rail vs the sheet.** The declared exception is
  `hidden` + hoisted state, with three assertions attached.
- **Two mounted availability fetches.** One hook above both placements.
- **Editing `src/components/ui/calendar.tsx`.** The cell size is a `className` variable override.
- **A grab handle on the sheet.** Drag-to-dismiss is out of scope; a handle implying it is an affordance that lies.
- **Installing shadcn `sheet`.** Resolved in Phase 11; reversing it needs the same treatment as any recorded decision.
- **`shadow-sticky` on the site header.** Its y-offset is negative — an upward cast for bottom-anchored bars.
- **A fifth key fact, or icons in the strip cells.** Variant B won without them; a hybrid is a fourth treatment nobody chose.
- **`4 courts` without `1 of `.** A booker must never read it as "you get all four".
- **An SLA hour count, a response rate, a verification badge or a superhost marker.** D-96 makes the first
  frequently false; TRUST-04 bans the rest outright.
- **A confirm dialog before the PayMongo redirect.** A second tap between a decided booker and paying, on a
  15-minute clock.
- **Removing the way back from checkout, or putting it in the header.** The first is the dead end D-59 names;
  the second breaks Phase 11's AC#5.
- **A carousel for listing photos.** Named in REQUIREMENTS.md § Out of Scope.
- **Saved searches, favourites, comparison, new filters, or an account nudge.** D-59 raises the bar on how
  well the existing flow works; it authorises nothing new. *If a proposal changes a requirement ID, it is not
  D-59 work.*
- **A results map.** Phase 18, D-136. It needs a bbox parameter the two-stage PostGIS search does not take.
- **A schema migration.** GATE-06 binds.
- **A baseline of the checkout without a frozen clock.** A guaranteed flake, and a flaky gate is a rubber stamp.
- **An OG baseline captured without a seeded published listing.** It is green forever while covering the
  `GenericCard`.
