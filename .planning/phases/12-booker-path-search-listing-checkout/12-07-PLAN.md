The six mosaic shapes (12-UI-SPEC § The gallery and lightbox). `MOSAIC_ASPECT` (16/9) is the outer box at
EVERY count, `gap-2`, `rounded-xl overflow-hidden`:

  N   shape                                        button
  0   the shipped 16/9 muted plate + `No photos yet`   none
  1   hero alone, full width                           none
  2   two equal columns                                none
  3   hero (2fr) + a stacked pair (1fr)                none
  4   hero (2fr) + three stacked in one column (1fr)   none
  5+  hero (2fr) + a 2x2 (1fr 1fr)                     `Show all {N} photos`

Below `sm:` the mosaic collapses to the hero alone and the button renders whenever `N > 1`. Tapping the
hero opens the lightbox on photo 1.

The lightbox:

  mechanism        `ui/dialog` at full screen on EVERY viewport. NOT `ResponsiveDialog`.
  hook             data-testid="photo-lightbox"
  scrim            bg-foreground/90, no text on it
  chrome           counter `{i} / {N}` (tabular-nums), prev / next, close — all on a `bg-background` plate
                   carrying `--foreground` ink, all >=44px. Never bare white text floating on a scrim:
                   that is the one surface with no page token behind it, and tokened controls on a tokened
                   plate is what keeps every pairing inside the declared inventory.
  keyboard         ArrowLeft / ArrowRight page; Escape closes (Radix); focus trapped and returned (Radix)
  accessible name  an sr-only DialogTitle: `Photos of {listing title}`
  nav labels       `Previous photo` / `Next photo`
  close label      `Close photos` — NOT the vendored default `Close`. The booker path renders TWO visible
                   close buttons (this and the booking sheet's `Close booking`), and two controls both
                   named `Close` are indistinguishable in a screen reader's element list.
  photo transition NONE. Paging swaps the src. A cross-fade between two arbitrary host photos is 200ms of
                   noise and a second thing to keep inside the motion budget.
  alt              `{title} — photo {i} of {N}` on BOTH the mosaic and the lightbox, replacing the shipped
                   `— cover photo` / `— photo {i}`.

⚠ TWO RADIX MECHANICS THE LIGHTBOX INHERITS AND MUST NOT GET WRONG (both recorded in
`patterns/responsive-dialog.tsx`): the `aria-describedby` opt-out object must be spread CONDITIONALLY,
because JSX keeps a key whose value is `undefined` and a ternary strips the wiring in both branches; and
sizing uses `max-sm:` variants only, never a JS breakpoint.

⚠ `tests/design/sheet-absent.test.ts` scans for a viewport-height arbitrary unit in the older form. Use the
dynamic-viewport unit, and do not quote the banned unit in a comment.

⚠ Broken image `src` is fine in tests — `e2e/price-parity.spec.ts` records that "the `<img>` exists" is all
these assertions need.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host-uploaded photo urls -> rendered `<img>` | Arbitrary Cloudinary `secure_url`s render in a full-screen surface |
| dialog -> background document | An overlay that does not trap focus or mark the background inert is a keyboard trap in reverse |
| server mosaic -> client island | The interactive layer must not drag the RSC-rendered plate client-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-07-PHOTOSRC | Information disclosure | lightbox `<img>` | accept | The lightbox renders the SAME stored Cloudinary `secure_url`s the mosaic already renders — no new upload, signing or transform surface, and no new origin. ASVS V12 partly-applies row, unchanged by this plan |
| T-12-07-FOCUSTRAP | Denial of service (accessibility) | overlay | mitigate | Radix owns trap, restore, Escape, scroll lock and the portal; the spec asserts focus RETURNS to the opening trigger by accessible name |
| T-12-07-NONAME | Denial of service (accessibility) | dialog title | mitigate | A required `sr-only` DialogTitle, asserted through `getByRole("dialog", { name })`; the two close controls carry distinct names, asserted |
| T-12-07-KEYLEAK | Tampering | arrow-key handler | mitigate | The handler is on the dialog content, never on `window`; a negative case asserts arrows do nothing while closed |
| T-12-07-HOOKGHOST | Repudiation | `selector-contract.ts` | mitigate | The `photo-lightbox` row and its string literal land in the same commit; the bidirectional gate fails otherwise |
| T-12-07-BOUNDARY | Information disclosure | server/client split | mitigate | `photo-gallery.tsx` stays hook-free and `"use client"`-free, asserted by grep; the island is a sibling |
| T-12-07-SC | Tampering | npm/registry installs | mitigate | Zero packages; no `sheet` block, no gesture library. `git diff --stat package.json` must be empty and `sheet-absent.test.ts`'s `package.json` scan must pass |
</threat_model>
