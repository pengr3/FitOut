<objective>
Build the spec that can see what jsdom cannot.

Purpose: `react-easy-crop` renders the crop-area element only when `state.cropSize` is truthy, which needs
a non-zero `getBoundingClientRect()` AND a decoded `<img>` with real naturals. Probed jsdom 29.1.1 has
neither — `getContext('2d')` null, `createImageBitmap`/`OffscreenCanvas`/`ResizeObserver`/
`URL.createObjectURL`/`Image.prototype.decode` all undefined, every `getBoundingClientRect()` zeros.
**In jsdom the crop stage does not exist in the DOM.** Everything geometric, gestural or pixel-bearing is
Playwright or human, and this is the Playwright half's foundation.

Output: `e2e/avatar-crop.spec.ts` and the session helper it needs.

**This repo has never driven a file input from Playwright** — `grep -rn "setInputFiles" e2e/` returns
nothing. This spec creates that convention, so it says how and why in its header rather than leaving the
next reader to infer it.

**What this plan may and may not claim.** It produces evidence for CROP-01. It does NOT discharge CROP-04.
Playwright can synthesise touch and can assert `touch-action`, but it cannot reach Safari's
`gesturestart`/`gesturechange` path — a genuinely different code path in the library, which
`componentDidMount` wires up separately and which no emulator fires — nor real finger occlusion of a
~183px stage, nor iOS momentum and rubber-banding, nor the OS file picker where D-174's re-pick bug
actually lives. **D-175 forbids claiming CROP-04 from a Playwright run, and the mechanics agree with the
decision.** Say so in the spec's header.
</objective>
