<interfaces>
The guard chain, in this ORDER (999.2 § 2e fixes it; only the decode/measure step was ever open):

  1. type    not in AVATAR_ALLOWED_TYPES        -> AVATAR_WRONG_TYPE_MESSAGE          no dialog
  2. size    > AVATAR_MAX_BYTES                 -> "Image must be 5 MB or smaller."   no dialog  (SHIPPED literal,
                                                                                      reused verbatim from
                                                                                      validation/profile.ts:46)
  3. decode  measureImage(url) rejects          -> AVATAR_UNREADABLE_MESSAGE          no dialog
  4. measure min(width,height) < AVATAR_MIN_SOURCE_PX -> AVATAR_TOO_SMALL_MESSAGE     no dialog
  otherwise: open ImageCropDialog. A shorter side in [200, 399] is NOT a refusal — the dialog opens with
  `maxZoom === 1`, so the zoom row renders disabled with AVATAR_SOFT_SOURCE_NOTE (rule F8). The user
  decides; the app does not decide for them.

The `accept` attribute is `image/jpeg,image/png,image/webp` — the same three types `AVATAR_ALLOWED_TYPES`
declares. The client re-checks anyway, because `accept` is a hint and not a gate.

D-174, one line in a `finally`, on EVERY path — accept, reject AND cancel:
  async function onAvatarChange(e) { try { ...guards... open... } finally { e.target.value = ""; } }
Without it the browser fires no `change` for a re-picked identical file and the flow dies silently.
`profile-form.tsx:78-93` has no reset at all today.

The save path, unchanged on the server (999.2 § 1b): `fd.set("avatar", blob, "avatar.jpg")` — a `Blob`
appended with a filename arrives server-side as a `File`, so `z.instanceof(File)` holds. `blob.type` is
`"image/jpeg"`, inside the allow-list plan 16-07 narrowed. On success: close the dialog, swap the preview
to the returned URL, `router.refresh()`. On failure: the dialog STAYS OPEN with the framing intact and the
shipped sentence `Could not upload your photo. Please try again.` renders inside it (rule F5).

Copy deltas against the shipped block, all from Delta-11 / Delta-14:
  size="sm"           -> size="touch"                (Delta-12; sm is now h-7 = 28px)
  text-xs             -> text-label                  (twice; text-sm would freeze the size against grove)
  accept="image/*"    -> the three MIME types
  "Uploading…"        -> RETIRED, no state left to describe
  helper string       -> AVATAR_HELPER (it now names WebP; do NOT reuse the shipped one)
