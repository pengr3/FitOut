# Phase 17 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## What this document is — read this first, because it is not what the other seven are

**This is a CONFORMANCE CONTRACT, not a design contract.** Phases 10–16 shipped a complete, gated
design system: 24 per-theme token names, four named type roles, a closed ten-entry accent list, a
40-row measured contrast inventory, one focus recipe, a four-tone status union, three card patterns,
one overlay primitive, four state families, and ~70 gate files that make `npm run build` fail on a
raw hex. **Phase 17 re-decides none of it.**

What this document does instead:

| # | Does | For |
|---|------|-----|
| 1 | **Restates the inherited contracts as machine-checkable INVARIANTS** — the values a cross-cutting sweep asserts, with the numbers pinned so a sweep cannot be written against a remembered version of the system | RESP-03, RESP-04, GATE-02 |
| 2 | **Names the measured adoption GAPS the earlier phases handed forward by name**, each with its owner file and its current number | DS-09, GATE-01, GATE-02 |
| 3 | **Declares the REMEDIATION RULES** — what an audit may change when a surface fails, and what it must escalate instead | all four |
| 4 | **Declares the ARBITRATION RULES** — which instrument wins when two gates disagree about the same pixel | GATE-02 |

**The one rule that governs every task in this phase:**

> **An audit finding is a measurement first and a fix second.** Where a fix is a token adoption, a
> missing accessible name, or an attribute, take it. Where a fix would change a declared value, a
> layout decision, a piece of product copy or a component's shape, **the finding is the deliverable**
> — record it with its number and escalate. The v1.1 roadmap's own words for this phase are *"an
> AUDIT, not a rewrite"*, and the failure mode it is warning about is a sweep that quietly redesigns
> nine surfaces under cover of a green gate.

**Scope narrowing that governs the whole phase: D-138 (2026-08-23).** `court` is FitOut's **single
product theme**. `grove` is a **token-contract probe** — never shippable, never presented as a brand
option, reachable only via `?theme=` outside production or a Playwright `localStorage` seed. So:
the axe pass is **court only**, the baseline sweep is **court only**, and the token contract is
proved by the fixed four-surface probe in `e2e/visual/theme-swap.spec.ts`, not by a second full
sweep. Where an inherited file's comment still says *"Phase 17's TWO-THEME axe pass"*
(`contrast-pairs.ts:27`, `pair-drift.test.ts:69`, `theme.ts:3`, `theme-provider.tsx:21`), it was
written before D-138 and **this document is the correction**; see § The court-only narrowing and
what it costs.

no `axe` at any version (verified 2026-08-28). Two devDependencies enter, both from the Deque
first-party scope, both dev-only, neither reaching the client bundle:

**Pin it exactly**, the same way `@playwright/test@1.60.0` and `tsx@4.22.4` are pinned. An axe minor

train the next reader to retry the gate — the rubber-stamp failure mode this milestone's own roadmap
names. Bumping it is a deliberate act with a re-baselined violation set, not a lockfile drift.

## Spacing Scale

**Inherited unchanged. Phase 17 authors ZERO new spacing values.** The declared legal set:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`*-1`) | Icon-to-label gaps inside a chip |
| sm | 8px (`*-2`) | Compact element spacing |
| — | 12px (`*-3`) | Dense row padding, table cells |
| md | 16px (`*-4`) | Default element spacing; card padding |
| lg | 24px (`*-6`) | Section padding |
| xl | 32px (`*-8`) | Layout gaps; empty/error panel padding |
| 2xl | 48px (`*-12`) | Major section breaks |
| 3xl | 64px (`*-16`) | Page-level spacing; desktop header height |

**Inherited exceptions, carried forward unchanged and re-asserted by this phase rather than
re-argued:** 56px (`h-14`, mobile header) · 176px (`w-44`, auth-slot reservation) · 80px
(`lg:top-20`, sticky-rail offset) · 85dvh (`max-h-[85dvh]`, sheet bound) · every box constant in
`src/lib/design/measurements.ts`. **Phase 17 adds none and retires none.** A new spacing value in a
Phase-17 plan is a scope alarm: an audit that needs a new box is a rewrite wearing an audit's clothes.

### The three floors this phase asserts, and they are three different numbers

The single most common way a cross-cutting sweep goes wrong is conflating these. They are named
here with their sources so a plan cannot pick the wrong one:

| Floor | Value | Source | Applies to |
|-------|-------|--------|-----------|
| **Viewport floor** | **320px** | D-131 | Every surface. `document.documentElement.scrollWidth <= clientWidth`. |
| **Conformance target size** | **24px** | WCAG 2.2 SC 2.5.8 AA | **Every interactive control, everywhere.** Already `TARGET_FLOOR_PX` in `e2e/overflow-320.spec.ts:905`. |
| **House touch size** | **44px** | DS-09 / D-22 | **Only** controls that declare `size="touch"`, and the primary actions each surface's UI-SPEC names. |

> **A blanket 44px assertion would be RED against shipped, reviewed, correct code** — the app ships
> deliberate sub-44 controls (the 32px header cluster, dense host table actions). That measurement is
> already recorded at `overflow-320.spec.ts:891-902` and this phase must not re-litigate it. 24 is the
> conformance bar; 44 is asserted **by name**, per surface.

### DS-09 — the one adoption gap in this section, and its exact number

`tests/design/brand-recipe.test.ts:721` ships a **measurement, not a requirement**, whose docblock
names this phase as its owner:

> *"DS-09 is recorded as Pending with Phase 17 as its owner, so this must not fail the build for
> sites that phase has not reached yet… The six left are Phase 17's to convert under DS-09, which is
> why this is a ceiling and not a zero."*

**Contract:** the ceiling at `brand-recipe.test.ts:759` moves from `toBeLessThanOrEqual(6)` to
`toBe(0)` — six `<Button>` elements that hand-roll `h-11` adopt `size="touch"` instead. `<Input>`,
`<SelectTrigger>`, `<InputGroup>` and `<Skeleton>` stay excluded: they genuinely expose no `touch`
size, which is the distinction WR-01 got wrong once already.

**If the six cannot all convert** — because one of them is inside a vendored primitive, or because a
conversion changes a rendered width the 320px sweep depends on — **lower the ceiling to the number
actually reached and name the survivors.** A ceiling that stays at 6 with a comment claiming victory
is the exact defect that measurement replaced.

**Do not respond by making `touch` a responsive default.** 10-06 considered and rejected it: it would
silently change every dense host table's mobile rendering at once. The CVA's own comment
(`ui/button.tsx:110`) names this phase as the catch precisely so the per-site conversion happens here.

Tailwind's re-declared `text-xs…2xl` ladder is legal and is not a fifth role. Arbitrary

### Two type invariants this phase turns from prose into instruments

Both are cross-cutting properties nothing currently measures, and both are typographic rather than
spatial — which is why they live here and not under RESP-03's overflow harness.

#### 1. The no-wrap clause (RESP-03) — a wrap is not an overflow, and no shipped gate can see one

`scrollWidth <= clientWidth` is green on a `₱1,234.00` that has wrapped onto a second line inside a
fixed-height bar. The text is clipped, not overflowing, and the harness reports success. RESP-03's
literal wording — *"no price, countdown or label wraps or overflows"* — is therefore **two**
assertions, and only the second one exists today.

**The instrument already exists and must be generalised rather than re-invented.**
`e2e/mobile-booker-path.spec.ts` case (b) measures each line's `clientHeight` against **its own
resolved `line-height`**, not against a literal:

```
clientHeight <= parseFloat(getComputedStyle(el).lineHeight) + TOLERANCE_PX
```

**Both of its guard-the-guard assertions are mandatory and must travel with it**, because each one
turns a silent pass into a red: (a) the element rendered non-empty text, and (b) `lineHeight`
parses to a finite number — a `normal` line-height yields `NaN`, which compares false against every
bound and would make the whole clause vacuous.

**Measured against the element's own resolved line-height, never a literal,** because the two lines
in the sticky bar are different type steps and every `--leading-*` token is per-theme.

**The declared no-wrap set** — the elements RESP-03 names, by their existing hooks:

| Class | Where | Why it may not wrap |
|-------|-------|---------------------|
| **Price** | The sticky bar's rate line · `data-testid="price-total"` · every `tabular-nums` money figure in a fixed-height box | A wrapped rate in a 64px bar is a clipped rate, on the one surface carrying the price at 320px |
| **Countdown** | The checkout header's live hold countdown (`HOLD_COUNTDOWN_BOX` = `h-8 min-w-24`) | A countdown that reflows on each tick is both a layout shift and a re-announcement hazard |
| **Label** | The sticky bar's `Service fee included` · every status chip label · every named 44px action's label | A disclosure the booker cannot finish reading is a disclosure that was not made |

#### 2. The heading-order clause (GATE-02) — handed forward by name from Phase 14

`[14-REVIEW WR-03]` assigns this phase the outline walk, and documents why nothing else can do it:

> *"IT SAYS NOTHING ABOUT `<h2>` AND BELOW. A surface whose sections skip from level one to level
> three has a broken outline and passes this file completely."* — `e2e/host-headings.spec.ts:93`

That blindness is what let 14-12 and 14-13 promote two `<h3>`-level advisories to `<h2>` on
`/host/listings/{id}/availability` unobserved, while all 28 of the file's level-one assertions stayed
green.

**Contract:** the outline walk is **added to the existing per-state loop in
`e2e/host-headings.spec.ts`, never as a second file** — the 28 states, their tells and their seeding
already exist there. Collect every heading on the resolved document in document order and assert no
level is skipped. **Watch it red against a deliberately SKIPPED level (`h1` → `h3`), not merely
against a duplicated one** — a duplicate is the easy case and a green against it proves nothing.

> ⚠ That spec seeds a database and **must be run alone**
> (`npx playwright test e2e/host-headings.spec.ts --project=chromium`). `e2e/availability.spec.ts:261`
> is a pre-existing standing red and is not this phase's to close.

Axe's own `heading-order` rule covers this on every other surface. The bespoke walk exists only
because the host routes need seeding that the axe sweep's route table may not carry.

| Role | court (product) | grove (probe) | Usage |
|------|-----------------|---------------|-------|
| Dominant (60%) | `--background` `#ffffff` | `--background` `#f7fcfc` | Page, surfaces, site header |
| Secondary (30%) | `--card` `#ffffff` · `--muted` `#f5f5f5` | `--card` `#ffffff` · `--muted` `#eaf3f2` | Cards, panels, footer, skeleton fill, status-chip tints |
| Accent (10%) | `--brand` `#da2d34` | `--brand` `#13807c` | The ten `ACCENT_USES` entries, and nothing else |
| Destructive | `--destructive` `#cd0916` (global, identical in both themes) | same | Destructive actions and genuine failure only |

**`ACCENT_USES` stays at exactly TEN entries.** It is pinned at the type level
(`AccentUseCountIsTen` in `src/lib/design/accent-uses.ts:212`), so an eleventh does not compile.
Phases 13, 14, 15 and 16 each appended zero. **Phase 17 appends zero.** An audit that discovers a
surface *wants* an accent has discovered a product question, not a bug.

**The contrast inventory is closed for this phase.** If the audit finds a rendered pairing the
inventory does not declare, the deliverable is **a measured row added to `contrast-pairs.ts` with its
reason** — never a colour changed at a call site, and never a silent omission. That rule is not new;
it is Phase 11's, restated because a cross-element sweep is exactly the instrument that will surface
one.

### The arbitration rule — which instrument wins, stated before anything disagrees

Three instruments now measure colour, and they measure different things. Without a stated order, the
first disagreement becomes an argument.

| Instrument | Authority over | Not authoritative over |
|------------|----------------|------------------------|
| **`tests/design/contrast.test.ts`** (culori, OKLab→sRGB, 8-bit rounding, gamma-space alpha compositing, `AA_EPSILON = 0.05`) | **Every DECLARED token pair, in both themes.** This remains *the* colour authority (D-12). | Anything it does not declare. |
| **axe `color-contrast`** (rendered DOM, court only) | **Rendered pairings the inventory does not declare** — the cross-element residue that same-string analysis cannot see. | A declared pair. axe uses a slightly different rounding and no epsilon; a 4.51-vs-4.50 disagreement on a declared row is **not** a finding. |
| **`tests/design/pair-drift.test.ts`** | Same-element class-pair drift in source. | Cross-element pairings — its own docblock says so. |

**Procedure when axe flags a pairing:**
1. Is the pair in `CONTRAST_PAIRS` or `EXCLUDED_PAIRS`? → **`contrast.test.ts` wins. Not a finding.**
   Record the disagreement as data if it is within 0.1 of the bar.
2. Is it a genuinely undeclared rendered pairing? → **It is a real finding.** Add the measured row to
   `contrast-pairs.ts` (or `EXCLUDED_PAIRS` with a stated reason, if it is decorative and carries no
   meaning). **Never fix it by editing a colour at the call site** — that reintroduces the
   per-call-site judgement Phase 10 removed.
3. Does the remediation require a token value to move? → **Escalate.** Moving a token re-derives 40
   pairs in two themes and invalidates 36 baselines. That is a Phase-10 amendment, not an audit task.

### The court-only narrowing, and what it costs — recorded, not glossed

Four shipped files hand their blind spot to *"Phase 17's TWO-THEME axe pass"*
(`contrast-pairs.ts:27`, `pair-drift.test.ts:69`, `e2e/helpers/theme.ts:3`,
`src/components/theme/theme-provider.tsx:21`). D-138 (2026-08-23) postdates all four and makes the
pass **court only**. The honest consequence, stated rather than left for a future reader to discover:

- **In `court`, the cross-element residue is fully covered** by the axe sweep on the rendered DOM.
- **In `grove`, it is covered only by the four-surface theme-swap probe** (`search-results`,
  `auth-login`, `terms`, `root-not-found`) plus the 24-name key-set parity check and the two-theme
  declared-pair table. A cross-element pairing that is legal in court and sub-bar in grove, on a
  surface outside those four, **is not detected.**
- **This is acceptable and is the point of D-138:** grove is a probe, not a shippable theme. No user
  can reach it. The residue would be a defect in a theme nobody sees.
- **It becomes a real gap the day grove — or any second theme — becomes shippable.** That is a
  DSFUT-02 concern (dark mode), and this paragraph is what a future milestone should re-read before
  turning a probe into a product.

**The four handoff comments must be amended in place** to say *court-only, with this limitation*, in
whichever plan lands the axe pass. A comment that promises coverage the phase deliberately did not
build is worse than no comment.

## RESP-03 — Every surface from 320px, with the sticky bar present

**Success criterion 1.** Three clauses, and only one of them is fully instrumented today.

### Clause A — nothing scrolls sideways at 320px

**Shipped.** `e2e/overflow-320.spec.ts` covers **seventeen named routes plus three route states, in
both themes**, via `e2e/helpers/overflow.ts` (`FLOOR_PX = 320`, `OVERFLOW_TOLERANCE_PX = 0.5`,
`MIN_EXAMINED_ELEMENTS = 8` as a scan-of-nothing guard) and reports **named offenders**, not just a
boolean.

**Phase 17's job is COVERAGE, not mechanism.** RESP-03 says *every* surface. The audit extends the
route table to the full shipped surface inventory and **records, per surface, either a measurement or
a named reason it cannot be reached.** A surface silently absent from the table is a surface that was
never audited, and the table is the artifact that makes that legible.

**Two inherited defects in this harness are Phase 17's to close** — both measured, both recorded:

| Finding | Owner | The fix |
|---|---|---|
| **[16-D9]** The `/listings/[id] · sheet open` row measures the wrong box. With the sheet open `<body>` becomes a 320px box that clips its own content, so the document-level clause **cannot fire** and the per-element clause reported `clientWidth 320` with **48 named offenders on the sheet** and 14 on the crop dialog. The row that exists *specifically because* the sheet is where the floor is hardest is the row proving nothing. | `e2e/overflow-320.spec.ts` | **One line:** `scope: '[data-testid="responsive-dialog"]'` on the sheet row, using the already-shipped `expectNoOverflowWithin`. |
| **[15-12]** AC#30's target-size scan **races the surface it measures** — it can read controls before the resolved document replaces the skeleton. | same | Await the surface's own tell before `expectTargets`, the way the AC#22 rows already do. |

### Clause B — with the sticky bar present

**Not instrumented.** No gate asserts the bar is *there*; the sweep measures pages on which it may
have silently stopped rendering. The bar is `fixed inset-x-0 bottom-0 z-(--z-sticky) … lg:hidden`
(`booking-sticky-bar.tsx:167`) at `STICKY_BAR_HEIGHT` = `h-16` = **64px**, with `STICKY_BAR_CLEARANCE`
= `pb-20` = **80px** (64 + 16) on the two pages that carry one.

**Contract — three assertions, on `/listings/[id]` and `/listings/[id]/book`, at 320px:**

1. `[data-testid="booking-sticky-bar"]` (resp. the checkout bar) **is visible**, and its
   `boundingBox().height` is **64**.
2. Its bottom edge is within tolerance of the viewport's bottom edge — it is *pinned*, not merely
   present in the DOM.
3. **The bar does not occlude the document's last interactive control.** The `pb-20` clearance is
   what guarantees this, and asserting the clearance class is not the same as asserting the outcome:
   scroll to the bottom, and the last focusable element's box must not intersect the bar's box.

**And the bar is absent where it must be:** at `lg:` and above the bar is `hidden` and the desktop
sticky rail carries the price instead. Assert the absence at 1280px too — a bar that renders at both
widths is a forked variant, which is RESP-04's failure, found by RESP-03's harness.

### Clause C — no price, countdown or label wraps

**Not instrumented beyond one surface.** See § Typography clause 1 for the instrument, its two
mandatory guards, and the declared no-wrap set.

## RESP-04 — One component tree, no forked mobile/desktop variants

**Success criterion 2.** The named surfaces: **search, listing detail, calendar, wizard, checkout,
and every list surface.**

### The four sanctioned techniques (inherited from Phase 11, restated as the audit's checklist)

1. **Reorder with CSS, never with conditional rendering.** `{isMobile ? <A/> : <B/>}` needs JS to know
   the viewport, breaks SSR, doubles the VR surface, and duplicates content for screen readers.
2. **Move one instance; do not render two.** Two instances of a client island double-mount,
   double-submit, and produce two focus targets.
3. **One dialog, two presentations** — `patterns/responsive-dialog.tsx`. `src/components/ui/sheet.tsx`
   must not exist (`tests/design/sheet-absent.test.ts`).
4. **One source of truth for links, two placements for the DOM** — and the inactive copy uses
   **`hidden`**, not `sr-only` and not `opacity-0`, so it leaves the accessibility tree and exactly
   one navigation landmark exists at any viewport.

### The audit's instrument — a source scan plus a rendered count, because neither alone is enough

**Source scan (Vitest, DB-free, in `tests/design/`):** no file under `src/app/**` or
`src/components/**` renders a viewport-conditional JSX branch. Measured baseline, 2026-08-28:
`src/` contains **exactly one** `matchMedia` call site and **zero** `useMediaQuery` imports.

**Rendered count (Playwright, the half a source scan cannot do):** for each named surface, the
count of elements carrying its identifying `data-testid` is **1** at 320, 768 and 1280 — not
"1 visible", **1 in the document**. `[data-testid]` resolves against `display: none` nodes exactly
as it resolves against painted ones, which is precisely why the count is the right assertion and
"is visible" is not.

### The one sanctioned exception, already argued and NOT to be re-opened

`src/components/host/publish-checklist.tsx` — `usePublishChecklistPlacement()` reads
`matchMedia("(min-width: 64rem)")` and returns `"panel" | "collapsible"`.

**This is compliant, and it is compliant for the reason RESP-04 exists.** It does **not** render two
trees and hide one: it **chooses one node**, so the one-instance count holds at all three widths. Its
docblock records the full argument, its SSR fallback (the small-screen placement — the safe
direction), and its measured cost (one frame of the collapsed trigger on a wide screen). The audit's
job is to **assert the one-instance property on this component**, not to remove the hook.

**A second component reaching for the same hook is a finding**, not a precedent. The technique is
sanctioned where a *count over the document* is the pinned property and CSS cannot deliver it. If the
audit finds a second, record it and escalate before generalising.

## GATE-02 — Keyboard, focus, and the axe pass

**Success criterion 3.** Four deliverables.

### 1. The focus recipe — one recipe, app-wide, already gated

```
focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background
```

`--ring` measures **7.46 / 7.11** on background, **7.46 / 7.36** on card, **6.84 / 6.52** on muted —
past the 3.0 non-text bar with margin in both themes. **No control may rely on a 50%-alpha ring**
(arithmetically impossible to reach 3:1 — 10-UI-SPEC § Focus Recipe).

**The one declared exception, which is not a defect to "fix":** the `RowCard` overlay-link form
(`after:absolute after:inset-0 … focus-visible:after:ring-2`) **omits `ring-offset`**, because an
overlay pseudo-element filling its container has no surface to offset into. `ring on card` = 7.46 /
7.36 clears the bar without the band. An audit that "corrects" this renders a 2px band inside the
card's own content.

**Reading a focus indicator has exactly ONE definition in this suite:** `expectRing` in
`e2e/helpers/focus.ts`. A ring is a `box-shadow`, not an `outline`. **A second definition is
forbidden** — D-16's one-import-site rule, and the drift it prevents is silent in the worst
direction: the day DS-05 stops painting a `ring-*`, one copy would be updated and the other would
keep reporting green about a mechanism that no longer exists.

### 2. The keyboard walk — the shipped half, and the gap

**Shipped:** `e2e/auth-keyboard.spec.ts` walks **six auth documents, 59 stops**, measuring an
indicator on *every* stop, built on `e2e/helpers/focus.ts`'s `walkForward` / `walkBackward` /
`probeCandidateStops` / `WALK_BOUND = 40` / `partitionDevOverlay` / `resetFocusToTop`.

**The gap:** those six documents are the only ones with a recorded walk. GATE-02 names five surface
families that have none — **the calendar, the slot picker, the wizard, dialogs and sheets** — and
they are named because each is a *composite* interaction where reachability is not implied by any
per-control assertion.

**Contract — reuse `helpers/focus.ts`, extend the walk, per surface assert all five:**

| # | Property | Why it is separate |
|---|----------|--------------------|
| 1 | **Reachable** — every interactive element appears in the forward walk | The base WCAG 2.1.1 claim |
| 2 | **Operable** — the element's action fires from the keyboard (Enter/Space; arrows where a composite widget owns them) | Reachable ≠ operable; a focusable `<div>` with a click handler is reachable and dead |
| 3 | **Indicated** — `expectRing` passes on every stop | The DS-05 recipe, on real pixels |
| 4 | **Escapable** — no keyboard trap; `walkBackward` returns the same descriptor sequence reversed | A trap is invisible to a forward-only walk |
| 5 | **Returned** — closing a dialog or sheet restores focus to the trigger | Focus dumped to `<body>` is a silent dead end for a screen-reader user |

**Do NOT convert the shipped accessible-name selectors to test ids.** `src/` carries **zero** test
ids on interactive elements by design: 92 `getByRole` / 30 `getByLabel` queries assert accessibility
as a side effect, and replacing them trades a real guarantee for a brittle one
(`selector-contract.ts`). A `data-testid` is added **only** where a role or label query cannot express
the target — structural containers, skeleton wrappers, state panels.

**The composite-widget observation from Phase 15, and it is an observation:** `/signup`'s radio group
makes every radio focusable, so a keyboard user tabs *through* the group rather than into it and along
it with arrows. **WCAG 2.1.1 is satisfied either way** — every control is reachable and operable. What
differs is authoring practice against the WAI-ARIA pattern. If this phase changes it, it changes
`e2e/auth-keyboard.spec.ts`'s declared sequence in the same commit. If it does not, it records why.

## Remediation rules — what this audit may change, and what it must escalate

The single highest-risk failure mode of this phase is a sweep that fixes nine surfaces into a
different product. These rules are the boundary.

### May fix in place, no escalation

| Change | Because |
|--------|---------|
| Adding a missing `aria-label` to an icon-only control | A control with no accessible name fails SC 4.1.2 outright; the name is not a design decision |
| Adding `role="status"` + `aria-busy` + an `sr-only` label to a skeleton | It is the **condition** that makes the 1.09:1 fill exclusion legal, not a nicety |
| Converting a hand-rolled `h-11` `<Button>` to `size="touch"` | Adopting a declared token — DS-09's whole point |
| Adding `whitespace-nowrap` / `min-w-0` to satisfy the no-wrap clause | Both are already the shipped idiom at the sticky bar |
| Adding padding to reach the 24px conformance floor | WCAG 2.5.8 AA is a conformance requirement, not a house style |
| Adding a `data-testid` to a **structural container** the sweep must scope to | Explicitly sanctioned by the GATE-04 scope rule |
| Adding a measured row to `contrast-pairs.ts` for a rendered pairing axe found | The declared mechanism for exactly this |
| Fixing a heading level to close a skipped step | `heading-order` is an axe conformance rule |
| Correcting a stale comment that promises coverage this phase did not build | An inaccurate comment is a defect |

### Must escalate — record the finding, do not fix

| Change | Because |
|--------|---------|
| Any token **value** moving | Re-derives 40 pairs × 2 themes and invalidates 36 baselines. Phase-10 amendment. |
| An 11th `ACCENT_USES` entry | The list is closed and type-pinned. A surface that wants accent is a product question. |
| A 4th card pattern, a 2nd overlay mechanism, a 5th type role, a new spacing value | Each is a declared closed set. |
| Any product **copy** change | Copy is owned by the surface's own UI-SPEC. See § Copywriting. |
| Any change to booking, payment, capacity or availability **logic**, or moving a computation client-side | **D-130.** The GiST `EXCLUDE`, the advisory-locked admissions counter, webhook-as-sole-confirm-authority and server-side price/availability authority are untouchable. |
| A schema migration | **GATE-06.** Scope alarm, raised explicitly. |
| Removing a control, a disclosure or a state to make a 320px measurement pass | The measurement is reporting a real constraint. Deleting the thing being measured is not a fix. |
| Reversing a recorded decision (installing `sheet`, adding `@tailwindcss/typography`, making `touch` a responsive default, re-forking a header) | Each was considered and rejected with a stated reason. Reversal needs the same treatment, not an audit commit. |

### The escalation format

Every escalated finding lands in `deferred-items.md` with: **the measurement** (a number, in a named
theme, at a named width, on a named route), **the owner file**, **why it was not fixed here**, and
**the cheapest correct fix**. That is the format Phases 13–16 already use, and it is what made this
phase's inheritance legible instead of archaeological.

## Copywriting Contract

**Phase 17 ships no product surface, so it authors no product copy.** Every user-facing string is
owned by the surface's own UI-SPEC and is preserved verbatim. What this phase *does* own is
**accessible-name copy** — text that exists only for assistive technology, which is copy nonetheless
and is exactly what an a11y audit adds.

| Element | Copy |
|---------|------|
| **Primary CTA** | **None.** This phase adds no CTA and changes no CTA label. The shipped `variant="brand"` labels stand verbatim: **"Book this space"**, **"Confirm & pay"**, **"Invite people"**, **"Find a space"**, **"Create your first listing"**. |
| **Accessible name — icon-only controls** | The **visible action**, not the icon. `aria-label="Profile"`, `aria-label="Menu"`, `aria-label="Notifications"` — never "icon", never "button", never a filename. Where a label is CSS-hidden below a breakpoint, the wrapper carries `aria-label` and the glyph carries `aria-hidden="true"` (the shipped `ProfileLink` mechanism). |
| **Two mechanisms, two reasons — do not merge them** | **`hidden`** removes content from the accessibility tree: correct for the nav-duplication case (one landmark at any viewport), **wrong** for an icon-only control, which it would leave with no accessible name at all. **`aria-label`** names an icon-only control. Applying either in the other's place is a real WCAG 4.1.2 failure, and this repo has already shipped that bug once. |
| **Loading announcements** | `sr-only`, naming **what** is loading: **"Loading your bookings"**, **"Loading spaces"**, **"Loading this listing"**. Shipped; preserved verbatim. |
| **Empty state heading / body** | **No change.** All eight converted empty states keep their shipped copy, including `/host/requests`' **"You're all caught up"**. |
| **Error state** | **No change.** **"Something didn't load"** / *"We hit a problem loading this page. Trying again usually fixes it."* + **"Try again"** + a group-specific route out. Never a bare "Something went wrong" with one button. |
| **Destructive confirmation** | **None in this phase.** No Phase-17 task performs or introduces a destructive product action. The `destructive` recipe (tint at rest, solid fill + `--destructive-foreground` on hover) is inherited unchanged and unused. |
| **Gate failure messages** *(the copy this phase genuinely authors)* | Every new assertion's failure message names **the measurement, the theme, the width, the route and the element** — never "assertion failed". A gate whose message has only ever been produced by a passing run is a message nobody has read; drive it with a synthetic input in a self-test, the `leak.test.ts:208-212` rule. |

**Copy rules this phase inherits and must not break:**

- *Occupancy and unavailability are normal states — never errors, never red.* An unlisted space is not
  an error page; an empty inbox is not a failure.
- *Never blame the user.* No "invalid", no "illegal", no "you did something wrong".
- *Every error names what to do next.* A state with no action is a dead end.
- *A rate is not a total (D-75).* The audit may not turn one into the other to make a box fit.

## Anti-Patterns — reject these in plan review

**Scope**

- **Treating this as a design phase.** A new token, role, pattern, spacing value or accent use in a
  Phase-17 plan is a rewrite wearing an audit's clothes.
- **Fixing a finding by deleting the thing being measured** — removing a disclosure, a control or a
  state so a 320px box fits.
- **Absorbing a schema migration** because a fix seemed to need one. GATE-06 is a scope alarm.
- **Moving a computation client-side** to make an interaction feel better. D-130.

**Instruments**

- **A second definition of "visible focus indicator."** `expectRing` in `e2e/helpers/focus.ts` is the
  only one. A ring is a `box-shadow`.
- **An axe assertion with no vacuity guard.** Zero violations over a page that failed to load reads
  exactly like a pass.
- **`disableRules` on the axe builder.** Exclusions are `.exclude(selector)` with a committed reason.
- **Asserting 44px on every control.** The conformance bar is 24 (SC 2.5.8 AA). 44 is asserted by
  name, per surface. A blanket 44 is red against reviewed, correct code.
- **A no-wrap assertion against a literal line-height**, or one without its two guards (non-empty
  text, finite `lineHeight`). A `normal` line-height parses to `NaN` and makes the clause vacuous.
- **Measuring the sheet row at document level.** With the sheet open `<body>` is a 320px box that
  clips its own content — scope to `[data-testid="responsive-dialog"]` (16-D9).
- **A "green" read off a generation run.** GATE-01's evidence is a green **comparison** run on the
  phase's head commit (13-16).
- **Converting shipped `getByRole` / `getByLabel` selectors to test ids.** Trades a real accessibility
  guarantee for a brittle one.
- **A second `host-headings` file.** The outline walk joins the existing 28-state loop.
- **Watching heading-order red against a DUPLICATED level.** The failure mode is a SKIPPED level.

**Inherited decisions that must not be reversed by an audit commit**

- **Installing shadcn `sheet`** — two focus traps, two escape behaviours, two baseline sets.
- **Adding `@tailwindcss/typography`** — a second, un-gated type system.
- **Making `size="touch"` a responsive default** — considered and rejected (10-06); it silently
  changes every dense host table's mobile rendering.
- **Adding `ring-offset` to the `RowCard` overlay link** — renders a 2px band inside the card.
- **Re-forking or merging the three header compositions** — D-04.
- **Committing a grove baseline** — D-138.
- **Adding a fifth theme-swap surface without amending D-138 in prose.**
- **"Flipping" a leak gate that is already blocking**, or reporting that flip as work done.
- **Updating `LAST_MIGRATION` to make GATE-06 pass.**
