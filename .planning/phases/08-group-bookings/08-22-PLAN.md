<objective>
Close `08-REVIEW-gaps.md` **HG-01** — the edit-path half of `deferred-items.md` item 7 the code review surfaced.

08-20 put the surcharge-reachability rule (`included < maxOccupancy` whenever `extraHeadFee > 0`) on `publishSchema`, which runs ONLY in `publishListing`. But a host edits a listing — including an already-**published** one — through `saveListingStep` (`src/app/actions/listing.ts:97`), which re-validates with the permissive `draftSchema` and writes `included` / `extraHeadFee` / `maxOccupancy` straight to the live row (`:136-148`) with **no publish re-gate**. So a host can publish a valid per-head listing and then, on the routine "edit my price" workflow, set `included >= maxOccupancy` (or lower `maxOccupancy` below `included`) and it saves silently — reproducing exactly the revenue-loss bug 08-20 claims to close, just one step later. This is the same class as the already-documented WR-09 (publish-time validation not re-enforced on edit), now on the surcharge field.

**The fix:** in `saveListingStep`, when the persisted listing is already `published` and a per-head fee is in effect, apply the same cross-field rule against the EFFECTIVE post-save values and reject the edit. `assertOwnership` already returns the full row (`SELECT *`), so the persisted `included` / `extraHeadFee` / `maxOccupancy` are in hand with no extra query — essential, because a sparse autosave may carry only one of the three and the guard must read the other two from the row. Drafts stay permissive (publishSchema still catches them at publish). To keep the publish gate and the edit gate from ever drifting, the user-facing message becomes one shared exported constant used by both.

**Scope boundary — edit path only.** This does not change the publish gate (08-20), the pricing engine, or draft autosave semantics. It does not touch the money/checkout path. It closes the one HIGH finding from the gap-closure review so item 7 is fully closed for both the publish and the edit surface.

Purpose: a host cannot make a per-head surcharge unreachable, whether at publish OR by later editing a live listing.
Output: `saveListingStep` rejects an unreachable-surcharge edit on a published listing; one shared reject message; a DB-backed mutation-proven test.
</objective>
