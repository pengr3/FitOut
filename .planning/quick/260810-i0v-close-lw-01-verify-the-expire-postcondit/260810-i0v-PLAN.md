<objective>
Close **LW-01** — the first half of v1.0 milestone-audit tech-debt item #5. `expireCheckoutSession`
(`src/lib/paymongo.ts:250-279`) currently tolerates a repeat-expire as success only when the thrown error
message matches BOTH `/\(400\)/` and `/already\b.*\bexpired/i`. That is string-matching a third party's
prose on the money path. If PayMongo rewords, localizes, or re-codes that 400, the tolerance silently stops
matching, the fail-closed catch reverts to genuine-failure behaviour, and the recovery-path livelock 08-21
closed (T-08-84) silently reappears — with no automated detector, since the unit tests pin the *currently
observed* string and the only real-API proof is the gated `RUN_LIVE_PAYMONGO_PROBE=1` suite that is not in CI.

Replace inference-from-prose with **verification-from-the-provider**: on ANY error from the expire POST, do
exactly ONE re-probe with the `getCheckoutSession(id)` helper that already exists in this same file
(`src/lib/paymongo.ts:289`), and tolerate the error as success **only if the provider itself reports
`status === "expired"`**. The postcondition of expire — *this session can never be paid* — becomes a fact
read back from PayMongo instead of a guess made from an error sentence.

Purpose: this is a MONEY-PATH change. The failure it prevents is silent and third-party-triggered.
Output: a probe-verified `expireCheckoutSession`, a rewritten and mutation-proven test block, the NT-01
title correction, and four planning documents brought in line — with **T-08-74 left accurately OPEN**.
</objective>
